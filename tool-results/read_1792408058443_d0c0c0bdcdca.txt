    40→## 2. Engine overview
    41→
    42→### 2.1 Pipeline end-to-end
    43→
    44→The engine is a staged pipeline (MP §3): **input** turns a `SourceSpec` (file,
    45→URL, synthetic test source) into a byte stream with deadlines; **probe** scores
    46→formats over a bounded lookahead; a **demuxer** is instantiated and emits
    47→timestamped packets per track; packets flow through **bounded per-medium
    48→queues** into **decoders** behind the `codec-api` traits; decoded audio goes
    49→through the **audio-engine** (conversion, filters, mixing) into an
    50→**audio-output** device whose real-time callback is fed from a ring buffer;
    51→decoded video frames go through the **video-engine** presentation scheduler to
    52→the **renderer-wgpu** surface. One **media-clock**, audio-master by default,
    53→drives timing. Subtitles, chapters and metadata ride the same pipeline as timed
    54→events. The **playback-engine** session object owns the state machine, mints
    55→generation IDs, and orchestrates every transition. Playlists live outside the
    56→pipeline and interact with it only by issuing source/queue commands.
    57→

    97→### 2.3 Ownership rules
    98→
    99→1. The engine owns playback state and every media decision (MP §2): which
   100→   tracks are default-selected (rules from `product.toml`, MP §5), buffering
   101→   watermarks, seek target snapping, frame-drop policy, device fallback order.
   102→   The UI owns presentation and component state, nothing else.
   103→2. The playback session object is the **single writer** for mutable playback
   104→   state (position, rate, selected tracks, state-machine node). Everything
   105→   else holds read snapshots delivered as events.
   106→3. The renderer is isolated from decode and demux (MP §3.4): `renderer-wgpu`
   107→   depends only on media-types frame handles and its own surface types. It
   108→   never sees packets, demuxers or codec types.
   109→4. Crates depend downward only (MP §3.1–3.2, 3.8): media-types is the leaf;
   110→   input/demux depend on media-types + shared interfaces; codec-api depends on
   111→   media-types; audio/video engines depend on codec-api + media-clock; the
   112→   playback-engine depends on all of the above; nothing engine-side depends on
   113→   UI, Tauri, wasm-bindgen, or platform crates except through the adapter
   114→   traits in §3.9. CI enforces this with the boundary check (MP §3.8).
   115→5. No cyclic dependencies, no global mutable state; cross-thread communication
   116→   is via explicit channels, ring buffers and generation-checked queues only.
   117→6. Test utilities may depend on production crates, never the reverse (MP §3.7).
   118→
   119→## 3. Shared type foundations (`media-types`)
   120→
   121→(a) **Responsibility.** The leaf crate that defines the explicit vocabulary
   122→types every other crate speaks (MP §8 bullet 1). No I/O, no threads, no
   123→platform.
   124→
   125→(b) **Type sketch.**
   126→
   127→```rust
   128→pub struct TimeBase { pub num: u32, pub den: u32 }        // tick = num/den s
   129→pub enum Ts { Present(u64), Missing, Invalid }            // raw ticks, no sentinels
   130→pub struct PacketTs { pub dts: Ts, pub pts: Ts, pub dur: Ts }
   131→
   132→/// Normalized media time in nanoseconds. Constructed only via checked
   133→/// conversions from (Ts, TimeBase); conversion never wraps silently.
   134→pub struct MediaTime(i64);
   135→impl MediaTime {
   136→    pub fn from_ts(t: Ts, base: TimeBase) -> Option<MediaTime>; // None on overflow
   137→    pub fn saturating_add(self, rhs: MediaTime) -> MediaTime;
   138→}
   139→
   140→pub type TrackId = u32;
   141→pub enum TrackKind { Audio, Video, Subtitle, Data, Unknown }
   142→pub struct TrackInfo {
   143→    pub id: TrackId, pub kind: TrackKind, pub codec: CodecId,
   144→    pub language: Option<LangTag>, pub title: Option<String>,
   145→    pub default_selected: bool, pub bit_rate: Option<u64>,
   146→}
   147→
   148→/// Reference-counted, non-UTF8 byte buffer (candidate: see doc 04).
   149→pub type Bytes = /* alias chosen in doc 04 */;
   150→
   151→pub struct Packet {
   152→    pub track: TrackId, pub ts: PacketTs, pub keyframe: bool,
   153→    pub data: Bytes,                       // may be empty (container-level event)
   154→    pub discontinuity: bool,               // explicit, set by demuxer
   155→}
   156→pub type Generation = u64;                 // minted only by playback-engine
   157→
   158→pub enum PixelFormat { /* Rgba8, Nv12, I420(=Yuv420P), ... enumerated */ }
   159→pub enum SampleFormat { I16, F32, PlanarF32, /* ... */ }
   160→```
   161→
   162→(c) **Threading.** None; all types are `Send + Sync` plain data.
   163→(d) **Errors.** Conversions return `Option`/`Result`, never wrap. `Ts::Invalid`
   164→is carried, not corrected: repairing timestamps is a demux-stage policy, and it
   165→must be observable (counted, event-emitted).
   166→(e) **Invariants.** `MediaTime` is only produced by checked conversion; no
   167→sentinel values exist (`u64::MAX` is a legal tick count, not a marker);
   168→`TimeBase.den != 0` enforced by constructor.
   169→(f) **Tests.** Property tests (candidate: see doc 04) over random
   170→`(Ts, TimeBase)` pairs: overflow never wraps, missing/invalid propagate,
   171→round-trip within precision; unit tests for documented saturation semantics.
   172→
   173→## 4. Per-subsystem specifications
   174→
   175→### 4.1 input — byte-stream access abstraction
   176→
   177→(a) **Responsibility.** Turn a `SourceSpec` into a `ByteStream`: positioned
   178→reads with explicit seekability, size, deadlines, and cancellation. Implements
   179→file, HTTP(S) (Phase 6), and test synthetic sources. Knows nothing of formats.
   180→
   181→(b) **Trait sketch.**
   182→
   183→```rust
   184→pub enum Seekability { Seekable { size: u64 }, Unseekable { total: Option<u64> } }
   185→pub enum ReadErr { Eof, Timeout, Interrupted, Unreachable, Denied, Corrupt, Gone }
   186→
   187→pub trait ByteStream: Send {
   188→    /// Reads up to buf.len() bytes; Ok(0) == Eof is an error variant, not a trap.
   189→    fn read(&mut self, buf: &mut [u8], deadline: Instant) -> Result<usize, ReadErr>;
   190→    /// Non-consuming lookahead used by probe. Returns bytes actually available.
   191→    fn peek(&mut self, out: &mut Vec<u8>, want: usize, deadline: Instant)
   192→        -> Result<usize, ReadErr>;
   193→    fn seek(&mut self, to: u64) -> Result<u64, ReadErr>;      // Err if unseekable
   194→    fn position(&self) -> u64;
   195→    fn seekability(&self) -> Seekability;
   196→    /// Cooperative cancellation checked between internal read chunks.
   197→    fn set_cancel(&self, token: CancelToken);
   198→    fn source_meta(&self) -> SourceMeta { /* mime hint, uri, content headers */ }
   199→}
   200→pub trait SourcePlugin { /* manifest-selected factory: SourceSpec -> ByteStream */ }
   201→```
   202→
   203→(c) **Threading.** One reader thread per open source (§9). The thread performs
   204→blocking reads and honors `deadline` and the cancel token; adapters for sockets
   205→must use timeout-capable APIs (candidate: see doc 04) so deadlines are real,
   206→not advisory.
   207→
   208→(d) **Errors.** Typed `ReadErr`; `Timeout` is not fatal: the session decides
   209→(persistent timeout on a file → `Error(ResourceLimit)`; live/network source →
   210→stay in `Buffering` and keep retrying within policy). Secrets (URLs with
   211→credentials, headers) are redacted in logs and errors (MP §12).
   212→
   213→(e) **Invariants.** Reads never exceed the deadline except by a documented
   214→adapter margin; cancellation is observed within one internal chunk (≤ 64 KiB
   215→of transferred data) [PROPOSAL: bound]; `peek` never consumes — the probe
   216→prefix is handed to the demuxer, so unseekable sources are never re-read.
   217→(f) **Tests.** Unit: synthetic stream with scripted faults (delay, truncate,
   218→reset, garbage). Property: read/seek positions always consistent with
   219→`Seekability`. Integration: missing file, unreadable file, file that shrinks
   220→mid-read, interrupted network (scripted socket source), source that hangs
   221→forever (deadline fires). Fuzz: malformed URI parsing.
   222→
   223→### 4.2 media-probe — bounded format detection
   224→
   225→(a) **Responsibility.** Identify the container format from a bounded lookahead
   226→window, with confidence scores, and select the demuxer plugin. Never probe
   227→unbounded data (MP §12: bound probing depth).
   228→
   229→(b) **Type sketch.**
   230→
   231→```rust
   232→pub struct ProbeHit { pub format: FormatId, pub score: u8 /* 0..=100 */ }
   233→pub trait ProbePlugin {
   234→    fn probe(&self, prefix: &[u8], meta: &SourceMeta) -> Option<ProbeHit>;
   235→}
   236→pub struct ProbeConfig { pub max_lookahead: usize, pub min_score: u8 }
   237→```
   238→
   239→Defaults [PROPOSAL, overridable from `product.toml` resource limits]:
   240→`max_lookahead = 64 KiB` hard-capped at 1 MiB; `min_score = 60`. Probing reads
   241→*only* through `ByteStream::peek` up to `max_lookahead` bytes; there is no code
   242→path that probes more.
   243→
   244→(c) **Threading.** Runs on the session's open path (the input reader thread
   245→fills the peek buffer; scoring itself is trivial CPU work on the session
   246→thread).
   247→
   248→(d) **Errors.** No hit ≥ `min_score` → `Error(Unsupported)` carrying whatever
   249→is known: magic bytes inspected, mime hint, size. Never a guess presented as
   250→fact (MP §8 bullet 6).
   251→
   252→(e) **Invariants.** Scoring is a pure function of `(prefix, meta)`; ties break
   253→by plugin priority from the manifest (MP §6), then by shorter prefix consumed
   254→[PROPOSAL]. The probe never consumes stream bytes; the selected demuxer
   255→receives `prefix` as already-read data. One-shot probing in v1: a format that
   256→only becomes identifiable deep in the stream is reported unsupported, not
   257→silently re-probed [PROPOSAL — VLC's "format growing" behavior is out of scope
   258→v1, revisit in Phase 5].
   259→(f) **Tests.** Unit: known-prefix corpus per format plugin. Property: for any
   260→input, lookahead bytes read ≤ `max_lookahead` (instrumented stream asserts
   261→this). Fuzz: random prefixes must never panic any probe plugin. Integration:
   262→files with valid content but wrong extension (extension is a hint, not truth),
   263→empty files, 1-byte files.
   264→
   265→### 4.3 demux — container parsing, track discovery, packet emission, seeking
   266→
   267→(a) **Responsibility.** Parse the container, expose tracks, duration and
   268→seekability; emit packets with explicit timestamps; implement the seek
   269→contract including keyframe indexes.
   270→
   271→(b) **Trait sketch.**
   272→
   273→```rust
   274→pub enum SeekSupport { Fast { indexed: bool }, SlowLinear, None }
   275→pub struct DemuxCtx<'a> {
   276→    pub cancel: &'a CancelToken,       // checked between packets
   277→    pub on_tracks: &'a dyn FnMut(&[TrackInfo]),  // discovery may be incremental
   278→}
   279→pub trait Demuxer: Send {
   280→    fn open(prefix: Bytes, stream: Box<dyn ByteStream>, cfg: &DemuxConfig)
   281→        -> Result<Self, DemuxError> where Self: Sized;
   282→    fn tracks(&self) -> Vec<TrackInfo>;              // snapshot, may grow
   283→    fn duration(&self) -> Option<MediaTime>;         // None = unknown, never guessed
   284→    fn seekability(&self) -> SeekSupport;
   285→    /// Returns the *actual* positioned time (≤ target normally; formats may
   286→    /// only approximate). On Err the demuxer MUST be left in a defined state
   287→    /// (see invariant D4) — this is what makes failed seeks recoverable.
   288→    fn seek(&mut self, target: MediaTime) -> Result<MediaTime, DemuxError>;
   289→    /// Next packet; Err(Eof) at end of stream. Interrupted if cancelled.
   290→    fn read_packet(&mut self, ctx: &mut DemuxCtx) -> Result<Packet, DemuxError>;
   291→    fn keyframe_index(&self, track: TrackId) -> Option<Vec<MediaTime>>; // sparse ok
   292→}
   293→```
   294→
   295→(c) **Threading.** One demux thread per active source, owns the `Demuxer`
   296→instance exclusively. No locks: packets flow into the bounded queues (§4.4).
   297→
   298→(d) **Errors.** `DemuxError::{ Unsupported, Corrupt { offset, detail }, Eof,
   299→Interrupted, ResourceLimit }`. Corrupt-but-skippable data: drop the damaged
   300→packet/run, count it, emit a `DamagedData` event, continue — bounded recovery
   301→(MP §8 bullet 4). Structural corruption that desynchronizes parsing: attempt
   302→resynchronization once within a bounded window [PROPOSAL: 1 MiB or 1000
   303→packets], else fatal `Corrupt`.
   304→(e) **Invariants.**
   305→- D1: every emitted packet carries `PacketTs` with explicit variants; repairs
   306→  (e.g., interpolating from durations) are counted and flagged via
   307→  `discontinuity = true` or a repair counter, never silent.
   308→- D2: keyframe flags are format-truth: `keyframe=true` only when the container
   309→  or codec grammar guarantees a random-access point.
   310→- D3: track discovery may be incremental; `TracksChanged` events are emitted
   311→  whenever the snapshot grows.
   312→- D4: a failed `seek` leaves the demuxer at a defined position (either the
   313→  pre-seek position or EOF) with a valid parsing state; this is the foundation
   314→  of §6's failed-seek behavior.
   315→- D5: `read_packet` observes cancellation between packets (returns
   316→  `Interrupted`), so a stuck demuxer cannot outlive its generation by more
   317→  than one packet.
   318→(f) **Tests.** Per-format conformance kit (MP §6): valid corpus with recorded
   319→expected track lists and packet counts; truncated-at-every-offset corpus;
   320→corrupt-byte-injection corpus; property tests that emitted timestamps are
   321→monotonic within a discontinuity-free run; seek tests: seek(N random targets)
   322→must land within the format's documented tolerance of a keyframe ≥ target-or-
   323→below per policy. Every demuxer plugin has a registered fuzz target (MP §6).
   324→
   325→### 4.4 packet-queue — bounded queues, backpressure, generation stamps
   326→
   327→(a) **Responsibility.** Bounded packet and frame buffers between demux,
   328→decode, and the engines; enforce backpressure; drop stale generations at every
   329→boundary (MP §8 bullet 2).
   330→
   331→(b) **Type sketch.**
   332→
   333→```rust
   334→pub struct BoundedQueue<T> { /* condvar + Mutex<VecDeque<Stamped<T>>>>, or
   335→    lock-free MPMC from doc 04 behind this type [PROPOSAL: start with the
   336→    simple version, swap internals later without changing the API] */ }
   337→pub struct Stamped<T> { pub gen: Generation, pub value: T }
   338→pub struct QueueLimits { pub max_packets: usize, pub max_bytes: usize,
   339→                         pub max_duration: MediaTime }   // whichever hits first
   340→
   341→impl<T> BoundedQueue<T> {
   342→    /// Parks the producer while full. Wakes on: space, generation bump, or
   343→    /// deadline. Producer rechecks its own generation after every wake.
   344→    fn push(&self, item: Stamped<T>, gen_check: &CancelToken)
   345→        -> Result<(), PushAborted>;
   346→    /// Consumer-side; Err(Empty) means "would block", callers poll or await.
   347→    fn pop(&self) -> Result<Stamped<T>, QueueEmpty>;
   348→    fn flush(&self, new_gen: Generation);  // O(len): drop all, publish gen
   349→    fn watermark(&self) -> Watermark;     // {low, high} hit flags, bytes, span
   350→}
   351→```
   352→
   353→Defaults [PROPOSAL, config in `product.toml` cache limits]: audio queue 1.0 s /
   354→200 packets, video queue 2.0 s / 300 packets, both hard-capped in bytes by the
   355→memory budget; subtitle/event queue small and duration-only.
   356→
   357→(c) **Threading.** Producers: demux thread (packets), decode workers (frames).
   358→Consumers: audio pump, video scheduler. The internal lock is held only for
   359→deque pushes/pops — never across I/O or decode (MP §8 bullet 3).
   360→(d) **Errors.** No fallible behavior of its own; `PushAborted` means "your
   361→generation is stale or the queue closed" — the producer must stop, not retry.
   362→(e) **Invariants.**
   363→- Q1: at most `max_packets`/`max_bytes`/`max_duration` items resident, ever
   364→  (property-tested).
   365→- Q2: after `flush(new_gen)` returns, no `Stamped` with `gen < new_gen` can be
   366→  popped, and a later `push` of an old-gen item is dropped at the boundary.
   367→- Q3: backpressure is the only flow control: the demux thread parks when full;
   368→  it never spins, never drops fresh data, and never blocks the session thread.
   369→- Q4: watermark state is the single input to `Buffering` state transitions.
   370→(f) **Tests.** Property: bounds hold under adversarial interleavings
   371→(model-check a small state machine: push/pop/flush concurrent). Race tests:
   372→producer parked on a full queue when flush happens must wake and observe
   373→`PushAborted` within a bounded number of wakeups. Unit: duration accounting
   374→with missing timestamps (unknown-duration packets must not wedge the
   375→`max_duration` computation — they count as 0 toward duration but still count
   376→in packets/bytes [PROPOSAL]).
   377→
   378→### 4.5 codec-api — decoder traits, negotiation, output declaration
   379→
   380→(a) **Responsibility.** Define the stable traits all decoders implement
   381→(built-in plugins today; OS hardware decoders behind the same traits after the
   382→Phase 0 ADR, MP §2). Own the push/pull decode contract, capability
   383→negotiation, and the decoder error model.
   384→
   385→(b) **Trait sketch.**
   386→
   387→```rust
   388→pub enum DecStatus { Ok, NeedMoreInput, Drained }
   389→
   390→pub struct DecoderConfig { pub codec: CodecId, pub extradata: Option<Bytes>,
   391→                           pub max_width: u32, pub max_height: u32, /* limits */ }
   392→/// Output declaration: the engine builds its conversion path from this.
   393→pub struct VideoOutDesc { pub pix_fmt: PixelFormat, pub w: u32, pub h: u32,
   394→    pub aspect: AspectRatio, pub color: ColorDesc /* primaries, range */ }
   395→pub struct AudioOutDesc { pub rate: u32, pub layout: ChannelLayout,
   396→                          pub sample_fmt: SampleFormat }
   397→
   398→pub trait VideoDecoder: Send {
   399→    fn negotiate(&mut self, cfg: &DecoderConfig) -> Result<VideoOutDesc, CodecError>;
   400→    fn send(&mut self, pkt: Packet) -> Result<(), CodecError>;      // non-blocking
   401→    fn receive(&mut self, out: &mut Vec<VideoFrame>) -> Result<DecStatus, CodecError>;
   402→    fn flush(&mut self);   // drop reorder buffers; next output restarts at a keyframe
   403→    fn drain(&mut self);   // emit everything decodable, then DecStatus::Drained
   404→}
   405→pub trait AudioDecoder: Send {
   406→    fn negotiate(&mut self, cfg: &DecoderConfig) -> Result<AudioOutDesc, CodecError>;
   407→    fn send(&mut self, pkt: Packet) -> Result<(), CodecError>;
   408→    fn receive(&mut self, out: &mut Vec<AudioFrame>) -> Result<DecStatus, CodecError>;
   409→    fn flush(&mut self);
   410→    fn drain(&mut self);
   411→}
   412→```
   413→
   414→Capability negotiation is manifest-driven (MP §6): each decoder plugin's
   415→manifest lists `formats` (codec IDs), priority, and limits; the engine registry
   416→selects by codec ID then priority; config may disable/reorder, never invent
   417→(MP §5). If no decoder exists for a track's codec: the track is reported
   418→`Unsupported` in `TrackInfo`-derived selection state — playback continues with
   419→the other tracks, and the UI shows a truthful unsupported state (never
   420→fabricated silence or frames, MP §8 bullet 6).
   421→
   422→(c) **Threading.** One `AudioDecoder` instance owned by the audio pump thread;
   423→`VideoDecoder` instances owned by decode workers in a pool sized to cores
   424→(persistent per track so internal state survives). `send`/`receive` are
   425→non-blocking; the worker parks on packet availability, not inside the decoder.
   426→
   427→(d) **Errors.** `CodecError::{ Unsupported, CorruptPacket { detail }, Fatal,
   428→ResourceLimit }`. Contract: `CorruptPacket` affects only the current packet —
   429→the decoder must return to a state where it can accept the next packet
   430→(decoders for formats where a damaged packet poisons following ones must
   431→document that and emit `Fatal` instead). Decoders never panic (workspace lints
   432→deny `panic`, MP §13). `Fatal` from a video decoder ends only that track's
   433→decode with a `TrackFailed` event; audio `Fatal` is session-fatal because the
   434→clock master is gone.
   435→(e) **Invariants.** Frames leave `receive` only with `Ts` resolved to
   436→`MediaTime` by the caller (engine applies the track's time base and
   437→discontinuity policy — decoders deal in raw ticks or packet-relative timing,
   438→per their capability); `flush` makes the next `receive` return nothing until a
   439→`send` after the flush; output after `drain` is `Drained` forever until
   440→`flush`. Output format may change mid-stream (stream switching); `receive`
   441→then returns a `FormatChanged(VideoOutDesc)` marker event [PROPOSAL] and the
   442→engine rebuilds the conversion path.
   443→(f) **Tests.** Contract test suite shipped in `testkit`, run against every
   444→decoder plugin (plugin conformance, MP §6): flush/drain state machine
   445→exercised exhaustively; corrupt-packet corpus per codec; decode-to-EOF; output
   446→determinism (same input → identical frame hashes — required for differential
   447→tests against external oracles, MP §13). Fuzz: bitstream parsers get dedicated
   448→fuzz targets with memory and time bounds.
   449→
   450→### 4.6 playback-engine — session model and state machine
   451→
   452→(a) **Responsibility.** The orchestrator: one `Session` object per playback;
   453→owns the state machine, mints generations, applies commands at defined points,
   454→wires the pipeline, and emits the event stream the command layer (doc 05)
   455→forwards to every client.
   456→
   457→(b) **Types and state machine.**
   458→
   459→```rust
   460→pub enum SessionState { Idle, Opening, Probing, Demuxing, Buffering,
   461→                        Playing, Paused, Ended, Stopped, Error }
   462→pub struct SessionHandle { /* Send commands, receive events */ }
   463→// Events (full list is doc 05's contract; engine-side subset):
   464→// StateChanged, TracksChanged, Buffering{range}, SeekAccepted, Seeked{req,act},
   465→// SeekFailed{reason, position}, FirstFrame{ts}, Ended, Error(stage,e),
   466→// DamagedData{count}, DeviceLost, ClockMasterChanged, TrackFailed
   467→```
   468→
   469→Full transition table (trigger → target, with side effects):
   470→
   471→| From | Trigger | To | Side effects |
   472→|---|---|---|---|
   473→| Idle | `Open(source)` | Opening | mint session epoch; spawn input thread with open deadline; emit `StateChanged` |
   474→| Opening | stream ready | Probing | run probe (§4.2) |
   475→| Opening | input error / deadline | Error | typed `Error(Inaccessible…)`; teardown |
   476→| Opening | `Stop` | Stopped | cancel token; join threads |
   477→| Probing | format ≥ min_score | Demuxing | construct demuxer with probe prefix; emit initial `TracksChanged` |
   478→| Probing | no format | Error | `Error(Unsupported, known magic/mime)` |
   479→| Demuxing | first playable packet queued | Buffering | watermark accounting begins |
   480→| Demuxing | EOF before watermark (short media) | Playing | immediate start, then quick drain to `Ended` |
   481→| Buffering | high watermark | Playing | clock un-paused; audio output started; first frame presented → `FirstFrame` |
   482→| Buffering | EOF before high watermark | Playing | short media: start with what exists |
   483→| Buffering | `Stop` | Stopped | flush, join |
   484→| Playing | `Pause` | Paused | clock frozen; audio sink paused (device kept); demux fills to high watermark then parks |
   485→| Paused | `Play` | Playing | clock resumes |
   486→| Playing | low-watermark underrun | Buffering | clock frozen; `Buffering{…}` event |
   487→| Playing | EOF + queues drained | Ended | clock stops at end; session retained (seek back allowed) [PROPOSAL] |
   488→| Ended | `Seek` | Buffering | seek flow §6, then Playing |
   489→| any active | `Stop` | Stopped | new generation; flush all; join; emit `SessionClosed`; engine → Idle |
   490→| any active | fatal error | Error | typed error; teardown as Stopped |
   491→| Playing/Paused/Buffering | `SwitchTrack` | Buffering | pipeline generation bump; flush affected limbs; demux rewinds/advances as needed; re-prime |
   492→| any active | `SetSource` (replacement) | Opening | new session epoch; old pipeline torn down concurrently under its stale generation; fresh open begins |
   493→
   494→**Command application points.** Commands are validated twice (MP §3.9): shape
   495→at the command layer boundary, then semantics at application time on the
   496→session thread. The session thread is the single writer and applies commands
   497→only between pipeline ticks — it never runs I/O or decode itself, so command
   498→latency is bounded by one tick (target: < 5 ms [PROPOSAL: measured in Phase 3
   499→benches, MP §11]). Commands invalid for the current state (e.g. `Pause` in
   500→`Idle`) return `CommandRejected{reason}` — a typed result, never an error
   501→crash. Accepted ≠ completed: e.g. `Seek` returns `SeekAccepted` immediately;
   502→truth of completion is the later `Seeked` event (MP §2 truthful UI).
   503→
   504→(c) **Threading.** One session thread per `Session`. Owns: state, generation
   505→counters, watermark policy, clock anchor decisions. Communicates: command
   506→inbox (mpsc), event bus (broadcast), and control atomics to demux/decode/
   507→schedulers.
   508→(d) **Errors.** Every failure names its stage (MP §8 bullet 4):
   509→`Error{stage: Open|Probe|Demux|Decode|AudioOut|VideoOut|Resource, kind}`.
   510→Open failure never yields a Playing-looking session (MP §8 bullet 4).
   511→(e) **Invariants.** S1: state transitions occur only on the session thread.
   512→S2: a session in `Error`/`Stopped` is inert: no thread it spawned is joinable
   513→later than a documented teardown deadline [PROPOSAL: 2 s]. S3: the session
   514→thread performs no blocking call with unbounded duration. S4: source
   515→replacement never reuses the old epoch's demuxer, queues, or decoders.
   516→(f) **Tests.** Model-based property tests: the transition table above is the
   517→model; random command sequences (open/play/pause/seek/switch/stop interleaved)
   518→must never (i) reach an illegal state, (ii) emit events out of the documented
   519→order per command, (iii) hang (all with virtual time). Integration: the §8
   520→scenario list maps here 1:1. Soak: open/play/stop 1000× watching for leaks
   521→(queue resident bytes, thread count, fd count — via testkit instruments).
   522→
   523→### 4.7 media-clock — audio-master timing
   524→
   525→(a) **Responsibility.** Provide `now(): MediaTime` for the whole pipeline,
   526→anchor it to the audio output position when audio exists, fall back explicitly
   527→when it does not, correct drift, and re-anchor on discontinuities.
   528→
   529→(b) **Type sketch.**
   530→
   531→```rust
   532→pub enum ClockMaster { AudioOutput, SystemMonotonic }
   533→pub struct ClockAnchor { pub media: MediaTime, pub at_sample: Option<AudioSampleCount>,
   534→                         pub at_instant: Option<Instant> }
   535→pub trait PlaybackClock: Send + Sync {
   536→    fn now(&self) -> MediaTime;                 // media time, monotonic per anchor
   537→    fn master(&self) -> ClockMaster;
   538→    fn reanchor(&self, media: MediaTime);       // used at open, seek, discontinuity
   539→    fn set_rate(&self, rate: f64);              // 1.0 default; range-checked
   540→}
   541→```
   542→
   543→(c) **Threading.** No dedicated thread. The audio pump updates the anchor from
   544→device sample counters (read atomically); readers (`now()`) are wait-free
   545→(seqlock-style or two-word atomic — no locks on the read path; the internal
   546→short lock, if any, is never held across I/O).
   547→(d) **Errors.** The clock has no failure modes of its own; it reports master
   548→changes (`ClockMasterChanged`) as events. Missing audio track or unsupported
   549→audio → master is `SystemMonotonic`, and the UI is told (truthful state, not a
   550→silent approximation).
   551→(e) **Invariants and semantics.**
   552→- Audio-master: `now() = anchor.media + (device_samples - anchor.at_sample) /
   553→  rate` when audio is running; the device sample counter is the only trusted
   554→  progress source. Video never advances the clock.
   555→- Monotonic: within one anchor epoch, `now()` never goes backwards; on
   556→  `reanchor` (seek, discontinuity) a jump is expected and reported.
   557→- Discontinuity: demuxer flags (packet `discontinuity`, PTS jumps beyond a
   558→  threshold [PROPOSAL: half the queue duration]) cause the session to
   559→  `reanchor` at the next audio frame actually output, and video re-syncs
   560→  against the new anchor.
   561→- Drift correction: video presentation error is absorbed by the video
   562→  scheduler (§4.10). Audio-side drift (device clock vs media rate) is absorbed
   563→  by a bounded micro-resampler in audio-engine: correction rate limited to
   564→  ±1000 ppm [PROPOSAL — final number from Phase 3 measurements; the limiter
   565→  itself is the invariant, not the value].
   566→- Pause: `now()` freezes (audio device paused, sample counter frozen); resume
   567→  continues from the same media time.
   568→(f) **Tests.** Unit: anchor arithmetic incl. rate ≠ 1. Property: monotonicity
   569→under concurrent readers during reanchors; virtual-clock determinism. Tests
   570→for the fallback: audio-less media keeps playing on system time and emits
   571→`ClockMasterChanged`. Overflow: extreme sample counts and rates.
   572→
   573→### 4.8 audio-engine — filters, conversion, mixing, gapless
   574→
   575→(a) **Responsibility.** Take decoded `AudioFrame`s from every active audio
   576→track, convert to the mixer format, run the user filter chain, mix, convert to
   577→the device format, and feed the output ring. Also owns gapless transitions.
   578→
   579→(b) **Type sketch.**
   580→
   581→```rust
   582→pub struct AudioPipeline { /* built per track: decoder-out -> filters -> mixer in */ }
   583→pub trait AudioFilter: Send {
   584→    fn input_desc(&self) -> AudioOutDesc; fn output_desc(&self) -> AudioOutDesc;
   585→    fn process(&mut self, inp: &[AudioFrame], out: &mut Vec<AudioFrame>);
   586→}
   587→/// Insertion points (fixed by design, contents are config-driven, MP §5):
   588→///  A: decoder output (per track) — e.g. format normalization
   589→///  B: user filters (EQ, compressor, spatializer — profiles/, MP §4)
   590→///  C: mixer stage — per-track volume/pan, summing
   591→///  D: device adaptation — rate/channel/format conversion, micro-resample
   592→pub struct MixPoint { pub track: TrackId, pub gain_db: f32, pub pan: PanLaw }
   593→```
   594→
   595→(c) **Threading.** The audio pump thread (§9): pull frames → filter chain →
   596→mix → push into the SPSC ring feeding the device. The pump is deadline-driven:
   597→it must keep the ring above a safety level computed as device latency + jitter
   598→margin [PROPOSAL: 20 ms default]. The pump never allocates per frame (buffers
   599→preallocated at format negotiation).
   600→(d) **Errors.** Filter graph construction failures are `Error(Resource)` at
   601→setup; runtime filter faults isolate to a bypass of that filter plus an event
   602→— audio continues (bounded recovery, MP §8 bullet 4). Underrun (pump too slow)
   603→is measured and reported as `AudioUnderrun{count}` (MP §11 metric), audible
   604→glitch policy: output silence, never repeat old audio.
   605→(e) **Invariants.** One mixer format chosen at first track negotiation
   606→[PROPOSAL: floating-point planar at the track's rate, converted at stage D];
   607→later tracks convert into it. Sample counts leaving the pipeline map 1:1 to
   608→device samples advanced (clock correctness depends on this). Per-track volume
   609→never clips the sum before stage D limiting [PROPOSAL: soft limiter at stage D
   610→end, on by default, configurable].
   611→(f) **Tests.** Unit: conversion correctness (rates, layouts) against
   612→generated sine/sweep signals; mixer sums; gain math. Property: for any filter
   613→chain, `out_samples == in_samples` unless the filter declares a rate change
   614→(model-checked). Gapless: two synthetic tracks spliced at a sample boundary —
   615→no gap, no overlap, no clock jump. Fuzz: filter parameter ranges.
   616→
   617→### 4.9 audio-output — device abstraction, real-time rules
   618→
   619→(a) **Responsibility.** Own the OS audio device behind an adapter trait; run
   620→the real-time callback; handle device loss and device switching (platform
   621→adapters implement the trait; OS types never leak, MP §3.6).
   622→
   623→(b) **Trait sketch.**
   624→
   625→```rust
   626→pub struct DeviceDesc { pub name: String, pub layout: ChannelLayout,
   627→                        pub rate: u32, /* pref format */ }
   628→pub enum SinkEvent { DeviceLost, DeviceChanged, Underrun(u64) }
   629→pub trait AudioSink: Send {
   630→    fn open(&mut self, want: AudioOutDesc) -> Result<DeviceSession, SinkError>;
   631→    fn pause(&mut self) -> Result<(), SinkError>;
   632→    fn resume(&mut self) -> Result<(), SinkError>;
   633→    fn latency(&self) -> MediaTime;
   634→    fn sample_counter(&self) -> u64;   // the clock's truth source
   635→}
   636→/// The callback contract (RT rules below):
   637→pub trait RenderCallback {
   638→    /// Copy interleaved frames from the ring into `out`. Runs on the device's
   639→    /// high-priority thread.
   640→    fn render(&mut self, out: &mut [f32]);
   641→}
   642→```
   643→
   644→(c) **Threading + real-time rules (binding, MP §8 bullet 3).** The callback
   645→executes on the OS device thread. Inside `render` it is **forbidden**: any
   646→lock except the SPSC ring's wait-free index swap; allocation; logging; syscalls;
   647→unbounded loops. Enforcement: `testkit` provides a fault-injecting allocator
   648→and a lock-tracer that run the callback under an allocator hook which panics
   649→(or flags in tests) on allocation [PROPOSAL: tooling detail]; code review plus
   650→these tests are the gate. The callback only: reads ring indices, `memcpy`s
   651→frames, fills silence on underrun, increments the sample counter.
   652→(d) **Errors.** `DeviceLost` (unplug, server restart) → event; session policy:
   653→switch to the next device from the configured fallback order, or enter an
   654→explicit `Buffering`-like suspended state if none — playback position is
   655→preserved, never silently restarted [PROPOSAL: suspend-and-notify default].
   656→Open failure at start is a typed `Error(Device)`.
   657→(e) **Invariants.** The sample counter is monotonic and never rewinds across
   658→device switches (offset-carried). Callback worst-case execution time is bounded
   659→and measured (testkit asserts under synthetic CPU load) [VERIFY: per-platform
   660→numbers to be recorded in Phase 3].
   661→(f) **Tests.** `NullSink` and `CapturingSink` in testkit for determinism;
   662→`VanishingSink` that drops the device mid-stream; `StallingSink` that stops
   663→pulling. Platform integration runs against real devices labeled as
   664→real-hardware evidence (MP §13).

   666→### 4.10 video-engine — presentation scheduling
   667→
   668→(a) **Responsibility.** Decide *which* frame is on screen *when*: consume
   669→decoded frames, compare against the clock, schedule presents to the renderer,
   670→apply the late-frame/drop policy.
   671→
   672→(b) **Type sketch.**
   673→
   674→```rust
   675→pub struct PresentRequest { pub frame: VideoFrameHandle, pub when: MediaTime,
   676→                            pub gen: Generation }
   677→pub enum DropPolicy { Never, Late { threshold: MediaTime }, Auto }
   678→pub struct SchedulerCfg { pub policy: DropPolicy, pub max_repeat: usize,
   679→                          pub target_lead: MediaTime /* vsync lead */ }
   680→```
   681→
   682→(c) **Threading.** One scheduler thread (vsync-paced via the renderer's frame
   683→callback or a timed wait). Pulls frames from the video frame queue, keeps a
   684→small reorder window, emits `PresentRequest`s to the render thread.
   685→(d) **Errors.** None fatal: a missing frame means repeat the previous; a
   686→missing *track* means the renderer shows background + subtitles if any.
   687→(e) **Invariants and policy.**
   688→- Frame timing: present the frame with the largest `pts ≤ clock + target_lead`
   689→  [PROPOSAL: lead = half a frame duration]. If none is due, repeat the last
   690→  frame (up to `max_repeat`, then background) — video is subordinate to the
   691→  audio clock, always.
   692→- Late frames: `pts < clock − threshold` → drop, count, advance (`DropPolicy::
   693→  Late`, threshold default one frame duration [PROPOSAL]; configurable, MP §5).
   694→  Audio is never dropped for video's sake.
   695→- Inter-frame reorder (B-frames) is the decoder's job (codec-api); the
   696→  scheduler only handles display order.
   697→- Deinterlace: out of scope here; a later video filter plugin (MP §6) inserted
   698→  between decode and schedule — the insertion seam exists in the pipeline
   699→  (frame filter point), and this document reserves it.
   700→(f) **Tests.** Deterministic harness: virtual clock + synthetic frames with
   701→known PTS → assert exact present/drop/repeat decisions for every policy
   702→parameter combination (exhaustive over small grids). Property: no frame is
   703→presented out of order; drops are monotone in lateness. Integration: A/V sync
   704→scenario (§8) measures `|audio_pts − video_pts_presented|` at each present and
   705→asserts it stays within a stated tolerance [PROPOSAL: ±10 ms after first
   706→frame; tightened with evidence].

   708→### 4.11 renderer-wgpu — GPU surface, color, scaling, compositing
   709→
   710→(a) **Responsibility.** Turn `PresentRequest`s into pixels on a surface:
   711→color conversion (YUV→RGB), scaling and aspect handling, background, and
   712→subtitle compositing. Isolated: it consumes frame handles and render
   713→parameters, nothing else (MP §3.4). On desktop it must also work behind the
   714→Tauri webview (native surface behind a transparent webview, or frame streaming
   715→to a canvas — the Phase 2 prototype decides, MP §7; web build uses
   716→WebGPU/WebGL, MP §10).
   717→
   718→(b) **Type sketch.**
   719→
   720→```rust
   721→pub trait RenderSurface {          // implemented by: native wgpu surface,
   722→    fn resize(&mut self, size: Extent2D);   // canvas/WebGL bridge (web), test headless
   723→    fn present(&mut self, frame: PresentRequest) -> Result<(), RenderError>;
   724→}
   725→pub enum AspectMode { Fit, Fill, Stretch, Crop16x9 /* config-driven set, MP §5 */ }
   726→pub struct RenderParams { pub aspect: AspectMode, pub crop: Option<Rect>,
   727→                          pub background: ColorDesc, pub subtitle_layer: Option<TexId> }
   728→```
   729→
   730→(c) **Threading.** One render thread owns the surface, the wgpu device and all
   731→GPU resources. Receives `PresentRequest`s via a small mailbox (latest-wins:
   732→a new request replaces an unsent one — rendering never back-pressures decode
   733→[PROPOSAL: mailbox depth 1]).
   734→(d) **Errors.** Surface loss (window closed, GPU reset) → `RenderError::
   735→SurfaceLost`; the session degrades to audio-only with an explicit event, or
   736→reattaches when a new surface is provided (resize is non-fatal by
   737→construction).
   738→(e) **Invariants.** Color conversion happens in shaders on the GPU (MP §11:
   739→GPU color conversion); the CPU→GPU upload path is the only allowed frame copy
   740→and it is zero-copy for compatible buffer layouts when the decoder's output
   741→supports import [VERIFY: per-backend capability, recorded per platform].
   742→Scaling/aspect math is pure and unit-tested against reference rectangles.
   743→(f) **Tests.** Headless wgpu surface in testkit renders frames to an offscreen
   744→buffer and compares against CPU reference conversion within tolerance.
   745→Property: aspect/crop math never produces empty or inverted rects. Screenshot
   746→tests of the compositing result (video + subtitle layer) with synthetic
   747→textures.
   748→
   749→**Subtitle compositing [PROPOSAL].** Subtitle events are rasterized on the CPU
   750→(text shaping and glyph rasterization — candidate: see doc 04) into an RGBA
   751→atlas uploaded as a texture per event; the video shader composites: video →
   752→color convert → tone/scale → then alpha-blend the subtitle layer with the
   753→event's position. Rationale: keeps text rendering out of the real-time path
   754→(events change at ~Hz, not per frame), keeps the renderer generic (it
   755→composites *a layer*, not "subtitles"), and gives one compositing code path
   756→for all subtitle formats. Chapters/metadata never composite — they are events
   757→only.

   761→(a) **Responsibility.** Parse subtitle formats (embedded tracks from demux and

   801→### 4.13 playlists — data model and deterministic order semantics
   802→
   803→(a) **Responsibility.** Own the playlist data model, repeat/shuffle/order
   804→semantics as pure data transforms, and the queue concept. It contains no
   805→playback logic — it drives the engine exclusively through commands
   806→(`SetSource`, on `Ended` → next item).
   807→
   808→(b) **Type sketch.**
   809→
   810→```rust
   811→pub struct PlaylistItem { pub id: ItemId, pub source: SourceSpec,
   812→    pub title: Option<String>, pub duration: Option<MediaTime>, pub meta: Metadata }
   813→pub struct PlaylistModel { items: Vec<PlaylistItem>, /* stable ids */ }
   814→pub enum Repeat { Off, One, All }
   815→/// Deterministic shuffle: the play order is a pure function
   816→/// (seed, repeat, item ids, queue) -> sequence of ItemId.
   817→pub struct PlayOrder { pub repeat: Repeat, pub shuffle_seed: Option<u64> }
   818→pub struct QueueOp { /* PlayNext(itemId), PlayNow(itemId), Remove(id) ... */ }
   819→```
   820→
   821→Shuffle is a seeded permutation computed as a data transform (Fisher–Yates
   822→over item ids with the recorded seed) — same seed + same items ⇒ same order,
   823→property-tested. "Play next" is an insertion into the remaining order, not a
   824→mode. Repeat does not loop the iterator implicitly: it is expanded into the
   825→computed sequence in bounded chunks [PROPOSAL: expand one cycle ahead, so an
   826→infinite All-repeat never materializes an infinite list].
   827→(c) **Threading.** None of its own; the model is owned by whoever loads it
   828→(the app shell via command layer). The engine's only interaction is receiving
   829→`SetSource`.
   830→(d) **Errors.** Load errors are per-item (unreachable file stays in the list
   831→marked unavailable — from engine open results); a broken item never blocks the
   832→sequence.
   833→(e) **Invariants.** Item identity is stable across reorders (ids, not
   834→indices); the computed order is a permutation of exactly the current item set
   835→(property); repeat+shuffle keeps the permutation property per cycle [PROPOSAL:
   836→reshuffle per cycle with a derived seed, documented].
   837→(f) **Tests.** Property: order is a permutation; deterministic for a seed;
   838→repeat-expansion terminates per chunk; queue insert/remove semantics against a
   839→model. Fuzz: playlist format parsers (M3U/PLS first, Phase 5). Integration:
   840→gapless handoff to the engine (§4.8) at item boundaries.

   842→## 5. Cancellation and generation semantics
   843→
   844→MP §8 bullet 2 requires that seek, stop, source replacement and track switch
   845→cancel old work via generation IDs so stale packets and frames cannot
   846→reappear. This section is the exact lifecycle.
   847→
   848→**Two-level generations [PROPOSAL].**
   849→- **Epoch** (session generation): minted on `Open` and on `SetSource`
   850→  (replacement). Everything owned by an epoch — input thread, demuxer, queues,
   851→  decoders, device session — is destroyed with it.
   852→- **Pipeline generation** (sub-generation, resets each epoch): minted on
   853→  `Seek`, `SwitchTrack`, `Stop` (final), and discontinuity-driven re-anchor.
   854→  Epoch = (epoch, pipeline) pair compared for equality; comparisons are
   855→  "different epoch OR different pipeline ⇒ stale".
   856→
   857→**Minting.** Only the session thread mints, atomically publishing the pair to
   858→a `CancelToken` (`Arc`-shared snapshot: epoch u64, pipeline u64, plus an
   859→interrupt flag). Mint order is program order on one thread — no races by
   860→construction.
   861→
   862→**Checking points (every stage, every hop).**
   863→1. Input reads: between chunks (deadline + token).
   864→2. Demux loop: between `read_packet` calls (D5); parked producers wake on
   865→   token change.
   866→3. Queue push: the demux driver stamps the *current* token generation onto
   867→   each `Stamped` at push; `push` itself compares against the queue's
   868→   published generation and drops mismatches (Q2) — this is the boundary that
   869→   makes in-flight producers harmless.
   870→4. Queue pop/flush: `flush(new)` is called by the session before any new
   871→   producer starts; consumers then only ever observe current-generation items.
   872→5. Decode workers: check the token before `send` and before enqueuing each
   873→   output frame; a worker holding a parked decoder aborts via queue
   874→   `PushAborted`.
   875→6. Audio pump: on token change, drops pending frames, calls `flush()` on the
   876→   decoder, drains the ring to silence, then waits for the new generation's
   877→   first packet.
   878→7. Video scheduler: drops every queued/late frame whose stamp differs;
   879→   renderer mailbox is replaced wholesale.
   880→8. Events: any event in flight when a generation is minted is delivered but
   881→   tagged `superseded: true` [PROPOSAL] so the UI can discard rather than
   882→   flash stale state.
   883→
   884→**Guarantee (testable).** After the session publishes generation G and the
   885→flush of each queue has returned, no packet or frame with stamp ≠ G can be
   886→popped, decoded-into-output, presented, or mixed into audible output. This is
   887→a property test in testkit (§8): a fuzz of interleaved
   888→seek/switch/stop/replacement commands against instrumented sinks that assert
   889→every observed stamp equals the live generation.
   890→
   891→**Interaction with bounded queues.** Queues never grow to absorb stale
   892→producers: the push-boundary check (3) drops stale items *counted* (metric
   893→`stale_dropped`), and parked producers receive `PushAborted` on flush, so
   894→memory stays within bounds during cancellation storms (e.g. rapid repeated
   895→seeking). Teardown order for `Stop`: mint → cancel token interrupt → flush
   896→queues (producers abort) → join threads with deadline (S2) → destroy device
   897→session.
   898→
   899→## 6. Seek specification
   900→
   901→Step-by-step (numbers = ordering constraints):
   902→
   903→1. **Accept.** `Seek(target, flags)` arrives on the session thread. If the
   904→   state is `Idle/Opening/Probing` → `CommandRejected`. If demuxer
   905→   `seekability == None` → `SeekFailed{NotSeekable}` (never reported as
   906→   success, MP §8 bullet 4). Validated seek → emit `SeekAccepted` (≠
   907→   completed) and return to the client.
   908→2. **Bump.** Mint pipeline generation G+1; publish token.
   909→3. **Flush pipeline.** Flush packet queues and frame queues (producers abort
   910→   per §5), flush audio decoder and ring (to silence), flush video decoder
   911→   (drop reorder buffers), clear renderer mailbox and subtitle active set.
   912→   Clock is frozen at the *old* position (UI shows a seeking state, not a
   913→   fabricated new one).
   914→4. **Demuxer seek.** Call `Demuxer::seek(target)`.
   915→   - With keyframe index: position directly to the keyframe at or before
   916→     target (within format tolerance).
   917→   - `SlowLinear`: bounded linear scan [PROPOSAL: cap at 1000 packets or 2 MiB
   918→     of parse work; exceeding → `SeekFailed{TooSlow}` with the session still
   919→     at its old position and playable].
   920→   - Returns actual position A (containers that can only seek approximately
   921→     report the truth).
   922→5. **Re-prime.** Demux emits packets from A; decode until the first keyframe
   923→     packet per enabled track has produced ≥ 1 output frame (video) and the
   924→     first audio packet is queued.
   925→6. **Clock re-anchor.** `clock.reanchor(A_adjusted)` where `A_adjusted` is the
   926→   first *audio* frame's own timestamp if audio exists (anchor on truth, not
   927→   request); otherwise A. Video scheduler snaps to the new anchor with no
   928→   drop-count penalty for the first frame after a seek (documented exemption
   929→   in the drop policy).
   930→7. **First-frame report.** Renderer presents the first frame → `FirstFrame{ts}`
   931→   event; clock unfreezes; audio output resumes. Emit `Seeked{requested,
   932→   actual}` — completion truth.
   933→
   934→**Failed seeks.** If step 4 errors: emit `SeekFailed{reason, position: <old>}`.
   935→By invariant D4 the demuxer is at a defined, parseable position, so the
   936→session *explicitly* chooses: (i) resume demux/decode from the old position
   937→(state preserved — the default), or (ii) if the demuxer reports itself broken
   938→post-seek, enter `Error` (degraded explicitly, never a false success). Steps
   939→5–7 failing (e.g. corrupt data at the landing point) degrade identically:
   940→`SeekFailed` or `Error`, plus `DamagedData` events.
   941→
   942→**Re-anchoring coherence.** During steps 2–6 the state is `Buffering`
   943→(seeking) — no `Playing`-looking output. A second `Seek` arriving mid-seek
   944→simply re-runs from step 1 against the in-flight generation (repeated-seek
   945→storm safety, MP §13 scenario "repeated seeks").
   946→
   947→## 7. First vertical slice (Phase 2, MP §16)
   948→
   949→Goal (MP §16 Phase 2): one real file from open to decode to audio and video on
   950→screen, through the command layer, from CLI (`lumen play file`) and from the
   951→UI. The slice exercises: input, probe, demux, packet-queue, codec-api,
   952→playback-engine, media-clock, audio-engine, audio-output (real device),
   953→video-engine, renderer-wgpu (native surface or canvas streaming per the
   954→webview prototype), command layer, and a minimal event set.
   955→
   956→**Candidate container/codec pairs evaluated [PROPOSAL]:**
   957→
   958→1. **WAV + PCM only.** Simplest possible (RIFF parsing is trivial, PCM is
   959→   passthrough). Rejected as *the* slice: it exercises no video path, no
   960→   presentation scheduler, no A/V sync — Phase 2's point is the full vertical.
   961→   Retained as the first integration milestone within the slice (audio-only
   962→   playback lands days earlier and de-risks audio-output early).
   963→2. **AVI + MJPEG (video) + PCM (audio).** AVI is a simple RIFF container with
   964→   one 'movi' chunk list; per-frame keyframe semantics (every MJPEG frame is a
   965→   keyframe) make seek trivially correct; MJPEG decoding is baseline JPEG
   966→   decoding, for which well-maintained pure-Rust candidates exist (candidate:
   967→   see doc 04; audit gate applies); PCM passthrough requires no real decoder
   968→   state machine. Costs: JPEG decode is real work (DCT, huffman) and AVI's
   969→   index ('idx1') handling has quirks.
   970→3. **Ogg + Theora + Vorbis.** Clean formats, but two inter-frame-adjacent
   971→   codecs with real entropy coding and granulepos timestamp semantics — the
   972→   codec cost dwarfs the container cost and delays the vertical.
   973→
   974→**Recommendation [PROPOSAL]: candidate 2, AVI + MJPEG + PCM**, with candidate
   975→1 as the in-slice audio milestone. Rationale: the container is simple enough
   976→to finish, the video path is genuinely exercised end-to-end (real decoder
   977→plugin, real frame timing, real GPU conversion), every frame being a keyframe
   978→makes the seek contract honest and testable, and no patent-encumbered video
   979→bitstream is required (JPEG baseline patent situation is clear for decode;
   980→recording in doc 04 and the risk register, MP §14).
   981→
   982→**Real vs stubbed in the slice:**
   983→- Real: input (file), probe (WAV + AVI scorers), demux (WAV + AVI), queues,
   984→  codec-api (PCM "decoder" + MJPEG decoder), session state machine (full),
   985→  clock (audio-master + system fallback), audio-engine (conversion only, one
   986→  track, no user filters), audio-output (one platform first, then the other
   987→  two), video scheduler, renderer (YUV→RGB or RGB path, fit aspect),
   988→  command layer, events.
   989→- Stubbed/differed: playlists (single file), subtitles (none), filters (empty
   990→  chain), network input, track switching (single audio + single video track),
   991→  device-loss policy (event only), hardware decode (Phase 0 ADR).
   992→
   993→**Acceptance criteria (must be objectively checkable):**
   994→1. `lumen play fixture.avi` opens the file, shows video on screen, plays
   995→   audio, and both stop at `Ended`; exit code 0; a second run is identical.
   996→2. The same through the UI via the command layer: Play/Pause/Stop reflect
   997→   engine state truthfully (accepted vs completed distinguished in the UI).
   998→3. Seek (to 3 positions incl. 0 and near-end) lands within ±1 frame of a
   999→   keyframe and audio resumes within 300 ms [PROPOSAL: number revised with
  1000→   Phase 3 measurements].
  1001→4. Ctrl-C / window close during playback exits within the teardown deadline
  1002→   with no audio device left open.
  1003→5. `cargo test` suite for the slice passes: unit + property + the integration
  1004→   scenarios of §8 applicable to the slice (open/play/pause/seek/repeated
  1005→   seeks/short media/reopen/exit-during-playback).
  1006→6. No `unsafe`, no C toolchain in the build (local gate, MP §13).
  1007→
  1008→**Fixtures.** Generated, legally clean (MP §13 corpus rules): a `testkit`
  1009→fixture generator produces (a) WAV files (sine/noise, rates, bit depths,
  1010→truncated variants) and (b) AVI+MJPEG+PCM files by encoding synthetic frames
  1011→with a tiny in-tree baseline JPEG *encoder* written for testkit only
  1012→[PROPOSAL: a minimal deterministic baseline-JPEG writer, ~hundreds of lines,
  1013→keeps fixtures license-clean and reproducible; alternatively a pure-Rust JPEG
  1014→encoder candidate — see doc 04]. Recorded expectations: frame count, frame
  1015→hashes, duration, track list. Malformed variants: truncation at every 256-byte
  1016→boundary, bit flips, missing 'idx1'.

  1018→## 8. Engine test strategy
  1019→
  1020→**testkit crate** (MP §4; depends on production crates, never the reverse,
  1021→MP §3.7):
  1022→- `VirtualClock`: implements `PlaybackClock`; manual time advance; scripted
  1023→  drift; used by every deterministic test.
  1024→- `ScriptSource`: `ByteStream` from a byte buffer plus a fault script
  1025→  (delay-before-read, hang-forever, truncate, reset, corrupt, shrink). This is
  1026→  the "interrupted network" scenario driver.
  1027→- Sinks: `NullAudioSink`, `CapturingAudioSink` (records sample hashes),
  1028→  `VanishingSink` (device loss), `StallingSink`; `FrameRecorder` (video
  1029→  presents with stamps, hashes, drop counts).
  1030→- `SessionHarness`: builds the whole pipeline on virtual devices, steps it
  1031→  deterministically (single-threaded mode where workers run inline — the same
  1032→  code paths, scheduling only differs), and asserts on the event log.
  1033→- Instruments: resident-bytes counters for queues, thread/fd counters for
  1034→  leak tests, allocation/lock fault-injection for the audio callback (§4.9).
  1035→
  1036→**Property tests** (candidate framework: see doc 04):
  1037→- Time-base conversions (MP §8 bullet 1): overflow, discontinuity, missing
  1038→  timestamps (§3 f).
  1039→- Queue bounds under adversarial interleavings (§4.4 f).
  1040→- Generation races: the §5 guarantee as a machine-checked property over
  1041→  random command storms.
  1042→- State-machine model checking against the §4.6 table.
  1043→- Scheduler decisions over parameter grids (§4.10 f); shuffle permutation
  1044→  properties (§4.13 f).
  1045→
  1046→**Integration scenarios** mapped 1:1 to MP §13's list:
  1047→
  1048→| MP §13 scenario | Driver in testkit | Pass condition |
  1049→|---|---|---|
  1050→| open | `ScriptSource` valid + variants | correct tracks/duration or typed error |
  1051→| play | `SessionHarness` + sinks | `FirstFrame` + audio samples flow; A/V stamps within tolerance |
  1052→| pause / resume | virtual clock freeze | no samples while paused; resumes at same media time |
  1053→| seek | §6 flow on 3 targets | `Seeked{actual}` within tolerance; no stale frames |
  1054→| repeated seeks | 100 random targets, no waits between | no stale output ever; bounded memory; all complete or typed-fail |
  1055→| A/V sync | instrumented sinks over full playback | drift within §4.10 tolerance |
  1056→| track switching | multi-track synthetic container | new track's first frame follows switch generation |
  1057→| corrupt / missing files | fault scripts + malformed corpus | typed `Corrupt`/`Inaccessible`, bounded recovery counts |
  1058→| interrupted network | `ScriptSource` hang/reset scripts | `Buffering` then resume or typed error; no hang |

  1062→| exit during playback | drop session mid-decode | teardown within deadline, device closed |

  1074→## 9. Threading summary
  1075→
  1076→| Thread | Owns | Communicates via | May block? | Real-time? |
  1077→|---|---|---|---|---|
  1078→| Host/UI thread (app, not engine) | UI/webview, command client | command layer (doc 05): mpsc in, event bus out | yes | no |
  1079→| Session thread (1 per playback) | state machine, generations, clock anchor decisions, watermark policy | command inbox, event bus, control atomics | bounded waits only (S3) | no |
  1080→| Input reader (1 per source) | `ByteStream` instance, open deadline | byte buffer + condvar to demux | yes — I/O, deadline-bounded | no |
  1081→| Demux thread (1 per source) | `Demuxer` instance | bounded packet queues (§4.4) | parks on full queue; wakes on generation | no |
  1082→| Video decode workers (pool, N = cores-capped) | `VideoDecoder` instances | packet queue in, frame queue out | CPU-bound; no I/O, no locks held | no |
  1083→| Audio pump (1) | audio decoder(s), filter chain, mixer | frame queue in, SPSC ring out | bounded by ring safety level | near-RT |
  1084→| Audio device callback (OS thread) | nothing — stateless reader of the SPSC ring | SPSC ring indices | **never** | **yes** |
  1085→| Video scheduler (1) | reorder window, drop policy state | frame queue in, present mailbox out, clock reads | no (vsync-paced waits) | no |
  1086→| Render thread (1) | wgpu device, surface, pipelines | present mailbox (latest-wins), resize events | GPU present may block briefly | no |
  1087→| Subtitle/parse worker (1, light) | external-file parsers | timed-event queue to engines/events | file I/O bounded by input deadlines | no |
  1088→| Playlist prefetch worker (app-side) | next-item open | issues `SetSource` via command layer | yes | no |
  1089→
  1090→Rules recap (MP §8 bullet 3): no async runtime in decode paths; no lock is
  1091→held across blocking work (the only locks are short queue/ring critical
  1092→sections); the audio callback obeys §4.9's forbidden-operations list.
