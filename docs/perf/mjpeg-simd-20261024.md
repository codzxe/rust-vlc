## 1. What was SIMD'd (predecessor work, merged)

- V-3: in-place Huffman decode (no per-block coefficient buffer).
- SSE4.1 IDCT **pass-1** (row transform) via `std::arch` intrinsics +
  runtime `is_x86_feature_detected!("sse4.1")` dispatch at
  `ScanHooks::transform`; pass-2 stays scalar; scalar fallback default on
  non-x86_64. Bit-exact vs the scalar reference (see §3).

## 2. Measurement design (identical-walk ablation)

`stage_bench` (this repo, `crates/codecs/examples/`) times the SAME
bitstream through the same walk with only the transform hook swapped:

- **full (SIMD)** = production `DecodeContext::decode` (dispatch → SSE4.1
  kernel when the CPU has it — it does here);
- **full (scalar)** = new `ScalarIdctStages` arm: identical parse +
  huffman + store + assemble, `transform` pinned to `idct::idct_block`.

2 warm-up passes; N measured passes; arms interleaved inside each pass so
machine drift hits all arms equally; medians are the record, min-of-passes
recorded as stability evidence. Per-pass rows land in the raw file. The
end-to-end ffmpeg comparison protocol (decode-to-null, best-of-1, fresh
process per run, `speed_bench.py`) is the one the 2026-10-22 baseline used;
its pre-SIMD rows are cited unchanged in §4.

## 3. Bit-exactness proof (why the two arms measure the same output)

- `idct_simd::tests::dispatch_is_bit_exact_vs_scalar` — 256-block seeded
  equality, dispatch vs scalar (in-crate test, part of the 172/0 codecs
  suite at merge time).
- `stage_bench` itself refuses to time any file where the staged walk
  diverges from the production walk (byte-equal frames + metadata) — that
  gate ran green on every fixture below before any timing.

## 4. Results (measured medians)

bad news: these are the numbers, unfiltered.

## 6. What remains (next headroom, in measured order)

1. **Assemble/color path** — 45.7% of the avi-av walk (RGBA conversion +
   upsampling). Top single target now.
2. **Huffman** — 27.8–44.0%; V-3 landed, further gains need wider
   read/decode fusion.
3. **[PROPOSAL] Dispatch default**: per the brief's own rule ("if SIMD
   does not win, say so and keep scalar"), the measured no-win argues for
   flipping the dispatch default to scalar (keep the kernel + bit-exact
   test for a future AVX2 two-pass rewrite). Leaving it SIMD-default also
   defensible (parity, no loss). Lead decision — not flipped this session.
4. End-to-end post-SIMD lumen-vs-ffmpeg run (§4.3 handoff) + the uhd4k
   fixture row.
