# Baseline provenance record — W25 redesign re-pin + wave-K 25-route completion (w26.k20, j20 P2-4)

This record closes the provenance gap found by the wave-J tooling review
(`docs/waves/w26/reviews/w26.j20.md`, P2-4): the full baseline re-pin of
2026-11-12 — the biggest reskin in the project's history — happened with no

## Why a re-pin was legitimate (doc 08 §6.5 deliberate-change clause)

The committed baselines (Solstice v2 + wave-3, 2026-11-09) predated the
**W25 Figma redesign** — waves a–g of program w26 re-skinned every screen to
the W25 design language (`docs/waves/w26/CONTRACT.md` §1–§2: near-black
surfaces, the single orange accent `#d37918`, Inter, control-only rounding;
the Solstice sunset/tape/keycap aesthetic is dead by contract). Every pixel
of every screen changed intentionally, so every baseline was invalidated at
once. Tolerance was **not** loosened: `threshold: 0.1` (perceptual YIQ) +
`maxDiffPixelRatio: 0.001`, unchanged (`e2e/visual/visual.spec.ts:96-99`).

Concurrent with the re-skin, the W25 re-anchor made **orange** the product
default accent (`scripts/gen-tokens.mjs` `DEFAULT_ACCENT`, ThemeProvider
initial state, `tokens.css` `:root`, `e2e/theme.spec.ts:19-23` all agree).
That resolves the issue-#37 discrepancy the old honesty note recorded: the
grid anchor and the product default are now the same thing, so the grid
baselines depict exactly what ships. The stale "Solstice Keyvox gold" note
in `manifest.ts` was rewritten this lane (j20 P2-5).
