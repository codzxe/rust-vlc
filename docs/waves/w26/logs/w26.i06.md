## What shipped (all in the two files below)

1. **h13 #1 — scroll-required preset rows un-clickable (the functional NO).**
   Root cause lived in shared `ui/src/components/menu/Dropdown.tsx` (~L269):
   an unstable INLINE ref callback (`ref={(node) => { node.scrollTop = 0 }}`)
   re-ran on every re-render, so the mousedown→focus→`setActiveIndex`
   re-render yanked `list.scrollTop` to 0 mid-click and the row escaped the
   cursor between mousedown and mouseup (h13's "Full treble" event log:
   `click@718,548 → lumen-dropdown__list`, `select()` never fired).
   **The Dropdown.tsx scrollport proposal (logged for i16/Lead as instructed):
   replace the inline callback with the existing stable `listRef` and move
   the `scrollTop = 0` reset into an effect keyed on `open`** — proposed diff:

   ```diff
   - <div ref={(node) => { if (node) node.scrollTop = 0; }} …className="lumen-dropdown__list">
   + <div ref={listRef} …className="lumen-dropdown__list">
   + useEffect(() => {           // runs ONCE per open, not per render
   +   if (!open) return;
   +   if (listRef.current !== null) listRef.current.scrollTop = 0;
   + }, [open]);
   ```

   **STATUS: LANDED.** w26.i16 shipped exactly this root fix in
   `Dropdown.tsx` L185–195 (stable `listRef` + open-keyed effect) together
   with the shared menu.css quiet-ink grammar, before this lane's final pass.
   Equalizer-side history: this lane first shipped a legitimate workaround —
   `equalizer.css` scoped the EQ list to its full content height (372px

   362×348), restoring the frame's clip composition (row 8 clipped, list
   scrolls). Verified live (below): both scroll-required rows are now
   pointer-reachable on the frame's 348px list.
