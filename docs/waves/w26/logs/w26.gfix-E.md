### g19-P1-2 · One Escape closed the whole dialog — FIXED (scoped seam) + Lead note
The Lead's `stopPropagation` in `Dropdown.tsx` is correct but **cannot fire
inside a Dialog**: `Surface.tsx`'s focus trap listens for Escape with a
NATIVE `keydown` listener on the dialog node — a bubble-phase ANCESTOR of
React's delegated root — so the trap sees Escape first, itself calls
`stopPropagation()` (killing the Dropdown's React handler) and closes the
dialog. Verified broken end-to-end before fix: `{dialogOpen:false}` after one
Escape. **Seam fix (my files):** `AddSubtitlesDialog.guardedClose` — while any
`.lumen-dropdown__list` is open in the window, an escape-dismiss is redirected
to that dropdown's trigger `.click()` (the Dropdown's own close-and-restore:
list closes, focus returns to the trigger); the dialog closes only when no
list is open. Verified live (real flow + harness): first Escape →
`{dialogOpen:true, listOpen:false}`; second Escape → dialog closes. Same for
the footer FilenameMatchControl dropdown. 2 regression tests added.
**Lead follow-up:** root fix belongs in `components/surface` (trap checks for
open popups) or `components/menu` (capture-phase listener); my guard can then
be retired.
