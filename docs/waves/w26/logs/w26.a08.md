## Decisions & coordination

1. **`.lumen-panel` name collision** — the theme lane's new base sheet
   (`ui/src/theme/lumen.css`, landed mid-wave) defines `.lumen-panel` as the
   r12–14 CARD grammar. My square app-panel therefore ships as `.lumen-pane`
   (collision-free). NEEDS-LEAD: unify naming (suggest theme sheet keeps
   `.lumen-panel` for cards OR retires it in favor of `.lumen-card`).
2. **`.lumen-separator` shared with the base sheet** — theme sheet owns the
   hr grammar (border:none + inset margins); my component layers only
   orientation geometry with higher-specificity `data-orientation` selectors
   (deterministic in both cascade orders; vertical hairlines reset margin).
3. **Dialog radius 14 vs "r19–21"** — mission text says sheet/dialog r19–21,
   but every dialog frame measures rx14; token lane set `--radius-window:
   14px`. I consume `--radius-window`; if the Lead wants 19–21 for sheets,
   it's a one-token swap (`--radius-app: 19px` exists).
4. **Token requests for the token lane (w26.a01)** — landed values verified
   correct (#191919/#0e0e0e/#222222/#404040, r14 card, r30 pill, orange
   accent, Inter). Remaining asks: `--font-size-label` is 16px — spec wants
   15px section headers (SectionHeader consumes it; either re-value label to
   15 or add a section-header size); `--shadow-card` is
   `0 4.76px 4.76px rgb(0 0 0 / 38%)` vs frame-measured
   `0 0 12px rgb(0 0 0 / 38%)` (no y-offset) — minor, their call;
   `--shadow-overlay` `0 4.76px 5.9px / 0.7` vs measured
   `0 8px 15px rgb(0 0 0 / 46%)` — their call.
5. **Sheet shadow** — no sheet frame exists; sheets are dialog-variant
   overlays, so they carry `--shadow-overlay` like dialogs. [VERIFY] if a
   frame says otherwise.
