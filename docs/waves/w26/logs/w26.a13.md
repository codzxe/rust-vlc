## The three failing tests → green (38/38 pass)

All three were assertion-SCOPE collisions with sibling-lane content, not
PlayerScreen regressions (PlayerScreen already renders no title bar and hosts
the hero):
1. **"does not duplicate the window title bar"** — jsdom's role engine
   (dom-accessibility-api 0.5.16) lacks the HTML-AAM scoping exception, so the
   playlist panel's internal `<header>` inside my `<aside role="complementary">`
   surfaces as a second `banner`. Real browsers scope it to generic (verified
   reasoning; browser a11y trees implement HTML-AAM scoping). Fix: assert no
   `.lumen-player__topbar`, no `h1 "Player"`, and no banner OUTSIDE
   complementary scopes. Strength kept: any unscooped banner fails the test.
2. **"shows the empty state … Open-media affordance wired to the shell dialog
   event"** — the playlist lane's queue panel renders its own honest
   empty-queue CTA with the same label "Open media" (dispatches the same
   `lumen:open-media`). Fix: scope queries to the canvas region (the hero's
   home). The click → `lumen:open-media` assertion is unchanged (1 call).
3. **"hides the empty state once media is present; has-media regions appear"**
   — same duplicate-CTA collision. Fix: scope the absence to the canvas;
   STRENGTHENED the "has-media regions appear" half by rendering
   `openPanels={["media-info"]}` + media and asserting the media-info
   complementary landmark now appears (previously that half asserted nothing).

Also: reworded one dated "Solstice" comment credit in `context.tsx` (neutral
wording; no functional change). No other Solstice remnants in my files
