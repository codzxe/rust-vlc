### 2. The seed (`schemas/settings.toml` → `npm run settings:generate`)

- `[areas].known` = the 13 Figma areas **+ `engine`** (the ui=false escape
  valve), ordered to the Figma sidebar so no re-sort is needed.
- New [[setting]] rows, all frame-measured defaults (analysis C8/C12/C13):
  - **controls** (ungated): `controls.skip-very-short/short/medium/long`
    (3 s / 10 s / 60 s / 300 s, duration-ms inputs), `controls.mouse-single-
    click/double-click/scroll-wheel/horizontal-scroll` (enums),
    `controls.mouse-reverse-scroll-direction` (bool). Hotkey bindings stay
    dynamic keymaps data (areas/hotkeys), NOT [[setting]] rows.
  - **recording** (feature_gate `recording`, false in product.toml → hidden +
    inert per rule F2): `recording.directory` (path, "~/Videos"),
    `recording.format` (enum mp4-remux / wav).
  - **extensions**: `extensions.load-on-startup` (bool, ON; gate
    `wasm-extensions`, false → hidden until Phase 7). The add-on LIST is
    dynamic data like hotkeys, rendered by the sibling area component.
- All existing entries (global/interface/privacy/playback/performance/engine +
  the crash-isolation extensions rows) untouched — filenames and placement
  preserved; folds are registry-level, not schema moves.
- Generator fixes (in `ui/scripts/gen-settings-screens.mjs`, prior-approved
  lane scope): emitted `SettingValueType` now includes `path`/`url`/`percent`
  (the recording.directory `path` row previously broke the generated TS), and
  title msgids flow through a `msgid()` seam so the file type-checks before
  b19 registers the new keys.

Result: `npm run settings:check` → **OK (8 ui areas, 33 ui entries, 44
total)** — generated areas: global, interface, privacy, controls, playback,
performance, recording, extensions; the other 5 (video, audio, subtitles,
library, network) are hand/sibling areas with no seeded rows (their content is
hand-authored or dynamic data; siblings own those files).
