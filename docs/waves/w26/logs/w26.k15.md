## What was fixed

### P2-1 — SubtitlePickList identity-reset steals focus (SubtitlePickList.tsx)
The reset effect keyed on the `candidates` ARRAY IDENTITY; the focus effect
refocused on every `activeIndex` change. Two repros, both fixed:
- **Repro A** (online search): the reset+refocus yanked the caret out of the
  search input on every keystroke. Fix: the focus effect now skips any
  transition where the listbox subtree does NOT already own focus
  (`tookInitialFocus` mount flag: the FIRST pass still moves focus in, APG
  mount behavior, pinned by the existing "starts focused" test).
- **Repro B** (non-memoized host array, the documented mount-recipe shape):
  Fix: the reset keys on a CONTENT SIGNATURE (`length|first|last`) — identity
  churn with identical content no longer resets roving focus.
Legit resets (content actually changed) still land on row 0 and refocus only
while the listbox owns focus. Regression tests: 3-test suite (repro A, repro
B, in-listbox content reset).

### P2-2 — MediaList engine-scope rows keyboard-dead (MediaList.tsx + options.css)
Engine-scope rows (the component's documented purpose; ships in the harness
today, hosts tomorrow) were a clickable div with no keyboard path, and the •••
was `display:none` until `:hover/:focus-within` — unreachable by Tab. Fix: a
transparent native `<button class="lumen-plo-mrow__play">` stretches behind
the row content (`inset: 0`, z-index 0, `aria-label="Play <title>"` composed
from the registered `player.controls.play` verb + runtime title); the ••• is
lifted above it (`position: relative; z-index: 1`). Tab reaches the play
target, Enter/Space activate natively, focusing it is `:focus-within` on the
row → the existing rule reveals the •••. The row div itself carries no handler
anymore (no nested role=button around a real button — the axe
nested-interactive rule `semantics="grid"` exists for). Local-scope rows
(shipment: /playlist browse) render no play target (honest presentation,
unchanged; PlaylistScreen's roving controller keeps owning their kebab).
Real-browser proof: 5/5 harness probes (targets exist + named, focus-within
brightens the row, trusted Enter AND Space click the button).
