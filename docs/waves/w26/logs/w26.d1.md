## 4. Fixes applied (all verified in-browser + unit-pinned)

1. **App.tsx — dropped the `onOpenMedia` re-dispatch** (a13 open issue 4 /
   a10 issue 3 / a15 issue 5): StageOverlays already dispatches
   `lumen:open-media`; App's callback made it fire TWICE per hero CTA. The
   prop stays on PlayerScreen's frozen public API (hosts' composition seam);
   App just stops passing it.
2. **Ctrl+E opens the Tools dialog** (c5's VLC-parity ask): keymap.ts
   DIALOG_KEYMAP_TOML gained the VERBATIM row from keymaps/default.toml
   (`effects-and-filters = { key = "Ctrl+E", ui_action = "av-effects",
   mode = "player-focused" }` — the real spelling; c5's log suggested
   ui_action "open-tools", the keymap file says "av-effects", data wins),
   and PlayerScreen's dialog-keymap handler maps it to
   `openToolsDialog("audio")` (VLC's "Extended settings" front page = audio
   effects). No `when` gate — tools render honestly on idle sessions.
3. **Escape closes the windowed screens** (frames imply dismissal):
   SettingsScreen (through the SAME dirty-gated `requestClose` seam as the ✕
   — unsaved changes open the confirm dialog) and ShortcutsScreen (→
   `/player`, same as ✕). Overlay guard: `[role="dialog"], [role="menu"],
   .lumen-dropdown__list` + `event.defaultPrevented` — an open overlay's
   focus trap always wins. Guard deliberately does NOT match every
   `role="listbox"`: the shell sidebar's VirtualList is a persistent
   listbox, not an overlay (caught by the browser audit after jsdom passed —
   jsdom has no AppShell sidebar).
4. **Onboarding accent radiogroup got real radio semantics + arrow roving**
   (the SwatchGroup keyboard contract): `aria-pressed` buttons →
   `role="radio"` + `aria-checked` + roving `tabIndex` (selected = single
   tab stop), Arrow keys move focus AND selection with wrap-around
   (orange→red→…→gray→orange, frame order).
