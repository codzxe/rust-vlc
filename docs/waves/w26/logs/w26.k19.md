## J19-1 (P1) — tab audit maxStops=40 blind truncation — CLOSED

`tabThrough` now returns **`{ stops, exhausted }`** where `exhausted` is
`"body"` (focus returned to the body — open-surface screens fully walked),
`"wrap"` (a focus trap cycled — modal surfaces fully cycled), or **`null`**
(budget ran out mid-walk). The test **fails on null** with a "raise
maxStops" message — a prefix audit can never pass again. Budgets are
per-route in `TAB_ROUTES` (~2.5× measured stops: 80 default, **400 for
/keyboard-shortcuts**), and the two dialog routes joined the audit with the
**trap-aware wrap rule**: a wrap is legal only as a jump to the TRAPPING
CONTAINER's first focusable (stop records its `[role="dialog"]` /
`.settings-window` ancestor + that container's own DOM-first tabbable), not
the page minimum.

**Measured (live probes, this session):** /keyboard-shortcuts = **149 stops,
wrap at stop 148 → dialog first focusable idx 21** (walk enters at 23 — the
Dialog's focus-on-open pulls focus to the search field; the wrap validates
the trap contract, ring 2px solid accent on all 149, 0 invisible, 0 outside
the trap, 843 ms); /open-network-stream = 4 stops + wrap → 21 = trap first
focusable. **Regression proof (run):** dropping the shortcuts budget back
to the old 40 → the test FAILS at the exhaustion assertion (the exact
silent-truncation the review flagged). Settings-global wrap still lands on
the window's first focusable; player/playlist/onboarding still end at body.
