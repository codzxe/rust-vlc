### g06 P1-2 — open menus lock the chrome (the stranding bug)
`useChromeAutoHide` now locks from TWO sources: the call site's `locked` prop
(panels/customize, unchanged, Lead-owned) + a DOM-truth overlay lock — a
`MutationObserver` re-checks `document.querySelector('[role="menu"],
[role="dialog"]')` on every mutation; menus/dialogs are conditionally rendered
by their owners (ControlBar app menu, canvas MenuPopup, ContextMenu, Dialog all
mount `role="menu"`/`role="dialog"` only while open), so present === open with
zero ownership coupling. While locked: no idle timer, no fade; a menu opened
while hidden reveals AND locks in one transition. **Live-verified:** canvas
context menu open 4s → `data-chrome="locked"`, menu `visibility: visible`, band
opacity 1 (was: hidden + faded under the menu). App menu open 4s → `locked`,
**focusInsideMenu: true** (the g06 stranding repro is dead). Close → idle
re-arms (hidden at 3.6s). 3 new tests (menu lock, dialog lock,
hidden→locked transition); 13/13 in the file.
