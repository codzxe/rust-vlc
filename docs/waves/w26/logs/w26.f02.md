## Decisions

1. **No Dropdown API change** — the existing component serves settings as-is
   (verified by reading `Dropdown.tsx`: labelKey/identity resolver, density,
   className all sufficient). `Dropdown.test.tsx` untouched, 12/12 pass.
2. **Settings control skin lives in `setting-field.css`, scoped under
   `.settings-field__control .lumen-dropdown--compact …`** — one specificity
   class above menu.css/form.css so the skin wins regardless of bundle order;
   the shared primitives keep their grammar on every other surface. (The
   settings.css lane f03 expected exactly this — their comment: "the Dropdown
   rule lives in setting-field.css".)
3. **Trigger anatomy** (frame `Settings - playback.svg` "Dropdown"): 320×36
   rx6, rendered as a 2px `--color-surface` ring around a
   `--color-surface-panel` fill (r6 outer → r4 inner edge = the frame's inner
   316×32 rx4 rect). Open trigger `--color-surface-selected` (Setting
   Preset.svg). Open list: `--radius-menu` (r10–12, mission pin), borderless
   panel + component shadow, 44px options (Dropdown.svg 360×44 rx4), orange
   check on selected (component grammar).
4. **enum → Dropdown applies to every plain enum row** (privacy
   crash-reports, playback subtitle-mode, controls mouse ×4). Special widgets
   (ThemeModePicker, LocalePicker — f03 already moved LocalePicker to a
   Dropdown) and the codecs F2-gated hand widget are untouched (not my files).
5. **No unit suffix** on duration values ("3 s" in the frame) — not in the
   findings list (e08 MATCH-passed the seeded values); noted as possible
   polish for the seed lane.
