## Fixes landed

### P1-1 — /miniplayer toggle lies over the :has()-suppressed column (CLOSED)
j05's live repro: on /miniplayer, clicking "Toggle playlists sidebar" flipped
`aria-expanded`→true, dropped `hidden`, and persisted `"open"` while
variants.css's `:has([data-variant="miniplayer"])` kept the column `display:none`.
Three-part fix, all in AppShell.tsx:
1. **Gate** — `toggleSidebar` is an honest no-op while `onMiniplayerRoute`
   (early return): aria never claims a suppressed column, nothing persists for
   a toggle that did nothing. (Chose the review's "gate" option over
   "add sidebarOpen to the route-effect deps": the deps change would re-run
   the player-route collapse on every user toggle and break the pinned
   one-sidebar convergence test, and the toggle's persist would still write
   the phantom "open" before the effect re-collapsed.)
2. **Harden** — `loadSidebarOpen` now checks `/miniplayer` BEFORE the stored
   preference, so a deep-link with another route's stored "open" never starts
   open over the suppressed column (previously honest only after the
   mount-effect repaint). The stored preference is only read — it survives
   for real-column routes.
3. Route-change-into-/miniplayer collapse (w26.i20) unchanged — the gate
   covers the resident-user path the old suite missed.

**Regression tests (2):** "ON /miniplayer the toggle is an honest no-op — no
aria flip, no un-hide, no phantom persistence" (two clicks, all three signals
+ localStorage pinned) and "a stored OPEN preference never surfaces over the
suppressed /miniplayer column (and survives it untouched)". **Proven to bite:**
temporarily removing the gate fails the first test with
`aria-expanded="true"` — the exact lying state — then restored.

### P2-1 — hide-UI chrome stayed focusable/AT-visible (CLOSED, CSS-only)
appshell.css hide-UI layer now adds `visibility: hidden` with a delayed 0s
step (`transition: opacity 160ms ease, visibility 0s 160ms`); the reveal path
(`visibility 0s 0s`) flips visibility back instantly while fading in. Kept the
seam one-sided (PlayerScreen mirrors data-lumen-chrome; no player-lane edit).
Reduced-motion: the hidden-state rule carries higher specificity than the
existing `transition:none` block, so it got its own kill inside the same
`no-descending-specificity`-scoped media query. Grep: no `visibility:visible`
overrides anywhere under the chrome (inheritance-safe).

### P2-2 — strip portal had zero runtime test (CLOSED)
Three integration tests in AppShell.test.tsx using a minimal
`useAppShellStrip()` consumer (imports the context exactly like PlayerScreen):
portals into `.app-shell__strip` **outside `<main>`** with the
`lumen-player lumen-player--strip` host classes; strip stays EMPTY without a
consumer (`childElementCount===0`, the `:empty` proxy); consumer renders
**in place** on the null default (isolated host). A moved provider or dropped
`ref={setStripHost}` now fails in CI.

### P2-3 — impure setState updaters (CLOSED)
- `persistSidebarOpen` moved OUT of the `setSidebarOpen` updater
  (`const next = !sidebarOpen; setSidebarOpen(next); persistSidebarOpen(next);`,

- `setQuery("")` moved out of the `setSearchOpen` updater into a
  `useEffect` on `searchOpen === false` (filter-drop-on-close semantics
  unchanged; existing test green).
