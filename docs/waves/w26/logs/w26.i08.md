## Root-fix proposals for i16 / Lead (the required log)

i16's `clippingBounds` container measurement **landed and is correct** — that
half of the proposal is done. What remains for the shared primitive:

1. **Viewport-escape fallback in `Dropdown.tsx`.** The flip picks the roomier
   CLIP side, but when the list fits NEITHER side of the clip container (any
   content-sized dialog with a list taller than the body — the HDR rest state),
   it still clips. Proposal: after the clip-box decision, if neither side fits,
   fall back to the viewport (portal the list, or the `position: fixed`
   computed-coordinate escape this lane ships scoped in
   `useDropdownScrollportFlip.ts` — fixed escapes every overflow clip while
   keeping the DOM child relationship, so outside-click/Escape/typeahead keep
   working; re-glue coordinates on scroll/resize). The video tools' scoped
   stopgap can then be deleted. Last resort: cap to the roomier side
   (already in menu.css as max-height 320 — make it room-derived instead).
2. **`menu.css` trigger `text-align: start`.** UA `button { text-align: center }`
   centers every dropdown's selected value; every W26 frame inks it left
   (vision flagged it on 3 independent compares here before I pinned it
   pixel-wise). Currently only the two video triggers override scoped; the EQ
   presets, settings and subtitles dropdowns all still render centered.
3. Minor: shared trigger value inset is 8–10px (`--space-inset` padding) vs the
   HDR frame's 16px — a padding-token decision, not urgent.
