## What was fixed

### j04-1 (P1) — Escape-yield selector wedged Folder-2/3 shut
`popupOwnsFirstEscape` (Surface.tsx:73-83) replaces the bare
`node.querySelector('[role="listbox"], [role="menu"]')` subtree query — popups
are now matched by **OPEN STATE, wherever they live**:

1. document-wide open-trigger query:
   `[aria-haspopup][aria-expanded="true"]:not([aria-haspopup="dialog"])` —
   Dropdown/VisualizerModeSelect/MenuPopup hosts render their popup nodes only
   while open, and the trigger's expanded bit is the honest open state for
   in-tree, fixed and portal-mounted popups alike ("dialog" triggers excluded —
   their expanded bit is the surface's own state);
2. focus-outside-surface fallback: if focus sits inside a listbox/menu OUTSIDE
   the surface subtree (portal/fixed context menus), the focused popup owns the
   key.

In-flow listboxes INSIDE the surface (SubtitlePickList candidate states, the
MiniPlayer queue) never match → the dialog closes on the first Escape again.
Regression tests in the owning suite (j04-3 harness, below). k15 note: the
`guardedClose` dropdown branch (j04-14) is now unreachable dead code in
AddSubtitlesDialog — retire it on your next touch.
