pointer/keydown while armed) re-rendered the app's biggest tree at

## J06-2 (P1) — pendingToggle never cleared on failure — CLOSED

`pendingToggle` was cleared only by `session.state-changed`. **Fix
(context.tsx):** all three failure paths resolve it — (1) the dispatch
ERROR envelope (`isToggleCommand` guard, so a failing NON-toggle never
falsely resolves an outstanding toggle), (2) the transport-failure catch
(host unreachable — no state change can ever arrive), (3)
`playback.error` (the engine transitioned to an error, not the requested
play/pause). The header comment + `PlayerState.pendingToggle` doc state
the full resolution set.

**Regression tests (context.test.tsx, new file):** toggle→ERROR clears
the flag + surfaces the typed error (the exact stuck-spinner repro);
toggle over a REJECTING transport clears it + `not-ready` error; happy
path unchanged (accepted keeps pending, state-changed resolves); a
failing seek does NOT resolve an outstanding toggle; async
`playback.error` resolves it.
