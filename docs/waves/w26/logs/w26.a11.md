## Flow implemented (verified, not changed in shape)

```
FIRST RUN  (lumen.onboarding.v1 absent / complete ≠ true)
  /                 → /player → [gate: RequireOnboarding] → /onboarding
  /player           → [gate] → /onboarding
  /player/music     → [gate] → /onboarding
  /miniplayer       → [gate] → /onboarding
  /onboarding       → wizard (OnboardingEntry)
  every other route → renders directly (card 4.F1 gates ONLY the player home:
                      /playlist, /media-info, /settings/:area, /discovery,
                      /convert, /keyboard-shortcuts, /open-network-stream,
                      /dev/tokens, * → 404 stay reachable on first run)

AFTER FINISH/SKIP  (complete = true, persisted via onboardingState)
  /                 → /player  (home; empty state = onboarding-style hero)
  /onboarding       → redirect /player (wizard never shows again)
  all routes direct (incl. /settings → /settings/global)

BYPASS (NEW this lane)
  ?onboarding=1 on any player route → first-run gate treated as satisfied
  for that navigation only. Nothing is written to the onboarding store
  (localStorage stays null). Enter on the player routes themselves;
  the / → /player redirect does not carry the query.
```

The gate already existed (`RequireOnboarding` wraps the three player routes;
`OnboardingEntry` keeps /onboarding honest after completion) — verified and
KEPT as-is. The only functional addition is the `?onboarding=1` bypass
(`useOnboardingBypass()` in App.tsx), needed because dev-shots always starts
a fresh browser profile, so player shots need a way past the gate:
`node scripts/dev-shots.mjs player:/player?onboarding=1`.
