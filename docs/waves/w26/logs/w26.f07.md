## Findings fixed

## Decisions

- **Pointer-mode detection** reads the `style` prop (`left`/`top` in px), not
  `getComputedStyle` — vitest runs without CSS applied, so a computed-position
  gate would be untestable in jsdom. Contract documented on the prop.
- **Submenu flip via inline `transform`**, not a CSS class: keeps the base
  anchor for the fits-case, composes with hosts' own CSS flips, avoids
  re-measure loops.
- **No `max-height`/`overflow-y: auto` scroll guard** on popups: an overflow
  scroll container would clip the horizontally flying-out submenus (e12 F2
  would regress). With 48px rows the 14-row canvas menu (683px) fits every
  viewport ≥ 700px tall after flip/shift; below that the window edge still
  cuts it — residual, below the 1024×768 quality bar, accepted.
- Anchored (menubar-style, depth 0, no px style) popups keep their CSS
  anchor — ControlBar's opens-up menu and MenuBar are unaffected (verified:
  no `style` prop there).
- Separator color → `var(--color-surface-raised)` (#222222 exact frame value;
  semantically a surface, cited `right-click menu.svg`).
- Panel fill height 683px + 2px border = 685 live (border is e12 F11, P3, not
  mine; noted). Hover fill stays `--color-surface-hover` #262626 vs frame
  #1F1F1F — observation for f15/Lead, not in my findings.
