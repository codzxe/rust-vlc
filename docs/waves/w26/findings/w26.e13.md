## Findings

### F1 — Bypass + open-media kicks the user to /onboarding mid-flow (P3, dev-tool edge)

**Step observed**: probe `realpath-probe` path B (not the real-user path).
**Evidence**: on `/player?onboarding=1` (store empty), clicking a demo clip in the open-media dialog routes via `navigate(openPathRoute(source))` to param-less `/player`, which the first-run gate redirects to `/onboarding` — the wizard hijacks the session mid-open (shot 07e; reproduced 2×). The REAL user path (wizard completed first) is unaffected: open clip → stays `/player`, playback live (shot 07d), confirmed in the main flow.
**Location**: `ui/src/screens/open-media/OpenMediaDialog.tsx:131` (`navigate(openPathRoute(source))`) × `ui/src/App.tsx:87-102` (`RequireOnboarding`).
**Suggested fix**: dev-tools lane — have `openPathRoute` preserve the `onboarding=1` query (or let the bypass set a session flag); cosmetic for real users, but it will surprise dev-shots/screenshot tooling that opens media.
**Confidence**: HIGH (reproduced; code path traced).

### F2 — ToolsCard shared skeleton is exported + tested but unused by the 8 shipped tools (P3, hygiene)

**Step observed**: player tools dialog (segment 2).
**Evidence**: `ToolsCard` (ToolsDialogShell.tsx:143-185, renders `.tools-card__toggle`) is only used by its own test; the three real card components each roll their own toggle (`EqualizerTool.tsx:139` `eq-tool__toggle`, `DynamicsCard.tsx:69` + `VideoCard.tsx:75` `dynamics-tool__toggle`), so `dialogs.css:333-383` `.tools-card__*` rules only fire in tests. DOM-verified: live toggles carry `eq-tool__toggle`/`dynamics-tool__toggle`/`viz-tool__toggle` only.
**Location**: `ui/src/screens/player/dialogs/ToolsDialogShell.tsx:143`; consumers above.
**Suggested fix**: tools lane — compose `ToolsCard` in the three card components (deduplicates the toggle/collapse logic) or drop the unused export; note e14 F1 separately flagged the hardcoded copy constants in the same file.
**Confidence**: HIGH (code + runtime DOM).
