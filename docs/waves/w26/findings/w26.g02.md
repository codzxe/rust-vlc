## Findings

### [g02-P1-1] Selected-accent dot ring never renders (CSS selector vs ARIA mismatch)
- **Step/reproduce:** appearance step (frames 6–10 all show it). `/onboarding` → Next ×2 → click any accent dot → no ring appears around the selected dot, on any accent, at any viewport.
- **Responsible files:** `ui/src/screens/onboarding/onboarding.css` (line ~539) vs `ui/src/screens/onboarding/OnboardingScreen.tsx` (accent buttons, ~lines 728–741).
- **Frame evidence:** `Onboarding-6..10.svg` each carry `<rect width="60" height="60" rx="30" stroke="<accent>" stroke-opacity="0.3" stroke-width="4">` around the selected dot (cyan at x=363, blue 443, violet 523, pink 603, gray 683 — dots 5–9). Reference PNG pixel sample at ring edge: `(16,54,65)` = cyan @30 % on #0E0E0E. Implementation screenshot pixel sample around the selected cyan dot: flat window bg `(22,22,22)`.
- **Code evidence:** buttons render `role="radio"` + `aria-checked`; CSS targets `.onboarding__accent[aria-pressed="true"]::after` — never matches. `getComputedStyle(sel, "::after").borderStyle === "none"` for all 5 accents.
- **Fix direction:** change the selector to `.onboarding__accent[aria-checked="true"]::after` (geometry already frame-exact: inset −10 px, 4 px, 50 %, opacity .3). Add a test asserting the selected dot's ring.

### [g02-P1-2] Appearance choices (theme mode + accent) are not persisted — silently revert on next launch
- **Step/reproduce:** wizard → appearance → pick **Light** + **gray** → finish → /player renders light/gray → **reload** → back to dark/orange. `localStorage["lumen.settings.overrides.v1"]` stays `null` the whole time.
- **Responsible files:** `ui/src/screens/onboarding/OnboardingScreen.tsx` (appearance step calls `theme.setModeSetting/setAccent` only); `ui/src/theme/ThemeProvider.tsx` (setters are state-only, lines 108–117); persistence read exists (`settingsThemeSync.ts` `readPersistedThemeMode/readPersistedAccent`) but nothing in onboarding ever writes it.
- **Frame evidence:** frames 6–10 ARE the personalization step ("Select your preferred theme and color."); sibling steps playback/subtitles in the same screen wrap in `SettingsProvider` + `AutoApplySettings` and DO persist — the asymmetry means the wizard's first-run answer evaporates.
- **Fix direction:** wrap the appearance step in the same `SettingsProvider` + `AutoApplySettings` seam writing `interface.theme` and `global.accent-color` (keys already declared in `settingsThemeSync.ts`), or persist on `complete()`.
- (Run log: during=gray/light → afterFinish /player gray/light → afterReload orange/dark, overrides null.)

### [g02-P2-1] Working-step heading is 32 px; frames measure ≈24 px
- **Step/reproduce:** appearance step heading "Select your preferred theme and color." at any viewport.
- **Responsible files:** `ui/src/screens/onboarding/onboarding.css` (`.onboarding__title` uses `--font-size-display` for every step).
- **Frame evidence:** `Onboarding-6.svg` heading path bbox 427.7×23.2 (≈24 px type; 39 % of window width). Live: 32 px, text width 532 px (49 % of window). The display token IS right for the welcome/done hero ("Welcome to VLC!" ≈32 px, 251.6 px wide) — the frames run working steps one size down.
- **Fix direction:** a ~24 px working-step heading treatment (needs a token decision — `--font-size-title` is 18 px); keep hero at display.

### [g02-P2-2] No hover affordance on theme cards or accent dots
- **Step/reproduce:** appearance step, hover Light card / any accent dot — zero visual response (no bg/shadow/transform change; live-probed).
- **Responsible files:** `ui/src/screens/onboarding/onboarding.css` (no `:hover` rules for `.onboarding__theme-card` / `.onboarding__accent`).
- **Frame evidence:** frames are static (no hover state shown), but CONTRACT §7 quality bar requires hover/focus/active states; Back/Skip/Next already comply via `button.css`.
- **Fix direction:** quiet hover per design language (e.g. swatch `box-shadow` accent hairline or slight brighten on card; dot ring preview or scale on hover), focus ring already inherited from the global floor.
