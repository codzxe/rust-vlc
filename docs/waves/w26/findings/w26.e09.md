## Findings

### F1 — P1 (unshipped surface): the sorting/view options layer and thumbnail/media views are mounted NOWHERE in the app

- **Surface:** `/playlist` + player playlist dock vs `Sorting_Options.png`,
  `View_Options.png`, `thumbnail.png`, `media.png`.
- **Evidence:** import graph — `PlaylistOptionsToolbar` / `PlaylistOptionsViews`
  are imported only by `options/harness.tsx` + tests
  (`rg "from \./options|playlist/options" ui/src` → 0 app-route hits).
  `PlaylistScreen.tsx` renders only the library rows; `PlaylistPanel.tsx`
  (player dock) renders its own prev/next/shuffle/repeat/clear controls, no
  toolbar. On live `/playlist` there is no sort trigger, no view trigger, no
  grid/list body — the four frames cannot be reached by any user action.
  The in-code integration recipe points at `docs/waves/w26/logs/w26.b10.md`,
  **which does not exist** (logs dir has no b09/b10 files).
- **Location:** `ui/src/screens/playlist/PlaylistScreen.tsx:50-97`,
  `ui/src/screens/playlist/options/PlaylistOptionsToolbar.tsx:1-31`.
- **Suggested fix:** Lead mounts `<PlaylistOptionsToolbar />` in the playlist
  panel header meta row and `<PlaylistOptionsViews />` in the body (inside
  `PlaylistProvider` + `PlaylistOptionsProvider`) — per the recipe recorded
  in `options/index.ts:5-12`; needs a host with queue entries (an
  "open playlist" view of the library, or the player dock).
- **Confidence:** high (DOM + import graph; components themselves verified
  frame-exact via harness).

### F2 — P1 (unshipped surface): the Add-Subtitles flow is unreachable — no affordance exists in the product

- **Surface:** subtitle flows vs `subtitle_one/multiple/sub_filename.png` +
  the 4 `Add Subtitles to Playlist` folder states.
- **Evidence:** `AddSubtitlesDialog` is imported only by
  `subtitles/harness.tsx` + tests (0 app-route imports). On live `/player` a
  DOM sweep of every button/menuitem for `subtitle|caption|srt` returned **0
  hits**; the only designed entry — queue-row menu "Add subtitle tracks" — is
  `disabled: true` ("no event seam", `PlaylistPanel.tsx:341`) and with no
  engine the queue has 0 rows (`QUEUE_ROWS: []`), so even that entry never
  renders. The dialog is frame-exact (see table) but unreachable.
- **Location:** `ui/src/screens/playlist/PlaylistPanel.tsx:338-341`,
  `ui/src/screens/playlist/subtitles/AddSubtitlesDialog.tsx:27-29` (mount
  recipe comment).
- **Suggested fix:** wire an affordance — enable the queue-row menu entry and
  open `AddSubtitlesDialog` with `mediaNames={entries.map(entryDisplayTitle)}`,
  or add a subtitle action in the player/control-bar menu; the dialog's props
  (`mediaNames`, `candidates`, `onSave`) are already the host seam.
- **Confidence:** high (DOM sweep + import graph).

### F3 — P1 (interactive breakage): library rows' hover fill / kebab / click / right-click only cover the left ~36% of each row (ContextMenu wrapper doesn't fill the row)

- **Surface:** `/playlist` library rows vs `playlist.png` ("rows ~66px r10
  with icon + title + `•••` on hover").
- **Evidence:** `.lumen-plpage__row-wrap` (the ContextMenu wrapper) gets
  `height: 100%` but **no width** (`playlist.css:229-231`) and
  `.lumen-context-menu` has no width rule in `menu.css` → the wrapper shrinks
  to content: **224px wide inside a 614px `.lumen-vrow`** (measured).
  Hovering at row x+100 → `.lumen-lrow:hover` fill `#262626` + kebab reveal;
  hovering at row x+500 → `:hover` chain stops at `.lumen-vrow`
  (`playlist.css:103-106` intentionally makes the vrow transparent), **no
  fill, no kebab, no click-select, no right-click menu**. The `•••` renders
  at ~204px from the row's left edge, hugging the title, not at the panel's
  right inset as the frame shows.
- **Location:** `ui/src/screens/playlist/playlist.css:229-231` (root cause);
  same wrapper-shrink class already logged for queue rows by the c6 lane
  (`PlaylistPanel.tsx:26-27` — "`.lumen-vrow` > wrapper fill needs a list.css
  rule (menu lane)").
- **Suggested fix:** `.lumen-plpage__row-wrap { height: 100%; width: 100%; }`
  (or a shared `.lumen-vrow > .lumen-context-menu { width: 100% }` rule in
  `list.css`, which also fixes the queue rows — coordinate with the menu
  lane).
- **Confidence:** high (reproduced with two hover positions + pixel samples;
  screenshots `a9-row-hover-left.png` vs `a10-row-hover-right.png`).
