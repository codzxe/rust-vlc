## Findings

### g18-P2-1 · Media view · the hover "•••" row actions never render on `/playlist`
- **Screen/reproduce:** `/playlist` → open any saved playlist (media view) → hover a row: the title
  brightens to `#C6C6C6` (✓) but no kebab/dots appear, ever. Pixel scan of the right 60px of hovered
  rows (`05-media-hover.png`): **0 bright pixels**. DOM: `.lumen-plo-mrow__menu` **does not exist**
  (`menuBtnExists: false`, `anyKebab: false`).
- **Frame evidence:** `media.svg` pins TWO hover states whose defining anatomy is Vector 36–38 — Ø3
  dots, 6px pitch, `#8F8F8F`, ending ≈24.5px from the row's right edge (hover-watched y188 + 
  hover-unwatched y138). The CSS for it exists (`options.css .lumen-plo-mrow__menu/__dots`) but is dead
  on this route.
- **Responsible files:** `ui/src/screens/playlist/PlaylistScreen.tsx` (renders
  `<PlaylistOptionsViews />` with no `onEntryMenu`), `options/PlaylistOptionsToolbar.tsx:39-42`
  (forwards nothing), `options/MediaList.tsx:64,115` (menu button mounts only when `onMenu` defined).
- **Fix direction:** wire a real seam — e.g. per-entry `onEntryMenu` opening the existing
  ContextMenu grammar (Open/Add-subtitles/Remove class) or the AddSubtitles flow scoped to that
  entry — so the frame's hover affordance is honest, not absent. (A dead kebab would violate the
  no-dead-affordance rule; absence violates the frame. The seam must do something.)
- **Confidence:** high.

### g18-P2-2 · Thumbnail grid · artwork well is imperceptible — `opacity: 0.3` washes fill AND glyph
- **Screen/reproduce:** `/playlist` → open "Anime to Watch" → View options → Grid View: cards render
  as near-flat rectangles; the 252×142 artwork region is visually indistinguishable from the card.
  Pixel scan of card 1's art region (`07-thumbnail-grid.png`, 35,784 px): well bg reads **#161616**
  (21,21,21) vs card `#191919` (25,25,25) — Δ4/255; the placeholder glyph peaks at **#3c3c3c** with
  only **64 px** brighter than #232323. Same wash in light mode (`#dedede` @0.3 over `#efefef`).
- **Frame evidence:** `thumbnail.svg` — the artwork (252×142 rx4, 10px inset) is a full-bleed image
  and the card's dominant region. The implementation's own token intent (`--color-surface-deep`
  `#0e0e0e` well + tertiary glyph) is defeated by `opacity: var(--opacity-muted)` (=0.3) applied to
  the whole `.lumen-plo-card__art` element.
- **Responsible files:** `ui/src/screens/playlist/options/options.css:163-172`
  (`.lumen-plo-card__art { opacity: var(--opacity-muted) }`), `options/ThumbnailGrid.tsx:37-39`.
- **Fix direction:** drop the element-level opacity; keep the well fill at full `--color-surface-deep`
  and mute only the glyph (e.g. `color: var(--color-content-tertiary)` + opacity on the Icon, or a
  dimmer dedicated token). The empty well then reads as a deliberate inset, not a void.
- **Confidence:** high.

### g18-P2-3 · Create dialog · disabled Save is a generic gray button, not the frame's dimmed tinted pill

- **Fix direction:** disabled tinted buttons keep their tint and dim via `opacity: .5` (frame-exact);
  coordinate with the button lane (shared primitive — affects all `tinted` consumers).
- **Confidence:** high on the delta; fix ownership is cross-lane.
