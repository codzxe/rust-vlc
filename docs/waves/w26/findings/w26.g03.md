### [g03-P1-1] Default `/player` opens TWO left sidebars — one-sidebar rule violated
- **State/repro:** first-run `/player` (seeded onboarding-complete, fresh localStorage), dark or
  light, ≥1100px wide. `dev-shots player:/player`; DOM: `.app-shell__sidebar` x=52..260 (208px,
  `hidden=false`) AND `.lumen-player__sidebar` x=260..476 (216px, open).
- **Frame evidence:** `Player.png`/`Player.svg` = rail (0..50) + ONE sidebar (50..427) + canvas
  (427..1920). Both sidebars are identical `#0E0E0E` deep surfaces split by a hairline — reads as a
  duplicated column bug; 33% of the window is left chrome vs the frame's 22%.
- **Responsible:** `ui/src/components/appshell/AppShell.tsx` — `loadSidebarOpen()` defaults OPEN with
  **no route awareness**; the f08 seam ("shell sidebar default-CLOSED on /player") that
  `PlayerScreen.tsx:9-13` and `player.css` document was never implemented. Cross-lane (appshell
  f08/a10 ↔ player a13/f09). NOTE for Lead: the two lane logs claim contradictory "Lead decisions"
  — f09/e02-F3 says the DOCK is the default-open one (shell sidebar closes); a10 says the SHELL
  playlists sidebar is Player.png's sidebar (dock should flip closed, "prepared 1-line flip"). Pick
  one owner; today NEITHER landed and first paint shows both (f09 log line 19 admits it).
- **Fix direction:** route-aware first-run default in AppShell (`/player` → shell sidebar closed;
  stored preference wins) **or** flip the player dock default to closed — either restores the
  one-sidebar composition; the toggle convergence already works (a10 verified).
