## Findings

1. **[g13-P1-1] Subtitles area overflows the window — 3 of 14 rows invisible at 1440×900.**
   - Screen+reproduce: /settings/subtitles, 1440×900, no interaction. Outline thickness
     (row y913), Outline color (y959), Shadow (y1005) sit below the window bottom (y884); the
     Text-opacity scale labels are clipped mid-block (y880–896). `content.scrollHeight=1012` vs
     `clientHeight=787`. Frame shows ALL 14 rows inside the 1048×865 window (Shadow toggle ends
     y863). Overflow is intrinsic (1012 > 815 even at full 865 window height).
   - Responsible: `ui/src/screens/settings/areas/subtitles.tsx` (3 staged notes, +~30px each);
     `ui/src/screens/settings/settings.css` (shared: uniform 46px row pitch vs frame 42 on
     toggle rows, 44px section gap vs 38, content top padding 44 vs frame 33) — settings.css is
     f03-owned, cross-lane.
   - Frame evidence: Settings - subtitles.svg row bands y114/156/202…(pitch 42–47), headers
     y83/276/423; capture /tmp/shots-w26g13/subtitles.png + /tmp/cap-w26g13/extract.log.
   - Fix: consolidate the staged note to ONE area-level line (or move to the ⓘ titles), and take
     the shared pitch/gap/header-offset down to frame values in settings.css.

2. **[g13-P2-2] Font row renders a dropdown; frame pins a text input.**
   - Screen+reproduce: /settings/subtitles → Appearance → Font. Current: `.lumen-dropdown--compact`
     320×36 with chevron, value "System, sans-serif". Frame: 318×34 rx5 #090909 well + 2px #191919
     stroke, NO chevron (rect y456; the frame's five chevrons sit at y172/218/365/566/763 — Font
     is not among them).
   - Responsible: `ui/src/screens/settings/areas/subtitles.tsx` (`StagedDropdownRow` used for
     `subtitles.font`).
   - Fix: render the staged Font row as an inert input-style field (color-row well grammar with
     text, no chevron).

3. **[g13-P2-3] Every subtitles control dimmed to opacity 0.5 vs frame's full-strength controls.**
   - Screen+reproduce: /settings/subtitles — computed opacity 0.5 on `.lumen-switch`,
     `.lumen-dropdown__trigger`, `.lumen-segmented__segment`, color wells; pixels read
     half-strength (#121212 field vs #191919, #5c3710 thumb vs #AB6314). Frame controls are live.
   - Responsible: `ui/src/screens/settings/areas/subtitles.tsx` (staged disabled pattern; module
     header documents it as config-never-invents pending the `subtitles.*` schema seed).
   - Fix: schema owner seeds `subtitles.*` [[setting]] rows so the area goes live (handoff
     docs/waves/w26/logs/w26.f04.md). Until then consider full-strength inert presentation
     instead of opacity dimming (frame-credible now, honest affordance kept).

4. **[g13-P2-4] Segmented control (Size values): 11px labels and unequal cells vs frame ≈15px / 2×157 equal.**
   - Screen+reproduce: /settings/subtitles → Appearance → Size values. Measured: cells
     "Relative" 162.2px / "Pixels" 151.8px (frame 2×157), font-size 11px (`--font-size-caption`)
     vs frame labels ≈15px; active #371F06+#D37918 and 32px/rx4 anatomy correct.
   - Responsible: `ui/src/components/form/form.css` (`.lumen-segmented__segment`:
     `font-size: var(--font-size-caption)`, `flex: 1 0 auto`) — form-lane file, cross-lane;
     manifests on this screen.
   - Fix: `font-size: var(--font-size-section)` and `flex: 1 1 0` (equal cells).
