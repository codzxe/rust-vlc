## Method

1. Dev server confirmed up: `curl http://localhost:5173/player` → 200.
2. `dev-shots.mjs network-stream:/open-network-stream
   shortcuts:/keyboard-shortcuts --out /tmp/shots-w26.e12 --port 5173` → OK.
3. Playwright harness (`/tmp/w26e12-menus.mjs`, `…round2/3.mjs`,
   `…queuerow*.mjs`, `…shortcuts.mjs`, `…1024.mjs`; `createRequire` from
   `ui/package.json`, `@playwright/test`): reproduced every reachable open
   menu state + both dialogs at 1440×900 and 1024×768, captured screenshots
   (`/tmp/shots-w26.e12/*.png`, 16 files) and deterministic DOM metrics
   (boxes, computed styles, aria roles, keyboard event results, console
   errors) → `/tmp/w26e12-metrics{,2,3,4}.json`, `/tmp/w26e12-shortcuts.json`,
   `/tmp/w26e12-1024.json`.
   NOTE: `/player` is gated behind first-run onboarding; used the documented
   `?onboarding=1` bypass. Player queue rows / discovery volumes were empty in
   the demo shell → those two menus verified by code-read (marked [VERIFY]).
4. `z-ai vision` comparisons attempted 6× over ~15 min (2 fails → 60 s wait →
   retry → further retries): **every call returned HTTP 429** (rate-limited).
   Per contract fallback, verdicts below are based on deterministic DOM
   measurements + a pure-node PNG pixel sampler (`/tmp/w26e12-pixels.mjs`,
   zlib+unfilter decode, same-coordinate color sampling of live shot vs frame
   render). All VLM verdicts are **[VERIFY]**; the DOM/pixel evidence is
   measured, not estimated.
5. Code-read: `ui/src/components/menu/*` (MenuBar, MenuPopup, MenuItem,
   ContextMenu, Dropdown, menu.css), `PlayerScreen.tsx` canvas menu,
   `ControlBar.tsx` app menu, `PlaylistScreen/PlaylistPanel`,
   `DiscoveryScreen`, `ShortcutsScreen`, `NetworkStreamScreen` + CSS,
   settings `effects.tsx`, `EqualizerTool.tsx`, generated tokens.

## Findings

### F1 — P1 — Canvas right-click menu is never viewport-clamped; effectively always clipped at 1440×900
- **Surface**: `/player` canvas context menu (vs `right-click_menu.png`).
- **Evidence**: opened at canvas top (x958, y91): popup 280×849 →
  bottom = **940 > 900** (`menu-canvas-ctx-top.png`, `/tmp/w26e12-metrics3.json`
  `canvasMenuTop.overflows: true`); at mid-canvas (y443) bottom = 1292. The
  panel (14 rows × 58 px + 3 separators × 9 px + 8 px pad = 849 px) can only
  fit if opened at y ≤ 51 — the canvas starts at y31, so in practice the tail
  rows ("Open Media", "Quit VLC") are cut off. Worse at 1024×768. Frame panel
  is 683 px and would fit at the same points.
- **Location**: `ui/src/screens/player/PlayerScreen.tsx:814-832` (MenuPopup
  `style={{left, top}}`, no clamping/flip); `ui/src/components/menu/menu.css:219-224`
  (`.lumen-context-menu__popup` fixed, no max-height).
- **Suggested fix**: clamp/flip the fixed popup inside the viewport (and/or
  adopt 48 px rows, F3, which alone brings it to 683 px).
- **Confidence**: measured, reproducible.

### F2 — P1 — Canvas-menu submenus open off-screen right (no flip)
- **Surface**: `/player` canvas menu → "Playback" submenu (vs `Profiles.png`
  flyout grammar).
- **Evidence**: submenu panel x1237 w400 → right edge **1637 > 1440** (197 px
  clipped, `/tmp/w26e12-metrics3.json` `canvasSubmenu.overflowsRight: true`;
  `menu-canvas-submenu.png`). `.lumen-menu--submenu` always opens
  `left: 100%`; only the ControlBar app menu carries a local opens-LEFT
  override (`controls.css:266-271`). Also: comfortable submenus have
  `min-width: 400px` (menu.css:76) vs the `Profiles.png` flyout 265 px.
- **Location**: `ui/src/components/menu/menu.css:89-93, 76`.
- **Suggested fix**: edge-aware submenu side selection (as controls.css
  already does locally) + 265 px submenu width per frame.
- **Confidence**: measured.

### F3 — P2 — Comfortable menu rows 58 px vs SVG-truth 48 px (all big menus)
- **Surface**: canvas menu, queue-row menu (vs `right-click_menu.png`,
  `file_context_menu.png`, `playlist_context_menu.png`, `menu.png`).
- **Evidence**: canvas menu rows 58 px (measured), panel 849 px vs frame
  683 px (14 rows). Analysis §A1/§C1: every menu frame is exactly
  `8 + 48×rows + separators`; icons 20×20 (live comfortable 22 px), labels
  ≈15 px (live 16 px `--font-size-label`). Compact density is 40 px vs
  Setting-Preset 40/42 — compact is fine.
- **Location**: `ui/src/components/menu/menu.css:105` (`height: 58px` —
  comment cites "task W26 58–60px", which contradicts the SVG-ground-truth
  analysis doc).
- **Suggested fix**: comfortable rows 48 px, icon 20, label ≈15 px, panel
  height from the §C1 formula.
- **Confidence**: measured + analysis doc (SVG ground truth).
