## Findings

### F1 — Dark: `content-tertiary` body text fails 4.5:1 on every dark surface — **P1** (WCAG 1.4.3 AA)
- **Routes**: all 13 `/settings/*` (sidebar group labels "App/Media/System"), `/miniplayer`, `/open-network-stream`, `/keyboard-shortcuts`, `/convert` (17/21 routes).
- **Evidence**: computed `color: rgb(107,107,107)` (#6b6b6b = `--color-content-tertiary`) at 11–14px/400–500 on panel/raised: **3.30:1** (#6b6b6b on #191919), 3.74:1 on surface #090909, 2.99:1 on raised #222222 — axe `color-contrast` (serious). E.g. `.settings-sidebar__group-label` (h3 "App"), `.lumen-mini__title[data-empty]` ("Nothing playing"), `.network-stream__hint`/`__optional`, `.shortcuts__headcell` ("Action/Hotkey/Global"), `#convert-browse-gate`.
- **Location**: `ui/src/tokens/generated/tokens.css:40` (`--color-content-tertiary: #6b6b6b`); consumers `ui/src/screens/settings/settings.css:256`, `ui/src/screens/player/variants/variants.css:176`, `ui/src/screens/network-stream/network-stream.css:111`, `ui/src/screens/shortcuts/shortcuts.css:265`, `ui/src/screens/convert/convert.css:104`. All carry `/* frame: #6B6B6B */` Figma-port comments — the Figma source itself is sub-AA.
- **Suggested fix**: token lane raises dark tertiary to ≥4.5:1 on panel (≈#858585+) OR screens move body-size tertiary copy to `--color-content-secondary` (6.16:1 ✓) and keep tertiary for disabled/decorative/large text. Needs Lead ruling on the frame-fidelity conflict.
- **Confidence**: high (measured + axe).

### F2 — Light theme: systemic contrast failures incl. accent tokens — **P1** (WCAG 1.4.3 / 1.4.11)
- **Token-level** (`tokens.css:111-131` light block):
  - `--color-accent` NOT overridden in light → #d37918 on surface #f0f0f0 = **2.83:1** (fails 3:1 UI text/graphics);
  - `--color-accent-bright` #e8851a on panel #efefef = **2.34:1**; accent on panel 2.80:1;
  - `--color-content-secondary` #6e6e6e on #f0f0f0 = **4.47:1** (body-text fail by 0.03); tertiary #9a9a9a = 2.47:1.
  - Note: light `--color-accent-icon` #c2711a = 3.25:1 PASSes — the per-mode adaptation pattern already exists in the same block.
- **Runtime** (live light-theme axe): `.app-shell__sidebar-count` / `.app-shell__plrow-label` / `.lumen-playlist__count` / `.lumen-empty__title` #6e6e6e on #dedede = **3.78:1** (player, settings, shortcuts); `.settings-sidebar__group-label` #9a9a9a on #eeeeee = **2.42:1**; `.settings-nav__label` 4.39:1; `.settings-topbar__reset` + `.shortcuts__title` 4.47:1; `.shortcuts__headcell` 2.44:1; `.lumen-dropdown__value` #646464 on #d4d4d4 = 3.99:1.
- **Location**: `ui/src/tokens/generated/tokens.css:111-131` (generated from `themes/tokens.json` — token-lane fix), consumers across appshell/settings/shortcuts CSS.
- **Suggested fix**: token lane adds light-mode `--color-accent` (≈#c2711a-like, mirroring accent-icon), re-tunes `--color-accent-bright` (needs ≤ #b45f0f-ish for 3:1 on #efefef; current #e8851a is the *hover* value), darkens light secondary to ≥4.5:1 (e.g. #676767 → 4.76:1).
- **Confidence**: high (computed + live axe).

### F3 — `nested-interactive`: VirtualList rows wrap interactive content in `role="option"` — **P1** (axe serious, ~all routes)
- **Routes**: every route rendering the app-shell playlists sidebar (all except `/onboarding`); heaviest on `/playlist` (sidebar rows + playlist-page rows with kebab buttons, 5 nodes).
- **Evidence**: axe `nested-interactive` — `.lumen-vrow[role="option"]` contains `<a class="app-shell__plrow">` (AppShell.tsx:567) or `.lumen-lrow__kebab` buttons. Interactive-inside-option is not announced reliably by screen readers.
- **Location**: root `ui/src/components/list/Virtual.tsx:95` (`<div role="option" aria-selected={false}>` around arbitrary `renderItem` output); consumers `AppShell.tsx:557-569`, playlist/discovery/media-info screens. Note `aria-selected={false}` is also hardcoded — wrong for non-selectable navigation lists.
- **Suggested fix**: rows with interactive content should not be `role="option"`: switch sidebar/playlist lists to `role="list"/"listitem"` (or presentation) and drop hardcoded `aria-selected`; keep listbox/option only where the row itself is the select target.
- **Confidence**: high (axe, 20/21 routes).

### F4 — Dropdown trigger: visible value not in accessible name — **P1** (WCAG 2.5.3 A)
- **Routes**: `/settings/audio` ("Equalizer preset"), `/keyboard-shortcuts` ("Search scope"), `/convert` ("Target") — any `Dropdown` consumer.
- **Evidence**: axe `label-content-name-mismatch` — `<button aria-label="Equalizer preset"><span class="lumen-dropdown__value">Flat</span></button>`; visible text ("Flat") is not part of the accessible name.
- **Location**: `ui/src/components/menu/Dropdown.tsx:228` (`aria-label={label}`) + `:233` (visible `selectedLabel()`).
- **Suggested fix**: `aria-label={`${label}: ${selectedLabel()}`}` (or a visible wrapper label + unlabeled trigger).
- **Confidence**: high.

### F5 — `/miniplayer` has no h1 — **P2** (wave-a "sr-only h1 contract"; axe page-has-heading-one)
- **Route**: `/miniplayer` only (20/21 routes have exactly one h1: Player ✓ SettingsScreen.tsx:223, Player ✓ PlayerScreen.tsx:747, Playlist/Discovery/NetworkStream/Shortcuts/Convert/MediaInfo/Onboarding ✓).
- **Evidence**: `document.querySelectorAll("h1").length === 0`; strongest heading is `<h2 class="lumen-mini__title">` (MiniPlayer.tsx:210).
- **Location**: `ui/src/screens/player/variants/MiniPlayer.tsx` (no h1 rendered).
- **Suggested fix**: sr-only h1 "Miniplayer" (pattern: PlayerScreen.tsx:747 `lumen-player__sr-title`).
- **Confidence**: high.

### F6 — `<footer role="region">` — **P3** (aria-allowed-role, minor)
- **Routes**: `/player`, `/player/music`, `/miniplayer`.
- **Evidence**: axe `aria-allowed-role` — `<footer … role="region" aria-label="Playback controls">` / "Miniplayer controls"; `region` is not an allowed role on `footer`.
- **Location**: `ui/src/screens/player/PlayerScreen.tsx:840-848`, `ui/src/screens/player/variants/MiniPlayer.tsx:132-136`.
- **Suggested fix**: `<section role="region" aria-label=…>` (keeps the labelled region) or drop the role (labelled footer = contentinfo landmark).
- **Confidence**: high.

### F7 — `/onboarding` has no banner landmark — **P3** (contract deviation, likely intentional)
- **Route**: `/onboarding` — 0 banner vs "exactly one banner (title bar)" (all 20 app-shell routes have exactly one effective banner: `header.app-shell__banner`; other `header`s are correctly scoped inside `nav`/`main`/`section` so they don't double as banners).
- **Evidence**: `[role="banner"], header` count = 0 on the gate screen; `main` ✓ and h1 "Welcome to Lumen" ✓.
- **Location**: `ui/src/screens/onboarding/OnboardingScreen.tsx` (no app shell by design — first-run gate).
- **Suggested fix**: Lead ruling — accept as intentional (gate has no chrome) or add an sr-only banner.
- **Confidence**: high (observation), low (whether it counts as a defect).
