# w26.e19 — Light-mode & theme-switch coherence verification

**Agent:** verifier w26.e19 · **Scope:** LIGHT theme + theme-switch mechanism across ALL routes
(player, music, miniplayer, playlist, discovery, 13 settings areas, network-stream, shortcuts,
media-info, convert, onboarding). VERIFICATION ONLY — nothing was fixed.
**Authorities:** CONTRACT.md §2 ("dark + light both coherent", video canvas stays dark in BOTH
themes, accent stays orange), figma-fidelity-spec.md §"Light mode" (`surface #f0f0f0`,
`panel #efefef`, `content.secondary #6e6e6e`, `border #d9d9d9`, accent `#d37918`,
"video canvas STAYS DARK #2b2b2b–#333 in BOTH modes — the picture-frame rule").

## Method

**Mechanism found (code-read):**
- `<ThemeProvider>` mounted once at app root (`ui/src/main.tsx:55`); applies
  `data-theme`/`data-accent` on `<html>` (`ui/src/theme/ThemeProvider.tsx:73-77`); default
  `modeSetting="dark"` (`ThemeProvider.tsx:50`); `"auto"` resolves via
  `matchMedia("(prefers-color-scheme: light)")` (`ThemeProvider.tsx:42-67`).
- Persistence: localStorage **`lumen.settings.overrides.v1`** (JSON overrides object,
  `ui/src/screens/settings/persistence.ts:15`); theme key **`interface.theme`**, values
  **`"dark"` / `"light"`** (schema enum, `schemas/settings.toml:67-69`). `"auto"` ("system")
  exists ONLY in `ThemeModeSetting` + onboarding cards — not in the schema enum.
- The only consumers that push the setting into ThemeProvider: `useSettingsThemeSync`
  (`ui/src/theme/settingsThemeSync.ts:34-46`), mounted ONLY in `SettingsScreen.tsx:140` and
  `ThemeModePicker.tsx:20`. Picker = RadioGroup "Dark"/"Light" on `/settings/interface`
  (schema placement `screen = "interface"`); labels `settings.value.interface-theme.*`.
- Onboarding appearance step live-previews via `ThemeContext.setModeSetting/setAccent`
  (`OnboardingScreen.tsx:617,739`); playback/subtitles steps are the only ones that WRITE
  settings (AutoApplySettings, `OnboardingScreen.tsx:289-295`).

**Commands run** (dev server already up, `curl …/player` → 200):
1. `/tmp/w26e19-light.mjs` — Playwright sweep: `addInitScript` seeds
   `lumen.settings.overrides.v1={"interface.theme":"light"}` (+ onboarding done), visits all 21
   routes fresh-load, records `html[data-theme]`, screenshots → `/tmp/shots-w26.e19/light/`.
2. `/tmp/w26e19-live.mjs` + `/tmp/w26e19-live2.mjs` — real-picker live switch (label clicks on
   `/settings/interface`), in-session client-side sweep (pushState+popstate) of every route,
   music/mini canvas computed styles, `"System"` card on onboarding with
   `emulateMedia({colorScheme})` flips. `/tmp/w26e19-onboard3/4.mjs` — wizard light capture +
   persistence proof. `/tmp/w26e19-switchon.mjs`, `/tmp/w26e19-scrim.mjs` — toggle-ON ink and
   scrim probes. `/tmp/w26e19-audit.mjs` — deterministic per-route audit: dark-patch scan
   (opaque bg, rel-luminance < 0.1, ≥ 40×40px, stays-dark allowlist), text-contrast scan

3. `z-ai vision` per CONTRACT §5: **rate-limited 429 on every attempt** (2 fails, 60 s wait,
   retry failed; 2 later retries also 429). Per contract fallback: visual verdicts below are

## Findings

### F1 — P1 — Persisted LIGHT theme is NOT applied outside /settings/* on fresh load
**Route:** all 10 non-settings routes (`/player`, `/player/music`, `/miniplayer`, `/playlist`,
`/discovery`, `/open-network-stream`, `/keyboard-shortcuts`, `/media-info`, `/convert`,
`/onboarding`).
**Evidence:** fresh-load sweep with persisted `interface.theme=light`:
`theme=dark` on all 10 routes (`bodyBg=rgb(9,9,9)`); `theme=light` on all 13 `/settings/:area`
routes (`bodyBg=rgb(240,240,240)`). Full JSON: `/tmp/w26e19-light.json`. In-session
client-side navigation from a light settings page keeps light on every route (so the loss
happens on reload / deep link / app restart).
**Location:** `ui/src/main.tsx:55` (ThemeProvider mounted with no settings hydration);
`ui/src/theme/ThemeProvider.tsx:50` (default "dark"); `ui/src/theme/settingsThemeSync.ts:34`
+ mount sites `SettingsScreen.tsx:140`, `ThemeModePicker.tsx:20` (sync only runs on settings
routes).
**Suggested fix:** hydrate the theme at app root — e.g. read the persisted
`interface.theme` override (or mount a root `SettingsProvider` + `useSettingsThemeSync`) so
`modeSetting` initializes from the store instead of the hardcoded dark default.
**Confidence:** certain (empirical, twice-reproduced).

### F2 — P2 — Onboarding "appearance" step does not persist the theme (or accent) choice
**Route:** `/onboarding`.
**Evidence:** fresh profile → wizard → appearance step → "Light" card → finish ("Get
started"): `localStorage["lumen.settings.overrides.v1"] === null` afterwards; in-session
theme stays light (ThemeProvider state) but a restart reverts to dark (compounds F1).
**Location:** `ui/src/screens/onboarding/OnboardingScreen.tsx:146-152` (THEMES),
`:617` (`theme?.setModeSetting(card.setting)` — preview only), `:739` (accent, preview only);
AutoApplySettings wraps only playback/subtitles (`:289-295`).
**Suggested fix:** write `interface.theme` through the wizard's SettingsProvider on
selection/finish (needs schema enum extension to also persist "system"/"auto").
**Confidence:** certain (empirical + code-read).

2.45; `p.convert__field-gate` 2.45 (`convert.css:107`). (Excluded after checking:

**Location:** value: light block `--color-content-tertiary: #9a9a9a`
