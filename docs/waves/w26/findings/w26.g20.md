## Findings

### [g20-P1-1] Menu icon accent never paints — every "orange" menu icon renders gray
- **Screen/reproduce**: /player → open app menu → "Profile" / "Customize
  Player" icons are #8F8F8F gray (frame: two-tone w/ #AB6314 head-dot / wand
  tip). Right-click the canvas → all 15 row icons gray (frame: every
  right-click_menu.svg icon carries an #AB6314 detail).
- **Evidence**: DOM — wrapper `.lumen-menu__icon` computes rgb(211,121,24)
  under `.lumen-menu__item--icon-accent`, but the inner `svg.lumen-icon`
  computes **rgb(143,143,143)**: `icon.css` `.lumen-icon { color:
  var(--color-stroke-icon) }` is a DIRECT rule on the svg and beats the
  inherited wrapper color (`stroke="currentColor"` resolves to the svg's own
  color). PIL pixels: canvasmenu.png "More Settings" icon region (enabled
  row) = (143,143,143) only; zero orange pixels in any menu icon region.
  Control case: settings sidebar accent WORKS (its rule targets the svg
  itself) — painted #D37918, proving the mechanism.
- **Files**: `ui/src/components/menu/menu.css` (accent rule targets only the
  wrapper), `ui/src/components/icon/icon.css` (`.lumen-icon` base color);
  consumers passing `iconAccent: true`: `ui/src/screens/player/PlayerScreen.tsx`
  (canvas menu, all rows), `ui/src/screens/player/controls/ControlBar.tsx`
  (app menu rows 8/10), `ui/src/screens/playlist/PlaylistPanel.tsx` (all 8
  queue rows), `ui/src/screens/discovery/DiscoveryScreen.tsx` (rows 2–6).
- **Fix**: one line in menu.css — `.lumen-menu__item--icon-accent
  .lumen-menu__icon .lumen-icon { color: var(--color-accent-icon); }`. Note:
  post-fix icons become FULL orange while frames are two-tone (#8F8F8F base +
  #AB6314 detail); either accept full-accent (document) or port two-tone
  glyph variants (icons.tsx already tags `two-tone` sheets).

### [g20-P2-1] Accelerator + shortcuts-header color renders #828282, frames say #6B6B6B (token value wrong)
- **Screen/reproduce**: app-menu/canvas-menu accelerators and
  /keyboard-shortcuts column headers. PIL: accel glyphs (130,130,130).
  Frames: menu.svg, right-click menu.svg, Keyboard Shortcuts.svg all fill
  **#6B6B6B**.
- **Root**: `--color-content-tertiary: #828282`
  (`themes/tokens.json` → `ui/src/tokens/generated/tokens.css:40`); menu.css
  (`.lumen-menu__accelerator`) and shortcuts.css cite "frame #6B6B6B" but
  resolve to this token. w26.f07's log claim "var(--color-content-tertiary)
  (#6b6b6b exact frame match)" is factually wrong — no token carries #6B6B6B.
- **Files**: `themes/tokens.json` + `ui/src/tokens/generated/*` (token lane),
  consumers `ui/src/components/menu/menu.css`,
  `ui/src/screens/shortcuts/shortcuts.css`.
- **Fix**: retune dark `--color-content-tertiary` to #6B6B6B (and the light
  counterpart) or add a dedicated accelerator token; audit other tertiary
  consumers before retuning.
