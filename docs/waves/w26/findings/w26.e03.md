## Findings

### F1 — P1 · Light theme · persisted `interface.theme` is not applied outside settings
- **Evidence:** localStorage seeded with `lumen.settings.overrides.v1 =
  {"interface.theme":"light"}` + onboarding done; direct load `/player?onboarding=1` →
  `document.documentElement.dataset.theme === "dark"`, canvas bg `rgb(9,9,9)`.
  Navigate to `/settings/interface` → theme flips to `light` (sync mounts), SPA-nav to
  `/player` → stays light (canvas `rgb(43,43,43)`, dock sidebar `rgb(222,222,222)`).
  So light mode on the player is reachable ONLY after a settings surface has mounted
  in the session; a fresh app start / deep link renders dark despite the saved choice.
- **Location:** `ui/src/theme/settingsThemeSync.ts:41-45` (effect only runs when
  mounted); mount sites `SettingsScreen.tsx:140`, `ThemeModePicker.tsx:20`;
  `ThemeProvider.tsx:50` defaults `"dark"`.
- **Suggested fix:** mount the theme sync at the app root (bootstrap-read the persisted
  `interface.theme` in `ThemeProvider` init, or mount `useSettingsThemeSync` under a
  lightweight `SettingsProvider` in `main.tsx`/`App.tsx`). Cross-lane: theme lane +
  Lead (App.tsx owner).
- **Confidence:** high (live-verified both paths).

### F2 — P1 · Light theme · seekbar + volume track well effectively invisible in light mode
- **Evidence:** frame `Player - Light.svg`: seek well `#DEDEDE` 1238×28 r6
  (`<rect x="254" y="1039" …/>`), played fill `#D8BA9A` (`Rectangle 11` 98×24 r4).
  Ours: `controls.css:172` (`.lumen-controls__seek .lumen-slider__track`) and
  `controls.css:220` (volume track) use `var(--color-surface)` → **#f0f0f0** on the
  light chrome strip **#f5f5f5** (1.03:1). Pixel scan of the light playing shot: track
  region reads rgb(240) vs strip rgb(245) — the 528px-wide track (DOM-probed
  x=504..1032, h=28) is visually absent; only the 8×24 orange playhead bar and the
  green volume wedge float on the strip. Vision (light compare) reported it as
  "missing the full-width seek track". Dark mode matches the frame (#090909 well).
- **Location:** `ui/src/screens/player/controls/controls.css:169-174, 217-225`.
- **Suggested fix:** mode-scoped well value (frame: dark #090909 = surface, light
  #DEDEDE = surface-deep) — needs a dedicated "well" token or a
  `:root[data-theme="light"]` override in controls.css (token-lane handoff).
- **Confidence:** high (frame-measured + pixel-verified).

### F3 — P1 · cross-variant · engine truth lost on player-route remount: empty hero renders while media plays
- **Evidence:** open "Big Buck Bunny" on `/player` (hasMedia=true, no hero, timecode
  00:00:01) → SPA-nav `/playlist` → back to `/player`: `data-has-media="false"`, the
  first-run hero `[data-overlay="empty"]` "No media open" renders over the canvas
  WHILE the demo engine keeps playing (C2 timecode keeps advancing: 00:00:03).
  Same root cause hits `/player/music` entered after opening media (hasMedia=false →
  chrome stays locked; the music title still restores via C2's `media.get-info`
  mount probe, so the stage is less broken there).
- **Location:** `ui/src/screens/player/states/context-bridge.ts:91-104`
  (`usePlayerEngineView` starts at idle, reduces live events only — no mount snapshot)
  vs `ui/src/screens/player/context.tsx:407-411` (C2 context DOES probe
  `system.get-state-snapshot` on mount — the two seams disagree after remount);
  consumer `PlayerScreen.tsx:554-567` derives `hasMedia` from the bridge.
- **Suggested fix:** seed the bridge view from a mount-time `system.get-state-snapshot`
  (or derive `hasMedia`/overlays from C2's snapshot-restored `playbackState`).
- **Confidence:** high (live-verified on both /player and /player/music; shot
  `player-remount-while-playing.png`).

### F4 — P2 · Hide-UI · auto-hide is unreachable windowed (and with no media)
- **Evidence:** windowed `/player`, cursor idled 3.6s → `data-chrome` stays
  `"locked"` (no media) / would stay `"visible"` with media — code gates
  `enabled: isFullscreen` and `locked: !hasMedia || openPanels.length > 0`
  (`PlayerScreen.tsx:571-574`; `useChromeAutoHide.ts:23-30`). The faded state is
  verified working in fullscreen WITH media (see PASS below). doc 08 §4.3 marks the
  fullscreen scoping `[PROPOSAL]`; VLC parity hides controls on windowed idle too;
  the frame (`Player - hide UI.svg`) does not disambiguate (it is a full-bleed video
  with an r19 window stroke, no chrome at all).
- **Suggested fix:** Lead decision — arm auto-hide windowed when media is present, or
  keep the [PROPOSAL] scope and document it in the lane log.
- **Confidence:** high (code + live probe).
