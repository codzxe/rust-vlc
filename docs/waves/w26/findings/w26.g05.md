## Findings

### [g05-P1-1] Player seek track is invisible in light mode
- **Surface / reproduce**: `/player` with light seed, idle (no media). The 581×28 seek track renders `var(--color-surface)` `#f0f0f0` on the control bar `var(--color-surface-chrome)` `#f5f5f5` — ΔRGB 5/255 ≈ **1.04:1**. Measured: 570×20 track interior is uniformly `#f0f0f0`, bar above/below uniformly `#f5f5f5`. Only the 8px accent thumb reads; the scrub track bounds do not. The volume wedge's bare track region uses the same token.
- **Reference evidence**: `Player - Light.svg` has **no bar background** — the controls float over the dark video with `data-figma-bg-blur-radius="50"`; the track is `#DEDEDE` r6 sitting on the DARK pattern backdrop, i.e. clearly delineated (app dark mode mirrors this: `#090909` track on `#161616` bar, Δ16).
- **Responsible files**: `ui/src/screens/player/controls/controls.css` (`.lumen-controls__seek .lumen-slider__track`, `.lumen-controls__volume-slider .lumen-slider__track`) — player lane.
- **Fix direction**: light override stepping the track down (e.g. `var(--color-surface-muted)` `#d4d4d4` + 1px `#d9d9d9` hairline), or adopt the frame's floating-strip anatomy (controls over the dark canvas with backdrop blur) which also resolves the P3-2 delta.

### [g05-P2-1] Shortcuts edit-pencil glyph below 3:1 in light mode
- **Surface / reproduce**: `/keyboard-shortcuts` light. `.shortcuts__edit` (292 instances; Hotkey-column ones are real links to Settings → Hotkeys) renders at `--color-stroke-icon` `#9a9a9a` on the `#f0f0f0` keycap = **2.55:1** (measured stroke pixels `#9a9a9a`/`#b0b0b0`). Dark equivalent: `#8f8f8f` on `#090909` ≈ 5.2:1. The wrapper's own `color: var(--color-stroke-border)` resolves to `#d9d9d9` (1.19:1) — currently overridden by `.lumen-icon`'s base color, but both paths are under the 1.4.11 bar.
- **Responsible files**: `ui/src/screens/shortcuts/shortcuts.css` (`.shortcuts__edit`, line ~361) — shortcuts lane; `ui/src/components/icon/icon.css` (base `--color-stroke-icon`).
- **Fix direction**: mirror the w26.d2 placeholder fix pattern — `:root[data-theme="light"] .shortcuts__edit .lumen-icon { color: var(--color-content-secondary); }` (hover already walks to `content-secondary`; consider tertiary→secondary rest, bright hover).

### [g05-P2-2] Keycap chips lose all separation in light mode
- **Surface / reproduce**: `/keyboard-shortcuts` light. Keycap `var(--color-surface)` `#f0f0f0` on window `color-mix(panel 95%, surface)` ≈ `#efefef` — ΔRGB **1** (dark: Δ16, and `Keyboard Shortcuts.svg` frames keycaps as `#090909` r6 chips on the `#191919@0.95` window). The chip silhouette disappears; only floating text remains.
- **Responsible files**: `ui/src/screens/shortcuts/shortcuts.css` (`.shortcuts__keycap`, `.shortcuts__window`).
- **Fix direction**: light override keycap → `var(--color-surface-raised)` `#ffffff` (2.5:1-ish lift + keeps r6 chip read), or darken the window mix for light.

### [g05-P2-3] Playlist sidebar row labels fail AA in light mode
- **Surface / reproduce**: `/player` and `/playlist` light. `.app-shell__plrow-label` = 11px `var(--color-content-secondary)` `#6e6e6e` on `.app-shell__sidebar` `var(--color-surface-deep)` `#dedede` = **3.79:1** (11px text needs 4.5; dark: `#8f8f8f` on `#0e0e0e` ≈ 5.97:1 ✓). Computed + measured on both surfaces.
- **Responsible files**: `ui/src/components/appshell/appshell.css` (`.app-shell__plrow`, `.app-shell__plrow-label`) — appshell owner.
- **Fix direction**: light override row ink → `var(--color-content-primary)` (7.6:1), or lift the light sidebar to `#efefef` (panel) which also closes the gap to the reference's `#E7E7E7` sidebar fill.

### [g05-P2-4] Systemic: two repinned light tokens fall short of WCAG on the surfaces they land on (token lane)
- **Surface / reproduce**: all light surfaces. (a) `--color-content-tertiary` `#767676` passes 4.5:1 **only on pure `#ffffff`** (4.54); on `#f0f0f0` 3.99, on `#dfdfdf` settings window 3.41 — e.g. `.settings-field__reset` 11px caption ink. (b) `--color-stroke-icon` `#9a9a9a` maxes at **2.82:1 on white** — every non-button decorative icon in light mode fails 1.4.11's 3:1 (appshell sidebar-toggle, settings nav glyphs, shortcuts pencils). `button.css` already carries local light remaps for icon *buttons* (`--color-stroke-icon: var(--color-content-secondary)`), confirming the shortfall is known.
- **Responsible files**: `themes/tokens.json` → `themes/generated/tokens.css` (token lane owner).
- **Fix direction**: repin light `content-tertiary` ≤ `#6b6b6b` (4.9:1 on `#f0f0f0`) and `stroke-icon` ≤ `#8a8a8a` (3.0:1 on `#f0f0f0`); re-audit the local button.css remaps after.

### [g05-P3-1] App identity dot uses dark-mode accent in light topbar
- **Surface / reproduce**: all appshelled surfaces, light. `.app-shell__appdot` = `var(--color-accent)` `#d37918` on `#f5f5f5` chrome = exactly **3.0:1** (borderline). The light reference marks the topbar app glyph `#C2711A` (`--color-accent-icon`, 3.2:1) — the token created for exactly this.
- **Responsible files**: `ui/src/components/appshell/appshell.css` (`.app-shell__appdot`).
- **Fix direction**: `background: var(--color-accent-icon)`.

### [g05-P3-2] Light player keeps solid control bar vs reference's floating controls (cross-theme anatomy, not light-specific)
- **Surface / reproduce**: `/player` light renders a full-width `#f5f5f5` bar (y 855–900); `Player - Light.svg` has **no** bar rect — play pill `#D37918` (58,1039), track `#DEDEDE` (254,1039), fill `#D8BA9A`, knob `#E8851A` float on the dark video with 50px backdrop blur. The dark frame (`Player.svg`) *does* have a `#1B1B1B` 54px bar, which the app mirrors in both themes — so this is a frame-vs-frame inconsistency the player lane should arbitrate; light coherence itself is unaffected (interacts with P1-1).
- **Responsible files**: `ui/src/screens/player/controls/controls.css`, `ui/src/screens/player/PlayerScreen.tsx` — player lane.
- **Fix direction**: if floating anatomy is adopted for light, P1-1 dissolves; otherwise keep the bar and fix the track per P1-1.

## Lane summary

**Worst 3**: (1) [g05-P1-1] invisible seek track on the light player — core scrub control loses its affordance; (2) [g05-P2-4] systemic light repins (`content-tertiary`, `stroke-icon`) below WCAG on every non-white surface — affects settings, shortcuts, appshell chrome at once; (3) [g05-P2-1/-2] shortcuts pencil 2.55:1 + keycap chips at ΔRGB 1.

**Is light mode shippable?** Yes for a beta with known-contrast nits: all five surfaces render a genuinely coherent light theme (correct surfaces/hairlines/one accent, dark canvas preserved, dark-remnant-free, zero console errors, no 1024×768 clipping), and the WCAG-repinned tokens do render as pinned. Not shippable as *final* until the P1 seek-track fix lands; the P2 contrast items are cheap `:root[data-theme="light"]` overrides following the w26.d2 pattern already in the repo.
