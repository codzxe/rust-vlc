# w26.e18 — Responsive clipping audit (verifier report)

**Task:** w26.e18 (wave 26e) · **Mode:** VERIFICATION ONLY — nothing was fixed.
**Scope:** Responsive behavior + text clipping at 1440×900, 1280×800, 1024×768,
900×700 across 12 routes (player, player/music, playlist, settings
global/audio/performance, discovery, convert, media-info, open-network-stream,
keyboard-shortcuts, onboarding). Contract §5 ("spot-check 1024×768, nothing may
clip") + §7 quality bar.

## Method

1. Dev server confirmed up (`curl http://localhost:5173/player` → 200).
2. Playwright script (`/tmp/w26e18-audit.mjs`, `@playwright/test` via
   createRequire from `ui/package.json`): 4 viewports × 12 routes = 48 pages,
   localStorage cleared per navigation, screenshot each into
   `/tmp/shots-w26.e18/<viewport>/<route>.png` (48/48 captured), plus per page:
   - DOM overflow audit (every element, `scrollWidth/scrollHeight` vs
     `clientWidth/clientHeight` + 1px tolerance; skip `overflow:auto/scroll`,
     skip body/html),
   - horizontal document overflow (`documentElement.scrollWidth > innerWidth`),
   - leaf-text truncation on span/button/h1–h6/a/label/p/td/th with direct text
     nodes,
   - scroll-container census + sidebar visibility (`#lumen-app-sidebar`),
   - console/page errors.
   Raw data: `/tmp/w26e18-audit.json`.
3. Targeted follow-up geometry (Range line-rects, cluster bounding boxes,
   overlap tests) for the flagged candidates — `/tmp/w26e18-followup*.mjs`.
4. Visual spot-check via `z-ai vision` (3 calls succeeded before the vision API
   went 429-throttled for this sandbox; the 8-worst list was covered by DOM
   geometry instead — see per-finding evidence).

## Findings

### F1 — P1 (overlapping controls): seek-row remaining timecode prints on top of the duration timecode at 900×700

- **Route/viewport:** `/player` @ 900×700 (compact laptop). Not present at
  1024×768 / 1280×800 / 1440×900 (12px clearance at 1024).
- **Evidence:** `/tmp/shots-w26.e18/900x700/player.png` (+ cropped
  `/tmp/w26e18-vision/crop-900-controls.png`). Measured geometry:
  `.lumen-controls__seek` box 438→537px (99px wide) but its content is 160px
  (`scrollWidth 160 > clientWidth 99`, dx=61, overflow visible). Children:
  position "00:00:00" 438→496 (fits), seekbar 504→552 (15px past box), and
  remaining `--:--` 560→598 — while `.lumen-controls__right` starts at 549 with
  its duration `--:--` at 549→587, same y-band 664→692. **Two visible
  timecodes overprint each other with a 27px horizontal overlap.**
  (Full-page vision pass called this shot CLEAN — the 12px overprinted glyphs
  are below its discrimination threshold; the rect math is unambiguous.)
- **Location:** `ui/src/screens/player/controls/controls.css:63-69`
  (`.lumen-controls__seek { flex: 1 1 48px; min-width: 0; }` — shrinks below
  its content width) + `controls.css:51-59` (`.lumen-controls__right` is
  `flex: none; min-width: 0` — never yields) + `controls.css:163-167`
  (seekbar `min-width: 48px` floor). Elements:
  `ControlBar.tsx:270` (`data-time="remaining"`) vs `ControlBar.tsx:283`
  (`data-time="duration"`).
- **Suggested fix:** let the seek row keep a content floor (e.g.
  `min-width: max-content` on `.lumen-controls__seek`, or allow
  `.lumen-controls__right` to shrink with `flex-shrink: 1`), or drop/hide the
  seek row's remaining timecode below ~960px. Player-controls lane owns it.
- **Confidence:** high (measured rects, reproducible; comment at controls.css:61-62
  documents the intended 48px scrub floor but not the timecode spill).

### F2 — P3 (nit): docked-playlist footer text sits flush against the viewport bottom edge at 1024×768

- **Route/viewport:** `/player` @ 1024×768 (also 900×700).
- **Evidence:** `/tmp/shots-w26.e18/1024x768/player.png`. Vision flagged
  "hint text cut off at the bottom edge"; DOM measurement **refutes actual
  clipping**: `footer.lumen-playlist__footer` box bottom = 768 (= viewport),
  last text line bottom = 766 (`lastLineDelta = -2`), every ancestor
  `scrollHeight == clientHeight` — text renders fully, with only **2px**
  clearance.
- **Location:** `ui/src/screens/playlist/playlist.css:80-86`
  (`.lumen-playlist__footer` — `padding: var(--space-grid) var(--space-inset) 0`
  has **zero bottom padding**).
- **Suggested fix:** a few px bottom padding on the footer (or
  `padding-bottom: var(--space-grid)`), playlist-panel lane.
- **Confidence:** high that it is NOT clipped; medium that reviewers will call
  the 2px flush edge a visual defect.

### F3 — P3 (nit): dropdown arrow glyph box overflows its span by 5px (overflow visible, no clipping)

- **Route/viewport:** `/settings/audio`, `/convert`, `/keyboard-shortcuts` —
  all viewports incl. 1440×900 (constant, not viewport-dependent).
- **Evidence:** `span.lumen-dropdown__arrow` dx=5, overflow visible — the
  rotated `›` `::before` (menu.css:308-313) lays out slightly wider than the
  span. No document overflow, no ancestor clip; no visible defect observed in
  screenshots.
- **Location:** `ui/src/components/menu/menu.css:269-272, 308-313`.
- **Suggested fix:** give the arrow span an explicit width (e.g. `width: 1ch`)
  so the glyph box is contained. Menu-lane nit.
- **Confidence:** medium (arithmetic is real; visual impact likely nil).

### F4 — FALSE POSITIVES logged for the record (audit noise, no action)

DOM-overflow hits that are **intentional patterns** — future auditors should
skip these classes:

1. **sr-only utilities** (1px + `clip-path: inset(50%)` + `overflow: hidden`):
   `.settings-vh` (settings.css:43), `.shortcuts__vh` (shortcuts.css:43),
   `.lumen-player__sr-title`/`__sr-note` (player.css:117, 251),
   `.onboarding .visually-hidden` (onboarding.css:592),
   `.visually-hidden` (settings/areas/hotkeys/hotkeys.css:74). These dominate
   the raw offender counts (e.g. onboarding "8 offenders") — none are visible.
2. **EQ slider 4px hit-area overhang**: `.eq-tool__rows`/`__row`/
   `.lumen-slider__track` dy=4 at all viewports — documented intentional
   ("hit area with the thumb's 4px overhangs", equalizer.css:126-131).
3. **Playlist kebab dots**: `.lumen-lrow__kebab-dots` dx=6 — the 3-dot kebab is
   built from `::before`/`::after` at ±6px (list.css:411-436), by design.

### F5 — verification note: vision spot-check coverage

Only 3 `z-ai vision` calls succeeded (900×700/player → CLEAN; 1024×768/player →

75–240s backoffs — likely shared quota across the wave's agents). All remaining
"8-worst" screenshots were cleared by the DOM overflow audit + rect geometry
above instead; screenshots for every route×viewport are preserved under
`/tmp/shots-w26.e18/` for a later visual pass. `[VERIFY]` a human/vision pass
on `1024x768/settings-audio.png`, `1024x768/playlist.png`,
`900x700/player-music.png`, `900x700/onboarding.png`,
`1024x768/keyboard-shortcuts.png` once the API is available (DOM audit reports
zero real offenders on all five).

## Verdict

**Contract §5 passes**: at 1024×768 nothing clips (0 real offenders; F2 is a
2px-clearance nit). At 1440×900 and 1280×800: clean. One real responsive
defect exists below the contract floor: F1 (P1) timecode-over-timecode overlap
in the player control bar at 900×700.
