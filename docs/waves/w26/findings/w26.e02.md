## Findings

### F1 — P1 — Canvas context menu opens unclamped: clipped off the window (bottom AND right), not scrollable
- **Surface/route**: `/player` canvas right-click menu (w26.c6 surface).
- **Evidence**: right-click at canvas (900,700) → popup rect
  `top=731, bottom=1580` (viewport 900), `left=1376, w=280` (viewport 1440 →
  right edge 1656, 216 px off-window). Last item "Quit VLC" at y 1517–1575 —
  `visible: false`; `overflow: visible`, not scrollable. Mid-canvas open
  (400,300) → bottom = 1180 > 900, also clipped. Screenshot
  `state-canvas-contextmenu.png` / `state-canvas-contextmenu-low.png` — panel
  paint continues to the window edge at y=895. **[VERIFY]** (pixel + DOM).
- **Location**: `ui/src/screens/player/PlayerScreen.tsx:828`
  (`style={{ left: canvasMenu.x, top: canvasMenu.y }}` — raw pointer coords,
  no clamping) + `ui/src/components/menu/MenuPopup.tsx` (no viewport
  flip/clamp logic — menus lane owns it).
- **Suggested fix**: clamp/flip the popup inside the viewport in `MenuPopup`
  (benefits every menu consumer), or clamp at the canvas-menu mount site.
- **Confidence**: high (measured twice at two open points).
