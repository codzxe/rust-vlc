## Findings

### F1 — Registered-but-unwired keys: player control bar + tools shell read hardcoded module constants (P1)

**Evidence**: `ui/src/screens/player/controls/ControlBar.tsx:59-70` defines `CONTROLS_COPY` (`next: "Next"`, `fullscreen: "Enter fullscreen"`, `exitFullscreen: "Exit fullscreen"`, `cast: "Cast"`, `groupOutput: "Player controls"`) consumed at lines 185, 190, 341, 348, 387 as `IconButton label=`/`aria-label`. The identical 5 keys from `ui/src/i18n/keys/w26.a14.ts` ARE registered in `messages.ts:688-692` + `1664-1668` but referenced nowhere. Runtime proof (`/player?locale=pseudo`, Playwright): 4 untransformed aria-labels — `button[data-control=next] aria-label="Next — [pseudo]"`, `div aria-label="Player controls"`, `button[data-control=fullscreen] aria-label="Enter fullscreen"`, `button[data-control=cast] aria-label="Cast — [pseudo]"` (the `m()`-sourced reason halves ARE bracketed — proof the constant halves bypass the catalog). Same pattern in `ui/src/screens/player/dialogs/ToolsDialogShell.tsx:35-42` (`TOOLS_DIALOG_COPY` expand/collapse/close, used at 98-99, 170): `player.tools.expand-settings`/`collapse-settings` are registered AND correctly used via `m()` by `DynamicsCard.tsx:78-79` and `VideoCard.tsx:84-85` (same copy now flows two different ways), while `player.tools.close` is registered-but-unused. The a14/a18 "COPY NOTE" comments say "until the post-wave merge" — the merge happened (registration audit passes); the unwiring never did. The eslint rule can't see these (member expressions, `label` prop not in its attribute list).
**Location**: `ui/src/screens/player/controls/ControlBar.tsx:59-70` (+185,190,341,348,387); `ui/src/screens/player/dialogs/ToolsDialogShell.tsx:35-42` (+98,99,170).
**Suggested fix**: replace `CONTROLS_COPY.*` with `m("player.controls.next" | "player.controls.fullscreen" | "player.controls.exit-fullscreen" | "player.controls.cast" | "player.controls.group-output")`, `TOOLS_DIALOG_COPY.*` with `m("player.tools.expand-settings" | "player.tools.collapse-settings" | "player.tools.close")`; delete both constants. (Owner: player lane; `messages.ts` untouched.)
**Confidence**: HIGH (static + runtime + registration cross-evidence).

### F4 — Pseudo-length truncation: sidebar title + settings nav labels ellipsize at 1.5× (P3)

Both elements have intentional `overflow:hidden; text-overflow:ellipsis; white-space:nowrap` (`appshell.css:235-243`, `settings.css:306-309`), so degradation is graceful (ellipsis, no layout break; page h-overflow 0). sr-only "clips" (`lumen-player__sr-title`, `settings-vh`, `lumen-player__sr-note`, cw=1) are visually-hidden a11y elements — by design, not findings.
**Location**: `ui/src/components/appshell/appshell.css:235` (`.app-shell__sidebar-title`); `ui/src/screens/settings/settings.css:306` (`.settings-nav__label`).
**Suggested fix**: optional — give the rail title/nav labels a min-width or allow 2-line wrap if real-locale lengthening matters; otherwise accept ellipsis as designed degradation.
**Confidence**: HIGH (measured).

### F5 — No ICU placeholders anywhere; all interpolation is call-site template composition (P3, informational)

**Evidence**: `rg` over `messages.ts` values: zero `{…}` tokens (consistent with l10n:check `placeholders 0 ok`). Parameterized strings are composed in components: `MiniPlayer.tsx:290` `` `${count} ${m("playlist.panel.count-suffix")} · ${duration}` ``, `ControlBar.tsx:185` `` `${label} — ${m(reason)}` ``, `SettingsScreen.tsx:332` `{m("settings.unsaved-changes")} ({count})`, plus F2's `jump(time)`/`beyondEnd(duration)`. Word order is therefore fixed in English structure at each call site; translators cannot reorder. `pseudo.ts:33-61` and `l10n-check.mjs:94-110` already implement doc-07 §6.2 message-format placeholder grammar + passthrough — ready for `{name}`-style keys when the real locale-pack pipeline lands.
**Location**: catalog-wide; examples above.
**Suggested fix**: when the l10n pipeline arrives, migrate call-site compositions into parameterized catalog keys (start with F2's jump/delete/beyond-end and the count-suffix family).
**Confidence**: HIGH.
