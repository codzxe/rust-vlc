## Method

1. Dev server confirmed up (`curl http://localhost:5173/player` → 200).

3. Playwright (chromium, 1440×900 + 1024×768 spot-check): `/player?onboarding=1`

   (17 files: eq-expanded-top/bottom, eq-card-full, eq-presets-open,
   eq-value-chip-hover, eq-row-hover, compressor/spatializer/widener cards,
   visualizer card + mode-open + spectrum, dialog collapsed, 1024×768).
4. `z-ai vision` comparisons: **API rate-limited (429) for the whole session** —
   5 attempts over ~20 min incl. 60 s+ waits, all 429. Per the task's fallback
   protocol I recorded deterministic evidence instead: SVG ground-truth parsing
   (rects/fills/gradients of all 8 frames), Playwright `getComputedStyle` DOM
   probes, and PIL pixel measurement of both frame renders and screenshots
   (colors, geometry, structural-similarity thumbnails). VLM verdicts are
   marked **[VERIFY]** below; every number cited was actually measured.

## Findings

### F1 — EQ.svg vertical-fader frame is unmounted (the filed residual, confirmed)
- Severity: **P2** · Surface: Equalizer · Confidence: high
- Evidence: `EQ.svg` parses as a distinct presentation: 824×628 panel, title bar
  784×36 **rx2** `#090909`, body 784×489 **rx2** `#191919`, 11 **vertical**
  faders (tracks `transform="rotate(-90 …)"`, 16×320 rx6 `#090909`, flat
  `#371F06` fill, 8×24 rx4 `#AB6314` thumbs), per-column value chips 60×32 rx6
  `#090909`, per-fader `degrees` tick groups. The mounted `EqualizerTool`
  implements the *stacked-rows* frame (`Audio - Equalizer.svg`, 400×1622) and
  matches it frame-exactly (see verdict table). No surface in the UI renders the
  vertical-fader anatomy.
- Ruling: the mounted card correctly matches its cited frame (`Audio_-_Equalizer`);
  `EQ.png` is a second, unimplemented EQ presentation. Both frames are mapped to
  the equalizer in CONTRACT §3, so strictly one reference surface is missing.
- Location: `ui/src/screens/player/tools/equalizer/EqualizerTool.tsx` (rows
  variant); frame `design/figma/EQ.svg`.
- Suggested fix: Lead ruling — either accept the rows variant as the shipped EQ
  (annotate the frame map), or schedule a vertical-fader EQ surface (classic VLC
  "EQ" window) in a follow-up wave.

### F2 — EQ presets dropdown: row height/pitch + trigger layering drift
- Severity: **P3** · Surface: Equalizer presets panel · Confidence: high
- Evidence: mounted open list = 8 options @ **48 px / pitch 48** (shared
  `components/menu` Dropdown, `--space-item-pitch`); frame `EQ presets.svg` =
  rows 358×44 rx4 @ pitch 46 (list 362×348; mounted 390 tall). Mounted trigger =
  single-layer `#0E0E0E` (surface-deep) 366×48; frame trigger = two-layer
  (outer `#090909` + 2 px ring + inner 358×44 rx4 `#191919` field). The
  visualizer's own `viz-select` implements the two-layer grammar exactly — the
  two siblings are inconsistent.
- Location: `ui/src/components/menu/menu.css:336` (`.lumen-dropdown__option`
  min-height 48), `:225` area (trigger); consumer
  `ui/src/screens/player/tools/equalizer/EqualizerTool.tsx:161`.
- Suggested fix: scope a `eq-tool__presets` override (44 px rows @ 46 pitch +
  two-layer trigger) in `equalizer.css`, mirroring `viz-select`, or align the
  shared Dropdown grammar if the Lead prefers one primitive.

### F3 — Spec §2 audio-tools anatomy line drifts from every frame (adjudication)
- Severity: **P3** (documentation) · Surface: contract/spec vs frames · Confidence: high
- Evidence: CONTRACT/spec §2 says "card r8, chip r6 `#141414` white value, 14 px
  track r7 amber **gradient** `#371f06→#a5621a`, 8×20 handle". SVG ground truth
  (all 8 audio frames parsed): cards **rx6**, in-frame chip **rx5 `#090909` +
  `#191919` stroke, `#8F8F8F` ink** (`audio value.svg`: r6 `#0E0E0E`, `#969696`),
  track **16 px rx6**, fill **FLAT `#371F06`** (zero `<linearGradient>` in any
  audio frame), thumb **8×24 rx4 `#AB6314`**. The implementation follows the
  frames, which spec §0 declares the source of truth. Pixel-verified: frame fill
  measures (55,31,6) at left/mid/right (no gradient); mounted fill identical.
- Ruling: implementation CORRECT; the W25 §2 numbers (VLM-measured) are drifted.
- Suggested fix: Lead annotates spec §2 / CONTRACT §3 audio line with the
  SVG-measured values so later waves don't "fix" toward the wrong numbers.

### F4 — Base ValueChip white ink contradicts `audio value.svg` (cross-lane note)

- Suggested fix: form-lane decision (align base chip ink to the frames or keep
