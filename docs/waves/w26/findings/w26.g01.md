## Findings

- **[g01-P1-1] Selected accent dot shows no selected state — ring selector is
  dead code.** Step 3 (appearance). Repro: /onboarding → Next ×2; look at the
  9 accent dots: the selected one is indistinguishable except by theme color;
  no ring. Files: `ui/src/screens/onboarding/onboarding.css:539`
  (`.onboarding__accent[aria-pressed="true"]::after`) vs
  `ui/src/screens/onboarding/OnboardingScreen.tsx:734-741` (buttons emit
  `role="radio"` + `aria-checked`, never `aria-pressed`). Evidence: frame
  Onboarding-1.svg Frame 153 (60×60 rx30, 4px #D37918 ring at 30% opacity
  around the selected dot); runtime probe `::after content: "none"`; pixels at
  ring position = window bg #161616. Tests (21/21 green) assert attributes,
  not pseudo-elements, so this slipped through. **Fix:** change the CSS
  selector to `[aria-checked="true"]` (keep `::after` ring spec as-is — it is
  frame-exact), or add `aria-pressed` in TSX.

- **[g01-P2-1] Unselected accent dots render at full opacity — frame dims them
  50%.** Step 3. Repro: same as above; all 9 dots equally loud. Frame
  Onboarding-1.svg Frames 154–161 carry `opacity="0.5"` on every unselected
  dot; only the selected one is full-opacity. File:
  `ui/src/screens/onboarding/onboarding.css:522-531` (no opacity rule).
  Together with P1-1 the row has zero selected/unselected hierarchy. **Fix:**
  `opacity: 0.5` on `.onboarding__accent:not([aria-checked="true"])` (or use
  `--opacity-swatch-rest`, the Settings global.svg swatch grammar).

- **[g01-P2-2] Working-step headings ~40% oversized vs frame.** Steps 2–6.
  Repro: any working step; title renders 32px. Frame measurements (glyph
  bboxes): Onboarding-1 "Select your preferred theme and color." 427.7×23.2
  → ≈23px type; Onboarding-2 "Learn the basic keyboard shortcuts."
  404.3×22.9 → ≈23px. Welcome hero "Welcome to VLC!" 251.6×24.0 → ≈33px.
  Implementation: `.onboarding__title` uses `--font-size-display` (32px) for
  every step (`onboarding.css:146-154`). Only the hero steps should be
  display-size. **Fix:** working steps step down to ≈23–24px (frame-marked
  value or nearest new token; `--font-size-title` 18px undershoots).

- **[g01-P2-3] Theme cards and accent dots have no hover/active feedback.**
  Step 3. Repro: hover `[data-testid=onboarding-choice-*]` or
  `onboarding-accent-*` — computed styles identical to rest (probe: bg
  transparent, no transform, no outline change). Contract §7 quality bar
  (hover/focus/active/disabled). Files: `onboarding.css:310-321` (theme card
  — only `:disabled` styled) and `:522-531` (accent — only a box-shadow
  transition that never changes). Keyboard focus IS visible (global
  `:focus-visible` orange ring from lumen.css) and disabled states exist.
  **Fix:** label brightens + swatch hairline tightens on hover; pressed =
  ring opacity dip; dots get a hover ring (same art as the selected ring).

- **[g01-P2-4] Keycap chips draw a 1px #404040 border; the frame's caps carry
  a 3px #373737 inset stroke.** Step 2 (hint caps) + step 7 (tour, other
  lane). Frame Onboarding-2.svg: every cap = rx12 #1B1B1B fill + inner rx10.5
  rect `stroke="#373737" stroke-width="3"` — that chunky inset is the keycap
  depth. File: `onboarding.css:282-298` (`border: 1px solid
  var(--color-stroke-border)`). Pixel-verified 1px #404040. **Fix:** 3px
  border in a #373737-class stroke (frame-marked raw value or inset
  box-shadow), keep r12.

- **[g01-P3-1] Theme swatch radius 14px vs frame rx12.** `onboarding.css:332`

## Lane summary

Worst 3 problems: **[P1-1]** the accent-dot selected ring never renders
(dead `aria-pressed` selector vs `aria-checked` markup — the one true state
bug); **[P2-1+P2-3]** the accent row and theme cards lack any
selected-dimming/hover feedback, so the appearance step's core interaction
feels inert; **[P2-2]** every working-step title is 32px where the frames set
≈23px, making steps 2–6 shout.

**Family-level verdict: MATCH with GAPS.** The wizard is structurally
frame-faithful (window, cone hero, exact 156px card pitch, exact accent
palette, working settings rows, no clipping, zero console errors, honest
state machine) — this is nowhere near "worst UI ever seen." The gaps are
concentrated in *state styling* (one dead selector, missing hover/dim) and
*type scale* on working steps; all fixes are small, local, and in
`onboarding.css`/`OnboardingScreen.tsx` except the cross-lane notes
([P3-5], [P3-6], shortcuts-step nits).
