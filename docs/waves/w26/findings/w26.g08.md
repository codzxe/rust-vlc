## Findings

### [g08-P0-1] Customize panel is UNREACHABLE on /player — every real trigger dispatches an event nothing listens to
- **State+reproduce**: any attempt to open the panel on `/player` (seeded onboarding,
  demo media open). Probed all four triggers with media present: `lumen:open-customize`
  window event, canvas context-menu row “Customize interface… Ctrl+A”, app-menu row
  “Customize Player”, and the Ctrl+A keymap — **all four leave the DOM with zero
  customize nodes** (`p1_event:false, p2:false, p3:false, p4:false`; artifacts
  `10-player-media-clean.png`, `report.json`). Music mode is no escape hatch:
  `MUSIC_LAYOUT_TOML` declares no customize region (`variants/variantLayout.ts:69-88`).
- **Responsible files**: `ui/src/screens/player/PlayerScreen.tsx` (right-region gate
  `openPanels` lines 755-768 — no producer exists anywhere in `ui/src`; dispatchers
  lines 400, 695; comment line 57 promises “f12's CustomizeDialog owns the listener”
  but no listener exists), `ui/src/screens/player/controls/ControlBar.tsx:569`
  (dispatch-only), `ui/src/App.tsx:95-100` (PlayerRoute never passes `openPanels`),
  `ui/src/screens/player/layout.ts:383-388` (`visible_when = "has-media"` second gate),
  `layout.ts:400-404` (`ui_action = "open-panel:customize"` consumed by no renderer).
- **Frame evidence**: frames -1..-4 all show the panel OPEN over a playing player —
  unreachable means none of the four states exists in the product.
- **Fix direction**: one listener that owns panel state — e.g. PlayerRoute holds
  `useState<string[]>` for open panels, listens for `lumen:open-customize`
  (and consumes `open-panel:*` ui_actions from `layout.menus`), passes
  `openPanels=["customize"]` to PlayerScreen; the panel’s own ✕ already emits
  `lumen:close-panel` (CustomizePanels.tsx:350-353) — wire the close half too.
  Decide whether `has-media` should gate an editor that is also useful idle.
- **Confidence**: HIGH (code grep + runtime probes agree; e04 F1 reported the same
  class of gap — f09 added triggers but wired no host; still broken).

### [g08-P1-2] States -1..-4 have NO implementation: the live chrome is never editable/rearrangeable
- **State+reproduce**: frames -2/-3/-4 specify transport centered, title-bar pill and
  title-bar icon tiles relocated into the control bar (exact rects above). In the app
  the control bar and title bar have no edit mode at all — no dashed wells, no drag
  targets; the customize surface only reorders tiles INSIDE its own palette box
  (`CustomizePanels.tsx` `moveTile`/`removeTile`), and the implementer's frame mapping
  (“frame -1…-5 = drag-to-reorder, -6 = removed”) is **wrong for my frames**: the
  box content is byte-identical across -1..-4 (empty `Frame 225` diffs), so no in-box
  state distinguishes them — the distinguishing content is the chrome, which is absent.
- **Responsible files**: `ui/src/screens/player/customize/CustomizePanels.tsx`
  (header comment lines 17-22 mis-maps the frames; box-only drag model),
  `ui/src/screens/player/customize/panels.ts:17-25`, hosting side
  `ui/src/screens/player/PlayerScreen.tsx` (control bar has no customize hooks).
- **Frame evidence**: per-frame rect tables (above); raw dumps `/tmp/cap-w26g08/geom-{1,2,3,4}.txt`.
- **Fix direction**: when the customize surface is open, render the edit-well grammar
  (`1px #6B6B6B dash 4 4`, square) over the real control bar/title bar slots and make
  the panel's Save/Cancel own that arrangement (UI-owned layout state, doc 08 §4);
  or get an explicit Lead scope-cut ruling recorded in the wave plan.
- **Confidence**: HIGH on the frame facts; the fix scope is a Lead decision.

### [g08-P2-3] Hosting + anatomy: 320×800 right rail r30 vs the frames' centered 1048×655 modal rx14 (e04 F2, still unfixed)
- **State+reproduce**: harnessed capture `04-customize-clean-frame0.png` /

  HDR, Zoom, Right Sidebar, Quit VLC, VLC Settings, Thumbnail, File/Artist/Folder/
  Playlist Name, Properties, Replay, Chapters, Favorite, Bookmark, Playlists; and

  Capability gating is an honest reason for engine-bound fields, but the frame draws
  the full palette regardless; at minimum the catalog and grid grammar are off-frame.
- **Responsible files**: `ui/src/screens/player/player.css:247-270` (host),
  `ui/src/screens/player/customize/customize.css:63-128` (box grid `minmax(84px,1fr)`),
  `ui/src/screens/player/customize/panels.ts` (catalog),
  `themes/tokens.json` (via `--radius-card-lg`).
- **Fix direction**: host in a centered modal (r14, `#0E0E0E@95%` + blur halo +
  shadow; Cancel/Save footer grammar already matches), 9-column palette grid; or a
  Lead-approved rail adaptation with the radius corrected to ≤r14 and the tile
  catalog/frame quote reconciled.
- **Confidence**: HIGH on geometry (both sides measured).

### [g08-P2-4] Adjustment sections/sliders/dropdowns exist in the customize surface but in NO customize frame

  came from and keep the customize surface palette-only (frame-faithful), or get a
  Lead ruling that the merged surface is an accepted adaptation.
- **Confidence**: HIGH.
