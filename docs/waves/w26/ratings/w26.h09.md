## Top-5 defects by shamefulness

1. **Empty option labels in video Aspect ratio / Crop dropdowns — 10 unregistered msgids, blank trigger after pick.** Repro: `/settings/video` → open Aspect ratio → options 2–7 are blank; pick one → trigger value renders EMPTY (verified this session). Pointer: `ui/src/screens/settings/generated/schema.ts:1476,1496` reference `settings.value.video-aspect-ratio.{1:1…2.39:1}` / `settings.value.video-crop.{1:1…16:10}`; `ui/src/i18n/messages.ts` registers only `.automatic`/`.none` (grep-verified); `SettingField.tsx:164` resolves the missing key to an empty string with no fallback to the raw value. Fix: register the 10 msgids (or fall back to the raw enum value). Also an aria failure — listbox options with no accessible name.
2. **ⓘ info affordances: frame carries 12 (playback) + 8 (video) circles r7.5 #404040; live renders 0.** Repro: any row; SVG circle inventory `design/figma/Settings - {playback,video}.svg`. Known NEEDS-LEAD (gfix-B §4.1 — no hint copy exists, fabricating ~60 strings is content invention), but as shipped the row grammar visibly diverges from every Settings frame.
3. **Dropdown chevron is the wrong glyph.** Live: rotated "›" text glyph, 5×17 box @22–27px-from-right (`ui/src/components/menu/menu.css` arrow, shared control). Frame: 10×5 chevron-down stroke path, #8F8F8F 1.5, 33px-from-right (`M991 130L996 135L1001 130`, extracted this session). Visible on all 9 enum rows across the two screens; open since g11-P3-2, owned by the menu lane.
4. **Light mode ships dark controls on light panels.** Measured: window #BABABA@95% / topbar #C2C2C2 / panel #C5C5C5@95%, but switch tracks #090909, chips #371F06, dropdown faces #191919, input wells #090909 — and row labels #4E4E4E on #BBBBBB = 4.2:1, under WCAG AA for 15px. No light Settings frame exists, so nothing is "wrong vs frame", but it reads as one finished theme and one improvised one.
5. **Slider tick marks + column drift micro-sloth.** Ticks: 2×6 #151515 (neutral, lighter-than-bg, near-invisible) vs frame #1A1611 (warm, darker-than-bg); video slider rows pitch 44 vs frame 42, accumulating +12px at Reset (y596 vs 584) and +10 at Framing; playback scale labels 11px vs frame ≈12px; codecs content appends flat with no fold UI despite the registry's "fold" naming (+270px scroll). Each is small; together they're the difference between "matches" and "is the frame".

## Would I ship

Playback: **yes, with caveats** — it is the closest-to-frame screen in the family (13/13 rows, control anatomy frame-exact to the px); the caveats are the chevron glyph, the ⓘ decision, and the 22px scroll vs the frame's clip. Video: **no — not until defect #1 is fixed**; a Settings screen whose Aspect ratio control goes blank the moment a user touches it fails the bar no matter how frame-true its pixels are at defaults, and the fix is a 30-minute i18n registration. Both routes: 0 console errors across 10+ loads, clean 1024×768, working keyboard paths, honest gating — the engineering hygiene is real; the missing polish is i18n coverage and one shared icon.
