## Top-5 defects by shamefulness

1. **Save edits nothing real (state 7's entire premise).** The persisted arrangement (`lumen.player.toolbar.v1` = `{order:[31 ids], band:[favorite,bookmark,bookmarks]}` verified written) renders in no real chrome — `ControlBar.tsx` has no consumer; after ✕ the strip shows zero placed items while the frame shows the dropped tile in the live band. Repro: place tiles → Save → ✕ → probe strip. Files: `ui/src/screens/player/controls/ControlBar.tsx` (consumer missing), `ui/src/screens/player/customize/toolbarLayout.ts` (seam exported, unused). gfixA open gap #1, unowned.
2. **Focus dies on Save; Escape stops closing the modal.** Click Save → button disables → Chromium blurs to BODY → the in-surface Escape listener never fires: `focus.afterSave {active: BODY}` + Escape → `modalCount: 1`. The user is trapped until they click back inside or find the ✕. Repro: `capture2.mjs` `focus.afterSave`/`focus.escapeAfterSave` probes. Files: `ui/src/screens/player/customize/CustomizePanels.tsx` (Save handler), `ui/src/components/surface/Surface.tsx` (focus trap has no disabled-blur recovery).
3. **Frames 1–6's band states are unimplemented — one static overlay for six different frames.** No seek row above the transport (f1: 1879×35 @20.5,981.5), no centered transport (f2: @895.5/933.5/995.5), no shrinking slots or topbar wells (f3–f5), no band timecodes (00:02:10/00:25:40), no per-frame cluster shift. Files: `ui/src/screens/player/customize/CustomizePanels.tsx` (`CustomizeBand`, fixed cluster), `customize.css` band section. Logged by gfixA as open gap #2; no lane picked it up.
4. **The catalog renders 26 of 31 tiles and the frame's 4-row rhythm collapses to 3 (9/9/8 vs 9/9/9/4).** Record/Snapshot/PiP/HDR/Zoom are hidden by demo capability gating (honest per doc 05 §3, unit-tested at 31), so frame row 2 loses five cells and row 4 (Favorite…) starts mid-row-3 at col 5 instead of a fresh row at y=674. Files: `ui/src/screens/player/customize/panels.ts`, `capabilities.ts`, `client/demo-transport.ts`.
5. **Scrim + background composition diverges from every open frame.** A `rgba(0,0,0,.24)` scrim dims the player behind the modal (no customize frame carries one; f7's blur is post-drop), and the 216px queue dock stays open behind the modal where frames 0–6 present full-bleed video; in state 8 the dock is 216px vs the frame's 320px @1440 (104px narrow, g09-P3-6, player-composition lane). Files: `ui/src/components/surface/surface.css` (`.lumen-scrim`), `ui/src/screens/player/playlist/playlist.css` (dock width).

Micro-defects recorded, not ranked: played-bar 2px vs frame 8×24 (`customize.css` `.lumen-customize-band__seek-played`); band bg #161616 vs frame #191919 (Δ3, token consolidation); Cancel #191919 vs #1B1B1B (Δ2); instruction #828282 vs frame #6B6B6B (Lead WCAG ruling); tile labels mostly single-line at 102px cells where the frame wraps 2-line ("Forward 10s" 51.8×27.3); ✕ focus ring visible in programmatic-focus shots (a11y-correct, frame-bare).

## Would I ship it?

Not as the 9-state frame set. The modal editor (states 0–6) is genuinely frame-exact in its shell, catalog grammar, footer, and affordances — I would ship that core today with the scrim made optional and the gray deltas reconciled. I would NOT ship the promise the frames make: the customization visibly landing in the player. Until ControlBar consumes `lumen.player.toolbar.v1` (defect 1) and the Save/Escape focus bug is fixed (defect 2), this is a beautiful dead end. The band-state variants (defect 3) I would descope openly rather than leave six frames half-approximated by one static overlay.
