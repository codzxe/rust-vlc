## Top-5 defects by shamefulness

1. **The default-open sidebar is the wrong panel.** First-run `/player` opens the docked QUEUE ("Playlist / 0 items / Nothing in the queue", 216 px) where `Player.png`'s single sidebar is the PLAYLISTS browser (rows "Cool Songs" / "Anime to Watch") — the frame composition is one title-bar toggle away (`/tmp/shots-w26h03/frame-composition-1440.png` proves it renders correctly) but is not the default. Vision flagged it in both comparisons. Repro: fresh-seed `/player`, 1440×900. Owners: `AppShell.tsx` route-aware sidebar default ↔ `PlayerScreen.tsx` dock (the f08/a10-vs-f09 dispute g03 documented — the landed resolution picked the dock; the frame says otherwise).
2. **The populated canvas is a title-card, and the pause pill can't pick a color.** No `<video>`/`<canvas>` (documented 4.H1 handoff) means the state `Player.png` depicts cannot exist; meanwhile `controls.css:174` cites "B9: pause state `#6B6B6B`" and ships `--color-content-tertiary` `#828282`, and the frame renders `#D37918`. Repro: open demo clip → pill at 60,864 turns `rgb(130,130,130)`.
3. **Chrome token `#161616` vs frame `#1B1B1B`** on BOTH the title bar and the full-width strip — g03-P2-1, open across two waves, systematic on every `/player` state. `themes/tokens.json` → `--color-surface-chrome` (tokens.css:52). One-line token fix, twice reported, still shipping.
4. **Menu ink is one token step off everywhere.** Accelerators `#828282` vs frames' `#6B6B6B` (menu.css:220 uses `--color-content-tertiary`); disabled rows via `opacity: .5` → ≈`#545454` on `#191919` (2.32:1) vs the frames' `#6B6B6B`; the ctx menu also drops the frame's three `#AB6314` pressed-orange row icons. Repro: open app menu / right-click canvas; compare `menu.svg` / `right-click menu.svg` path fills (12×`#8F8F8F`, 7-8×`#6B6B6B`, 3×`#AB6314`).
5. **Context-menu frame deltas:** 15 rows vs the frame's 14 ("Customize interface…" — documented, still off-frame), 283 px vs 292 px, and the Record accelerator reads "Shift + R" from keymap DATA where `right-click menu.svg` prints "R" — display should follow the frame per contract §3. Repro: right-click canvas at idle; `PlayerScreen.tsx` `acceleratorOf` / `HOTKEY_BINDINGS`.

Honorable mentions: title-bar app mark is a 10 px dot, not the cone (g03-P3-1, open); open-media dialog 560 px wide vs the 1048 px dialog family, Cancel `#222`+border vs borderless `#1B1B1B`; queue panel reads "0 items / Nothing in the queue" while media plays.

## Would I ship this?

Not the flagship. The menus (8.6 / 8.2) are production-grade once the one-step ink errors are fixed — geometry is frame-exact and the keyboard/aria story is real. The open-media dialog ships with a width ruling and a Cancel repaint. But the player itself: I would not put a first-run screen in front of users where the hero's left neighbor is an empty "Nothing in the queue" panel instead of the playlists the design shows, nor call a centered filename a "populated" player while the transport pill argues with its own spec comment about what color it should be. Fix the sidebar default (one toggle-state decision), the chrome token (one line), and the pause pill (one token), and states 1–2 land at 8.5+ — the skeleton work since g03 is genuinely good, which is exactly why the remaining misses sting.
