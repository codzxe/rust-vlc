## Top-5 defects by shamefulness

1. **The thumbnail card's dominant region is still a void.** Well `#0e0e0e` vs card `#191919` =
   Δ11/255 with a 0.3-opacity glyph — improved from g18's Δ4, still flat enough that vision flags
   it unprompted. The frame spends 252×142 on artwork; we spend it on near-black. Either the
   artwork seam lands or the well needs a deliberate inset treatment (visible stroke or a step
   darker). `options.css:171-183`, `ThumbnailGrid.tsx:37-39`; repro: /playlist → Anime to Watch →
   View options → Grid View.
2. **`role="grid"` without arrow keys, both lists.** Focus lands on the grid, ArrowDown does
   nothing, `aria-selected` never flips, no `aria-activedescendant`; rows are div+onClick so
   direct keyboard activation doesn't exist — the only keyboard path into a playlist is
   kebab→Enter→menu→Open (works, but nobody will find it). WAI-ARIA grid pattern is half-implemented
   semantics. Shared `components/list/*` (list lane) + both screens; repro: /playlist, focus list,
   press arrows.
3. **Hover fill `#262626` vs spec `#1c1c1c` — every library hover, every session** (g18-P3-2, open
   through gfix-E; `options.css:64` even documents a third value, `#1F1F1F`). A one-token fix
   owned by the token lane, visible on the family's default screen. Repro: hover any library row.
4. **media.svg text tones unmapped: watched `#828282` vs frame `#6b6b6b` (Δ23), unwatched
   `#8f8f8f` vs `#969696` (Δ7).** The watched state — the frame's clearest signal, dimmer title +
   orange bar — reads half as dim as designed, weakening the exact seam gfix-E just wired.
   `options.css:221,231` (flagged in-lane for the token lane); repro: file menu → Mark as Watched.
5. **File-menu anatomy nits that a 12-row frame-port shouldn't have:** Mark as Watched's leading
   orange check-in-box icon is suppressed by the checkbox-indicator grammar
   (`MenuItem.tsx:65-70` — `!checkable` guard), and the panel is 280px vs `file context menu.svg`'s
   265px. `fileRowMenu.ts:80-87`; repro: /playlist → media row •••.

Honorable mentions: dialog helper `#828282` vs frame `#6b6b6b`; drop-zone r6 vs frame rx5; kebab
20px / `•••` 30.5px right offsets vs the frame's ≈24.5px; initial dialog focus on ✕ instead of
the title input; disabled menu rows dim their orange icons (honest, but the frame shows all-orange
and the menu reads "mixed" at a glance).

## Would I ship

The dialog: yes, today — post-gfix-E it is the closest thing to a frame-faithful surface in the
program I've graded so far, with the disabled-Save pill done to the pixel and real focus
management. The media list: yes — its geometry is frame-exact, its states are honest and live
(watched seam verified end-to-end), and its remaining sins are two text-tone tokens and a 6px dot
offset. The library: yes, with the token lane's hover-fill fix queued — structure and states are
right, the flatness is borrowed, not built here. The grid: not yet — not because anything is
wrong, but because its hero region is honest-empty and reads like a stub; land the artwork seam or
a deliberate well treatment before anyone screenshots it for a store page. Ship-blockers: none.
Family mean 8.6 — the highest "still not YES" bar I've graded; everything between here and 9+ is
token-lane arithmetic and one artwork seam.
