## Top-5 defects by shamefulness

1. **Sorting rows flex-crush at both mandated sizes** — the frame's 48px rows render 46.5px at
   1440×900 and **38.25px at 1024×768 (−20%)**; the gfix-E "scrollport" never scrolls
   (scrollH = clientH = 620 at 1024) because `.lumen-menu` is a flex column and
   `.lumen-plo__item` has no `flex-shrink:0`, so `max-height` compresses every row instead.
   The fix wave's own verification checked panel bounds, never row heights — the exact
   criterion ("both sizes reachable") passed while the anatomy it protects was destroyed.
   Repro: `/playlist` → open playlist → sort trigger; probe `.lumen-plo__item` heights at both
   viewports. Files: `ui/src/screens/playlist/options/options.css` (`.lumen-plo .lumen-plo__item`
   needs `flex: none`) or `ui/src/components/menu/menu.css`.
2. **Two-button footers 8px off-frame** — Folder-2/-3 pin Cancel/Save at y748–780 in a 72px
   band; the app's candidate/online states measure band 56px, buttons y756–788, because
   `.lumen-plsubs__foot`'s 12px padding only reaches 72px with the 48px match control mounted.
   Every state was footer-checked with the control present. Repro: harness `FolderMultiHarness`
   / `FolderOnlineHarness`; measure `.lumen-plsubs__foot` + buttons. File:
   `ui/src/screens/playlist/subtitles/subtitles.css` (`.lumen-plsubs__foot` min-height 72px).
3. **Unlogged glyph-ink drift Δ23/255** — pair/candidate glyphs render
   `--color-content-tertiary` `#828282` against the frame's `#6B6B6B`; the sheet logs the
   pill-label (Δ7) and leader (Δ9) deltas in its header but quietly maps the glyph to a token
   23 points brighter, across all four dialog states. Repro: computed style of
   `.lumen-plsubs-pair__icon` / `.lumen-plsubs-row__icon`. Files: `subtitles.css`, token-lane
   handoff.
4. **Popup chrome vs borderless frames** — both option panels add a 1px `#404040` border,
   r12 (frame r10) and a 4.76/5.9 shadow against the frames' borderless r10 panels with
   blur-7.5/dy-8; grammar-legal per §2, frame-wrong, and applied identically to both popups
   so it reads as system, not accident. Files: `options.css` / `menu.css`.
5. **Populated states unreachable in the shipped app + harness drift** — real mounts pass no
   `candidates`/`folderPath`, so users only ever see the honest empty state (g19-P3-5, still
   pending the Lead); meanwhile the dev-only fragment harness mounts the filename control
   outside `.lumen-plsubs` scope, so the lane's own sub_filename closeup renders a `#0E0E0E`
   0.9px-bordered trigger with the selected label lifted to `#EAEAEA` — the comparison
   tooling validates a control that doesn't match what ships. Files:
   `PlaylistScreen.tsx`/`PlaylistPanel.tsx` (host wiring), `subtitles/harness.tsx` (scope).

## Would I ship

The subtitle-dialog family yes, today: the pairs/multi/online windows are frame-measured to
the pixel (96px band, pills x9/x219/x429, rows y118/40px pitch, last pair bottom 718, footer
y728/748), states are honest, disabled Save keeps its dimmed tint, and the keyboard model —
focus trap, scoped Escape, roving focus — survived every probe I threw at it. I would NOT
ship the sorting popup as-is: a menu whose rows silently compress 20% at the contract's own
spot-check size is a defect wearing a fix's clothes, and it's a one-line `flex: none` — fix
it, re-measure the rows (not the bounds), and pin the two-button footer to 72px while you're
in the sheet. Family ships after 45 minutes of CSS; that's the size of the gap between 8.6
and 10.
