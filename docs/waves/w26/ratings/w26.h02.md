## Top-5 defects by shamefulness

1. **Light mode fails WCAG AA on the working steps.** 16px row/card labels #4E4E4E on the
   #ABABAB wizard window = **3.62:1** (AA needs 4.5), footer note #5F5F5F = **2.78:1** — measured
   live on shortcuts (light) and inherited by appearance/done via the same
   `--color-content-secondary/tertiary` on `--color-surface-chrome` pairing. Cross-lane token
   issue (theme lane; h01 logged it too), but it ships on every step of this family and nobody
   has owned it through two fix waves. Repro: /onboarding → appearance → pick Light → Next ×4.
2. **The shortcut tour's copy is typographic chaos.** Three casing conventions over 12 rows —
   "Play Pause" (no separator; frame "Play / Pause"), "Seek backward / forward",
   "Queue Toggle"/"File Browser Toggle"/"Subtitle Track Cycle" (Title Case; frames read
   "Show / Hide Queue", "Show / Hide File Browser", "Cycle Subtitle Track"), "Snapshot" vs
   "Take a Snapshot". Honest catalog data, lazy presentation; §2 sentence case violated on 8 of
   12 rows. Files: `ui/src/i18n/messages.ts:1579-1601` (hotkeys.*) +
   `OnboardingScreen.tsx:228-256` (SHORTCUT_ROWS).
3. **Footer note still 11px #828282 vs frame ≈13px #6B6B6B** (g01-P3-4, open). The CSS comment
   quotes the frame value and then uses the caption token anyway. `onboarding.css:524-528`
   (`.onboarding__footer-note`); repro: step 7, bottom-left.
4. **Keycap anatomy: right geometry, wrong ink.** Cap fill #191919 vs frame #1B1B1B, inset
   stroke #404040 vs frame #373737, and single-glyph caps run 48–60px wide against the frame's
   35–46 (padding 0 22px ≈ 6px/side too generous) — the chunky keycap depth the frame specifies
   renders softer and fatter. Pixel-verified at cap edge (582,256). `onboarding.css:289-308`.
5. **Step-7 CTA says "Next" where the frame says "Finish"** (plus the Lead-mandated Skip).
   Documented recomposition — the done step now carries the terminal "Get started" — but the
   shortcuts frame is the flow's original goodbye and the recomposed button row never says so.
   Lowest shame, most visible. `OnboardingScreen.tsx:825-837`.

Honorable mentions: window #161616 vs frame #0E0E0E (sanctioned, family-wide); caps "Shift" vs
frame "SHIFT"; P/N caps vs frame "<",">" for item nav (honest keymap data — the frame's own
binding set differs); blue/violet CTA ink deviation (deliberate, WCAG-superior — keep).

## Would I ship

The accent-variant system and the handoff, yes, today — post-gfix this is measurably
frame-exact (every accent hex, ring geometry to the pixel, pitch, dim, hover, roving keyboard,
immediate persistence, clean gate/redirect, zero console errors), and the blue/violet ink
deviation is the rare frame departure that improves the product. The done step ships the moment
the token lane fixes light-mode contrast. The shortcuts tour does not ship as-is in light mode
(AA failure), and even in dark it needs a copy pass (one casing convention, frame-parallel
labels) and the 13px footer note before I'd call it frame-faithful. None of it is "worst UI
ever" territory — this is a disciplined, honest build one copy pass and one token fix away from
a 9. Ship-blockers: light-mode AA only.
