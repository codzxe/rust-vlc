## 1. Token discipline (THE supply) — **8/10**

The three-layer pipeline is the real thing, not theater.

* **Grammar enforced, not aspirational.** parse.rs:338-361 rejects primitive references in primitives, semantic→primitive shortcuts; cycles detected with a chain (parse.rs:264-267); per-mode coverage validated (parse.rs:310-317); unsupported $type/category rejected. Layer rules have mutating-source tests (pipeline.rs:353-402).
* **Determinism verified end-to-end.** `cargo run -p theme-tokens --bin tokens-gen -- --out-dir` twice → byte-identical; both committed outputs (themes/generated/tokens.css, crates/.../generated/tokens.rs) match regeneration exactly. `emission_is_deterministic` (pipeline.rs:203) plus sorted declarations (emit.rs:197) and fixed number forms (emit.rs:302-318) back the doc 08 §3.4 claim.
* **One truth holds.** ui copy = crate output (tokens:check OK); ui side pins sha256 + all 84 names + value spot-pins (tokens.test.ts:43, 122, 136-174); the h20-F1-relevant values are pinned at three layers (tokens.json descriptions → generated CSS → tokens.test.ts:165-172).
* **content.quiet / content.accelerator split is sound** (tokens.json:702-714): same mined values today, separate alias+semantic entries so a future retune can diverge; scopes documented (quiet = non-text/inactive; accelerator = menu accelerators + two-tone icon ink, w26.i16). Emitted and pinned (tokens.css:36/40, 119/123).
* Deductions: the generated-output drift check exists (`tokens-gen --check`) but is wired into **no** CI workflow (ci.yml:399 explicitly SKIPs it; ui.yml has no tokens step) — a repin of tokens.json without regeneration is caught only if it changes counts or one of the pinned values; and emit.rs has a real section-split bug (Finding F2).

## 2. CSS architecture (lumen.css) — **7/10**

* Clean 8-layer composition, every color/font via `var(--…)`; no token redefinition anywhere in the sheet; layer-8 light overrides are specificity-planned ((0,3,0)/(0,3,1) vs component (≤0,2,1)) and each carries frame provenance. stylelint (standard config + color-no-hex + function denylist) is green on the file.
* The stylelint config's config-level exemption for `src/tokens/generated/tokens.css` (stylelint.config.js overrides block) is the right call — an inline disable would break the byte-drift guard.
* Deductions: 2 of the 3 advertised "shared primitives" are dead (F7), one documented ratio is arithmetically wrong (F6), and the header still sells `.lumen-row` as "the Settings/tools/menus row grammar" that no screen uses.

## 3. React quality — useMsg + pseudo determinism — **8/10**

* **pseudo.ts is genuinely deterministic** (pure function, no randomness), and the transform is defensive: top-level `{…}` tokens (incl. nested plural arms) masked with PUA sentinels and restored verbatim (pseudo.ts:33-61,75); `{{ }}` escapes survive; lengthening to ≥1.5× measured against the source length. Unit tests pin determinism, placeholder survival, and the switch for **all** keys (messages.test.ts:39-66); pseudo.render.test.tsx proves the seam reaches rendered headings across 7 routes with no `undefined`/`missing:` fallback.
* `useMsg` (messages.ts:2913-2918) is total (en-US fallback), and `setActiveLocale` cannot crash on unknown tags (2895-2897).
* Deduction: the hook reads a module-global and has no subscription/context — correct **only** because main.tsx:44-47 sets the locale strictly before `createRoot().render()`. A runtime locale switch would silently not re-render. Documented as a scaffold stand-in, but nothing (comment or type) stops the next lane from calling `setActiveLocale` mid-session (F8).

## 4. Test honesty — **6/10**

There is no diff.rs (tests/ contains pipeline.rs + semantic_lint.rs only). The functional equivalent (`tokens-gen --check`) is not in CI.
* tokens.test.ts:8 claims byte-identity is "enforced by `npm run tokens:check` … in CI" — ui.yml contains no tokens step (verified: zero matches).
* `emitted_documents_have_the_documented_structure` uses `contains()` only, which is why the F2 section-split bug ships unnoticed; messages.test.ts:25 pins `> 400` against a 1401-key catalog (a pin that can never fail meaningfully).

## 5. i18n infrastructure (the 1401-key catalog) — **6/10**

* Catalog integrity is excellent: 1401 union keys = 1401 strings, 0 missing/dupes/orphans, grammar clean, 1 placeholder well-formed; all 802 lane-file key instances (792 unique) are registered — no lane key renders through a seam today. The eslint `local/i18n-no-literals` rule loads the real allowlist and is itself unit-tested.
* **The registration workflow is broken where it matters** (F1): merge-i18n-keys.py's UNION_ANCHOR is self-consuming — the first merge rewrote `  | "settings.video.reset-picture";` into a non-terminal line, so the anchor (with `;`) no longer exists in messages.ts (union now ends `settings.value.video-crop.4-3`, line 1445). Proven by sandbox repro: with a genuinely-new key the script dies `AssertionError: union anchor count=0`. It only "works" today because every current key is already registered (early exit). The script also lives **outside the repo** (/home/z/my-project/scripts/) — not under version control, contradicting §8's durability intent. The *pattern* (per-lane files, Lead merges, never touch messages.ts) is sound; the tooling is not repeatable as claimed.
* **114 dead keys (8.1%)**: unreferenced by any source/e2e/tools file (26 customize.*, 14 onboarding.*, 13 menu.*, 10 screen.*, 9 player.* …) — the scaffold-era customize.* family was superseded by the tools screens' own keys. l10n-check's "orphan" rule only checks catalog↔union alignment; nothing detects keys no component consumes.
* 10 cross-file duplicate lane keys (w26.f01 vs w26.i14, identical values) and 139 duplicate en-US values (13× "Automatic", 11× "Off") — benign today, but the merge script has no cross-file conflict detection (a value conflict would only surface later as a duplicate-catalog error in l10n:check).
