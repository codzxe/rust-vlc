## Special-attention rulings (asked by the Lead)

1. **The 9-tick gamma data — CORRECT data, WRONG paint domain.** The row def
   (EssentialTool.tsx:82-90: min 0, max 10, step 0.1, initial 1.1, `ticks: 9`)
   matches the frame exactly: "Video - Essential.svg" `degrees_5` draws 9 ticks at
   x = 70.4…329.6 = **38 + 324·(i+1)/10 — the FILL domain (2px-inset)**, thumb
   center 70 (= fill 9.88%, value 1.1 ✓ through the i07 flush travel). But
   VideoSliderRow paints ticks at raw track percent (`left: ${left}%`,
   VideoSliderRow.tsx:82) → tick 1 lands at x 68.8 vs frame 70.4 (**−1.6px**),
   tick 9 at 331.2 vs 329.6 (+1.6px). Same for grain (9 ticks, ±1.6px), banding
   (6, ±1.4px), sharpen (3, ±1px), both 2-tick rows (±0.7px); the three 1-tick
   rows sit at x=200 (center) where the domains coincide — zero drift. This is
   j10's P2-3 drift, now frame-proven; see finding P2-1.
2. **The Crop "Bottom" field-sizing fix — SOUND, honest fallback, unpinned.**
   video.css:258-279 replaces the fixed 3ch reservation with
   `field-sizing: content; min-width: 1ch; max-width: 3ch` (+ content-box), with
   the vision-caught repro and frame measurements in the comment (value digit at
   input+73..80, 40px trailing, label 13..59). The fallback claim is accurate:
   without `field-sizing` the input's ~20ch intrinsic width clamps to
   `max-width: 3ch` — i.e., engines without support regress to the pre-fix
   truncation (progressive enhancement, documented). stylelint accepts the
   property. Deduction: nothing regression-pins this rule (P3-2) — a "cleanup"
   could revert the fix silently.
3. **ToolSliderRow vs VideoSliderRow duplication — CONFIRMED, drifted, and now
   frame-falsifiable.** VideoSliderRow.tsx is a line-for-line mirror of
   dynamics/ToolSliderRow.tsx (own header admits it, VideoSliderRow.tsx:1-7) —
   but dynamics got the w26.i07 tick-domain fix
   (`left: calc(2px + (100% - 4px) * … / 100)`, ToolSliderRow.tsx:84) and the
   video copy did not (VideoSliderRow.tsx:82 keeps the pre-fix full-width
   percent). I re-measured both frames: EVERY multi-tick video row draws its
   ticks on the fill domain (Essential: 38+324·i/(n+1); Colors sepia: x146/x254
   = 38+324·{1/3,2/3}), so the video paint is objectively off its own frames by
   up to 1.6px (≈3.6px at the 2.25× comparison scale). The stated duplication
   reason (label-key union hard-wired to w26.c2 keys) is solvable with a generic
   `<TKey>` + `resolveLabel` prop — same route j10 prescribed (P2-3). The
   covered-tick comparison itself is domain-consistent in both copies; only the
   painted x is wrong. (P2-1.)
4. **useDropdownScrollportFlip v2 — a SOUND stopgap, not a root fix (by its own
   admission), and the best-engineered workaround in the wave.** Architecture:
   defer-first (fits a clip side → the shared flip owns it — no double
   ownership), `position: fixed` escape only when neither clip side fits,
   re-glued on scroll/resize, capped last resort. Judgment, honestly: fixed
   positioning is the *correct mechanism* here — it escapes every overflow clip
   while keeping the list a DOM child, so the primitive's outside-click/Escape/
   typeahead keep working (a portal would have to re-implement all three);
   grep-verified no transform/filter/will-change ancestor exists on the dialog
   path (dialogs.css's only transform is a chevron rotate, :413-419), so the
   fixed-escape containing-block trap does not bite today. The pure decision
   (`resolveListPlacement`) is unit-pinned against live-measured geometries, jsdom
   zero-geometry degrades safely, and the root-fix handoff is logged twice. What
   keeps it a workaround: (a) escape mode is sticky per open — `reposition`
   re-glues coordinates but never re-runs the placement decision if geometry
   changes under an open list; (b) it is the THIRD clip-measurement
   implementation in the tree (Dropdown.tsx:24-40 `clippingBounds` = nearest
   clipper; hook's `clipBoxAround` = intersection of all clippers — more
   accurate, but two algorithms that can disagree); (c) the DOM half has zero
   automated coverage (P3-1). Verdict: keep until the primitive gains the
   escape (the logged proposal), then delete — it must not survive i16+1.
5. **The centered-trigger-label fix lineage — LANDED at the root; video's scoped
   copies now redundant (equalizer's too).** Lineage: i08's vision loop flagged
   it ×3 → pixel-pinned (frame "Auto" at x85-150, app now x71-132 at the 400px
   dialog) → scoped `text-align: start` on both video triggers (video.css:357,
   :378) → i16 adopted it shared (menu.css:316, whose comment explicitly calls
   the video.css/equalizer.css overrides "redundant, not conflicting"). The
   landing is correct and verified; the scoped declarations + the now-stale
   "should adopt it" comment (video.css:350-356) are cross-lane cleanup debt
   (P3-4). Video's own **off-lattice keyboard steps** (the j10 audio issue):
   PRESENT — see P2-2 (3 of 11 sliders).
6. **Staging pattern** (context for dimension scores): all four tools carry
   `data-staged-tool` + `data-pending-command` + a visible `role="note"` — the

## Dimension scores

### 1. Token discipline — **9/10**

Every color in video.css is `var(--…)`; all frame hexes live in comments with
SVG citations. The two raw-hex-adjacent sites are both sanctioned: frameData.ts
(#FF0000 = the frames' editable field DATA, isolated in a .ts data module with
citations — the analysis' "data, not theme" ruling) and CropTool.tsx:114-126
(frame-verbatim "Rectangle 14" link glyph, `stroke="currentColor"` carrying the
ink through `--color-content-secondary`, `/* frame: */`-marked). The HDR check
(video.css:404-413) is a token-painted masked path (`--color-accent-icon`) —
themeable where a data-URI color would not be; the mask's `%23000` is an alpha
shape, not a painted color. Raw px is structural geometry, each with a frame
citation. Deduction: swatch `border-radius: 2px` (video.css:117) is an
untokenized frame value — same sanctioned-structural pattern the dynamics lane
uses, but it is the one value a `--radius-swatch`-class token would own; minor.

### 2. CSS architecture — **7/10**

Stylelint 18/standard green; zero `!important`; no dead RULES (selector
inventory cross-checked); the `[hidden]` display guard comes from the composed
dynamics sheet (dynamics.css:102-104) and the collapsed body leaves the a11y
tree. Composition over re-declaration is real: VideoCard reuses the dynamics
card classes + imports the dynamics sheet verbatim; the HDR row-grammar
override was correctly DELETED when i16 landed the shared 44@46 grammar
(video.css:395-399 documents the removal — the anti-drift instinct j10 wanted).
`prefers-reduced-motion` covers the one transition (video.css:456-460). Deductions:
(a) two now-redundant scoped `text-align: start` declarations with a stale
comment (P3-4); (b) specificity jockeying over the Dropdown primitive — the
trigger re-skin needs `.video-tool .video-subdropdown .lumen-dropdown__trigger
[aria-expanded="true"]` (0,4,0, video.css:387-389) and explicitly re-declares
hover/open fills to keep the shared behavior alive — correct but order-dependent,
same shape as j10's P3-6; (c) the per-gap separator modifiers `video-sep--1..5`
(video.css:142-164) key frame measurements to positional classes — a

`video-row--toggle`, ColorsTool.tsx:140/:181) — redundant with the `data-row`
