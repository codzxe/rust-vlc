**Evidence (good):** clean hooks throughout — `useId` for title/form/aria wiring (no id collisions), `useState` initializer captures the engine position at mount for the goto prefill (GotoTimeDialog.tsx:73, correct per-open semantics), `useMemo` on the sorted copy so `[...bookmarks].sort` never mutates engine state (BookmarksDialog.tsx:113-116), the mount-fetch effect's `cancelled` flag + justified `eslint-disable` with rationale (BookmarksDialog.tsx:103-109). Utility purity: `parseTimeInput` and `naturalCompare`/`compareBookmarks` are pure, dependency-free, `Number()`-overflow-safe on digit runs (naturalSort.ts:30-38) — both exemplary.

**Evidence (deductions):**
- **The unit bug (see P1)** is first a code-quality failure: `timeUs = Math.round(state.position * 1000)` (BookmarksDialog.tsx:122) computes milliseconds in a variable named µs, and the file's own comments (:7, :121, :164) say µs. Code and comments disagree; schema says µs.
- BookmarksDialog subscribes to the whole player seam (`usePlayerControls()` → state), so every `timing.time-tick` re-renders the dialog while it's open, though it needs `state.position` only at add-time. Rows are memoized but reconciliation still runs per tick. Consistent with the app pattern, cheap in practice (per-open mount), still an avoidable subscription.
- `hidden` TabsPanels stay mounted (Tabs.tsx:110), so opening the tools dialog mounts **all eight tools at once** (11 EQ sliders + 4 dynamics/visualizer + 4 video). Deliberate a11y tradeoff (aria-controls always resolves), documented — acceptable, but it doubles initial mount work and is worth remembering when a ninth tool lands.

## 4. Test honesty — 7/10

**Evidence (good):** no snapshots, no theater-by-snapshot; assertions are wire-level and specific — `playback.seek` args pinned to `{ target: { kind: "absolute", time: 90 } }` (GotoTimeDialog.test.tsx:88-91), add/remove pinned to exact args (BookmarksDialog.test.tsx:145-148, 184-187), the natural-order render test seeds a scrambled engine list and asserts the **rendered aria-label sequence** (BookmarksDialog.test.tsx:193-218), and the three new w26.i09 focus pins assert *focus*, not just presence (ToolsDialog.test.tsx:45-67). The fake transports are honest engine mimics (BookmarkTransport reproduces id semantics and not-found errors). 53/53 green this session.

**Evidence (deductions):**
- **The suite certifies the wrong unit.** BookmarksDialog.test.tsx:135's title says "Add sends … position **in µs**" but the assertion is `{ time: 0 }` (line 147) — zero is unit-agnostic, and every add in the suite runs at position 0 (the transport never emits time-ticks). A single nonzero-position case (e.g. position 90s → expect `time: 90_000_000`) would have exposed P1. Meanwhile the render seeds speak milliseconds (`time: 300_000` renders "5:00", BookmarksDialog.test.tsx:196-201) while naturalSort.test.ts:39-43 speaks µs (`at(10_000_000)` commented "0:10") — **two test files in the same directory disagree about the wire unit**, and both pass.
- Harness export test no-ops in CI: harness.test.tsx:44-45 returns early unless `W26C5_HARNESS_OUT` is set, so the export path (fs writes, CSS inlining) is never exercised by a normal run. Dev-only tooling, honestly labeled, but it's an `it()` that always passes.
- Small gaps: no test pins `ToolsCard`'s `id` prop passthrough or `htmlFor` wiring of ToolsRow (the label association is the row's headline a11y claim); goto dialog's `inputMode`/prefill-at-nonzero-position untested.

## 5. i18n — 5/10

**Evidence (good):** ToolsDialog.tsx is the exemplary half — every user-visible string flows through `useToolsMsg()` (ToolsDialog.tsx:104-139), the lane keys file exists (i18n/keys/w26.c5.ts), the seam-first fallback is documented, and the central catalog now carries all `player.tools.*` keys (messages.ts:915-957, 2345-2387), so pseudo-locale covers the tools dialog today. Test expectations read keys, not literals (ToolsDialog.test.tsx:16, 53).

**Evidence (deductions):** the other three files are hardcoded English with no path to translation:
- `BOOKMARKS_COPY` (BookmarksDialog.tsx:48-59) — 10 strings including interpolating helpers; `GOTO_COPY` (GotoTimeDialog.tsx:47-57) — 9 strings. **No lane keys file exists for any of them** (w26.a18.ts registers only the 3 tools-shell keys), so the "central keys are the recorded follow-up" comments (BookmarksDialog.tsx:29-31; GotoTimeDialog.tsx:29-32) have no artifact behind them — the follow-up cannot be executed by the Lead because the keys were never written down. This is a straight §4.5 violation ("user-visible strings flow through useMsg() + MessageKey").
- `TOOLS_DIALOG_COPY` (ToolsDialogShell.tsx:43-50) duplicates strings whose central keys are **already registered** (messages.ts:2126-2128) — the shell could use `useMsg` today and doesn't, so `setActiveLocale("pseudo")` leaves expand/collapse/close English.
- The `local/i18n-no-literals` rule can't see any of this (it covers JSX text + a few attrs, not constant objects — rule source, tools/eslint-plugin-local/rules/i18n-no-literals.js:8-10), which is exactly how the gap survived nine waves.

## 7. A11y implementation — 9/10

**Evidence (good):** the wave-I i09 landing is real and verified against the primitive, not just the comments: `useSurfaceFocusTrap` focuses `querySelectorAll(FOCUSABLE_SELECTOR)[0]` in **DOM order** (Surface.tsx:78-79), and all three hosts render body-before-header with `order:-1` on the header (dialogs.css:73-74; ToolsDialogShell.tsx:100-119; BookmarksDialog.tsx:177-247; GotoTimeDialog.tsx:105-148) — so first focus lands on the tab pair / label input / time input, and the ✕ (DOM-last among chrome) is reached at the end of the cycle. Trap wrap is the primitive's explicit preventDefault+move logic (Surface.tsx:96-118) and the **test pins it** (ToolsDialog.test.tsx:57-67: Shift+Tab wraps to Close, Tab wraps back). Escape yields to open popups inside the dialog (Surface.tsx:82-94, the g19 fix) — i09's log claims live verification on viz/gradient lists. Tab semantics come from the primitive (roving tabindex, arrows/Home/End, aria-selected; Tabs.tsx:53-99) and the r6 de-pilling override (dialogs.css:321-323) touches paint only. aria wiring is complete: `aria-labelledby` on the dialog, `aria-expanded`/`aria-controls` on card toggles with bodies kept in DOM (ToolsDialogShell.tsx:169-195), label/for association on rows and fields, `aria-invalid` error flow via TextField. Delete buttons de-mute on hover AND `:focus-visible` (dialogs.css:264-266) — keyboard-only users are not stranded at opacity 0.3. dialogIcons are `aria-hidden` + `focusable="false"`.

**Evidence (deductions):** the jump row's `aria-label` (BookmarksDialog.tsx:211) **replaces** the visible time+label content — two bookmarks at the same timecode are indistinguishable to a screen reader ("Jump to 2:00" ×2); the label belongs in the accessible name. Also the "✕ stays … at the END of the tab cycle" wording (ToolsDialogShell.tsx:23-25) holds for every current mount but is DOM-order-fragile: the slot order is body→header→footer, so a future dialog with both a footer and this doc's claim would put footer buttons after the ✕ — one clarifying sentence would future-proof it.
