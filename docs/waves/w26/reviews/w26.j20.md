## 1. Token discipline (lint enforcement) — **8/10**

Enforcement is real and verified, not decorative:

- `local/semantic-tokens-only` **actually fires** — proven via stdin probe against
  `src/__probe__.tsx`: raw `#ff0000` literal, `{ fontSize: "12px" }`, JSX
  `style={{ color: "#00ff00", borderRadius: "4px" }}` all reported (rule at
  `tools/eslint-plugin-local/rules/semantic-tokens-only.js:42-79`). Unit tests pass.
- CSS side: `stylelint.config.js:50-61` — `color-no-hex`, `function-disallowed-list`
  (rgb/hsl/hwb/lab/lch/oklab/oklch/color; `color-mix()` deliberately allowed — correct
  call), `color-named: never`. `npm run lint:css` = zero violations over all of
  `src/**/*.css`. The one exemption (`src/tokens/generated/tokens.css`,
  `stylelint.config.js:96-107`) is scoped, documented, and guarded by the byte-compare
  drift check — the right shape.
- `npm run tokens:check` green; `themes/generated/tokens.css` ↔ committed copies
  byte-identical.

Gaps: rule only applies to `.tsx` (`semantic-tokens-only.js:38` returns `{}` for
anything else) — raw hex in `.ts` helpers (e.g. canvas code) escapes both lint systems.
No `/* frame: <Frame.svg> */` escape hatch exists in the rule, though CONTRACT §4.4
promises one for frame-measured ports (currently unexercised: 0 raw hex in src .tsx —
the rule being green is what makes this latent, not live). Template literals are
color-checked but not dimension-checked.

## Verdict: **REFACTOR**

The enforcement core is genuinely good — the token/stylelint/boundary/i18n lint stack
is real, tested, and verified firing; the four drift guards are green; tsconfig is
best-in-class. What drags it down: the lint gate is **red** (P1), the visual-baseline
provenance chain is broken (re-pinned without a record, honesty notes now false),
config route inventories lag the app by ~10 routes, the i18n rule misses
`placeholder` with a live untranslated string, and the bundle ships as one 854 kB
chunk behind a build warning that fires every time. None of this needs a rewrite; all
of it needs a one-day hardening pass plus a standing rule: **config comments and
MATRIX records are deliverables, not decorations.**
