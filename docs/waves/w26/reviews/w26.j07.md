## Dimension scores

### 1. Token discipline — **9/10**

Every color in controls.css flows through `var(--color-*)` (spot-checked all
56 declarations; raw hex appears only in measurement comments, e.g.
controls.css:121,148). The single raw-hex declaration — the volume signal
gradient — carries the required stylelint-disable with a `frame: volume.svg`
citation and a documented rationale (signal colors ≠ theme accents;
controls.css:364-365). TSX has zero hex in code. The `lumen/i18n-no-literals`
and `semantic-tokens-only` rules are active and green. One open item: the
comment's promised handoff `--gradient-volume-level` is consumed but never
defined (slider.css:243 falls back to accent; see P3-11).

### 2. CSS architecture — **8/10**

Stylelint standard green, zero `!important`, zero inline statics, zero dead
rules (full selector cross-check). Structure is a clean BEM-ish layering
(row → clusters → parts → popovers → motion), `prefers-reduced-motion`
respected (:830-834), and the 375px app-menu override wins by specificity
(0,2,0) with an explicit comment instead of import-order luck (:751-760).
Weakness: the play-pill ink is pinned by THREE stacked escalation blocks
(controls.css:212-216, 241-260, 269-272) reaching `(0,6,0)` with
`:root .lumen-player` prefixes to beat shared icon.css/button.css rules —
each block is honestly documented with its wave/defect provenance, but the
accumulation is a specificity arms race against shared sheets that will bite
the next person to touch the icon-button cascade (P3-10). The i03 popover
re-anchoring (wrapper static → strip-relative, :381-413) is a genuine
structural fix, not a paint-over.

### 3. React quality — **7/10**

Good: components split by cluster with unconditional hooks; the
NavigationSeam/router-optional split pattern (:163-182) is correct
rules-of-hooks hygiene; outside-pointer dismiss is focus-neutral by design
while Escape restores focus (e12 F8), and the tab-reset-on-open functional
`setOpen` (:815-821) avoids stale-tab state. The i16 mount and the frozen
`OPEN_CUSTOMIZE_EVENT` re-declaration are documented decisions, not accidents.

Bad:
- **The seam-resolver scaffolding is now dead and its type contract lies**
  (P1-1). All 41 keys across `w26.f13/gfixC/i03/i16` are REGISTERED in
  messages.ts (grep-verified every key), so every `m(key) ?? catalog[key]`
  fallback (ControlBar.tsx:105-108, 869) is unreachable. Worse,
  `LaneMessageKey = MessageKey | I03LaneKey` (:101) omits the gfixC half of
  `laneCatalog` (:95) — the catalog merge promises a fallback the type system
  forbids reaching (an unregistered gfixC key would be a compile error despite
  sitting in the catalog). AppMenuButton carries a SECOND, differently-shaped
  inline resolver (:869) and toolbarItems a THIRD (4-catalog chain,
  toolbarItems.tsx:52-63). The pattern was the correct §4.5 seam-first move
  during waves f–i; after the Lead's merge it is ~45 lines of misleading
  indirection in this file alone. Delete it.
- **Re-render hotspot:** the context value is `{state, actions}` memoized on
  `state` only (context.tsx:424), so every position tick re-renders the root
  `ControlBar` (:190-196) and all six subscribed clusters — including
  rebuilding the app menu's 13 `MenuEntry` objects + profile flyout
  (:919-1022) and all four PanelPopover trees while everything is closed.
  Tolerable at 1–4 Hz ticks on a 44px bar; there is no memo or state/actions
  split to stop it becoming a problem at scrub rates (P2-5).
- `PanelRadioRow` reimplements radio semantics worse than the existing
  `RadioGroup` primitive — see dimension 7 (P2-2).

### 4. Test honesty — **7/10**

### 5. i18n — **7/10**

All in-scope user-visible strings flow through `useMsg`/`MessageKey` or the
(seam-resolved) lane keys; accelerators are generated from keymap DATA, never
hardcoded (ControlBar.tsx:117-125 — exemplary); dynamic recents/profile names
ride the identity resolver per the Dropdown pattern (:893-913). Problems:
- The queue meta row hardcodes English unit grammar:
  `` `${count} ${tm("player.controls.queue-items")} - ${hours}h ${minutes}m` ``
  (ControlBar.tsx:637-640) — "items" is a key but the `h`/`m` suffixes, the
  hyphen join, and the word order are not localizable (P2-4).
- The position timecode's click face opens GotoTimeDialog, whose ENTIRE copy
  table is hardcoded English (`GOTO_COPY`, dialogs/GotoTimeDialog.tsx:52-60)
  — a documented pre-§4.5 follow-up that the lane-key mechanism has since
  made trivially fixable, surfaced directly through this lane's seam
  (ControlBar.tsx:383) (P2-6, cross-lane file).
- Dead registered keys left behind by lane successions:
  `player.controls.settings-popup` (gfixC.ts:27; the i03 gear now uses
  `menu.view.settings`) and `player.controls.group-tracks` — registered, used
  nowhere (P3-12).

### 6. Dead code / Solstice remnants — **7/10**

Zero Solstice remnants (all five greps clean). But the post-merge cleanup was
never done: the lane catalogs + resolver types (P1-1); `StopButtonState` and
`mapTransportControls().stop` have no component consumer since gfix-C removed
the stop button (state-mapping.ts:36-38,110-112; only tests + the frozen
export index.ts:14 keep it alive — defensible as frozen API, still dead);
`bandTiles` exported with no consumer (toolbarLayout.ts:102 via
customize/index.ts:18); the two dead i18n keys above; the pointless
`playback as PlaybackState` cast (state-mapping.ts:128); the error chip
reuses the `about` info glyph for an error surface (ControlBar.tsx:1070)
(P3-15/16).

### 7. A11y implementation — **8/10**

Genuinely good: `aria-haspopup`/`aria-expanded` on all five triggers;
`role="dialog"` non-modal panels with a real `tablist` (roving tabindex +
ArrowLeft/Right, SettingsPanel.tsx:131-159), tab↔tabpanel id wiring, focus
moved to the panel on open, Tab trapped inside, Escape restoring the trigger;
groups named (`role="group"` + labels on transport/volume/output);
disabled-with-reason composed INTO aria-labels
(ControlBar.tsx:353-357, 371-375); the duration toggle carries `aria-pressed`;
the error chip is a `role="status"` live region; accelerators are displayed
from keymap data in frame spelling; inert rows are honest (`aria-disabled`),
never hidden. The 900px floor fix (:74-80) preserves keyboard reachability by
overflowing as a whole instead of overpainting.

Deductions:
- `PanelRadioRow` renders `role="radio"` buttons with NO `radiogroup` parent,
  no roving tabindex, and no arrow-key selection — every radio is its own Tab
  stop, which contradicts both the ARIA radio pattern and this repo's own
  `RadioGroup` primitive (components/form/RadioGroup.tsx:29-32 does it
  right). Track selection is a primary surface; this is the strongest a11y
  finding (P2-2).
- The tablist omits Home/End (optional in APG, minor); the tablist's
  `aria-label` duplicates the dialog's label (SettingsPanel.tsx:133 — harmless
  redundancy).
