## 1. Token discipline — 8/10

**Evidence (good):** `button.css` carries **zero raw colors** — every fill/ink/radius/opacity is a semantic `var()`; enforced by Button.test.tsx:199-203 (regex-asserts no hex/rgb outside comments) and the passing eslint rule. Cascade-specificity reasoning is documented in-rule (button.css:108-115, 306-312). Swatch hexes (form.css:583-620) are frame-measured per `Settings - global.svg`, stylelint-scoped, and tested (SwatchGroup.test.tsx:75-81).

**Evidence (deductions):** form.css ships raw hex **inside var() fallbacks** — `var(--color-surface-input, #2a2a2a)` (form.css:72) and `var(--color-stroke-input, #3a3a3a)` (form.css:66, 209). I verified `--color-surface-input` / `--color-stroke-input` do **not exist** in `ui/src/tokens/generated/tokens.css` — the seam is still open with waves a–i done. Frame-marked + stylelint-disabled per §4.4's exception, so contract-legal, but 9 waves of drift risk. Also: 7 of the 9 swatch hexes equal existing `--color-eq-1..7` globals (e.g. `#e15032`, `#c49e23`) — the "per-accent primary tokens do not exist" comment (form.css:578-582) is true for accent-scoped tokens but the eq-token alternative was not considered/rebutted.

## 2. CSS architecture — 8/10

**Evidence (good):** stylelint green; no `!important` anywhere; no inline styles in any TSX (the pre-W26 inline-style object was replaced by `.lumen-field__label--hidden`, form.css:45-55 — contract §6 compliant); BEM-ish naming consistent (`__control`, `--sm`); reduced-motion covered for every animated control (button.css:233-241, 434-439; form.css:660-672); careful light-mode overrides with specificity companions (button.css:299-312).

**Evidence (deductions):** one **dead rule**: `.lumen-radiogroup__label` (form.css:306-309) — grep shows no component renders that class (RadioGroup uses `aria-label` only). The w26.d2 out-of-lane light-mode blocks (form.css:674-707, button.css:148-166, 290-312) duplicate knowledge across two files owned by this lane pair — acceptable as flagged, but the form/button split means every toggle fix must now land twice (see P2-3).

## 3. React quality — 7/10

**Evidence (good):** `forwardRef` + `displayName` on all ref-carriers; `useId` for label/error wiring (no id collisions); no hooks misuse; primitives are leaf components — zero re-render hotspots; controlled-input contracts honest (Checkbox test uses `readOnly` to avoid the controlled warning). Button's class-compose (`Button.tsx:55-62`) is clean.

**Evidence (deductions):**
- **Identical 12-line roving-keydown handler copy-pasted 3×**: RadioGroup.tsx:48-59, SegmentedControl.tsx:48-59, SwatchGroup.tsx:69-80. Should be one `useRadiogroupKeyboard(options, value, onChange)` hook — drift risk is real because the three already differ only in element typing.
- **Two full implementations of Toggle.svg**: form/Switch.tsx:25-52 duplicates button/Toggle.tsx:24-51, plus ~87 duplicated CSS lines (form.css:376-462 vs button.css:332-439). states.md (button/states.md:103-107, form/states.md:38-47) documents this as "both stay until the form lane unifies" — we are at wave J and it never unified.
- NumberField synthesizes a fake `ChangeEvent` with `as unknown as` (NumberField.tsx:43-47) — a type lie; consumers reading `e.target.name`/`isTrusted` get undefined/false. Documented (form/states.md:100-101), still an API wart.
- `hideLabel` means different things: TextField.tsx:28-38 drops the label node and uses `aria-label`; BrowseField.tsx:32-39 keeps a visually-hidden `<label>`. Both accessible, but same prop name, two mechanisms.
- NumberField steppers silently no-op when `value` is a string (NumberField.tsx:30, 40) — `value` is `string | number` per InputHTMLAttributes.

## 4. Test honesty — 8/10

**Evidence (good):** the jsdom/CSS-stub limitation is honestly documented up front (Button.test.tsx:7-16; both states.md "Honest gaps" sections) and worked around with `node:fs` CSS-source → token assertions that are actually strict (regex with selector + body, e.g. TextField.test.tsx:64-74). Behavioral coverage is real: aria wiring proven (TextField.test.tsx:20-27 asserts describedby points at the message id), clamp + bounds-disable (NumberField.test.tsx:15-29), roving tabindex (RadioGroup.test.tsx:26-31), wrap-around arrows (SegmentedControl.test.tsx:37-48). No weakened assertions found; snapshots are additive, not theater. 111/111 green.

**Evidence (deductions):** gaps that would have caught real bugs: no test asserts the native input receives `min`/`max`/`step` (would have exposed P2-1); per-option `disabled` untested for RadioGroup/SegmentedControl (only group-level, RadioGroup.test.tsx:47-53); SwatchGroup has **no disabled test at all**; IconButton's `aria-busy` CSS block (button.css:314-317) is untested in the CSS-source suite.

## 5. i18n — 7/10

**Evidence (good):** correct pattern throughout — every label/error/action string is caller-supplied (`label`, `error`, `actionLabel` props; SwatchGroup.test.tsx:45-59 proves localized `options` override defaults). No copy literals in any component except below. states.md:104-105 records the wiring decision.

**Evidence (deductions):** **"ON"/"OFF" are hardcoded English literals rendered visibly** — Toggle.tsx:41,45 and Switch.tsx:42,46. They are `aria-hidden`, but aria-hidden hides them from AT, not from sighted users: a de/fr/es locale still shows English. Contract §4.5 says user-visible strings flow through `useMsg()`; states.md:79 documents the deviation ("label text is not translated") but a deviation is not compliance. Also SwatchGroup's default labels are the raw English ids ("orange", "violet"…) exposed as accessible names (SwatchGroup.tsx:47) — safe only if every screen remembers to pass options.

## 6. Dead code / Solstice remnants — 7/10

**Evidence (good):** grep-verified **zero** Solstice remnants (sunset, tape, keycap, Nunito, `data-backdrop`) in both directories. `secondary` variant alias is API-freeze-required, documented. Old 48px `lg` button retired per states.md.

**Evidence (deductions):** the dead `.lumen-radiogroup__label` rule (§2); the Switch/Toggle duplication (§3) is the big one — two shipped primitives + two CSS blocks + two state tables for one frame control; BrowseField's `if (!disabled)` guard (BrowseField.tsx:54-56) is dead code — the button already carries `disabled={disabled}` so the handler can't fire; IconButton's doc promises a "spinner styling hook" (IconButton.tsx:19-20) that was never built (button.css:314-317 has opacity only).

## 7. A11y implementation — 7/10

**Evidence (good):** exemplary core patterns: `role="switch"`+`aria-checked` (correcting the task card's aria-pressed, documented, Toggle.tsx:13-22); `role="radiogroup"` with roving tabindex and 4-arrow wrap (tested); `aria-invalid`+`aria-describedby` error wiring on all three text fields; steppers are `tabIndex={-1}`+`aria-hidden` because native arrows/Home/End exist (NumberField.tsx:79-80); `accent-color` on native checks; consistent 2px accent `:focus-visible` rings everywhere; visually-hidden-label utility uses the clip-path pattern; prefers-reduced-motion honored. Contrast: the button-family OFF label was deliberately lifted to secondary (button.css:410-412, 4.F4 fix); d2 light-mode contrast remediations are documented with ratios.

**Evidence (deductions):**
- **NumberField bounds are not on the input** — see P2-1: without `min`/`max`/`step` attributes, keyboard users (native arrows) can step out of range while pointer users are clamped: two different contracts for one control, and the advertised "never fabricated out-of-range values" (form/states.md:22-23) holds only for the mouse path.
- `SegmentedControl`'s `invalid` prop is aria-only — no error class in the className compose (SegmentedControl.tsx:66) and no CSS rule; RadioGroup.tsx:66 does add `lumen-choice--error`. Same prop, divergent fidelity.
- The `id` prop never lands on the group element in RadioGroup.tsx:61-69, SegmentedControl.tsx:61-68, SwatchGroup.tsx:82-88 — it only seeds child ids, so consumers cannot `aria-describedby`/`aria-labelledby` the group by id.
- form Switch OFF micro label uses `--color-content-tertiary` (form.css:426) where button Toggle uses secondary — I computed #828282 on #191919 ≈ **4.57:1**, a razor-thin pass (vs 6.0:1 for secondary), and form states.md never records the 4.F4 analysis for its own copy.
- IconButton `loading` shows only a dim (no spinner glyph) — `aria-busy` without a visual pending cue for sighted users.
