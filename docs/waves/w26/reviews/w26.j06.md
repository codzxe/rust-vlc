## 1. Token discipline — 8/10

**Evidence.** Both sheets are token-pure in behavior: every color/radius/
shadow/spacing/font resolves through `var(--…)` semantics; the only runtime
inline styles are computed values (menu pointer coords PlayerScreen.tsx:1103,
progress width StageOverlays.tsx:159 — both contract-legal). Every raw hex in
player.css (:459, :508) and states.css (:296-332, :454-477, :606-627, :782) is
a light-mode "stays-dark canvas" pin carrying a
`stylelint-disable-next-line color-no-hex -- frame: …` marker with frame
provenance and the recorded token-lane handoff (a13/f15) — the picture-frame
rule is a real spec constraint, not an excuse. Structural px are each labeled
`/* structural */` with frame math (@1920 ×0.75). ESLint `semantic-tokens-only`
green; stylelint green.

**Deduction.** ~20 raw-hex light pins exceed the *letter* of contract §4.4
("raw hex ONLY in tokens.json and SVG ports") — a documented, temporary
deviation, but the longer the stays-dark canvas token stays unlanded the more
pins accrete (hero, scrim, home, browse, preview each re-pin the same five
values). Minor: the `--color-stroke-icon` in-subtree remap trick
(player.css:310-312, :512-514) and the preview card reaching into
`.lumen-slider__*` internals (states.css:697-726) bend the token system to
restyle owned-by-others chrome.

## 3. React quality — 6/10

**Evidence (good).** Honest decomposition for a component this size: module-
level pure builders (`canvasMenuEntries`, `canvasTrackSubmenu`,
`acceleratorOf`), satellite components (`PlaylistsDock`, `MediaSurface`,
`NowPlayingMark`, `PanelRegion`, `NavigationSeam`), per-open dialog mounts,
context value memoized (context.tsx:424), reducer+WeakMap cache in the bridge
(no stale-closure class of bugs), every effect cleans up (verified listener by
listener), keymap-driven behavior from DATA never hardcoded strings, and the
`.at(-1)` demo-transport ordering trap is documented with a pinned test
(PlayerScreen.tsx:697-708).

**Deductions (the hotspots).**
- **J06-1 (P1):** every `pointermove`/`pointerdown`/`keydown` while armed
  calls `setActivityNonce(n => n+1)` (useChromeAutoHide.ts:152-155) — a state
  update **per mouse event** in PlayerScreenInner's fiber, re-rendering the
  largest component tree in the app (ControlBar, dock, canvas, menu entries)
  at pointer-event frequency (60-120/s during ordinary mouse movement). No
  `React.memo` anywhere under `screens/player` (grep-verified). The nonce
  only needs to restart a timer — a ref-held timestamp + imperative
  `clearTimeout/setTimeout` (or a throttled nonce) achieves the fix with zero
  renders.
- **J06-2 (P1):** `pendingToggle` is set true on play/pause
  (context.tsx:286-297) but cleared **only** by `session.state-changed`
  (:344). The dispatch error path (:246-251) and transport-failure catch
  (:264-274) patch `lastError` and return without clearing it — a failed
  pause (engine error or host unreachable) leaves the transport control
  showing a perpetual pending spinner, violating doc 08 §5.1's "≤250 ms
  pending" truthful-pending contract. No test covers the error path.
- **J06-3 (P2):** the keydown effect's deps include the unstable `chrome`
  object (PlayerScreen.tsx:844) — `useChromeAutoHide` returns a fresh object
  literal per render (useChromeAutoHide.ts:167), so the window listener is
  removed/re-added on *every* render (which, per J06-1, includes every mouse
  move and time-tick). Destructure `visibility`/`show` or memoize the return.
- **J06-5 (P2):** `conditionCtx` mixes truth sources (PlayerScreen.tsx:846-853):
  `hasMedia` derives from engine truth (`derivedMedia`) but `hasVideo`/
  `hasChapters` read the raw `media` prop — a custom layout with
  `visible_when = "has-video"` never shows its region when the *engine*
  (not a host prop) reports video. Latent (default layout uses only
  `has-media`) but a real seam inconsistency.
- **J06-7 (P2):** browse grid keys are the item *name*
  (states/PlaylistBrowse.tsx:134-135) — duplicate filenames in a saved
  playlist (names-only store data, no uniqueness guarantee) collide.
- **J06-11 (P3):** the dialog trio (Goto/Bookmarks/Customize) is rendered
  twice — miniplayer branch (PlayerScreen.tsx:905-916) and main branch
  (:1152-1167) — duplicated mount blocks that will drift.
- **Decomposition verdict (asked for, honest):** PlayerScreen.tsx is 1,517
  lines because ~350 lines of self-contained canvas-menu subsystem (its own
  catalogs, keymap map, builders — :155-500) and the 210-line PlaylistsDock
  live in the screen file. Both are extraction-clean (zero screen-state
  dependencies beyond props). The inner component itself (~610 lines, 13
  hooks) is at the acceptable edge — every hook is small, commented, and
  correctly cleaned up — but it is the ceiling; the next feature (hide-UI
  surface, Record wiring) must not land in this file.

## 5. i18n — 8/10

**Evidence.** Every user-visible string flows through `useMsg()`/lane
resolvers — zero raw JSX literals (linter-enforced and grep-confirmed). The
lane-key seam is honest *and* already converged: the Lead registered
`player.dock.*`, `player.browse.*`, `player.preview.*`, `player.home.*`,
`player.canvas.menu.customize-interface/hide-playlists/show-playlists` in
messages.ts (verified :1176, :1221-1328, :2309+, :2607+), so the resolvers'
`?? catalog` fallbacks are now belt-and-braces, rendering identically before/
after merge as designed. Dynamic strings (track names, titles, folder chips,
error messages) correctly render as *values*, never re-keyed. Pseudo-locale
chain intact through the resolvers.

**Deductions.** The resolver pattern is implemented **four separate times**
with four shapes: the inline triple-catalog chain (PlayerScreen.tsx:1093-1094),
PlaylistsDock's `tm` (:1247-1248), PlaylistBrowse's `useLaneMsg`
(states/PlaylistBrowse.tsx:51-56), HomeOverlay's `tm`
(StageOverlays.tsx:420-421) — one shared `useLaneMsg(...keys)` helper in i18n/
kills three copies. The `m(key as MessageKey)` cast lies about the `Msg` type
(messages.ts:2918 returns `string` but yields `undefined` for unregistered
keys — the `??` compensates at runtime); typing `Msg` as `string | undefined`
would make the seam sound without a cast. Dead pre-i02 keys
`player.canvas.menu.show-queue`/`hide-queue` remain registered
(messages.ts:880,888 — Lead-owned file; log for cleanup).

## 7. A11y implementation — 7/10

**Evidence.** Strong foundations: canvas is a labelled `role="region"` with an
sr-only honest placeholder note (PlayerScreen.tsx:987-1002); a
screen-reader-only `<h1>` is always present (:964); the `<video>` surface is
`aria-hidden` with a documented double-announce rationale (:1444-1447);
progressbars are honest (`aria-valuenow` only when determinate,
StageOverlays.tsx:146-163); failures are `role="alert"`, transients
`role="status"` (StageOverlays.tsx:98-129); menu follows the WAI-ARIA
keyboard model (focus-on-open pinned PlayerScreen.test.tsx:841, Escape
restores focus, outside-pointerdown dismiss without focus theft
PlayerScreen.tsx:636-649); the dock's mode cluster carries `aria-pressed`/
`aria-expanded`/`aria-controls` for the revealed search
(:1315-1347); reduced-motion honored in both sheets; keyboard shortcuts
(F/ESC/I/Ctrl+T/Ctrl+E/Ctrl+A) all tested.

**Deductions.**
- **J06-4 (P2):** the canvas context menu — 14 rows carrying the *only*
  route to "Customize interface…", Hide-UI, and the track submenus — opens
  exclusively via `onContextMenu` (PlayerScreen.tsx:991-997). There is no
  ContextMenu/Shift+F10 binding anywhere in the player keymap (keymap.ts
  grep: no context-menu action; `PLAYER_SHELL_KEYMAP` kinds verified
  :229-248). Keyboard-only users cannot reach it — contract §7 "keyboard
  reachable" is missed. Fix: a `keydown` handler on the canvas region for
  `key === "ContextMenu"` (and Shift+F10) opening at the focused element.
- **J06-12 (P3):** `tracks.changed` casts `event.trackKind as "video" |
  "audio" | "subtitle"` (context.tsx:386) but the generated union includes
  `"data"` (commands.ts:104) — a data-track change writes a stray
  `selections.data` key; `secondaryAudio` happens to be legal
  (TrackSelections, commands.ts:114). Guard or widen the map.
- P3: the dock duplicates the shell sidebar's `"Playlists"` complementary
  landmark name when both are open (PlayerScreen.tsx:1255) — two same-named
  `role="complementary"` regions in one landmark scan.

**Overall: 7.4 / 10** — **Verdict: KEEP** (with directed fixes).

This is disciplined, unusually well-documented code carrying the app's
hardest seam surface (engine truth, remount cache, portals, four CustomEvent
contracts) with an honest, non-theatrical test suite. It is not free of
rot: the auto-hide nonce fix is correct but bought with a per-mousemove
re-render storm on the app's biggest tree (J06-1), the truthful-pending
contract has no error-path recovery (J06-2), the flagship canvas menu is
mouse-only (J06-4), and the screen file is one extraction away from its
complexity ceiling. Fix the two P1s and J06-3/4/5 in wave K; extract the
canvas-menu module and PlaylistsDock before the next feature lands here.
