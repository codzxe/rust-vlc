## Dimension scores

### 1. Token discipline — **9/10**
Every color is a semantic token; raw hex appears only under
`stylelint-disable color-no-hex` with a `frame:` citation
(variants.css:73-74, 443-444, 497-499, 533-534, 538-539 — the stays-dark
picture-frame surfaces, each logged as a token-lane handoff; customize.css:38-39
well-ink). Frame px values all carry `frame:` comments. Light-theme stays-dark
overrides follow player.css precedent. Dock: nothing — the closest miss is
`#371F06`-as-`--color-accent-tinted` approximations documented at
variants.css:121 (accurate today).

### 2. CSS architecture — **9/10**
Zero `!important`; stylelint green; no dead rules found (every class
cross-checked against JSX: `.lumen-playlist__empty`, `.lumen-toolbar-items__*`,
sr-title/note all resolve). The two documented composition seams
(`:has()` shell-sidebar suppression variants.css:415-417; `:has(>` scrim
neutralization customize.css:54-56) are narrow and cited. The
dead-selector regression class (strip portal) is guarded by the dual-anchor
band rule (variants.css:632-637) + CSS-rule pin tests. Only nit: the band
chrome rule's dual anchor is redundant (both selectors hit the same portal'd
element) and the tick-field rules (562/591/618) rely on the footer's own
`data-variant` — correct, but a comment already says so; fine.

### 3. React quality — **7/10**
Hooks are correct (rules-of-hooks respected via the NavigationSeam split,
toolbarItems.tsx:268-287); engine truth never optimistic; per-open mount for
the modal. Deductions:
- **P2-1** MiniPlayer.tsx:386-432 — 45-line inline duplicate of the
  generalized enqueue seam (above).
- **P2-3** toolbarItems.tsx:226-240 — real-bar cycle tiles (Playback speed,
  Zoom) compute `cycleArgs(control, null)` per render and never subscribe to
  completions/events (the box half does, CustomizePanels.tsx:171-246), so
  repeated clicks dispatch the same default-based args forever (rate stuck at
  1.25). Shuffle/repeat escape via the playlist context; rate/zoom do not.
- Micro: `useLaneMsg`/`useStageMsg` allocate a merged catalog object every
  render (MiniPlayer.tsx:87, MusicMode.tsx:70); MiniQueue rebuilds
  sources/addEntries even while the popup is closed; `Number("") === 0`
  slips past the `Number.isInteger` guard in onRowDrop
  (MiniPlayer.tsx:441-443); toolbarItems.tsx:115-255 map body is mis-indented
  (6-space); no memo on MiniQueue (fine at this scale, noted).

### 4. Test honesty — **8/10**

### 7. A11y implementation — **7/10**
The wave-I fixes are present and tested: Dialog focus trap + opener restore
(Surface.tsx:75-124), Save focus moved to the in-dialog ✕ before the disable
commits (CustomizePanels.tsx:517-522; tested at
CustomizePanels.test.tsx:639-678), the focusout keeper pulling dead BODY
focus back (CustomizePanels.tsx:342-358, tested at 666-678), sr-only h1 on

leaves the a11y tree (opacity, not display; variants.css:162-179). The
DOM-truth overlay lock covers open menus/dialogs incl. the customize modal.
Deductions:
- **P2-2** MiniPlayer.tsx:524-552 — the mini queue renders `role="listbox"`
  whose container has no tabIndex and whose `role="option"` rows are plain
  divs: no keyboard focus, no Enter/Space activation of `playItem`, and
  reorder is HTML5-DnD-only (mouse). The customize box got its keyboard-safe
  path (click/Delete/Alt+Arrows); the mini queue never did. The full panel's
  VirtualList does this right (viewport tabIndex=0) — reuse that grammar.
- aria-label on generic `<span>` slots is a no-op for AT
  (CustomizePanels.tsx:782, 834, 843, 848) — give them a role or drop the
  attribute (P3-9).
