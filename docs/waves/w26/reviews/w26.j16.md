## Dimension 3 — React quality: **6/10**

The architecture is genuinely good — an external-store wizard state
(`useSyncExternalStore`, onboardingState.ts:107-117) with a swappable persistence seam,
corrupt-store-total hydration, a derived 8-step state machine with clamped navigation
(:672-673), and honest per-step components. But there is one functional P1 and a cluster
of P2s:

- **P1 — the subtitle-languages field eats its own separator (controlled-input
  normalization loop).** `value={languageList.join(", ")}` + an onChange that splits /
  trims / filters empty (OnboardingScreen.tsx:418-431). Typing `en,` normalizes the
  draft to `["en"]`, the re-render hands the input `"en"`, and React's controlled-input
  sync reverts the comma the user just typed (the same reverts trailing spaces). A user
  **cannot type a second language** — only pasting a complete `"en, de"` string works
  (a single change event survives the round-trip). The field is also untested, which is
  why this shipped. Fix: keep a local raw-string state while focused (or an uncontrolled
  input hydrated from the draft), parsing only on blur/submit.
- **P2 — the default-rate NumberField writes unclamped, out-of-schema values.** The
  free-text path does `Number(event.target.value)` → `setValue` with only an
  `isFinite` guard (OnboardingScreen.tsx:382-385): clearing the field persists
  `playback.default-rate: 0` (schema min 0.25, schema.ts:1017), typing `9` persists 9
  (max 4), and `AutoApplySettings` commits each intermediate keystroke to the overrides
  store. The NumberField's own steppers clamp (NumberField.tsx:26-31) — the wizard's
  onChange must too, and the schema bounds are already imported (`min`/`max` are passed
  to the field but never enforced on write).
- **P2 — ShortcutsScreen's `useMemo`s are defeated by an unstable dependency.** `useMsg`
  returns a fresh closure every render (messages.ts:2913-2919 — no `useCallback`), so
  `ordered` and `visible` (ShortcutsScreen.tsx:377-381, deps `[groups, m]` / `[ordered,
  m, query, scope]`) recompute on **every render**, not just on query/scope change:
  every keystroke re-maps labels over 146 rows, re-runs the numeric-aware sort and
  refilters — then re-renders all rows (no row memoization). The 30s jsdom timeouts the
  test file carries (ShortcutsScreen.test.tsx:49,63,230) are corroborating evidence of
  the render weight. Fix: memoize `m` in `useMsg` (one-line, benefits every consumer)
  or depend on `[query, scope]` only.
- **P2 — OpenMediaDialog never received the w26.i17 first-field focus fix** its two
  sibling dialogs got: the shared trap focuses the first DOM focusable — the ✕ close
  glyph (Surface.tsx:77-79) — so at rest Enter **dismisses** the dialog instead of
  submitting, and a focus ring can paint on the close glyph. Netstream
  (NetworkStreamScreen.tsx:122-124) and shortcuts (ShortcutsScreen.tsx:371-373) both
  add the `urlFieldRef/searchRef` focus effect; open-media has none (no ref, no effect,
  no test). Same family, same fix, missing third copy.
- **P3s:** (1) `AutoApplySettings` + `apply()` run a double `SETTINGS_ENTRIES` scan and
  a synchronous localStorage JSON write on **every keystroke** of the settings steps
  (SettingsProvider.tsx:108-124) — bounded, but a debounce or commit-on-step-exit is
  the right shape; (2) `skip` and `finish` are byte-identical functions
  (OnboardingScreen.tsx:676-683) — collapse them; (3) `nextRequestId` guards nothing in
  any of the three dialogs (onboarding :591-599, netstream :142-155, open-media
  :118-132): the counter increments but no response checks staleness, so a late
  request-1 response can overwrite request-2's notice state; (4) open-media's
  `openSource` fires on every row click — a stray double-click sends two
  `session.open`s.

## Overall

**Mean: (7 + 8 + 6 + 7 + 7 + 8 + 7) / 7 = 7.1 / 10.**

**Verdict: KEEP** (fix-forward). The architecture is the wave's good outcome: an honest
external-store wizard, one settings/theme persistence seam proven at both ends, real
keymap data in both shortcuts surfaces, and dialog semantics done properly in two of
three dialogs. Nothing here warrants a refactor. But the P1 (a first-run field that
cannot accept its own input format) plus the two missing-sibling-fix P2s (open-media
focus, netstream error announcement) and the unclamped rate write are all cheap,
localized fixes that should land before the wave merges — each is a copy of a fix this
same wave already shipped somewhere else.
