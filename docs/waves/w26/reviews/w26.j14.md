## 3. React quality — 7/10

**Evidence (good):** The provider is a genuinely honest state machine — `null` means "engine has not reported" everywhere (PlaylistProvider.tsx:46-58, snapshot seeding :106-131, `feature-not-exposed` flagging :120-126, :181); membership/order/current are event-authoritative (:134-173); commands dispatch through the catalog with S-class applied-state reads (:230-242). Pure queue math is factored into queue.ts and shared by provider + drag + row actions. Virtualized 10k-row render is tested bounded (PlaylistPanel.test.tsx:132-145). `useGridRoving` keeps container-focus APG semantics with kebab keys preserved (PlaylistScreen.tsx:172-215). The "+" affordance (PlaylistPanel.tsx:106-135, 198-229) reuses the shared `useEnqueueSources`/`enqueueEntries` module with `aria-haspopup`/`aria-expanded`, outside-pointer dismiss, Escape + focus-restore — the e12 F8 contract.

**Evidence (deductions):**
- **The enqueue seam is duplicated, not generalized.** `enqueueSources.ts:19-65` exists precisely to generalize the i04 MiniPlayer seam (its header says so), and PlaylistPanel consumes it — but `MiniPlayer.tsx` still carries the full inline copy (~lines 385-431: DEMO_CLIPS mapping, desktop-shell hiding, recentOpenings, location dedup, add-empty/separator/open-media menu shape). ~45 duplicated lines that will drift (they already differ subtly: MiniPlayer's add-empty rides the i04 `t()` lane-fallback, PlaylistPanel's rides the registered catalog `m()`).
- **Per-row O(n) recompute:** each `PlaylistRow` runs `playlist.entries.findIndex(...)` for play-next math (PlaylistPanel.tsx:315-319) while the panel *already* computed `currentIndex` at :141-142 — O(visible×n) per render for data the parent has.
- **Context identity churn:** `actions` useMemo depends on `entries`/`currentId` (PlaylistProvider.tsx:265) only because `playNext` reads them, so every queue change rebuilds actions → the context value → re-renders all consumers (MiniPlayer, panel, rows). A split state/actions context (or a ref for playNext) is the standard fix.
- **`useGridRoving` sync effect has no dep array** (PlaylistScreen.tsx:135-170): a full `querySelectorAll('[role="row"]')` + id/attribute rewrite pass after *every* commit of the host screen, including commits unrelated to the grid (dialog open, subs dialog state). Idempotent and virtualization-bounded, but wasteful; worse, row indices are recovered by parsing `style.top / itemHeight` (:145-147) — a documented-but-real coupling to VirtualList internals that silently breaks (NaN → skipped) if the primitive changes positioning.
- Synthesized `contextmenu` MouseEvent for the kebab (PlaylistScreen.tsx:514-526) and programmatic `.click()` on a class-named menu button (:414-418) are hacky seams; both documented, both fragile against component refactors.

## 7. A11y implementation — 8/10

**Evidence (good):** The wave-I grid model is the real APG activedescendant pattern, not decoration: `role="grid"`/`row`/`gridcell` come from the primitive (Virtual.tsx:105-123, with `aria-rowcount`), ArrowUp/Down/Home/End/Enter/Space implemented with clamping (PlaylistScreen.tsx:193-214), keys from nested kebab buttons deliberately keep their own behavior (:176-178, tested :459-468), the active row paints only while the grid holds focus (playlist.css:618-629), and the choice of activedescendant-over-roving-tabindex is argued in the block comment (:63-80) with the `aria-selected` limitation honestly logged to the list lane. Tests cover the full keyboard contract on both grids including round-trip active-row survival (:442-457) and the media grid's Enter→file-menu seam (:470-484). NewPlaylistDialog: initial focus lands on the title input (NewPlaylistDialog.tsx:54-58, tested PlaylistScreen.test.tsx:332-338), `labelledBy` + `aria-describedby` + labeled file input, sr-only input is focusable (playlist.css:435-442) so the drop zone is keyboard-reachable via focus-within. The "+" popup: `aria-haspopup="menu"` + `aria-expanded` (PlaylistPanel.tsx:203-204), Escape/activation restores trigger focus (:125-128). Queue rows carry an sr-only "Now playing" marker (PlaylistPanel.tsx:361).

**Evidence (deductions):** the dialog focus is a `setTimeout(0)` macrotask race against the shared focus-trap effect ordering (documented StrictMode workaround, NewPlaylistDialog.tsx:50-53) — timing-based, not contract-based; a `initialFocusRef` seam on Dialog would be robust. `aria-selected` pinned `false` on grid rows is a known list-lane seam (arrow movement is focus, not selection — screen readers won't announce a selected row). Grid tests `fireEvent.keyDown` directly on the grid element, never through actual focus + tab navigation, so the "paints only while focused" half of the contract is untested.
