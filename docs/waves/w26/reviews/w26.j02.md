## 1. Token discipline — 9/10

**Evidence.** menu.css is token-pure outside comments: every color is
`var(--color-*)`, every radius `--radius-*`, shadows `--shadow-overlay`, sizes
`--space-*`/`--font-*`. The only two raw hex *values* are the documented
accelerator-seam fallbacks at menu.css:259 and menu.css:266, each carrying
`stylelint-disable-line color-no-hex` + frame provenance + token-seam history
(token `--color-content-accelerator` **is live** in
`ui/src/tokens/generated/tokens.css:36` dark `#6b6b6b` and `:119` light
`#5f5f5f` — verified). Structural px (row pitch, 320px scrollport, 265px
context width, 20px icon slot) are each marked "structural" with frame
provenance per the family header comment. ESLint `semantic-tokens-only` green.

**Deduction.** The fallback hexes are now vestigial (the token resolves in both
themes), so `var(--color-content-accelerator, #6b6b6b)` can silently mask a
future token rename; and the entire light-theme override rule (menu.css:265-267)
is **dead** — see finding J02-4. Not a discipline breach (seam was legitimate
pre-w26.i19), but the seam's retirement was not completed.

## 2. CSS architecture — 8/10

**Evidence.** No `!important` anywhere. No inline static `style=""` — the only
runtime styles are computed pointer coordinates (ContextMenu.tsx:87) and the
clamp-effect mutations (documented as computed/dynamic). Selector graph is
BEM-flat and every class is reachable (`lumen-menu--submenu` consumed by
MenuPopup.tsx:328 + controls.css:764; density variants by Dropdown/MenuBar).
Cascade discipline is explicit (equal-specificity ordering documented at
menu.css:195-196). Stylelint standard config green. Comment density is high but
each block carries provenance that later waves actually used (f07/i16/g17/g19
changelogs inline).

**Deductions.**
- Dead rule: `:root[data-theme="light"] .lumen-menu__accelerator`
  (menu.css:265-267) only swaps the *fallback* of an always-defined token →
  zero effect (finding J02-4).
- The 320px scrollport cap is duplicated in two files with no cross-reference
  constant: `DROPDOWN_LIST_MAX_HEIGHT` (Dropdown.tsx:12) and `max-height: 320px`
  (menu.css:412). Drift risk (finding J02-5).
- `z-index: 10` in two places (menu.css:85, 398) with no layering token —
  hosts already override (controls.css:764 area); minor.

## 3. React quality — 8/10

**Evidence.** The scrollport/flip/Escape rework is genuinely well-engineered:
- **Pointer clamp** (MenuPopup.tsx:97-117): measures in `useLayoutEffect`
  (pre-paint), flips across the pointer, margin-shift fallback; idempotent by
  re-deriving from the `style` prop, never from mutated DOM. Covered by 5
  geometry-pinned tests including the exact e12 F1 repro numbers.
- **Submenu flip** (MenuPopup.tsx:119-139): transform-based so the CSS anchor
  survives; `Math.max(margin - rect.top, vh - margin - rect.height - rect.top)`
  correctly prefers top-in-viewport when both constraints can't hold.
- **Dropdown flip** (Dropdown.tsx:210-227): `clippingBounds` walking to the
  nearest real clipping ancestor (the h15/i16 dialog fix) is the right
  algorithm; `preferredDirection` semantics are honest — preference wins only
  when it fits, measured side otherwise, with 3 tests pinning exactly that
  contract.
- **Listener cleanup is complete and paired**: Dropdown.tsx:139-140,
  MenuBar.tsx:71-72, ContextMenu.tsx:55-56 (pointerdown), Dropdown.tsx:124-129
  (typeTimer), MenuPopup.tsx:142-148 (hover timers), Tooltip.tsx:46
  (clearTimers as unmount cleanup). No leaks found.
- The g17 root-fix comment (Dropdown.tsx:195-205) correctly explains why the
  inline ref callback was a bug; the replacement effect is sound.
- Escape stopPropagation scoping (Dropdown.tsx:255-263) is correct and
  documented with the g19 repro.

**Deductions.**
- `optionRefs`/`itemRefs` arrays are never pruned when the options/entries
  shrink (Dropdown.tsx:114, MenuPopup.tsx:89) — stale trailing entries;
  harmless today (indices always validated) but a latent trap.
- Callback refs are re-created every render (Dropdown.tsx:295-297, 338-340) →
  detach/attach churn per re-render while the list is open; cheap here, but the
  family already knows the pattern (the g17 fix was exactly this class of bug).
- No re-clamp on window resize/scroll for open popups (documented tradeoff for
  Dropdown trigger moves only); MenuPopup pointer popups keep stale clamps if
  the viewport shrinks while open. Edge case, noted.
- `activate()` on a submenu parent (MenuPopup.tsx:190-200) can open but never
  toggles closed on second click — minor UX asymmetry vs the menubar trigger.

## 7. A11y implementation — 7/10

**Evidence (strengths).** Roles are correct throughout (`menubar`/`menu`/
`menuitem{,checkbox,radio}`/`listbox`/`option`/`tooltip`/`separator`); roving
tabindex everywhere; focus is moved into menus on open and **restored** on
Escape/Tab/select on every surface; Tab focus trap (MenuPopup.tsx:228-233);
disabled items focusable-but-inert per APG (aria-disabled + inert activate);
`aria-current` (not aria-checked) for the selected profile — a correct and
unusual-to-get-right distinction (MenuItem.tsx:62, ProfilesFlyout.test.tsx:131-161);
separators skipped; typeahead skips disabled options; Escape scoping via
stopPropagation so host dialogs survive (Dropdown.tsx:255-263); keyboard focus
shows tooltips with no delay (APG). Outside-dismiss never steals focus.

**Deductions.**
- **J02-1 (P2):** Tooltip's `aria-describedby` sits on the non-focusable
  wrapper span (Tooltip.tsx:56) — the relationship is inert; SRs announce
  descriptions of the *focused* element, and focus lands on the child button.
  Tooltips are never announced. Fix: clone the describedby onto the child (or
  render it via a `<TooltipTrigger>`-style prop pass).
- **J02-2 (P2):** Dropdown's `aria-label={label}` (Dropdown.tsx:318) overrides
  the button's content, so the closed trigger's accessible name is "Subtitle
  track" — the selected value ("English") is invisible to SRs. Fix:
  ``aria-label={`${label}: ${selectedLabel()}`}`` or a visually-hidden value
  span outside the label override.
- **J02-3 (P2):** Accelerator ink `#6b6b6b` on `#191919`/`#1f1f1f` ≈ 3.1-3.3:1,
  light `#5f5f5f` on `#c6c6c6` ≈ 3.7:1 — below WCAG AA 4.5:1 for 15px text.
  Frame-pinned and token-owned (menu.css:253-259 documents the deliberate
  rejection of the WCAG-adjusted tertiary); flag to the token lane, not this
  family's call — but a harsh review must record it.
- MenuBar: ArrowUp on a trigger does not open the menu (MenuBar.tsx:86 handles
  ArrowDown/Enter/Space only) — APG menubar says ArrowUp opens and focuses the
  last item (J02-9).
- Dropdown list has no id/`aria-controls` from the trigger (list div,
  Dropdown.tsx:326-334) — acceptable per APG but a cheap add.
- ContextMenu's static `idPrefix="lumen-context-menu"` (ContextMenu.tsx:84)
  yields duplicate item DOM ids across co-existing instances (transient in
  practice thanks to pointerdown-dismiss, but MenuBar's useId pattern is right
  there).

## Verdict: **KEEP**

The scrollport/flip/Escape rework is the best code in the family — correct
algorithms, measured-before-paint, idempotent, honestly tested against the real
repro geometries, with complete listener/timer cleanup and a well-reasoned
`preferredDirection` contract. The ProfilesFlyout store is a clean
useSyncExternalStore seam with genuine app wiring and honest-data tests. The
three P2s are narrow, well-localized fixes (two a11y wiring bugs, one token-lane
contrast ruling); none warrant structural change. Recommended order for the
next touch: J02-1, J02-2 (small React diffs), J02-4/J02-6 (deletions), J02-8
(test backfill for the g19 fix).
