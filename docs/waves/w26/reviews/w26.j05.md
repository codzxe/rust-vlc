   seam.** The mechanism is sound: state-backed host (`ref={setStripHost}`,

   PlayerScreen portals its bottom region when the host is non-null

   player.css:53-60 neutralizes the `.lumen-player` base rules that would

  `.lumen-player` DOM query in the tree is either attribute-filtered
   (`.lumen-player[data-sidebar='open']`, AppShell.tsx:308/341 — the strip host
   carries no data-sidebar, safe) or ordered first-match in tests without the

   `display:flex`; empty → `display:none` on four routes. **But no test anywhere
   renders the provider + a consumer** (P2-2): the only "coverage" is CSS-rule
   string assertions (variants.test.tsx:405-420). A regression in
   stripContext.ts or the provider placement would move the full-window band
   back under the sidebar with every existing test still green.
2. **GatedShell first-run gate (i20) — SOLID.** App.tsx:120-128 wraps the whole
   shell layout (both provideMain groups, 165-186) in `RequireOnboarding` with
   the `?onboarding=1` per-navigation bypass; the gate is route-tree-level, so
   new routes inherit it. App.test.tsx:61-105 walks all 13 shell routes +
   404 fresh-run → wizard, and 141-161 pins the bypass semantics

   is not a11y-complete.** PlayerScreen.tsx:753-758 mirrors

## Dimension scores

### 1. Token discipline — **9/10**
Every color, font, radius, spacing and motion value in appshell.css and
lumen.css is a semantic `var(--…)`; raw hex appears only in comments with frame
citations (appshell.css:14-15,78,198,237; lumen.css:222,234,248,255,265 — all
`frame:` marked, values still token-driven). Raw px is confined to documented
structural geometry (bar height 53, rail width 181, sidebar 248, hits 203-204,
row pitch) per the composition-layer rule; `border-radius: 4px` at 206/231
carries `frame: Icon Wrapper.svg rx=4` citations. shellGlyphs paints from
`currentColor` only. No inline `style=""` anywhere in scope (grep-verified);
`semantic-tokens-only` eslint green. Dock 1: lumen.css §8b's
`color-mix(70% raised, hover)` (line 227) composes tokens but hardcodes the
ratio inline twice — a motion/blend-ratio token would keep the base sheet
composition-only (nit).

### 2. CSS architecture — **8/10**
Clean layering: geometry/state only in appshell.css, surfaces delegated to
Panel/`.lumen-pane` (verified: rail gets `lumen-pane` + `data-edges="end"`).
One `stylelint-disable no-descending-specificity` (481-511) — deliberate,
justified in place (html-level state layer must out-specify base rules),
scoped with enable. No `!important` (grep-verified). No dead selectors found
in appshell.css (every selector traced to a live element, including the
`:empty` strip and `[hidden]` sidebar overrides). lumen.css primitives
(`.lumen-panel/.lumen-row/.lumen-separator`) are used across the tree
(160 refs). Docks: the `body { margin: 0 }` reset lives in appshell.css:30-32
instead of the base sheet that already styles `body` (works only because
App.tsx imports AppShell unconditionally — P3-4); lumen.css §8 reaches into
other lanes' selectors (`.app-shell__rail/__sidebar/__appdot`,
