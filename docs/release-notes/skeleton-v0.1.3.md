# Lumen 0.1.3

Release tag: `v0.1.3`

This is the fourth tagged release of Lumen, a clean-room, from-scratch
reimplementation of a VLC-class media player: a 100 % Rust media engine
(playback state, probing, demuxing, decoding, filters, A/V pipelines,
synchronization, streaming, devices, playlists, subtitles) with a React +
TypeScript UI, an OS-webview desktop shell, and a wasm32 web build of the
same engine.

**The headline: Windows actually works.** In v0.1.2, no local file could
be opened on Windows at all — every path form was rejected. This release
fixes that, and makes the desktop app show its failures instead of
exiting silently.

## Scope (honest — read this before installing)

What this release actually does, per `docs/feature-matrix.toml`
(recomputed 2026-11-15 after the H.264 software-decode landing, w27):

- **38 of 73 format rows** are claimed (implemented or partial) on
  desktop: 14 containers, 7 video codecs, 9 audio codecs, 8 subtitle
  formats. **Zero rows are claimed for the web build.**
- **On Windows (and every OS), opening any local file now works**: by
  path (`C:\x.mp4`, `/home/x/x.mp4`), by `file:` URL
  (`file:///C:/x.mp4`, `file://localhost/C:/x.mp4` — same file, one
  behavior), by drag-drop and by command line. Windows quirks are
  handled (verbatim `\\?\` paths, `/C:/` drive forms) and network-style
  Windows paths (UNC) are rejected with a clear message. (w30.1/w30.2;
  the v0.1.2 defect: no local file opened by any path.)
- **The desktop app no longer fails silently.** If the app cannot start,
  it now says so: a crash log is written under `<tmp>/lumen/`, and on
  Windows (where a GUI app has no console) a native message box explains
  the failure — including the actionable hint when the WebView2 runtime
  is the problem. (w30.6)
- **Playback actually progresses in the app.** The shell now paces the
  engine (~30 times a second), so the position moves, time-ticks flow,
  and playback reaches the end instead of freezing after you press play.
  (w30.7)
- **What still doesn't work, plainly:**
  - **No sound on any OS yet.** The engine decodes and syncs audio, but
    the output backend is not enabled — playback is silent. (The
    honest register: `docs/KNOWN-LIMITS.md` §4.)
  - **The app shows no video yet.** The player surface is an honest
    empty region; the video-display path is built but not connected.
    The `lumen` CLI decodes and renders frames headless.
  - **Network addresses (http/https/HLS) don't play yet.** They are
    refused with a clear message; the streaming engine exists and
    enabling it for playback is the next release's work.
  - **The installer doesn't auto-launch the app.** After installing,
    start Lumen from the Start Menu or the new Desktop shortcut.

## Changes (since v0.1.2)

Generated by `scripts/release/release-notes.sh` — the commit range since
`v0.1.2`. Wave-level summary of what the tree contains at this tag:

- Curated wave summary (user-facing):
  - **Windows: open any local file.** One platform-aware path→address
    conversion replaces six hand-rolled copies; `file:` URLs now open
    through the local-file path; Windows drive/verbatim/UNC forms are
    handled or clearly refused. The six copied constructors and 21 naive
    test helpers were migrated to the one shared constructor, so this
    cannot silently regress per-site. (w30.1/w30.2/w30.5)
  - **A GUI that shows its failures.** Panic/crash information goes to a
    log under `<tmp>/lumen/`; on Windows a native message box with the
    WebView2 hint replaces the invisible exit. (w30.6)
  - **Playback that moves.** The desktop shell pumps the engine on a
    ~30 ms ticker — GUI playback progresses to the end; proven headless
    open→play→pump→Ended. (w30.7)
  - **Launch-proven installers + a Desktop shortcut.** The Windows
    release lane now actually launches what it builds — the extracted
    zip app (10-second survival check, failure receipts on red) and the
    installed app via the MSI upgrade test; the installer leaves both a
    Start Menu and a Desktop shortcut (it does not auto-launch — that
    decision is recorded); the placeholder stub binary is gone from
    every download, and the Linux/macOS launchers start the real app.
    (w30.8/w30.9)
  - **MP4 hardening.** A malformed sample table can no longer request a
    ~1 GB allocation from a 4-byte patch — corrupt tables are refused
    with a clear message; audio tracks that ffmpeg 7 or newer writes as
    raw PCM inside MP4 now play instead of being silently dropped;
    sync-sample lookups are faster (sorted + binary search). (w30.3)
  - **Streaming security hardening** (in the network stack, ahead of
    enabling network playback): credentials are never re-sent over a
    downgraded https→http redirect — the redirect is refused instead;
    digest-authentication parameter escaping fixed. (w30.4)

## Known limits (honest)

The full register is `docs/KNOWN-LIMITS.md`; the release-process
register is `docs/RELEASE.md` §"Known limits (honest register)". The
headlines users will hit:

- **No sound yet, on any OS** — the audio backend is not enabled;
  playback is silent while decode and sync run for real.
- **No video display in the app yet** — the player surface is an honest
  empty region; the CLI renders frames headless.
- **Network addresses (http/https/HLS) are refused** with a clear
  message; streaming playback is the next release's work.
- **The installer does not auto-launch the app** — start from the Start
  Menu or Desktop shortcut.
- **Binaries are unsigned.** No Windows code-signing certificate, no
  Apple Developer ID / notarization (external procurement blockers).
  Windows SmartScreen will warn; macOS Gatekeeper requires
  right-click → Open.
- **Web build: zero claimed rows** — the wasm engine exists and is
  smoke-built, but no format is claimed on web.
- **No updater, no telemetry** (all telemetry settings default OFF).
- Linux arm64 artifacts are best-effort (hosted-runner availability;
  the job is continue-on-error).
- "All formats supported" claims of any kind are prohibited
  (KNOWN-LIMITS §8, R-26) — the feature matrix is the authority for
  what works.
