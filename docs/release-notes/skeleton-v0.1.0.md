# Lumen 0.1.0

Release tag: `v0.1.0`

This is the first tagged release of Lumen, a clean-room,
from-scratch reimplementation of a VLC-class media player: a 100 %
Rust media engine (playback state, probing, demuxing, decoding,
filters, A/V pipelines, synchronization, streaming, devices,
playlists, subtitles) with a React + TypeScript UI and a wasm32 web
build of the same engine.

## Scope (honest — read this before installing)

What this release actually does, per `docs/feature-matrix.toml`
(recomputed 2026-11-10, `docs/audit/docs-sweep-20261110.md` §4.3):

- **37 of 73 format rows** are claimed (implemented or partial) on
  desktop: 14 containers, 6 video codecs, 9 audio codecs, 8 subtitle
  formats. **Zero rows are claimed for the web build.**
- The `lumen` CLI is the real engine surface in this release —
  headless decode, playback state, seeking, A/V sync. Audio output is
  the null backend by default (instrumented with sample/frame counters
  — Devil-Fix wave FX3, 2026-11-25); a real output adapter is admitted
  behind the optional `backend-cpal` build feature (ADR-005, amended),
  compiled by the windows-latest CI lane — and Devil-Fix wave FX4
  (2026-11-26) wired the shipped **CLI host**: the backend factory
  selects the cpal adapter when the feature is on and the volume/
  mute/balance/EQ verbs route to the pipeline controls (FX4-A01/A02;
  `--audio-backend`/`--no-audio` flags, FX4-A06) — while the
  desktop/tauri GUI lanes are pending verification (FX4-A03/A04) and
  audible output on real hardware is [VERIFY] pending the Windows CI
  run of the `audio-cpal-check` lane + a Windows release smoke
  (KNOWN-LIMITS §4).
- `lumen-desktop` is the ADR-004 std-only composition-root skeleton —
  it opens no window; it ships so packaging paths are exercised
  honestly. (Superseded for the shell itself: w28 built and shipped
  `lumen-tauri` — the real tauri app, v0.1.1/v0.1.2 artifacts; its
  frame lane is bounded and instrumented since Devil-Fix wave FX6,
  2026-11-26 — canvas at `ui/src/components/player/MediaSurface.tsx:342`, mailbox drop policy +
  produced/dropped counters FX6-A01, policy-aware ticker FX6-A02,
  bounded channel with overflow counters FX6-A03, UI frame-lane counter
  display FX6-A05 — with a user-watched Windows run still [VERIFY];
  `docs/KNOWN-LIMITS.md` §4. The v0.1.0 artifact itself predates w28.)
- No release has existed before this one; there is no upgrade path to
  test and **no update mechanism ships** (the MSI's frozen UpgradeCode
  makes future MSIs replace this one rather than co-install).

## Known limits (honest)

The full register is `docs/KNOWN-LIMITS.md`; the release-process
register is `docs/RELEASE.md` §"Known limits (honest register)". The
headlines users will hit:

- **Binaries are unsigned.** No Windows code-signing certificate, no
  Apple Developer ID / notarization (external procurement blockers,
  tracked in the wave program). Windows SmartScreen will warn; macOS
  Gatekeeper requires right-click → Open.
- **Audio: default builds render to the instrumented null backend**
  (ADR-005, amended by Devil-Fix wave FX3): the cpal adapter is
  admitted behind the optional `backend-cpal` feature and compiled by
  the windows-latest CI lane; the shipped **CLI host** is wired to it
  since Devil-Fix wave FX4, 2026-11-26 — backend factory +
  volume/mute/balance/EQ verbs (FX4-A01/A02; flags FX4-A06) — while
  the desktop/tauri GUI lanes are pending verification (FX4-A03/A04)
  and audibility on real hardware is [VERIFY] pending the Windows CI
  run of the `audio-cpal-check` lane + a Windows release smoke — see
  KNOWN-LIMITS §4.
- **The desktop binary opens no window** (ADR-004 skeleton —
  `lumen-desktop`, std-only). The tauri shell is real and shipped
  since w28 (`lumen-tauri`), its frame lane bounded and instrumented
  since Devil-Fix wave FX6 (2026-11-26, FX6-A01/A02/A03/A05); the
  user-watched Windows GUI run stays [VERIFY] (`docs/KNOWN-LIMITS.md`
  §4).
- **Web build: zero claimed rows** — the wasm engine exists and is
  smoke-built (`scripts/rc-smoke.sh` check 6), but no format is
  claimed on web.
- **No updater, no telemetry** (all telemetry settings default OFF).
- Linux arm64 artifacts are best-effort (hosted-runner availability;
  the job is continue-on-error).
- "All formats supported" claims of any kind are prohibited
  (KNOWN-LIMITS §8, R-26) — the feature matrix is the authority for
  what works.
