# ui/ — placeholder i18n lint-rule definitions

The React application lands in Phase 4; the files in this directory are placeholder rule definitions, not a working setup — `ui/.eslintrc.json` sketches the `lumen/i18n-no-literals` rule required by doc 07 §6.5 (JSX text nodes, literal string props on presentation components, and literal `aria-label`/`alt` are banned; user-visible text must come from `useMsg()` + a `MessageKey`), `ui/i18n-allowlist.json` is its deliberately empty exemption list (JSON cannot carry comments, so the entry format — including the reason/owner fields each entry must carry, mirroring the Rust-side allowlist in doc 07 §6.5 — is defined when the rule is implemented; choosing an existing community `no-literal-strings` rule vs. writing a small custom one is a Phase-4 `[VERIFY]` decision), and this directory intentionally has **no** `package.json`, so nothing here executes today and `cargo xtask gate` keeps skipping the `ui` lint/typecheck/test steps while catalog-side enforcement is already live in `crates/localization` (the five doc 07 §6.4 audit rules; `cargo xtask l10n-audit` CI wiring is card 1.E2).
