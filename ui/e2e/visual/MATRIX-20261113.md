## Addendum (same day, ~1h later) — the host-parity fix, 4th re-pin

The 2026-11-13 pin above did NOT hold on the runner: CI run 43378741271
failed the PR-lite lane 13/50 — media-info / discovery / convert /
onboarding / not-found / dev-tokens (dark) + player / playlist /
media-info / discovery / convert (light) — while every settings screen
stayed pixel-exact. Same code, same browser build: the differing
variable was the FACE. The k-wave font-asset purge had left the token
stack (`"Inter", -apple-system, "Segoe UI", Roboto, sans-serif`)
unresolved past `"Inter"` on every host — no face was bundled — so each
machine rendered through its own `sans-serif` default, and text-dense
screens diverged (sparse-text screens didn't).

Fix (durable, per the 2026-11-09 record's own guarantee "repo-bundled
type — no host font dependency"): **Inter v4.1 variable is now bundled**
(`ui/src/assets/fonts/InterVariable.woff2`, SIL OFL 1.1, LICENSE.txt
alongside; `fonts.css` `@font-face` with `font-display: block`, imported
first in `main.tsx`). The face travels with the app; `sans-serif` only
matters for glyphs Inter lacks.

Run record (4th re-pin, all with Inter):
- nightly `--update`: **216/216 (7.2m)**
- PR `--update`: 50 (1.6m, prior in-cycle)
- Compare verify: PR **50 passed (1.6m)**; nightly **216 passed (7.1m)**
- On-disk: 216 files, 208 changed vs the pre-Inter pins, 0 orphans.

The [VERIFY] in the Environment table above is now answered: with the
face bundled, the runner is expected to match these pins; the next CI
visual run is the proof. If it still diverges, the residue is NOT font
identity (it is now host-independent) — look elsewhere (render timing,
viewport chrome) before touching tolerance.

## Addendum 2 — wave-L round 3 (2026-11-13, run 43384519508): the residue WAS rasterization

The addendum above bet on "if it still diverges, the residue is NOT font
identity". The next CI visual run diverged: **19/30 PR cases failed at
~0.18% differing pixels** (bar: 0.1%), text-dense screens again, dark AND
light, sparse-text settings screens pixel-exact. Same face everywhere now
(bundled Inter) — so the differing variable moved one level down: glyph
RASTERIZATION. The pinning host's FreeType and the hosted runner's
(ubuntu-latest) hint glyphs differently; Chromium honors host fontconfig,
which made "same font bytes" insufficient.

Fix (browser-level, host-independent): **`--font-render-hinting=none`** on
the visual lane's Chromium launch (`playwright.visual.config.ts`
`use.launchOptions`). Hinting off + bundled Inter + the pinned chromium
build (156.0.8078.4 / playwright 1.64.1) = glyph pixels derive from the
font file alone — same on any Linux host. Tolerance untouched
(threshold 0.1 / maxDiffPixelRatio 0.001).

Run record (5th re-pin, all under the flag, this sandbox):
- PR `--update`: **50 passed (1.9m)**; compare verify **50 passed (1.6m)**
- nightly `--update`: **216/216 (sharded 108+108; 3.9m + 4.7m)**
- nightly compare verify: **216/216 (sharded 108+108; 3.5m + 3.6m)**
- On-disk: **208 baseline files changed** vs the Inter pins.

The next CI visual run is the proof of host-parity. If a residual lane
still diverges, the remaining variable is the chromium BUILD itself
(playwright version drift on the runner) — pin the browser revision in
the workflow before ever touching tolerance again.
