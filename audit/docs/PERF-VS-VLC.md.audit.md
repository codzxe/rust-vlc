## 1. Blunt verdict (document + methodology)

The document is the most honest perf report in the repo and simultaneously the least relevant to its own title. It is honest because it says, loudly and in four places, that **no wall-clock Lumen-vs-VLC timing number exists anywhere** and that every timing figure is vs **ffmpeg 7.1.5 on a shared 2-core sandbox**; I verified both statements against the tree and found no contradicting artifact. It is irrelevant-as-titled because "PERF-VS-VLC" contains exactly zero user-relevant VLC comparisons and zero user-relevant playback measurements: the audio "×realtime" rows are decode-throughput microbenches against a **null audio device** (no output path, no mixing, no underrun risk — the shipped product has no sound at all), the video rows are decoder+RGBA-assembly numbers with a **software compositor** and no presentation pipeline, the environment is `hardware_class = mock` (doc 10 §7.1: mock = VirtualClock, null/software sinks, CI VMs) on a contended 2-core sandbox, and the pipeline-latency numbers are host-measured wall clocks because the v1 event catalog lacks TTF events. The differential-vs-VLC half (§2–§3) is real evidence — recorded artifacts, ratified tolerances, honest 0/6 failures. The §4 timing half is a fallback record that cannot predict anything a user would experience. As the Phase 8 "perf-vs-VLC" gate artifact it is a nullity wrapped in honest labeling. Its factual errors are all staleness: the "h264/hevc: parsers only, no decoder" claims (§4.2 and the §5 summary) were true on 2026-11-10 and are false at HEAD (rust_h264 admitted w27; MP4 H.264 plays end to end — executed), and its §6 tool-run snapshot (64/252, feature-audit PASS) is now 66/61/66 and FAILURE.

## 4. Fabrication/inflation indicators

1. **Title vs contents**: "PERF-VS-VLC" as the Phase 8 gate artifact contains zero VLC performance measurements — the VLC half of the doc is decode-output equality only; the performance half is entirely vs ffmpeg. The title does not misstate this inside the text (§1 is blunt), but the artifact's role in the gate rubric is inflated by its name.
2. **Null-device throughput as product performance**: "every landed audio decoder is comfortably faster than realtime" (§4.1) is technically true and rhetorically empty — with a null audio device there is no realtime audio constraint to violate; the number cannot fail, so it cannot inform. Same class for video: software compositor, no presentation pipeline.
3. **Stale-by-design §6**: the "tool runs executed for THIS document" section quotes a feature-audit PASS that fails at HEAD — the report certifies tooling state it did not re-verify even for its own publication.
4. **No fabrication found in the measured record**: the raw artifacts, per-row values, and loss ratios all reconcile with the committed breadth/corpus files; the failure modes are staleness and relevance, not invention.
