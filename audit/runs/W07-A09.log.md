## Wave-7 hostile question — W07-A09's evidence-based answer

**Q1: Does the AAC-in-MP4 path work end to end in the shipped build?**
YES — decode, NO — sound. Call chain verified + executed: demux/src/mp4/mod.rs:449
(`mp4a`→"aac") + esds blob → apps/cli/src/pipeline_host.rs:288-292 seeded AacDecoder →
aac/decoder.rs#part2 configure (ASC mode, gates: aac.he_sbr/aac.profile/aac.channel_count/
aac.channel_config_pce) → per-packet decode → null device. Execution: baseline INDEX.md
§CORRECTION v2 — sample-aac.mp4 "Buffering → Playing → Stopped"; H.264(4:2:0)+AAC MP4
"PLAYS". The audio tree reachable in the shipped build: pcm (AVI/WAV/MP4 sowt/twos/...),
adpcm (pipeline_host starts_with("adpcm_")), flac, mp3, mp2, vorbis (ogg+mkv lanes),
opus, alac, aac — all dispatched in pipeline_host.rs:241-381 and all compiled (codecs
default features). DEAD in the audio tree: AC-3/E-AC-3 (mp4/mod.rs:451-452 mints
"ac3"/"eac3" descriptors but NO decoder code exists anywhere in crates/codecs/src/audio/
— falls to cli.codec_unavailable), TrueHD/MLP and MIDI (zero code, zero descriptors).
engine-info's "decoders: mjpeg, pcm_s16le" is a hard-coded literal that under-reports
(baseline standing defect) — do not use it as ground truth. Caveats found by me:
aac/decoder.rs#part2 F-001 (channel-truth trust — silent stale samples IF symphonia's
per-decode spec can disagree; symphonia source absent from sandbox, UNVERIFIED) and
F-002 (zero in-tree tests drive the shipped decode() path — baseline smoke is the only
execution).

**Q2: Is sample-rate conversion / resampling correct where it exists?**
There is NO sample-rate conversion in the shipped build. The only resampler is
`MicroResampler` (crates/audio-engine/src/resample.rs — W07-A02's assignment), a
±1000 ppm DRIFT-correction device (resample.rs:51-53 "device-vs-nominal ratio"),
installed per-channel at pipeline construction (pipeline.rs:130) and driven by the
drift governor — not a 44.1k↔48k converter. The shipped pipeline runs AT the source
rate (open_audio_session(channels, rate) → PipelineSpec{rate}) into the null device,
which accepts any rate, so no cross-rate path is exercised anywhere in baseline.
Correctness of the micro-resampler itself: out of my scope (W07-A02); my channel_map
audit establishes the routing feeding it is identity-only. A real audio backend will
need a true rate converter that does not exist yet (pipeline.rs:22: "the micro-resampler
is a later card" — drift only).
