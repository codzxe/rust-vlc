- HOW DOES A USER HEAR SOUND? They cannot, in any shipped build. The `lumen`
  CLI renders decoded audio into the null device's scratch buffer and drops it
  (host.rs:613-617: `let mut buffer = vec![0.0_f32; RENDER_QUANTUM*channels];`
  → `device.render(&mut buffer)` → buffer dropped); the render's only real
  effect is advancing the sample counter that paces the media clock. No OS
  audio library is linked anywhere (cpal.rs:43 gate false). The only
  potentially audible path in the repo is the browser AudioWorklet JS shim in
  apps/web (unverified in sandbox; not the shipped CLI). engine-info honestly
  advertises `audio.null-device` (baseline lumen-engine-info.txt).
