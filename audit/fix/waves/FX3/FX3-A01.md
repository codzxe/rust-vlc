# FX3-A01 — the cpal admission change (Route A, FIX-PLAN §3 F1.1)

## Approach

The assignment is the crate's own flip-point discipline (old cpal.rs
doc, lines 1–16) run to its end state: the admission change is **one
unit** — flip the gate const, land the real adapter behind
`cpal_backend`, delete the compile-time `assert!` gate + the refusal
arm + the `BackendNotAdmitted` marker, all in the same change. The
executed shape mirrors the ADR-011 precedent verbatim
(`crates/streaming/src/schemes.rs`: https admitted → seam vocabulary
deleted → acceptance pin that makes re-introduction fail loud):

- **Cargo.toml**: `cpal = { version = "=0.18.2", optional = true }`
  (pinned exactly, per the P0 record) behind
  `[features] backend-cpal = ["dep:cpal"]` — the repo's house style
  (codecs' codec-* gates). **No `default` feature**: the default
  dependency set stays workspace-internal (toml-parse-verified below),
  so default builds resolve nothing new; the workspace lock is NOT
  touched (orchestrator refreshes centrally, per the assignment).
- **src/cpal.rs** (full rewrite): under `#[cfg(feature =
  "backend-cpal")]`, the real `CpalBackend` implementing the crate's
  `AudioBackend` trait — enumerate (a constructor-time device
  snapshot with redacted `DeviceDesc`s), open (validate the
  interleaved-f32 shape → negotiate against the device's own
  supported-config table → build the `cpal::Stream` → `play()`:
  open IS the playing state), pause/resume (`Stream::pause`/`play`
  plus the shared pause flag, ordered so the counter freezes the
  instant a pause lands), `clock_source` (the crate's own
  `SampleCounter` — cpal has no position API on all hosts, P0 record
  R6), `underruns` (the crate's atomic), and the pump-side
  `AudioSink::write`/`latency` over the crate's `SpscRing` (the null
  sink's zero-heap-traffic byte-refill discipline, mirrored). **The
  device callback body is `render_into` verbatim** — the ADR-005
  conformance plan's clause 2 ("the adapter installs render_into as
  the cpal callback unchanged"): ring read (≤2 segments), silence on
  underrun, one counter advance, one underrun count; nothing else —
  no locks (shared state is single-word atomics), no allocation, no
  logging, no syscalls. The error callback counts, never logs
  (`stream_errors()` surfaces it). Under `#[cfg(not(feature =
  "backend-cpal"))]`, `cpal_backend()` returns the **null backend**
  (byte-compatible default/headless behavior). `AUDIO_ADR005_ADMITTED
  = true` (decision truth) plus the new `cpal_linked()` (build truth,
  `cfg!(feature)`) — closing the audit's "admission state
  unqueryable" gap (cpal.rs.audit.md §7).
- **lib.rs**: re-exports lose `BackendNotAdmitted`, gain `cpal_linked`
  + (feature-gated) `CpalBackend`; `builtin_backends()` puts the
  real adapter first **only under the feature** (its own enumerate
  tells the device truth; empty is honest), staying
  null-then-stub — exactly today's list — with the feature off.
  Module docs rewritten to the amended record.
- **stub.rs / device.rs**: doc-truth updates only (the stub is no
  longer "the placeholder until ADR-005 lands platform-* adapters" —
  the adapter lives in this crate behind the feature; the stub keeps
  the typed refusal slot for feature-off builds; stable error code
  `audio.os_backend_pending` unchanged).
- **tests/pcm_pipeline.rs**: the old seam test
  (`the_cpal_seam_refuses_with_the_typed_marker`) pinned the deleted
  marker and would not compile; replaced by the ADR-011-style
  acceptance pin `the_cpal_seam_is_admitted_and_constructs_a_backend`
  (const-asserts the flag true; the default build's answer is the
  null fallback).

## Assumed cpal 0.18.2 API surface (the compile oracle's checklist)

Per the assignment ("ground every cpal API call in the recorded
notes; note any API surface you had to assume — the Windows CI lane
is the compile oracle"). The P0 record R6 + the spike R6 ground:
the `Stream` data-callback receiving `&mut [f32]`, pause/resume,
default-device selection, device enumeration, no position API.
Beyond that, the adapter assumes (all from the 0.15→0.18 lineage,
none verifiable in this sandbox):

1. `cpal::default_host() -> Host` (infallible);
   `HostTrait::output_devices()` — an iterator whose **item is
   `Device`** (not `Result`).
2. `DeviceTrait`: `name() -> Result<String, _>`,
   `supported_output_configs() -> Result<Vec<SupportedStreamConfigRange>, _>`,
   `default_output_config() -> Result<SupportedStreamConfig, _>`,
   `build_output_stream(&StreamConfig, FnMut(&mut [f32],
   &OutputCallbackInfo) + Send + 'static, FnMut(StreamError) +
   Send + 'static, Option<std::time::Duration>)` — the 4-arg
   (timeout) form introduced in 0.15.
3. `SupportedStreamConfigRange`: `channels() -> u16`,
   `sample_formats()` (contains `SampleFormat::F32`),
   `min_sample_rate()/max_sample_rate() -> SampleRate`.
4. `SupportedStreamConfig::config() -> StreamConfig`; field shapes
   `StreamConfig { channels: u16, sample_rate: SampleRate(u32),
   buffer_size: BufferSize }`, `SampleRate(pub u32)` (`.0` access),
   `BufferSize::Default`.
5. `StreamTrait::play/pause(&self) -> Result<(), _>`;
   `Stream` is not assumed `Debug` (manual `Debug` impls on
   `CpalBackend` avoid that class of assumption entirely).

## Risks & followups

1. **Gate blocker, one line, not mine to land** (hard rule: outside
   my assignment; no FX3 row lists it — surfaced for the
   orchestrator): `boundaries.toml` `[crates.audio-output]` still
   has `external_allowlist = []`. The arch gate
   (`tools/xtask check_architecture`, manifest-table scan —
   optional or not) will report an EXTERNAL violation for `cpal`
   until the row gains `external_allowlist = ["cpal"]`. FX3-A02's
   landed paperwork (deny.toml, doc-11 allowlist, ADR) does not
   cover boundaries.toml. **Required companion edit, same wave
   commit.**
2. The feature-on code is compile-oracle-only so far: FX3-A07's
   lane runs `cargo check`, not `cargo test -p audio-output
   --features backend-cpal` — the ON-lane tests above are compiled
   and executed only when the lane (or a follow-up) runs that
   command; extending the lane is a one-line follow-up.
3. cpal API assumptions above (esp. `output_devices()` item shape)
   may need a mechanical fix on the first Windows compile — the
   fallback is small and localized (the `enumerate()` snapshot loop
   + trait imports).
4. Platform honesty: hosts without native stream-pause (ALSA) get a
   typed `audio.device_pause_failed` while the session degrades to
   silence (flag first, stream second — recorded in the code); the
   lockfile graph / RustSec refresh at admission is FX3-A02's
   recorded `[VERIFY-P1]` set, to be re-run by the orchestrator's
   central lock refresh.
5. Format-matrix/product.toml truth for the new feature surface is
   FX3-A08's row (docs) — `cpal_linked()` now exists for them to
   cite.
