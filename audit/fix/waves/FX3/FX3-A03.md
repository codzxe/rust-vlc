# FX3-A03 — the dead audio-controls surface, engine side (FIX-PLAN §3 F1.1c)

## Approach

The audit proved all the machinery existed and nothing called it: `Gain`,
`Mute`, `Balance`, `Eq3Band` (real RBJ biquads) had zero production callers;
the mixer sat permanently at `UNITY`; `audio.set-volume` was refused by every
shipped host. The shipped chain today (read in `apps/cli/src/pipeline_host.rs`,
read-only): `open_audio_session` → `AudioPipeline::new(PipelineSpec{tracks:1})`
→ `AudioLimb::stage` → `process → mix → take_output → NullSink`, controls
never touched.

**One premise drift, noted per the honesty contract:** the assignment assumed
"the crate surely has a control channel pattern" and "testkit has
deterministic NCO tone plans". Neither exists: audio-engine is std-only with
no threads and no channels (lib.rs "# Never"), and its actual control idiom is
**direct setters with typed validation, called between quanta** — the
`set_volume` / `set_drift` / `set_channel_map` discipline. `AudioControls`
mirrors exactly that idiom. testkit carries no signal generators (Must-asserts,
alloc counting, fixtures only), so the tests follow the crate's real
convention: inline deterministic integer-period sine generators + settled-tail
RMS/peak probes (eq.rs's own discipline).

The fix: a new `AudioControls` (the *session master chain*) owned by
`AudioPipeline`, run over the **mixed** quantum between the mixer (stage C) and
the drift seam / stage D — the effect machinery's first streaming
instantiation. It owns the concrete stage types and reuses their
`AudioEffect::process` implementations verbatim (no second DSP; a boxed
`EffectChain` would hide the parameters a runtime update must reach —
documented in the module docs). Stage order fixed by design: gain → mute →
balance → EQ.

**Zero behavior change when uncontrolled** (the acceptance bar): a fresh
chain is UNITY / not muted / no balance / no EQ, and `process` early-outs
without touching one sample — no loop, no allocation (the quantum
zero-allocation proof and every existing pipeline test keep holding
untouched). Runtime updates are a field swap (volume, mute) or an in-place
biquad coefficient recompute with **preserved filter state** (EQ) — never a
pipeline rebuild; the controls are read at `mix` time, so a host calling a
setter between quanta changes the next quantum.

## Test design

Integration (`tests/fx3_a03_master_chain.rs`, pure engine-level, no device):
- `fx3_a03_volume_changes_output_amplitude` — exact f32 halving (0.5 → 0.25)
  on the same pipeline, then UNITY restores the bit stream.
- `fx3_a03_mute_zeroes_output` — every sample exactly 0.0, frame count
  conserved (mute is silence, not a skip); unmute restores the exact prior
  bytes.
- `fx3_a03_eq3_attenuates_sine_at_band_center` — a 1 kHz sine (the mid peak's
  exact center) through −12 dB mid settles at ×10^(−12/20) (±5%, eq.rs's own
  tolerance); the reference is the same pipeline's uncontrolled quantum, so
  s16 quantization cancels in the ratio.
- `fx3_a03_balance_shifts_l_r_energy` — hard-left keeps L (0.8/√2 RMS) and
  silences R; p=+0.5 splits L/R by the constant-power law (cot 67.5°).
- `fx3_a03_eq_updates_apply_between_quanta_without_rebuild` — ONE pipeline
  binding across two EQ regimes (−12 dB → −6 dB): the settled ratio is the 6
  dB delta; this is the "without rebuilding" pin.
- `fx3_a03_uncontrolled_chain_is_bit_exact_unity` — a fresh pipeline vs one
  whose controls were exercised and returned to identity: byte-identical
  quanta and the exact pre-FX3-A03 values (the zero-behavior-change bar).
- `fx3_a03_control_validation_is_typed` — `audio.effects_balance_position`,
  the mono-session balance gate (`audio.effects_balance_channels`), the EQ
  band bound and the 8 kHz low-rate cliff (`audio.effects_eq_params`), and
  `Volume::from_db(771) → audio.gain_db_overflow`.
- `fx3_a03_getters_report_the_live_config` — read-back of every set/clear.

Unit (crate convention, inline `mod tests`): `controls.rs` ×4 (identity
no-op bit-exact; volume→mute→balance order; flat-EQ bit-exact + getter
tracking; typed validation incl. the balance stereo gate at process time);
`eq.rs` ×2 (`set_bands` recomputes with the state kept — 12 dB delta on the
same filter; the ±40 dB bound typed and fail-atomic); `volume.rs` ×1 (the
from_db overflow pin). All named `fx3_a03_*`.

## Risks & followups

1. **The host wiring is still the long pole**: no shipped host calls the new
   surface yet (that is FX3-A01/later waves' `AudioLimb`/verb work — by
   ownership). Engine-side the knob turns; user-side remains until wired.
2. `Balance` center is the pan law's −3.01 dB per channel (the stage's
   documented law), not unity — hosts wanting a no-op center must leave the
   stage absent (the default). Documented at both setter and module docs.
3. Two behavior-tightening guards landed with the control boundary (both
   audit-recommended "what correct looks like" shapes, both pinned by tests):
   `Volume::from_db(≥ ~771) → audio.gain_db_overflow` (W07-A02 F-001) and the
   ±40 dB EQ band bound (W07-A06 F-004). If the orchestrator wants them as
   separate rows they are trivially revertable; I judged them in-scope as the
   control boundary the activation exposes.
4. Pre-existing latent defects intentionally NOT fixed (other rows / noted in
   audit): pipeline mix-error paths' stale-pts/poisoned-staged-counts
   (W07-A04 F-001/002/003); stage-D has no clamp on the live path (W07-A09);
   Eq3Band's fixed 4 kHz corner refuses rate ≤ 8 kHz sessions (W07-A06 F-005,
   now surfaced typed through the new setter).
