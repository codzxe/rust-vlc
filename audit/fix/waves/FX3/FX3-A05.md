# FX3-A05 — null backend instrumentation (FX4 prep: the observable discard)

## Approach

The wave row: "null backend instrumentation: sample/frame counters +
stats accessor (test seam)". The audit's ground truth was "decodes
into null sinks" (null.rs.audit.md F-001: every shipped lane renders
into `NullBackend`; playback = decode → ring → scratch buffer → drop)
— unobservable from outside. The next wave's end-to-end acceptance
tests need counters, so the discard itself now keeps a ledger.

The design follows the crate's own accounting idioms exactly:

- **`SinkStats`** (counter.rs, alongside `SampleCounter`): five
  single-word `Relaxed` atomics — `buffers` (render calls served),
  `frames` (whole sample-frames consumed, the counter's instants
  unit), `samples` (f32 slots = frames × channels), `bytes`
  (interleaved f32 LE = samples × 4), `silence_frames` (the underrun
  subset, so `data_frames() = frames − silence` — the null-backend
  audit's F-002 arithmetic made a field instead of an invariant
  comment).
- **Recording point: driver-side, after the callback** — in
  `NullDevice::render`, immediately after `render_into` returns,
  before capture. This is the crate's documented discipline ("capture
  never runs under the real-time rules"); the RT core (`render.rs`)
  is **not touched at all**, its signature unchanged, so the
  no-blocking contract's callback path gains zero operations.
- **One shared ledger per session**, in the `Shared` state the two
  SPSC halves already share — read via `NullSink::stats()`,
  `NullDevice::stats()`, and `NullBackend::stats()` (Option — `None`
  before open, the `clock_source` precedent; stays readable after
  `take_device`, because it is session state, not driver state).
  All pub, no `unsafe`, std-only atomics (C5).
- Zero behavior change otherwise: it still discards, paused renders
  are still no-ops (they record nothing — nothing was consumed),
  refused writes count nothing, and the returned `RenderStats`,
  capture bytes, counter, and underruns are bit-identical.

No drift: the cited accounting (`Shared.underruns`/`written`,
`SampleCounter`) is exactly where the audit left it.

## Test design

Oracles derived from the audit's recorded facts (null.rs.audit.md §2
"what actually works" and its per-test table: counter counts data +
silence, one underrun event per starved callback, all-or-nothing
backpressure):

1. `fx3_a05_stats_report_exactly_the_pushed_samples` — N = 2 940
   samples (the corpus's 1470-frame stereo tick) through the ring,
   one render back out: ledger reads exactly N samples, N/2 frames,
   N×4 bytes, 1 buffer, 0 silence; halves read one shared ledger;
   ledger `frames` == `sample_count` (agreement with the pre-existing
   counter). Then the trait path: not-open → `stats() == None`;
   paused render records nothing; after resume exactly 1 buffer /
   2 samples / 8 bytes recorded; ledger readable from the backend
   after `take_device`.
2. `fx3_a05_underrun_accounting_is_unaffected_by_stats` — mono, 1
   data frame + starved 3-frame callback: underruns == 1, counter ==
   3 (exactly the audit-pinned semantics), ledger splits 1 data / 2
   silence; second starved callback: underruns == 2, silence 4, data
   still 1; refused writes (partial-frame, ring-full) record nothing.
3. `fx3_a05_concurrent_spsc_producer_consumer_counts_exactly` — the
   documented SPSC split executed concurrently: sink half on the
   producer thread (write/retry backpressure), device half on the
   consumer thread (16-frame quanta), W = 4096 frames, ring 64
   (real wrap churn). Assertions hold for ANY interleaving:
   `buffers == the consumer's own call count`, `silence_frames ==
   the consumer's own per-call sum`, `underruns == the consumer's
   own per-call event count` (the shared accounting proven exact
   under concurrency — no lost atomic updates), `data_frames == W`
   (data conservation), unit identities frames/samples/bytes, ring
   drained, and both halves' post-join ledger views identical.
   Termination: consumer loops until `data_frames == W` (writes are
   monotonic all-or-nothing ⇒ reachable exactly when drained), with
   a 10M-spin assertion guard.

Conventions: `tests/fx3_a05_*.rs` new file (no sibling collisions —
the crate's other suites are separate files); thread joins handled
with the repo idiom `Ok(..) => .., Err(_) => unreachable!(..)`
(clippy `panic`/`unwrap`/`expect` are workspace-denied); no
`#[global_allocator]` here, so no `serialize_tests()` needed
(zero_alloc's discipline is untouched by this file).

## Risks & followups

- **lib.rs coordination (FX3-A01):** my one-line `pub use
  counter::{SampleCounter, SinkStats};` edit sits in the same re-export
  block FX3-A01 edits for the cpal admission — a trivial textual
  merge, but flag it in the wave compile.
- The ledger is **consumption-side only** (recorded in the driver);
  the parked trait-path device records nothing until driven — honest
  (an undriven session consumes nothing), but FX4 tests wanting
  "written" totals should read the pre-existing
  `NullSink::written_frames()` alongside.
- `bytes` counts interleaved f32 LE (samples × 4) — the device
  buffer's byte total; if FX4 ever needs the *decoded-input* byte
  count (e.g. ADTS payload bytes), that is a different unit and a
  different counter — deferred, not silently conflated.
- Threads appear in `tests/` only (the lib.rs audit's "no threads are
  spawned here" claim is about src/ — the crate itself still spawns
  none).
- Not executed in this sandbox (no cargo): the three test oracles are
  derived from the audit-pinned semantics and the crate's own passing
  suites, but their green run is the orchestrator's central compile.
