# FX3-A04 — resampler activation (real 44.1 kHz ↔ 48 kHz SRC)

## Approach

Wave-07's engine map: "Resampler: LINEAR, ±1000 ppm drift-only, NO
44.1→48 conversion (convert.rs contains no SRC; pipeline refuses rate
mismatch) — dormant in shipped build anyway." Ground-truthing before
writing (the assignment's citations drifted slightly, per the honesty
contract):

- `convert.rs` is sample-FORMAT conversion only — its own audit
  (W07-A05) says so ("it contains no sample-rate conversion
  whatsoever; the only resampler in the crate is the ±1000 ppm
  `MicroResampler` in resample.rs"). So the dormant linear resampler
  lives in **resample.rs** (`MicroResampler`, whose module doc itself
  called track-rate conversion "a different, later card") — the SRC
  therefore landed in resample.rs, next to its twin; convert.rs is
  untouched.
- The rate-mismatch refusal is engine-side, not apps/cli:
  `pipeline.rs:288-289` returns `audio.rate_mismatch` in
  `AudioPipeline::process` (apps/cli only builds the spec from the
  first track, `pipeline_host.rs:1786`). Neither is edited — the
  assignment scopes me to "engine capability real + tested", the call
  wiring is a later wave's.

Design: a second type, `RateResampler`, in resample.rs — `MicroResampler`
and its 12 pinned tests are byte-for-byte untouched (drift behavior
preserved exactly, per "keep the existing drift-only linear
behavior"). `RateResampler` clones the twin's proven streaming shape —
linear kernel, exact `i128` cursor + rational fraction carry, one
history sample per channel, prefix/body/exact-tail emission split,
reused output planes — but takes its ratio from the two session rates
(reduced by gcd), so no ±1000 ppm limiter bounds it. Two deliberate
improvements over the twin, both audit-motivated: the phase advance is
a div/mod instead of the twin's subtraction loop (a pathological ratio
cannot spin — the twin's F-003 coupling class), and the geometry guard
covers plane-shorter-than-`in_frames` (the twin's F-002 panic class —
my type refuses with zero output, no panic). Equal rates are a
bit-exact passthrough fast path (a copy — even `−0.0` survives),
so a wiring wave can construct it unconditionally. Zero channel/rate
arguments are the typed `audio.pipeline_shape_invalid` refusal (the
same code `AudioPipeline::new` gives a zero spec).

Honesty (mandated): the module docs and type docs state LINEAR is the
crate's documented fidelity level — at drift-scale ratios (±1000 ppm)
the error stays in the top ~0.1 % of the spectrum, but a macroscopic
ratio shows the kernel's real limits: sinc² rolloff near the source
Nyquist when upsampling, un-pre-filtered aliasing above the
destination Nyquist when downsampling. No higher-quality kernel
invented.

## Test design

All oracles were machine-verified in Python before writing the
assertions (scratch in /tmp only; kernel, count closed-form,
differential, capacity bound, sine spectrum all simulated clean):

- `fx3_a04_sine_44100_to_48000_keeps_ratio_and_spectrum` — the
  headline: 0.1 s of 440 Hz at amplitude 0.5, streamed in 1470-sample
  quanta → output length equals the exact emission-rule closed form
  `⌊4409·160/147⌋+1 = 4799` (no tolerance — the naive duration ratio's
  4800 differs by the one final position whose kernel right-sample
  does not exist); Hann-windowed DFT: the 440 Hz bin dominates every
  off-tone bin (incl. the 140/740 Hz rational-phase modulation
  sidebands) by ≥5× (simulated: 19 000×); amplitude within 2 %
  (simulated: 0.5000; the kernel's sinc²(π·440/44100) ≈ 0.9998).
- `fx3_a04_non_integer_upsample_22050_to_48000_hits_the_ratio` /
  `fx3_a04_non_integer_downsample_48000_to_44100_hits_the_ratio` —
  320/147 and 147/160 over ramps: exact counts, monotone, inside the
  convex hull (the kernel cannot overshoot or fabricate).
- `fx3_a04_one_sample_quanta_carry_the_phase_and_reset_restarts` —
  1-sample quanta stress the tail-prefix at every boundary
  (quantumization must be invisible — sim-proven); then `reset()`
  restarts the phase (first output exactly the first sample).
- `fx3_a04_matching_rates_are_a_bit_exact_passthrough` — equal rates:
  count conserved AND bits identical (`to_bits`, specials incl. −0.0,
  NaN, ±inf — the copy path, proving the arithmetic path was not
  taken).
- `fx3_a04_zero_channels_or_zero_rates_are_typed_refusals` — the
  `audio.pipeline_shape_invalid` contract.
- `fx3_a04_ragged_or_wrong_shaped_planes_emit_zero_not_panic` — the
  drift twin's audit F-002 class done right at birth; non-sticky.
- `fx3_a04_long_stream_ratio_is_exact_with_no_cumulative_drift` —
  1000 × 1470 both directions land the exact closed forms
  (1 599 999 / 1 350 562) — no cumulative rounding, ever.
- `fx3_a04_channels_share_one_phase_by_construction` — the twin's
  coherence proof re-pinned on the rate path.
- `fx3_a04_split_kernel_is_bit_identical_to_a_single_loop_reference`
  — the strongest: an independent single-loop reference kernel (the
  twin's own differential-oracle shape, generalized from ppm to the
  rate pair) over 6 ratios × 2 channel counts × 14 quanta of lengths
  1..1471 with mid-stream reset — bit-identical outputs and counts
  (sim-verified as exactly equal before writing).

## Risks & followups

1. No cargo run was possible (RULES: the orchestrator compiles and
   tests centrally). Compile-verified by inspection and by copying
   compile-proven patterns from the same crate (the twin's exact
   borrow shapes, `testkit::Must` usage); every numeric oracle was
   simulation-verified. The one thing only the central build can prove
   is the f32-bit-level differential — the double-precision simulation
   shows exact value equality, and both kernels evaluate the identical
   expression `a + (b − a) · weight` with identical operands.
2. The wiring card remains: `AudioPipeline::process` still refuses at
   `audio.rate_mismatch` — a later wave must route the mismatched-rate
   track's planes through `RateResampler` (per-track after stage A, or
   session-level before stage D) and translate the output count into
   the quantum pacing. The module doc says exactly this.
3. lib.rs:44's doc line "track-rate conversion is a different, later
   card" is now half-stale (the card exists; the pipeline claim "never
   a silent resample" is still true). lib.rs is outside my file scope —
   left for the FX3-A08 docs pass or the wiring wave.
4. The drift twin's own audit findings (F-002 short-plane panic,
   F-003 hardcoded `/1000` capacity, F-005 doc overstatement) are
   untouched — out of scope, worth one small hardening pass.
5. No zero-alloc counting-allocator proof for `RateResampler` yet (the
   twin has `tests/zero_alloc_resample.rs`); the plane discipline is
   identical (resize + truncate into reused capacity), but if the
   wiring wave puts it on the hot path, a sibling proof is the
   follow-up.
