# FX3-A06 — media-clock SampleCounterSource wiring by open device session (doc 03 §4.9 edge)

## Approach

Survey first (rg over the tree, read-only outside my ownership):

- The trait **exists and lives here**: `crates/media-clock/src/source.rs`
  `SampleCounterSource` (`sample_count` monotonic-while-running,
  `sample_rate_hz`, 0 = unusable), alongside `MonotonicSource` /
  `InstantSource`.
- The **production implementation exists in audio-output** (read-only
  there; FX3-A01/A05 own those files this wave): `SampleCounter` in
  `crates/audio-output/src/counter.rs:84-92` implements the trait;
  `AudioBackend::clock_source()` (`device.rs:127`) returns
  `Option<Arc<dyn SampleCounterSource>>` — the "open device session"
  the audio-output Cargo.toml comment names.
- The clock **already consumes an injected counter**:
  `MediaClock::audio_master(Arc<dyn SampleCounterSource>, ...)`
  (`clock.rs:479`), wired in apps/cli at `pipeline_host.rs:1791`
  (`MediaClock::audio_master(sink.clock_source(), ...)`) — and
  audio-output's `tests/clock_truth.rs` already proves the production
  seam end-to-end over a driven null session. Read-only; no edits
  outside media-clock.

So the pieces existed and construction-time wiring existed. The missing
piece — the one the assignment's "runtime-pluggable" clause names, and
the gap FX4 hits at device re-open / ADR-005 Route-A re-wiring — is
that the truth source is fixed **at construction** for the life of the
clock: a live clock cannot be handed a *new* open session's counter
(the 3.B2 `with_backends` wired-audio slot is also construction-time).
Rebuilding the whole `MediaClock` at re-open loses the session
generation, epoch history, and every held `Arc<dyn PlaybackClock>`.

The minimal missing piece, implemented INSIDE media-clock:
`MediaClock::adopt_sample_source(source) -> Result<ClockSnapshot,
AdoptSourceError>` — a runtime swap of the audio truth source that
reuses `switch_locked`'s atomicity discipline, like-kind (audio→audio):
under one lock, carry the clamped position from the old source, swap
the source, re-anchor against the new source's own current reading
(fresh counter domain — different count and/or rate are anchored, never
extrapolated against the old anchor), carry the paused/ended freeze,
bump the anchor epoch exactly once, and refresh the wired audio slot of
a `with_backends` clock so later `switch_master`/demotions target the
new session's counter. A non-audio master refuses typed
(`AdoptSourceError::NotAudioMaster`) — installing a sample counter onto
a wall/video master would be a silent master promotion, which is
`switch_master`'s explicit business. No `MasterChanged` event is pushed
(from == to == audio is not a master change); the receipt is the
returned snapshot and the epoch bump.

## Test design

1. `fx3_a06_counter_advances_media_time_exactly_with_samples` —
   48 kHz in 2 400-instant chunks: every read exactly 50 ms further;
   44.1 kHz whole-second exactness; rate 5/4 maps 4 counter-seconds to
   exactly 5 media-seconds. `try_now()` agrees with `now()` at every
   step. The position is a pure function of the counter (doc 03 §4.7 e).
2. `fx3_a06_stalled_counter_stalls_the_clock_without_drift` — after
   1.5 s consumed, the counter freezes; 64 consecutive `now()` reads
   are **exactly** equal (tolerance zero — the documented ±1000 ppm
   budget is the absorbers' limiter in drift.rs, never the clock's read
   path), `try_now()` stays `Ok` at the same value, the anchor and
   epoch prove no self-re-anchor; resumption moves exactly one second
   for the next 48 000 instants.
3. `fx3_a06_runtime_source_switch_is_clean` — the FX4 narrative:
   session A (48 kHz) plays 2 s → A's counter regresses (device death:
   clock holds, `try_now` = Discontinuity) → re-open as B (44.1 kHz,
   counter starting mid-domain at 735): receipt carries the position
   exactly, master still AudioOutput, epoch +1, `at_sample` re-taken
   in B's domain; one second of B = exactly one media-second; A is
   dark (its count no longer moves the clock); a second swap (B→C) is
   equally clean; a `system_monotonic` clock refuses typed and is
   unchanged (still wall-driven afterwards).
4. `fx3_a06_adopt_refreshes_the_wired_audio_slot` — a `with_backends`
   clock adopts a new counter, switches away to video and back to
   audio: the switch-back runs on the **new** session's counter (this
   pins the wired-slot refresh — without it the clock would silently
   track the dead construction-time source), and the old source is
   dark.
5. `fx3_a06_unreadable_adopted_source_parks_until_first_reading` —
   adopting a rate-0 source parks the clock at the carried position
   (typed read refuses), the device "finishes opening" at 44.1 kHz, the
   first usable reading anchors with no jump, and consumption resumes
   exactly.

- F1.1 dependency: this is the seam FX4 needs when F1.1 Route A's
  cpal adapter re-opens a device under a live session — no clock
  rebuild, generation/epoch continuity preserved.
- Definition of done (FIX-PLAN §1.4 / RULES): code (additive, no public
  API churn beyond the assigned seam), the regression tests that would
  catch the gap (a runtime source swap previously had NO path — tests
  3–5 fail without `adopt_sample_source` existing), report filed.

**What FX4 must pass in (handoff):** the `Arc<dyn SampleCounterSource>`
from the open device session — i.e. `AudioBackend::clock_source()`
(audio-output, device.rs:127; the null backend's is the FX3-A05
instrumented counter, reachable via pub API from the app layer, not
from media-clock — L2 cannot depend on L4). Recipes: (a) normal open:
`MediaClock::audio_master(session.clock_source(), anchor, rate)` as
apps/cli does today; (b) device re-open/switch mid-session:
`clock.adopt_sample_source(new_session.clock_source())`; (c) if the
clock demoted off audio (master-loss), adopt refuses by design —
rebuild the clock or construct via `with_backends(...).audio(...)` and
use explicit `switch_master` (re-promotion after loss is deliberately
an engine policy card, not this seam).

## Risks & followups

- Compile/test not executed here (RULES: orchestrator compiles the
  wave centrally; no cargo in this sandbox — rustfmt is not installed
  either, so the three files are hand-formatted to the crate's style;
  line widths checked ≤100).
- The old stream's master-loss bookkeeping (lost bitset) is untouched
  by the swap — a re-promotion policy after a demotion remains an
  engine card (documented in the method docs); note that a demoted
  clock refuses `adopt_sample_source`, so FX4 must rebuild or use
  `with_backends`.
- `adopt_sample_source` while paused/Ended carries the freeze (same
  step as `switch_locked`) — traced by hand, not yet test-pinned; a
  follow-up test in the engine wiring card would pin it.
- audio-output's `with_base` offset-carry (audit counter.rs F-002)
  remains production-dead; when FX4 wires real backends it should
  either offset-carry the counter across switches or use this seam —
  both cures now exist.
