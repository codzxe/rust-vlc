# FX9-A01 — the five subtitle verbs, routed

## Approach

The defect (REALITY-SCORE rows 057-068, UNREACHABLE class): the catalog
defines `tracks.set-subtitle-track` (command.rs:166-171) and
`subtitle.add-file`/`set-sync`/`set-encoding`/`set-scale`
(command.rs:302-330, results AppliedSelector/AppliedDelayMs/
AppliedEncoding/AppliedScale at :558/:591/:612/:617), yet `route()`'s
catch-all answered all five with `[command-layer.unsupported-for-host]`
and host.rs had zero subtitle handlers. The fix is the FX4-A02/FX5-A03
audio-verb pattern, one section per layer:

1. **dispatch.rs** — five route arms (the audio verbs' arm shape) plus
   the five ids in `SERVED` (in synopsis order) and the module-doc row.
2. **host.rs** — five `pub(crate)` handlers that apply on the LIVE
   consumer via the pre-agreed FX9-A03 seam (exact names, not renamed;
   the seam is NOT in-tree at my run time — expected, A03 lands in
   parallel; the orchestrator compiles the merged wave):
   - `subtitle_add_file(path, encoding, select)` →
     `subtitle_add_sidecar(path, encoding, select)`; class-A
     `Accepted` per the catalog (spec.rs:441-447: class A, result
     "accepted") — the arrival truth is `tracks.list`'s sidecar row.
   - `subtitle_set_sync`/`subtitle_set_encoding`/`subtitle_set_scale`
     → the seam setters, each answering the seam's own read-back (the
     new absolute total / the applied encoding / the applied scale),
     errors mapped through the file's existing `wire_error` surface.
   - `set_subtitle_track` — the composition: a wire id naming one of
     `subtitle_sidecar_tracks()`' rows selects the SIDECAR lane
     (`subtitle_select_sidecar(Some(id))`, its must-use Result
     surfaced through `wire_error` — never dropped) while the engine's
     embedded lane deselects; any other id/`None`/`Auto` drives the
     ENGINE's `SelectSubtitle` session command
     (`SessionHandle::set_subtitle_track`, session.rs:416-433 — the
     class-S pre-table step, session.rs:148-152/:201) with the sidecar
     lane deselected (one active subtitle lane; the embedded lane runs
     first so an engine refusal leaves the sidecar untouched). The
     answer is the chain's read-back of what is NOW selected — the
     selected sidecar row, else the selected embedded row, else
     `None` — never the echoed request.
   - the engine half rides a new private `submit_subtitle_select`
     (the `dispatch_seek` submit-with-payload shape: allocate,
     `handle.set_subtitle_track`, `await_receipt`,
     Completed/Rejected-mapped, an `Accepted` receipt answered as the
     typed Internal it would be).
3. **track_snapshot** (host.rs:381, was `self.tracks.clone()`) — now
   appends the consumer's sidecar rows (`subtitle_sidecar_tracks()`),
   so `tracks.list` answers the chain's read-back (this is also the
   row source FX9-A06's GUI state feeds from). The embedded rows'
   subtitle flags stay truthful via a new drain-side mirror: the
   engine emits the lightweight `TrackSelectionChanged` confirmation
   (never the full-list `TracksChanged` that refreshes `self.tracks`)
   for every class-S subtitle select, so `drain_outputs` mirrors it
   into the embedded subtitle rows' `is_selected`.
4. **help.rs** — the SERVED/help-synopsis join: one SUBCOMMANDS row
   (machine mode, the audio row's shape) + its `catalog_ids` arm
   parsing to exactly the five ids; the synopsis-count test 20→25.
