# FX9-A04 — Embedded PGS subtitle track lane

## Approach

The defect (REALITY-SCORE row 064, subtitle-pgs UNREACHABLE; FIX-PLAN
§5 F3.1): the Frame vocabulary was text-only — `SubtitleCue.text` a
plain `String` with the bitmap payload deferred as a "Phase 5
vocabulary extension" (frame.rs:189-191) — so `Frame::Subtitle` had
zero producers tree-wide, while the engine side was fully ready
(`WiredKind::Subtitle`, `QueuePlan::for_kind`, `SelectSubtitle`, and
the TS demuxer already minting the `"pgssub"` descriptor for stream
type `0x90` at demux/src/ts/mod.rs:367). No decoder could deliver a
bitmap subtitle event; a TS+PGS file listed a subtitle track nothing
could feed.

Two layers, one contract:

1. **Vocabulary (media-types, L0, no new deps):** extend
   `SubtitleCue` with the pre-agreed OPTIONAL overlay payload —
   `overlay: Option<SubtitleOverlay>` where `SubtitleOverlay` is
   plain data with EXACTLY the A03-contract fields `width: u32,
   height: u32, rgba: SharedBytes, x: i32, y: i32, z: u16`
   (`SharedBytes` = the type the video limbs already use). Text cues
   are unchanged (`overlay: None`); a bitmap cue carries its pixels
   in `overlay` and leaves `text` empty — never both.
2. **Decoder (codecs, L3 → the sanctioned new `subtitles` L2 edge):**
   `codecs::subtitle::pgs::PgsSubtitleDecoder` implements the
   codec-api `Decoder` trait (`configure` + `decode` + `flush`) by
   reducing each TS PES packet through the in-house L2 grammar:
   `PgsDecoder::decode_display_set` (segment framing detected and
   stripped by the `PgsFraming` walk inside that call; the packet's
   PTS rescaled to the 90 kHz carriage base) → `PgsCueBuilder::cues`
   → one `Frame::Subtitle` whose cues are `SubtitleCue::bitmap`
   overlays (bitmap verbatim, x/y recovered exactly from the cue's
   anchor × reference extent, z = PCS object order, span from the
   display-set PTS).

**Timing model — the held display set.** PGS has no explicit end
times; the L2 builder closes a set's span one nanosecond before the
NEXT set's PTS. So the decoder holds each display set and emits it
when the next packet's PTS is known (half-open `[t0, next−1 ns]`);
the trailing set is emitted open-ended by `flush` (then flush stays
`Drained`). A zero-object set with a clean ledger is the
composition's own clear — held like any set; a damaged set with zero
composed objects (missing palette, truncation) is dropped whole and
holds nothing (blank from its PTS on).

**Engine lane semantics — verified and pinned** (assignment item 6):
* A subtitle track **decodes from open time**: `Pipeline::wire`
  (playback-engine/src/pipeline.rs:1051-1092) wires ONE limb per kind
  — the container-default (`TrackFlags::default_on`) else
  first-of-kind subtitle track — at the session generation; the
  subtitle kind is the OPTIONAL kind: a provider that cannot build
  the subtitle decoder deselects that track instead of failing the
  open (pipeline.rs:1036-1040, 1083-1087). Unselected subtitle
  tracks' packets are dropped at push.
* `SelectSubtitle` (`tracks.set-subtitle-track`,
  session.rs:148-152) is **class S**: it resolves the selector over
  `MediaKind::Subtitle` tracks and swaps the (optional) subtitle
  limb at the CURRENT generation — queue-close + decoder-cache
  recycle + fresh queue, no mint, no pipeline invalidation, no
  `state-changed` (the pre-table branch session.rs:1812-1814,
  `subtitle_select_step` session.rs:2221-2326); unresolvable selector
  → typed `TrackNotFound`. The lane is typed from the engine's own
  vocabulary (`WiredKind::Subtitle` tracks.rs:162; `QueuePlan::for_kind`
  total over it, pipeline.rs:386).
* `configure` therefore owes epoch hygiene: the decoder cache recycles
  instances across generations, so `configure` resets the L2 epoch —
  a recycled instance never presents the previous stream's objects.

## Test design

`crates/codecs/tests/fx9_a04_pgs_subtitle_decoder.rs` — an
integration test (RULES def-2: avoids edit collisions; uses only
deps already available: codec-api/codecs/media-types as deps, demux
+ codec_api::contract as existing dev-deps, subtitles via the new
sanctioned dep). Crafted display-set payloads mirror the
`subtitles` crate's own hand-crafted builders (PCS/PDS/ODS/END at
1920×1080, BT.709 studio white), including a `to_sup_framing`
helper that re-frames a stripped set with per-segment 4-byte PTS
prefixes — so BOTH carriage framings of `PgsFraming` are exercised
(the in-tree model's TS-PES PTS-prefixed form and the
Matroska-stripped form), under `PgsFraming::detect`'s deterministic
walk-consumption scoring. House style: `match`/`unreachable!("{e}")`
(no unwrap/expect), the `contract.rs` `configured()`/`packet()`
patterns.

* `…decode_emits_subtitle_frame_with_overlay_geometry` — the happy
  path in BOTH framings: set 1 held (NeedMoreInput, zero frames),
  set 2 emits set 1 closed; pins pts (the set's own), overlay
  geometry (2,2,10,20,0) recovered exactly from the anchor rationals,
  `rgba.len() == w·h·4`, opaque-white pixels, half-open span
  `[0, 999_999_999]`, empty `text`, generation.
* `…overlay_cues_z_ordered_per_pcs_object_order` — PCS lists object
  2 first: z 0/1 follow PCS order (not ODS definition order), each
  cue carries its own placement.
* `…flush_emits_trailing_set_open_ended` — flush emits the held set
  with `end == Stamp::Missing`, then stays `Drained` (no double
  emission).
* `…empty_and_truncated_input_is_typed_damage_never_error` — empty
  payload → `Recovered{1, CorruptInput}`; mid-set truncation and
  garbage bytes → `Recovered`, zero frames, never `Err`; the decoder
  stays usable (clean set decodes and flushes afterwards).
* `…stale_generation_packet_dropped_on_sight` — the contract's own
  `stale_packet_is_dropped_on_sight` helper (mjpeg contract-suite
  precedent) + the no-state-mutation proof: the very next
  current-generation packet decodes through the stale drop.
* `…configure_resets_epoch_for_recycled_decoder` — epoch banks
  populated, then re-`configure` (the recycle): a NORMAL-state PCS
  re-referencing the old epoch's object is typed damage, nothing
  held (flush `Drained` — without the reset it would compose stale
  pixels); foreign descriptor (`h264`) is typed `Unsupported`.
* `…ts_pgs_descriptor_and_engine_lane_semantics` — the interlock's
  machine-checkable halves: `demux::ts::TsStream` for stream type
  `0x90` mints descriptor `pgssub` + `MediaKind::Subtitle`; the
  decoder accepts exactly that descriptor and a `Frame::Subtitle`
  with an overlay cue flows out. The L4 engine semantics (which
  tracks decode; what SelectSubtitle gates — see Approach) are
  pinned by citation in the test docs with file:line references
  (playback-engine is not importable from an L3 crate test — the
  boundary manifest allows only codec-api/media-types/subtitles as
  internal deps).
* `…discontinuity_resets_epoch_mid_generation` — mid-epoch
  `packet.discontinuity`: the held set is dropped counted
  (`Recovered{1, Discontinuity}`), the epoch banks are released
  (the proof: a NORMAL PCS that WOULD compose the pre-discontinuity
  object yields nothing — flush `Drained`), and the same generation
  keeps decoding afterwards (fresh epoch-start set composes and
  flushes).

## Risks & followups

* **Compile verification is central** (the box forbids cargo by
  RULES): the hand-verified surface — trait signatures, pub-field
  APIs, the `PgsCueBuilder::cues`/`CompositedCue` shapes, the
  frame-vocabulary derives — was cross-checked line-by-line against
  the in-tree sources; residual typo-class risk remains for the
  orchestrator's build to catch. [VERIFY-central]
* `Cargo.lock` gains the codecs→subtitles dependency edge on the
  central refresh (no new lock nodes — subtitles is already a
  workspace member); explicitly left untouched per RULES.
  [VERIFY-central]
* The held-set model retains one display set (bounded by the L2
  64 MiB composed-RGBA cap) between packets — the price of closed
  spans; a presentation-time-closing consumer could avoid it, but
  the builder-owned rule was the assignment's directed path.
* The engine-lane semantics are pinned by citation, not import
  (L3 test cannot dep L4); if FX9-A03 lands its `decoder_for` arm,
  an end-to-end TS+PGS session test in apps/cli is the natural
  follow-up (A03's own suite covers the consumer half).
* `SubtitleCue::text`/`bitmap` constructors are additive; if any
  doc/matrix row claims "SubtitleCue is plain text" as a product
  property it is now stale (FX9-A07's matrix sweep owns the restate).
* Pre-existing, out of scope (W06-A01 audit, crates/codecs/src/lib.rs
  F-001/F-002): the crate-root doc's "no unsafe / zero external
  dependencies" claims were already false before this change; my edit
  only added the `subtitle` module-map entry and `pub mod` — the doc
  debt stays where the audit left it (a doc-wave item, not FX9-A04's).
