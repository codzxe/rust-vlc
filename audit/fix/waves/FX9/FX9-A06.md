# FX9-A06 — GUI subtitle track picker (plan F3.1, re-dispatch)

## Approach

The picker half-existed unfed: `canvasTrackSubmenu("subtitle", …)` (PlayerScreen.tsx) rendered
zero rows because no lane reported subtitle tracks and no `subtitle.add-file` affordance
existed, while the generated verb layer already carried the command. With FX9-A01 COMMITTED
(verified in-tree: `apps/cli/src/dispatch.rs:185-189` routes `SubtitleAddFile`, `host.rs:1720`
answers the class-A ACCEPT receipt, `host.rs:386 track_snapshot` appends the consumer's
sidecar rows, `pipeline_host.rs:1648 sidecar_tracks` mints `origin: external-subtitle` rows
from handle base 65,280), the UI half is this fix:

- **The add-file flow** — a hidden `<input type="file">` (NewPlaylistDialog's pattern, the
  tree's only file-input, found via rg) whose change reads the picked file's NAME and
  dispatches `subtitle.add-file { path, encoding: null, select: true }` through the player
  context's ONE dispatch lane. The entry is reachable two ways: the canvas context menu's
  "Add subtitles" row → `openSubtitleFilePicker()` window CustomEvent (the
  `lumen:open-media` / `lumen:open-tools` trigger-seam pattern) → `SubtitlePickerHost`
  (the ToolsDialogHost pattern — zero chrome, mounted beside `<ToolsDialogHost />`), and the
  full `SubtitlePicker` surface for standalone hosts.
- **The sidecar rows** — rendered from `state.tracks` exactly like the audio/video submenu
  rows (the existing `tracksOfKind`/`selectedTrackId`/`trackDisplayName` helpers); A01's
  snapshot enrichment feeds them. The canvas submenu's subtitle arm appends the add-file
  entry (separator + item) after the radio rows; the no-media branch stays the single
  "no media open" reason row (the existing PlayerScreen.test pin, untouched).
- **Refusal surfacing** — a typed `subtitle.add-file` refusal lands in the provider's
  `lastError` (the codebase's error surface — ControlBar's `ErrorSurface` renders from it);
  the read-back re-query never rides a refused add (dispatch now resolves a clean/failed
  boolean, gating the class-A read-back on the clean answer only).
- **No-player-context fallback** — the picker uses `usePlayerControlsOrNull()` (the
  EqualizerTool presence probe); a bare mount degrades its entry disabled with the
  REGISTERED `player.controls.reason.unknown` title; every key the module resolves is
  registered (asserted in the test after a lost run crashed on an unregistered key).
- **The dev-shell mirror** — `demo-transport.ts` gains the `subtitle.add-file` case
  mirroring the committed CLI host: the no-session `not-ready`/stage-session refusal, the
  unknown-format `unsupported`/stage-demux refusal (the SidecarFormat table: srt, vtt,
  ass/ssa, sup, idx → fourcc), the class-A ACCEPT receipt (no payload echo), and sidecar
  track state (handle base 65,280 + per-session counter reset, basename label, one active
  subtitle lane) that feeds `tracks.list` / the snapshot read-back.

## Risks & followups

- **The web shell's honest path limit**: the file input yields the picked file's NAME (no
  host-filesystem path exists in the browser shell — the AddSubtitlesDialog honesty note);
  the dev shell synthesizes the sidecar from it, and a real desktop host receives
  whatever path the host-side file dialog produces. The web `Blob` variant remains the
  catalog's `[VERIFY]` binding-layer extension.
- **Visual polish**: the picker owns no stylesheet this wave — the hidden input reuses
  the player tree's `lumen-player__sr-note` clip class and the standalone surface is
  unstyled (behavior-pinned); a dedicated `subtitle-picker.css` (and its mounting into a
  tools-dialog-style surface) is the CSS lane's followup.
- **Event-vs-pull parity**: the demo shell emits `tracks.list-ready` on sidecar arrival
  AND the context re-queries `tracks.list` after a clean add (belt and suspenders across
  event-fed and pull-only hosts); a real host that does neither would need a future
  re-query hook on submenu open.
- The `subtitle.set-sync`/`set-encoding`/`set-scale` verbs are served by the committed
  host (A01) but carry no UI affordance yet — the picker's scope was the row/menu
  deliverables only; a sync/encoding/scale surface is a followup assignment.
