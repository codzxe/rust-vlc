## Approach

The assignment threads a `&dyn font::GlyphPipeline` through both text render paths as `*_with_pipeline` twins while the existing free functions stay as zero-churn placeholder-pipeline convenience wrappers, so all 267 pre-existing tests compile untouched. On the SRT side the twins are `cue_layout_with_pipeline` (render.rs:218), `text_box_with_pipeline` (:323) and `place_plain_text_with_pipeline` (:383); on the ASS side `render_plain_text_cue_with_pipeline` (ass/render.rs:428) and `render_styled_cue_with_pipeline` (:565) — the exact names the FX9-A03 row declares as its call contract. The bridge that keeps the wrappers byte-identical is `nominal_glyph_metrics` (srt/render.rs:109): it maps the nominal `TextMetrics` cell/line-box onto `GlyphMetrics` with the font seam's pinned 80 % ascent ratio, so `MonospaceCellPipeline` over those nominal metrics reproduces the old geometry bit-for-bit. Measurement inside the twins is pipeline-driven: per-character advances via A02's `GlyphPipeline::advance` default method, summed in `u64` with `saturating_add` then `u32::try_from`-checked (no silent truncation), and one pipeline mask per glyph for the ink (coverage-tinted straight alpha). Ink and layout both run through whichever pipeline the caller threads — placeholder, A02's swash lane, or A03's `font::session_pipeline()`.

- `crates/subtitles/src/srt/render.rs` — the three twins (`:218`, `:323`, `:383`) plus `nominal_glyph_metrics` (`:109`); the legacy `cue_layout` (:300), `text_box` (:366) and `place_plain_text` (:423) are now one-line delegations to the twins with `MonospaceCellPipeline` over `nominal_glyph_metrics`, each documented `[pipeline: placeholder]`, and the `ZeroExtent` guards route through the twin.

## Test design

The file is compile-independent from A02's swash lane by construction: the real-metric claims run under a test-local variable-advance fake pipeline (`FakeLane`, e.g. `i`=1 vs `W`=20), proving the twins work over ANY `GlyphPipeline`, while the wrapper-equivalence claims run under `MonospaceCellPipeline`. Three pixel oracles deliver the assignment's list: `fx9_a05_per_char_advance_variance` (`i` narrower than `W` in both advance sums and rendered ink), `fx9_a05_non_solid_block_coverage` (alpha varies across a glyph instead of one solid block), and `fx9_a05_decoration_differences_preserved` (e.g. underline ink differs from undecorated). `fx9_a05_placeholder_wrapper_contract_byte_identical` renders a whole ASS cue family (the crate's own `ac_basic.ass` payloads — "Hello Lumen" & co, two-line breaks, spaces, unicode `é漢 W`, position override) plus SRT cues through both the legacy free fn and the twin-with-nominal-pipeline, asserting byte-identical output. `fx9_a05_twin_error_paths_stay_typed` checks both twins and both wrappers return the same typed error variants on reversed intervals, zero extent, margin overflow and empty text. `fx9_a05_styled_runs_render_through_the_pipeline` exercises per-run metrics, per-run colour tint and per-run pen accumulation with hand-computed widths (95 px across two runs at different font sizes). Two deliberate contract details from the header docs: `CueInterval` imports from its REAL public path `subtitles::model::time` (:45 — it is private in `model::cue`), and plain-path fixtures always carry genuinely renderable dialogue text since the plain twins render `cue.text` only (empty-text-with-runs is the typed `EmptyText` error). Everything is deterministic: no network, no display, no clock.

## Acceptance vs FIX-PLAN

FIX-PLAN §5 F3.1 names the hidden cost as "font loading … today all glyphs render as solid blocks — no font backend"; this task removes the second half of that blocker by making the render paths pipeline-agnostic, so the placeholder lane is now swappable wherever a real pipeline is threaded (A02 ships `SwashPipeline`; A03 threads `font::session_pipeline()` through these exact twins). The FX9-A05 TSV row's named deliverables — `place_plain_text_with_pipeline`, `text_box_with_pipeline`, `cue_layout_with_pipeline`, `render_plain_text_cue_with_pipeline`, `render_styled_cue_with_pipeline`, with legacy fns as placeholder convenience wrappers and honest `[pipeline: placeholder]` notes — are all present at the audited anchors, and the row's three pixel oracles (per-char mask variance, non-solid-block coverage, decoration-aware differences preserved) are the first three tests. REALITY-SCORE row 074 (textrender-subtitle-rasterizer UNREACHABLE: "placeholder block glyphs only, and unwired") is now addressable at the consumer side: the "placeholder only" clause is fixed by threading, the "unwired" clause is A03's step. What was intentionally NOT done here: switching any shipped default to a real pipeline, and touching `ass/layout.rs` (pipeline-agnostic by design).

## Risks & followups

The legacy free functions still render placeholder geometry by design — the real-glyph experience only materializes when callers (A03's CLI session lane) thread `font::session_pipeline()` into the twins; if A03 sticks to the legacy wrappers the render will stay nominal, which is the interlock's one soft spot. The tests' real-metric claims run under a fake variable-advance pipeline, so genuine anti-aliased glyph claims live in A02's swash tests — this file proves the threading contract, not the swash rasterization itself (a deliberate decoupling, but worth remembering when a bug only reproduces with real outlines). `ass/layout.rs` staying zero-diff means that if font-aware layout ever lands (e.g. metrics-dependent margins or kerning-aware alignment), it will need its own threading pass. All work is uncommitted on the worktree (no git/cargo in this lane, per rules) — the wave's central commit picks it up; the twin signatures are public API surface the FX9-A03 consumer already compiles against, so any rename is a cross-wave break.
