# FX4-A05 — the audio path's end-to-end observability (FIX-PLAN §3 F1.1, wave row "integration tests fx4_*")

## Approach

One NEW test file, `apps/cli/tests/fx4_audio_path.rs`, nothing in src/
(read-only in pipeline_host.rs/host.rs/dispatch.rs). The assignment's
four acceptance lanes plus the balance lane the seam contract names,
at two depths, split honestly:

- **Session level** (tests 1–5): the deepest lane that can actually
  OBSERVE the two subjects — the null ledger and the rendered
  samples. The `CliHost` keeps its `NullDevice` private and opens
  capture-less (`open_audio_session` hard-codes
  `NullConfig { capture: false }`), and its pump renders into
  pump-local `Vec<f32>` buffers, so NO pub path exists from the
  host-level harness to either observable. The session-level harness
  therefore drives the REAL machinery the host itself drives (the
  exact in-tree precedent: `tests/sync_scenarios.rs` — the same
  `open_audio_session(2, rate, 0)`, the same
  `session.limb.stage(&frame)`, the same
  `session.device.render(&mut buffer)` pump step):
  `open_audio_session` (the host's own open path, unchanged), real
  decoder-output-shaped PCM frames staged through the real limb
  (`process → mix → the runtime master chain → stage D → ring`), the
  pump's own quantum render loop plus the end-of-media tail drain, and
  the null device's own render buffer — where the controls become
  observable in samples.
- **Host level** (test 6): the wire verbs `audio.set-volume` /
  `audio.set-mute` through the real `lumen_dispatch` on a real
  `CliHost` session (the frozen contract (c) — FX4-A02's routing),
  asserting the catalog's own documented payloads, then running the
  media to its exact end to prove the live-control verbs do not break
  the session.

**Seams coded against the frozen contract, explicitly** (the sibling
edits were NOT yet in the tree when I started):
- (a) `AudioLimb::audio_controls()` — the live control entry
  (volume/mute/balance/EQ). I call it on the LIMB (`session.limb.
  audio_controls()`) because that is the only live-reachable half:
  the `AudioSession` struct is destructured at open (host.rs:939–946)
  and the limb is what persists inside the consumer — the piece
  FX4-A02's verb routing must be able to reach mid-session; the
  method names used are exactly `audio_engine::AudioControls`' own
  (`set_volume/set_muted/set_balance/set_eq` + the
  `volume/muted/balance/eq_bands` getters), which compile whether the
  seam hands back `&mut AudioControls` or a mirroring view.
- (b) `NullDevice::stats()` (FX3-A05's pub accessor, in the tree).
- (c) `Command::AudioSetVolume { volume }` / `Command::AudioSetMute
  { muted }` — catalog variants that exist today; routed answers
  asserted as the catalog's own `CommandResult::AudioVolume` /
  `AppliedBool` payloads.

**Where I stopped (the honest boundary):** the demuxer and decoder
stages are not in my lane — the full host run is already pinned

position 2 000 000 µs), and my lane starts at decoder-output shape

## Test design

1. `fx4_a05_end_to_end_audio_lands_in_the_counting_null_stats` — the
   fixture's own PCM facts are READ FROM THE FILE (RIFF walk: audio
   `strf` → 2ch/44 100, 60 `wb` payloads × 5 880 B), then the whole
   media walks the real session: 60 quanta staged through the real
   limb (decode-ahead regime; ring 131 072 > 88 200 so every write
   lands), the pump's own `while buffered ≥ RENDER_QUANTUM` render
   loop plus the tail drain. The ledger must count the media's PCM
   facts EXACTLY: frames 88 200 (derived from the file's bytes, then
   anchored against the 2.000 s × 44 100 Hz arithmetic), buffers 60
   (one per quantum), samples = frames × channels, bytes = samples ×
   4, silence 0 / data = frames (the data-vs-silence split: a fed ring
   renders no underrun silence), `stats.frames() == device.
   sample_count()` (the FX3-A05 ledger↔counter agreement), and the
   counter-fed audio-master clock reads exactly the duration
   (`snapshot().position.ticks == frames × 1e9 / rate`) — the
   "counting null path" closing media time.
2. `fx4_a05_volume_is_observable_in_rendered_samples` — the seam sets
   0.5 between quanta on the SAME session: the rendered s16 quantum
   (0.5, −0.5) halves to exactly (0.25, −0.25); the getter reads the
   live value back; UNITY restores the exact prior samples.
3. `fx4_a05_mute_is_observable_as_rendered_silence` — mute → every
   rendered sample exactly 0.0 with the frame count conserved
   (silence, not a skip); unmute restores the exact prior samples;
   the ledger's split keeps the muted render as DATA (`silence_frames
   == 0`) — FX3-A05's semantics pinned at the integration level: the
   silence split is the starved subset, not the muted subset.
4. `fx4_a05_eq_band_cut_attenuates_a_band_centered_tone` — the
   fx3_a03_eq3_attenuates_sine_at_band_center mirror through the whole
   session path: a 1 kHz sine (the mid peak's exact center) at
   48 kHz rides stage → ring → device render with −12 dB mid set via
   the seam; the settled-tail RMS ratio is 10^(−12/20) ±5 % on both
   channels (the reference is the same session's uncontrolled render,
   so s16 quantization cancels in the ratio).
5. `fx4_a05_balance_shifts_rendered_l_r_energy` — hard-left keeps L
   at amplitude/√2 by the constant-power law and silences R (the
   fx3_a03 balance mirror through the session path).
6. `fx4_a05_host_audio_verbs_route_to_the_live_controls` —
   `lumen_dispatch` on a settled `CliHost` session (the AVI fixture,
   the pipeline_accounting open pattern): `audio.set-volume 0.5`
   answers `Ok(Completed(AudioVolume { 0.5 }))`, `audio.set-mute`
   true/false answer `AppliedBool` — the `unsupported-for-host`
   refusal this wave replaces is gone — and the session still plays
   to its exact end (`Ended`, position 2 000 000 µs) through the live
   controls.

Oracles derived from: FX3-A05 (ledger fields and their exact
semantics), FX3-A03 (the volume/mute/EQ/balance magnitudes and the
settled-tail probe), the fixture's own bytes (machine-verified by a
RIFF parse in /tmp before writing the assertions), and the catalog's
documented verb payloads.

   coded `session.limb.audio_controls()` (method names mirroring
   `audio_engine::AudioControls` exactly). If FX4-A01 landed the
   entry as `AudioSession::audio_controls()` instead (or under
   different method names), my file needs a one-line realignment
   (`session.audio_controls()` / the mirrored names) — no semantic
   change. Same class of risk for FX4-A02's verb payloads: I assert
   the catalog's own documented `AudioVolume`/`AppliedBool` results;
   if their router answers a different shape, the match arms need the
   same one-line realignment. Both are frozen-contract reads, flagged
   here per the honesty contract.
2. **Balance/EQ verbs do not exist in the commands catalog** (only
   `audio.set-volume/get-volume/set-mute/list-devices/set-device/
   set-delay`), so contract (c)'s "set-balance/eq" cannot be driven
   through the wire — those controls are covered through the seam
   (tests 4–5). A future catalog card (F3.2's UI polish phase) would
   add the verbs; my seam tests already cover the engine side.
3. The host-level lane cannot observe the ledger or amplitudes (the
   device is private and capture-less). A follow-up src card could
   add a pub sink-stats accessor to `CliHost` (FX3-A05's report
   already names this seam); until then the session-level tests are
   the deepest observable lane — stated in the file's module docs.
4. Not compiled here (RULES: no cargo in this sandbox) — the six
   oracles are derived from in-tree pinned semantics (fx3_a03's own
   passing magnitudes, FX3-A05's ledger tests, the fixture's parsed
   bytes) and every API call was copied from proven in-tree usage
   (sync_scenarios/pipeline_accounting/fx3_a03 call shapes); the
   orchestrator's central compile is the gate.
5. Test 1's RIFF walker trusts the fixture's well-formed chunk sizes

   test would belong to a container-lane card, not this one.
