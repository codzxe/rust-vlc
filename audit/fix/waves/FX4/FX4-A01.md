# FX4-A01 — the pipeline's route to a real backend, at the session seam

## Approach

The row: "replace NullBackend::open_stream with backend factory (cpal
feature-aware, null fallback headless) + wire Gain/Eq3Band/mixer +
rate-mismatch resampler into the chain + expose audio_controls()".

**The two facts that shaped the design (both verified in-tree before
writing):**

1. **The build cannot carry a real backend.** apps/cli/Cargo.toml:49
   (`audio-output = { path = "../../crates/audio-output" }`) enables no
   feature, so `builtin_backends()` (crates/audio-output/src/lib.rs:160)
   is [null, stub] in every CLI build and `cpal_linked()` is false —
   the factory's cpal entry exists only behind the `backend-cpal`
   feature, which nothing forwards to the CLI. FX3-A01's own report
   named this wiring as "the next-wave FX4 wiring"; FX4-A06's parse
   doc records the consequence verbatim: "this build carries no real
   device backend, so both values construct the instrumented null
   backend today".
2. **The driven CLI session cannot ROUTE a real backend even when one
   is carried.** The host pump renders the concrete `NullDevice` half
   (host.rs:714-760 `advance_time`'s render loop, gated on the null
   ring's fill), and the limb's probe surface — the drain gate
   (`AudioLimb::buffered_frames`), the decode-park gate
   (`AudioLimb::ring_ready`), the seek boundary's written prefix, the
   drift observation's sample count — reads the null driver's own
   counters. The `AudioBackend` trait (crates/audio-output/src/
   device.rs:89-133) carries open/pause/resume/clock_source/underruns
   only; the cpal adapter's `buffered_frames`/`written_frames`/
   `sample_count` are concrete (cpal.rs:347-359), not
   trait-reachable. An opened real device therefore cannot serve the
   limb's sink this wave — the routing is a host-pump rework (the
   desktop lane, FX4-A03/FX4-A04) plus the trait's probe surface.

**The clock question the assignment asked me to check:** BOTH
selectable backends provide `clock_source()` after open — the null
backend's shared counter (null.rs:518-521, advanced by the pump's
device renders — the deterministic clock rides the null path) and the
cpal backend's own `SampleCounter` (cpal.rs:575-578, advanced by the
OS callback through `render_into`; pump.rs's `PcmPump` is the
reference pacing shape). The session anchors
`MediaClock::audio_master` over the selected sink's counter either
way — per-sink, preserved.

**The frozen contract's in-tree truth:** siblings FX4-A02 and
FX4-A05 had already landed code against the contract when I read the
tree — host.rs's `audio_limb_controls` helper
(`guard.audio_mut().map(AudioLimb::audio_controls)` typed as
`Option<&mut audio_engine::AudioControls>`) and fx4_audio_path.rs's
`session.limb.audio_controls().set_volume/set_muted/muted/volume/
eq_bands/set_balance/balance` calls. The contract is therefore the
**raw `&mut AudioControls` passthrough** (not a mirrored-handle
type), plus `ConsumerState::audio_mut` (the mutable twin FX4-A02's
helper calls). I matched it exactly — their code compiles against my
landed seam unchanged.

**The chain's placement (one honest design note):** the engine's
`AudioPipeline` exposes no mutable controls handle (FX3-A03
deliberately declined it — pipeline.rs:358-363), so the session's
LIVE chain is owned by the limb and run at the post-mix seam
(`AudioControls::process` on the deinterleaved mixed quantum,
between the mixer and the rate conversion — exactly FX3-A03's
documented position and stage order). The uncontrolled chain is the
exact identity and the equal-rate lane skips the seam wholesale, so
the default path is bit-identical to the pre-FX4 stage (the
acceptance bar, pinned by test). The one gate that moves: the raw
hand-off cannot pre-validate balance's stereo shape at set time
(the chain doesn't know the session's channel count) — the gate
fires at process time instead, surfacing through `stage` as the
typed `audio.effects_balance_channels` (documented on
`AudioLimb::audio_controls`, pinned by test).

**The rate-mismatch resampler (item 3's verification):** track-rate
SRC is NOT applied at the engine level — `AudioPipeline::process`
still refuses at `audio.rate_mismatch` (pipeline.rs:400-405, FX3-A04's
own "the wiring card remains" note). The session seam was missing it:
`open_audio_session` passed the track rate to both the pipeline and
the sink (no mismatch possible), and nothing resampled a sink clocked
at another rate. Wired at the session seam: a differing
(track_rate, sink_rate) pair constructs FX3-A04's `RateResampler`
into the seam — equal rates (every current construction) skip it and
keep the byte path.

**Invocation posture threading (item 4):** parse.rs (FX4-A06, in
tree) matched the assignment's description exactly — `Invocation.
audio_backend: Option<AudioBackend{Auto,Null}>` + `no_audio: bool`
riding the open command; no drift to adapt. The `no_audio → no audio
limb + wall_clock` threading is verified EXISTING (host.rs:937-952:
no audio geometry → no limb → `wall_clock`; parse.rs threads `--no-audio`
into the open command's own flag — run.rs:126-143). The
`audio_backend → posture` threading is the constructor's new
`AudioBackendPosture` parameter (parse's enum maps one-to-one); the
production call-site threading (host.rs's `open_session` passing the
invocation's choice into `open_audio_session_for`) is the host-file
owner's one-line follow-up — host.rs is FX4-A02's file this wave and
not mine to edit. Noted as the one open seam, not silently skipped.

## Test design

Oracles derived from the landed FX3/FX4 facts (two numerically
derived ones simulated in /tmp before pinning):

1. `fx4_a01_factory_posture_routes_the_instrumented_null_backend` —
   the build truth (`cpal_linked() == false`), both postures route
   `RoutedAudioBackend::Null`, and the driven session works
   end-to-end: 1470 staged frames land in the ring byte-exact (s16
   8192 → f32 0.25 in every slot), the device renders them back, the
   FX3-A05 ledger counts exactly (frames/samples/bytes, zero
   silence), the counter and the clock agree (1470 @ 44.1 kHz =
   33_333_333 ns — media-clock's round-half-up conversion
   re-derived). This is the byte-compatibility pin: the null
   fallback is the pre-FX4 behavior, unchanged.
2. `fx4_a01_rate_mismatch_resampler_wires_the_output_clock` — a 48
   kHz sink under a 44.1 kHz track: the ring holds exactly 1599
   frames — FX3-A04's own closed form ⌊(1470−1)·160/147⌋+1 (the
   naive duration ratio says 1600; the exact count is the oracle,
   re-derived by simulating the emission rule), every rendered
   sample is bit-exactly 0.25 (the linear kernel passes a constant
   exactly: a + (b−a)·weight with a == b), and the clock rides the
   SINK's counter: 1599 @ 48 kHz = exactly 33_312_500 ns.
3. `fx4_a01_audio_controls_volume_mute_balance_reach_the_ring` — the
   frozen contract through the REAL session: volume 0.5 halves every
   rendered sample exactly (0.125), mute zeroes with the frame count
   conserved, unmute restores the prior bytes bit-exactly, hard-left
   balance keeps L at 0.25 exactly and silences R at 0.0 exactly (the
   pan law's (1.0, 0.0) gains at p = −1), the session-level and
   limb-level entries answer one live chain (set through one, read
   through the other), and the raw hand-off's moved gate is pinned:
   a MONO session's `set_balance` takes the `Ok` and the next
   `stage` refuses typed (`audio.effects_balance_channels`) — loudly,
   never a silent mislabel.
4. `fx4_a01_eq_attenuates_the_band_center_through_the_session_seam` —
   the EQ is real DSP the seam reaches: a −12 dB mid cut on a 1 kHz
   tone settles at 10^(−12/20) of the SAME input's uncontrolled
   output (±5%; the reference is a second uncontrolled session, so
   the s16 quantization cancels in the ratio — FX3-A03's own
   tolerance discipline, at the session depth).

## Risks & followups

1. **The compile is the central build's** (RULES: no cargo here). The
   non-trivial shape is `write_through_seam`'s three-field-disjoint
   borrow (sink/controls/seam passed separately — the standard
   disjoint-field discipline, same as the sibling patterns); the
   match returning `(resampler.planes(), out)` vs `(seam.planes.
   as_slice(), frames)` is the one borrow the central compile
   actually proves.
2. **The raw `&mut AudioControls` hand-off trades a gate for the
   contract's shape:** the pipeline's own surface pre-validates
   balance's stereo shape at set time; the raw handle cannot, so a
   mono session's `set_balance` succeeds and the next `stage`
   refuses typed (documented, test-pinned). FX3-A03's read-only
   rationale is answered loudly, not silently — but the set-time
   gate is the pipeline surface's privilege.
3. **Two chain instances now exist** (the limb's live one and the
   pipeline-internal one FX3-A03 placed): same type, same stage
   implementations, different owners — the pipeline's stays the
   exact identity in the CLI lane (no CLI code drives it), so no
   double-apply in production; an engine-level driver + the limb
   seam would compose. The engine-side surface remains live for the
   fx3_a03 tests (both suites green by construction).
4. **The real-device lane's remaining distance:** feature forwarding
   (one Cargo.toml line), the `AudioBackend` trait's probe surface
   (buffered/written/sample — audio-output follow-up), and the
   host-pump rework to drive an OS-callback device. The routed-record
   enum (`RoutedAudioBackend`) is the vocabulary the `RealDevice`
   variant lands in; the `Auto` preference arm already consults
   `cpal_linked()` so a linked build's routing decision is recorded,
   not silent.
5. **The host-side posture threading** (host.rs threading the
   invocation's `audio_backend` into `open_audio_session_for`) is
   the host-file owner's one-line follow-up — the seam, the enum and
   the mapping are landed and documented; host.rs was FX4-A02's file
   this wave and the 3-arg default (Auto) keeps their in-tree call
   compiling unchanged.
