## Approach

The assignment asked four things about the tauri lane (my file domain
`apps/desktop-tauri/src/**` only): (1) does the app construct its
host/pipeline so audio flows — the audio backend factory inherited
post-FX4-A01, no discard shortcut; (2) remove any skip if one exists;
(3) check the audio/event channel for the W14-A07 unbounded-queue class
and treat it or hand it off precisely; (4) regression tests
`fx4_a04_*`.

I read the full pump lane (`app.rs` complete, `frame_channel.rs`,
`lib.rs`, `main.rs`, `tests/single_command.rs`), then traced the
construction chain out of the tauri crate into the shared host
(`apps/desktop/src/shell.rs`, `apps/desktop/src/dispatch.rs`,
`apps/cli/src/host.rs`, `apps/cli/src/pipeline_host.rs`,
`crates/audio-output/src/lib.rs`, `crates/commands`), and the CI lanes
that build/test this crate (`ci.yml` tauri-check, `release.yml`).

**The verification answer: the tauri lane inherits the audio path by
construction and contains no skip.** The wrapper owns no pipeline
construction of its own — everything flows through the same objects
the CLI lane drives. Consequently there was no code defect in my file
domain to fix (item 2 resolved to "nothing to remove"), and the
deliverable became the regression tests that LOCK the inheritance
against future drift, plus the precise FX6 handoff note for the frame
queue. Zero `src/` changes; one new test file.

## Findings (all re-derivable by rg)

1. **Construction is shared, not per-host.** `app.rs:290-292` manages
   exactly one `ShellState(Mutex::new(ShellRuntime::new(
   DEFAULT_EVENT_CAPACITY)))`. `ShellRuntime::new` (apps/desktop/src/
   shell.rs:126) builds `ShellHost::new()`, which adopts the CLI's own
   `lumen_cli::host::CliHost::new()` (apps/desktop/src/dispatch.rs:84,
   the ARCH-5 reuse). No tauri-side host/pipeline constructor exists
   anywhere in `apps/desktop-tauri/src/**` (rg `CliHost|pipeline` in the
   crate → zero hits outside comments naming the adopted host).

2. **The audio session opens in the SHARED open path.** `session.open`
   — whether from a webview invoke (`runtime.dispatch(&request)`,
   app.rs:151, options passed verbatim from the wire) or from the
   argv/drag-drop funnel (`runtime.open_path` → `open_file_request`,
   options `Default::default()`, apps/desktop/src/dispatch.rs:225) —
   routes to `CliHost::open_session` → `apps/cli/src/host.rs:937-953`:
   whenever audio geometry survives selection it calls
   `pipeline_host::open_audio_session(channels, rate, anchor)`
   (apps/cli/src/host.rs:944) — the exact site FX4-A01's backend
   factory (crates/audio-output `builtin_backends()`, lib.rs:160-167,
   feature `backend-cpal` off by default with null fallback) will own.
   The tauri lane therefore inherits the factory automatically the
   moment FX4-A01 lands; no tauri-side wiring is needed or possible.

3. **No discard shortcut.** `OpenOptions`' default is
   `no_audio: false` (crates/commands/src/catalog/types.rs:240-252);
   the only `no_audio: true` constructions in the repo are the CLI
   `--no-audio` parse path (apps/cli/src/parse.rs:286) and web-host
   test paths. In `apps/desktop-tauri/src/**` there is no audio cfg
   gate, no env early-out, no options rewrite: the crate's only `cfg`s
   are `cfg(windows)` for the fatal-dialog sink in `main.rs`
   (rg `cfg\(` in the crate confirms).

4. **The tauri pump drives audio.** `spawn_event_pump` (app.rs:190)
   calls `runtime.pump_session()` (app.rs:204) → `CliHost::
   pump_wallclock` (apps/cli/src/host.rs:534) — poll + the
   wall-bounded device advance + end-tail play-out: the audio device
   is rendered by the pacer, identical host semantics to the CLI lane.

5. **Audio does NOT ride the frame channel; the audio/event egress is
   bounded in shell code.** Audio renders into the device ring
   (AudioLimb/NullDevice — the future real backend's callback pulls the
   same ring); it never crosses to the webview. Engine events ride
   `lumen://event` through `BoundedEventSink` — capacity
   `DEFAULT_EVENT_CAPACITY` = 64, drop-oldest, counted, conserving
   (apps/desktop/src/dispatch.rs:151-196; `ShellRuntime::event_stats`).
   The W14-A07 unbounded-queue class lives one layer down: tauri's
   per-webview `ChannelDataIpcQueue` (frame_channel.rs audit F-002,
   vendored tauri-2.12.5 `ipc/channel.rs:47-54`) — fed only by
   `send_record` (`Channel<InvokeResponseBody>::send`), i.e. the
   FRAME lane only.

## Changes per file

- **apps/desktop-tauri/tests/fx4_a04_audio_lane.rs** (NEW — the only
  change). Two tests:
  - `fx4_a04_tauri_runtime_audio_lane_runs_to_end` — constructs the
    runtime exactly as app.rs does, opens the audio-only fixture
    (`tests/fixtures/generated/valid/wav_pcm_s16le_44k1_st.wav`) via
    the wrapper's own funnel (`open_path`), plays via the single
    command (`dispatch`), and drives it with `pump_once` (the
    deterministic twin of the ticker's `pump_session`) to `Ended`.
    Asserts the audio-lane observables on public host seams:
    `audio_lane_counters()` accepted > 0 (in an audio-only session every
    accepted frame is audio — a discard shortcut leaves it at zero),
    `position_us() > 0` (audio-only media advance only through the
    audio-master sample counter; a limb-less session latches at 0
    forever — issue #16), `Playing` + `Ended` reached, egress conserves.
    Deliberately does NOT assert time-ticks: default interval 250 ms >
    the 0.2 s fixture.
  - `fx4_a04_open_funnel_keeps_the_audio_track_enabled` — the
    discard-shortcut oracle at the wire level: `open_file_request`'s
    `session.open` carries `no_audio == false`, `no_video == false`,
    not paused, from position 0. Any future funnel drift that disables
    audio fails here before engine behavior changes.
- **No `src/` changes** — the audit questions resolved to
  "already-correct by construction" (findings 1–5). Both `app.rs` and
  `frame_channel.rs` read in full; nothing in my audio scope required
  an edit, and the frame-lane items (`records.last()` shipping, the
  unbounded tauri queue, the 10 ms cadence) are F1.2's later-wave
  scope, not mine to touch.

## Test design — CI-gated, per the assignment's instruction

The crate cannot build on this box: `pkg-config --exists
webkit2gtk-4.1` → absent (verified). So `tests/single_command.rs` is
itself CI-gated (its body is a source scan, but its test binary links
the lib — wave-14's W14-A05 finding). My tests ride the same gate:
ci.yml `tauri-check` (ci.yml:775-779) runs `cargo test
--manifest-path apps/desktop-tauri/Cargo.toml --locked --all-targets`
on ubuntu-latest with webkit2gtk-4.1 installed and ui/dist built, so
both tests compile+run there. They were authored against the proven
headless seam tests in apps/desktop/src/shell.rs (same runtime, same
fixtures, same pump loop — those run in the workspace CI lane and are
the oracle). No new dependencies; no dev-dependencies edit. rustfmt
(edition 2021, the allowed exception) run clean on the file.

## Risks & followups

1. **The tests have never executed** (CI-gated; authored against the
   proven apps/desktop/src/shell.rs seams). If the WAV fixture's
   drive-to-Ended needs more pumps than 512, the bound assertion fails
   loudly in tauri-check — a calibration fix, not a design change.
2. **The shipped GUI stays null-backend until someone enables
   `backend-cpal` in apps/desktop-tauri's graph.** The tauri crate
   (and the release lane's `cargo build --release --locked
   --manifest-path apps/desktop-tauri/Cargo.toml`) builds default
   features only; post-FX4-A01 the factory therefore falls back to
   null in the shipped GUI. Enabling the feature is a Cargo.toml
   dependency/feature edit — prohibited for me (RULES) and needing the
   Lead's call (the audio-cpal-check lane, ci.yml:840, is the compile
   oracle; tauri-check installs no ALSA dev packages, so flipping it
   there would break the lane — Windows/release-lane scope).
3. Observed, out of my scope (for the owning waves): W14-A02's
   pump-dies-on-poison (app.rs:199-201) survives FX1's fix; F-004
   argv-open events emitted before the UI listener exists; F-013
   `frame_channel_bound` still production-dead. None are audio-lane
   defects; left untouched.
