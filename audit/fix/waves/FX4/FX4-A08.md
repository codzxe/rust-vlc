# FX4-A08 — UI controls real: volume slider + EQ panel call the real IPC verbs

## Approach

Grounding first, because it reshaped the assignment's premise — one
premise drift, noted per the honesty contract:

1. **The volume slider was NEVER the dead widget.** Wave-15's own per-file
   audit (Volume.tsx.audit.md, W15-A01) verdicts it REAL with the full
   three-hop chain verified: `ControlBar.tsx:477-482` (value from
   engine-reported `state.volume`, commit → `actions.setVolume`) →
   `context.tsx` `dispatch({ args: { volume }, cmd: "audio.set-volume" })`
   → the client transport (the single `lumen_dispatch` lane). Mute rides
   the identical seam (`audio.set-mute`). The dead half was the HOST's
   refusal (wave-07: "`audio.set-volume` refused by every shipped host")
   — FX4-A02's half, not the UI's. So the volume deliverable here is the
   fix-wave regression pin set (`fx4_a08_volume_ipc.test.tsx`), not a
   rewire: if the widget ever regresses to dead local state (onCommit
   detached, payload reshaped, round-trip broken), the lane goes red.

2. **The dead widget was the EQ panel** (wave-15 finding #5: "10-band
   equalizer UI vs engine's 3-band Eq3Band; audio.set-eq command absent;
   faders interactive-but-local-only"). FIX-PLAN §3 F1.1 rules the
   reconciliation: "cut the UI to 3 bands and say so — do not invent 7
   more bands." Delivered exactly that: the panel renders Preamp + the
   engine's Eq3Band trio (low 250 Hz shelf / mid 1 kHz peak / high 4 kHz
   shelf — crates/audio-engine/src/effects/eq.rs's fixed corners, the
   frequencies in the visible labels), the morphing header copy says
   "Open/Close 3-band equalizer", and every fader commit / preset pick
   dispatches the real `audio.set-eq` verb through the SAME dispatch lane
   the working controls ride: `EqualizerTool` → `usePlayerControlsOrNull()`
   → `PlayerActions.setEq` → the provider's `dispatch` →
   `wire.send` (one transport, one monotonic requestId counter).

3. **The verb id + payload — and the sibling's confirmed drift.** The
   catalog today carries `audio.set-volume`/`get-volume`/`set-mute` only
   (ids.rs — rg'd). FX4-A02's landed report (DONE) is explicit: there is
   NO `audio.set-eq` in `crates/commands` and none was added — serving
   one would be a catalog edit outside every FX4 row's file domain; the
   host seam it built "reaches the full `AudioControls` (`set_eq`
   included) … the day the catalog grows those ids the routing is a
   dispatch arm away." The UI therefore dispatches the verb id the wave's
   own contract names — the id the UI's pre-wave staging markers named
   (`PENDING_COMMAND`), the tsv row's "eq family", and the id FX4-A07's
   docs pass cites — with the payload mirroring the engine setter it
   feeds: `AudioControls::set_eq(low_db, mid_db, high_db, preamp)` in
   the wire's camelCase convention (`{ lowDb, midDb, highDb, preampDb }`).
   Until the catalog id lands, the shipped host answers the dispatch with
   the typed `unsupported-for-host` refusal — which this UI SURFACES in
   the error chip (never silently swallowed; pinned by test). The catalog
   codegen (ui/src/generated/commands.ts, "never hand-edit") carries the
   command in the union after a central `cargo xtask codegen` refresh;
   until then ONE typed forward-declaration seam (`EqSetArgs`/
   `EqSetRequest` in context.tsx — the k07 lane-key pattern applied to a
   command payload) constructs the request.

4. **Mute/balance**: mute is surfaced by the ControlBar cluster and
   already rides the real verb — pinned here. Balance is NOT surfaced by
   any component in this file domain: the pre-wave balance slider was
   RETIRED from the settings area (effects.tsx's own "RETIRED" note) and
   no balance UI exists — nothing to wire, no pretense added.

## Risks & followups

1. **The eq verb is CONFIRMED absent from the catalog in this wave's
   tree** (FX4-A02's landed report, drift #1: no `audio.set-eq` in
   `crates/commands`; serving one was outside every FX4 row's domain).
   Consequences, precisely: (a) the UI's dispatch is REAL at the wire —
   same transport lane, same envelope, same monotonic requestId — but the
   shipped host answers `unsupported-for-host` (dispatch.rs's catch-all)
   until the catalog grows the id and FX4-A02's "one dispatch arm"
   routing lands; that typed refusal surfaces in the UI's error chip
   (pinned — never swallowed), so the user sees the honest state, not a
   dead widget pretending; (b) the payload this fix sends —
   `{ lowDb, midDb, highDb, preampDb }`, the direct mirror of the
   engine's `AudioControls::set_eq(low_db, mid_db, high_db, preamp)` in
   the wire's camelCase convention — is the natural shape the future
   catalog arm will want; if it differs (field names, a `bands` object,
   a linear preamp), the reconciliation is ONE construction site:
   `EqSetRequest` in ui/src/screens/player/context.tsx plus the matching
   args in the two dispatch tests — a mechanical field rename, no
   architecture; (c) the codegen refresh (ui/src/generated/commands.ts
   union + schemas) must accompany the catalog id — the forward
   declaration carries the request until then (the cast is documented at
   the seam). Related wave-doc drift, for the orchestrator: FX4-A07's
   docs pass states "`audio.set-balance`/`set-eq` route to the
   pipeline's `audio_controls()`" — FX4-A02's own report discloses they
   do NOT (only volume/mute/get-volume route); those doc sentences need
   the softening FX4-A07's risk #1 itself anticipates.
2. **The settings-area Effects mount is still host-local + staged**
   (effects.tsx is outside this assignment's file domain): its EQ enable
   / preset / panel rows keep their `data-pending-command="audio.set-eq"`
   markers and never send — now honestly annotated in effects.test.tsx
   as the settings-side contract while the PLAYER-side mount dispatches.
   Its staging copy ("Engine stage ready — commands staged until the
   audio effects command card") is stale post-FX4-A02 and belongs to
   that area's owner — noted, not silently edited.
3. The engine's EQ state has no snapshot/event feed (StateSnapshot
   carries volume/mute only), so the faders remain the editing surface
   and the engine's typed refusals surface via the error chip — the
   never-optimistic posture is preserved; a `config.`-area EQ
