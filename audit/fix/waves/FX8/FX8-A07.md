## WCAG ledger (3 exclusions: 1 resolved in code, 2 documented-accepted)

All ratios computed with python3, WCAG 2.x relative luminance
(`L = 0.2126·R' + 0.7152·G' + 0.0722·B'` with the sRGB transfer function;
ratio = (L1+0.05)/(L2+0.05)):

**1. settings-audio (RESOLVED IN CODE)** — the light selected values-row
label painted `var(--color-accent)` on the flipped light tint:

- OLD: `#d37918` on `#d8ba9a` = **1.75:1** (axe serious, AA needs ≥4.5:1).
- FIX (`setting-field.css`, the w26.d2 button-lane light-sweep precedent):
  `:root[data-theme="light"] .settings-field__control .settings-values__row--selected
  { color: var(--color-content-primary) }` → light resolves to **#161616 on
  #d8ba9a = 9.83:1**. Dark is untouched (base rule keeps the accent:
  #d37918 on #371f06 = **4.79:1**, AA holds for the default accent the
  a11y suite audits).
- Holds across **all 9 light accent tints** (light tints flip per accent;
  content-primary does not): orange #d8ba9a **9.83**, red #d6a69c 8.44,
  yellow #d4c79e 10.74, green #9cd6a7 10.85, cyan #9acad8 10.18, blue
  #9ab1d8 8.32, violet #b192e0 **6.94 (worst)**, pink #da98c0 7.96, gray
  #b9b9b9 9.22 — every accent ≥4.5:1.
- The `ROUTE_EXCLUSIONS["settings-audio"]` entry is **deleted** from
  `ui/e2e/a11y.spec.ts` — a regression now FAILS the per-PR a11y suite
  (the ui job runs `npm run test:e2e` on every push/PR) instead of being
  accepted; a deletion note records the fix.

**2–3. settings-library + settings-network (DOCUMENTED-ACCEPTED)** — the
staged "pending change" rows dimmed at 0.3 opacity
(`var(--opacity-muted)`, the Figma frames' own disabled-row grammar):

- WCAG **1.4.3 "Incidental" exception**: text that is part of an INACTIVE
  user interface component has no contrast requirement — these rows are
  inert by design (`data-staged`, disabled controls, the staged reason on
  `aria-describedby`/`title` + the sr-only note). The low ratio is exempt,
  not waved through.
- Measured reality: the label `#8f8f8f` @0.3 over `#0e0e0e` composites to
  **#353535 on #0e0e0e = 1.57:1** (browser alpha compositing
  `α·fg + (1−α)·bg` per sRGB channel — matches the w26.k19 axe ledger).
- Proven unfixable at the frames' own 0.3 dim: even pure **#ffffff @0.3
  over #0e0e0e composites to #565656 = 2.63:1 < 3:1** (over #090909 it is
  2.59:1); white would need **α ≥ 0.334** for 3:1 and **α ≥ 0.450** for
  4.5:1. A compliant dim would have to abandon the frames' opacity grammar —
  a design decision, not a bug fix; the entries keep their markers/modes so
  any NOVEL color-contrast node on those routes still fails the suite.
- Their `reason` strings in the ledger now document the exemption + the
  unfixability math (replacing "logged for the settings lane").
- Out of scope per assignment (other agents' css / no other css touched):
  the staged-row presentation itself lives in staged.css/settings.css.
