## The pin method

`scripts/quality/pin_fixtures.py` (python3 stdlib only, FX8-A01
status_truth.py house style):

- **Census (closed, in-code — the xtask model):** a `FAMILIES` table
  (27 parent stems → directory/extension/derivative-op set/provenance) +
  the two oracle sidecars; the manifest's 28 registered paths are read at
  run time and excluded (the xtask gate stays their authority). Expected
  member set = parents + per-family derivatives + sidecars = 88.
- **Per-row emission:** `path` (MANIFEST convention, relative to
  tests/fixtures/), `family`, `op` (parent/trunc0..4/flip1/4/16/garbage0/
  oracle-sidecar), `provenance` (the family's ffmpeg authorship record,
  quoting the suite provenance header), `sha256`, `size_bytes`
  (TOML `_` grouping, the MANIFEST convention); rows sorted by path;
  self-validated by re-parsing the emitted TOML (`tomllib`) and re-checking
  count/sort/uniqueness/row round-trip before the file is written.
- **Exit codes (all re-run live, see FIXV1 tests note):** write exit 0;
  `--check` exit 0 (no drift) / exit 1 (deleted row, deleted fixture,
  byte drift — the drift class is named in the message) / exit 2
  (unknown family or unknown derivative op — the census refuses to guess
  rather than understate; a manifest-side hole also surfaces as exit 2,
  never silence). A census change means editing the script first, then
  regenerating — exactly how `cargo xtask fixtures` owns its 28.
- **Census proven (independent cross-check):** tree 116 = manifest 28 +
  unregistered 88 = pins 88 (set equality re-derived with tomllib + os
