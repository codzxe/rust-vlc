# FX8-A02 — CI: the status-truth lane + the fail-closed tail

## Approach

ci.yml is the merge-blocking core (push/PR/merge_group on main), so the
status-truth gate is a JOB there, not a standalone workflow — the
assignment's exact framing, and the sibling contract FX8-A01's report
records (".github/workflows/ci.yml (FX8-A02) runs `bash
scripts/quality/status_truth_check.sh`"). Its provenance was verified
before wiring: `scripts/quality/status_truth.py`,
`scripts/quality/status_truth_check.sh`, and
`docs/generated/status-truth.toml` all exist (ls), and the gate run on
the real tree exits 0 (`status-truth: OK — committed status truth
matches the source-derived truth`).

The job is placed directly after `schema-validation` — the same
generated-artifact drift family (schema-gen --check / codegen --check /
fixtures --check / feature-matrix v0) — and follows ci.yml's job
conventions exactly: `# ---` banner explaining what/why/exit-codes,
kebab-case job id, parenthetical `name:`, `runs-on: ubuntu-latest`,
`timeout-minutes:`, steps opening with the SHA-pinned checkout, then the
named run step. It deliberately has NO toolchain-assert/rust-cache step:
the gate is python3-stdlib-only, runs no cargo (FX8-A01's design), and
pretending otherwise would be dead weight. Placement convention check:
every key/shape used (`uses:` with SHA + trailing version comment,
`name:`, `run:`) is byte-shaped like the neighbors.

For the F2.3 tail: rg census over the four owned files for
`continue-on-error`, `|| true`, `set +e`, and J-reporter patterns
(`99_run_all` / `reporter` / `report.py` / `scripts/quality`
invocations). Exactly ONE executable fail-open existed across all four
files: ci.yml's tauri-check ldd smoke —
`missing=$(ldd target/debug/lumen-tauri | grep "not found" || true)`
(old line 813) — where ldd's own exit never propagated (FIX-PLAN §4
F2.3 "`|| true` leftovers"). It is rewritten fail-closed: ldd runs
ALONE with its exit code asserted first, the scan reads the captured
output file, and grep's no-match exit 1 (no "not found" lines IS the
healthy case) is consumed by an `if`, not by a `|| true` — so the block
contains zero `|| true` at all. The other three files need no code
change: census-verified fail-open-free (details below).

## Risks & followups

* **Runner-verifiable only:** like every workflow in this repo, the
  new lane has no live-run proof from this sandbox (CI
  billing-blocked history per the audits); the gate itself is fully
  proven locally (green + both red classes), and the step→job status
  mapping is GitHub-native (nonzero rc = red). First live run should be
  watched once — it is the same class of risk the file's own
  "First-run status" notes record for other lanes.
* **`timeout-minutes: 5`** is the only value in the new job not
  matching a sibling (siblings use 10-60); valid syntax, generous for a
  seconds-long stdlib job, but a style reviewer may prefer 10.
* **F-002 leftover (NOT mine, noted for the next wave):** tauri-check
  line 819 `|| cargo install cargo-deny --version 0.20.2 --locked` —
  the dead `${DENY_BIN:-...}` fallback (audit F-002, supply-chain
  pin-consistency) is a `||` FALLBACK, not an exit-swallow (the deny
  check's rc propagates), so it is outside F2.3's fail-open class; it
  wants the cargo-deny job's SHA-256 download block replicated.
* **The gate is anchor-brittle by design:** any edit to the five
  parsed sources shifts line anchors in the committed TOML → red until
  regenerated (FX8-A01's risk note; the regen command is printed by
  the gate and in the job banner). PRs touching apps/cli or
  crates/commands must run the one-line regen.
* **`ldd-smoke.txt`** is a scratch artifact in the runner workspace
  (same class as cargo-metadata.json / deps-tree.txt /
  wasm-size-report.txt in other jobs) — never uploaded, discarded with
  the runner; noted so nobody hunts for a missing artifact.
* **Old-block nuance, recorded for honesty:** under GHA's actual
  `-eo pipefail` the OLD block happened to go red on a failing ldd
  anyway (the display line's pipefail), so the practical damage was
  the false "all dynamic dependencies resolve" message in the log and
  the check's total dependence on incidental shell flags — under plain
  `bash`/`bash -e` (and any future shell-default change) it was a full
  false green (rc 0, reproduced). The new block asserts ldd's rc
  explicitly and is red with a truthful message in every shell mode.
