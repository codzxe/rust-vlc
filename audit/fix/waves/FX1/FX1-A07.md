# FX1-A07 — ASS `\pos` overflow + ASF header child-size check (FIX-PLAN §2 F0.4i+j)

## Approach

Both findings are the same class — one unchecked arithmetic op on
attacker-controlled parsed fields — and both have an audit-prescribed
one-line "what correct looks like" that preserves every existing
semantic:

- **F0.4i** (W09-A01 F-001, S2): `to_percent`'s `let q = (num + den / 2) / den;`
  at `crates/subtitles/src/ass/parser.rs:722` — **no drift**, the exact cited
  line. The mul steps around it were already `checked_*`; only the rounding
  add was bare. Fix: `num.checked_add(den / 2)?` — the audit's own wording.
  Overflow now flows into the closure's existing `None` →
  `position_overrides_unmappable` path: the crate's documented honest-refusal
  policy ("never clamped" — the `(0..=100)` filter remains the sanity bound
  for every non-overflowing coordinate). No public API change; lib.rs's
  "no panics on any input" headline contract now holds on this path.
- **F0.4j** (W04-A10 F-001, S1): `let end = off as u64 + size;` at
  `crates/demux/src/asf/header.rs:558` — **no drift**; the asf module lives
  exactly where cited (`crates/demux/src/asf/header.rs`). A crafted child size
  ≥ 2^64 − off overflowed the add (debug: panic; release: wrap past the
  `end > header_size` guard into a `start > end` slice panic). Fix:
  `let Some(end) = (off as u64).checked_add(size) else { typed refusal }` —
  the same `error::bad_object_size(header_offset + off as u64)` the
  neighboring `size < 24` and `end > header_size` arms already mint, and the
  same `checked_add` discipline the sibling `walk_top_level` (now ~:1059)
  already follows. No new error kind, no behavior change for well-formed
  files.

Checked arithmetic (not saturating) was chosen deliberately: a saturating
clamp would silently move a cue / walk past the buffer — the audit's own
"never a silent clamp; MP §8 prefers honest data" policy. The assignment's
"clamping to sane coordinates" is what the existing `(0..=100)` percent
filter and the `end > header_size` guard already do; the fix only removes
the panic/wrap escape hatch from those guards.

## Test design

Two NEW integration-test files (per assignment; no edit collisions with
sibling agents), only existing deps — the subtitles file uses std + the
crate's own public API; the demux file uses `demux`/`media-types`/
`plugin-api` (all regular deps of the crate, exactly like
`strl_advisory.rs`/`adversarial_gaps.rs`).

**ASS (`fx1_a07_ass_overflow.rs`)** — `fx1_a07_ass_pos_overflow…`:
- The audit's EXECUTED reproduction verbatim: `PlayResX: 9223372036854775`
  + `{\pos(92233720368547,10)}` (num 9.2234e18 + den/2 4.6117e18 → add
  1.3835e19 > i64::MAX; both operands individually in range — this is the
  input that exited 101 pre-fix), plus the sibling class
  `{\pos(9223372036854775,9223372036854775)}` where the numerator mul
  itself overflows.
- Asserts: parse completes (the test's survival IS the no-panic proof),
  2 cues with exact texts/times, `position_overrides_unmappable == 2`,
  `position_overrides_applied == 0`, `applied_override_tags == 2` (tags
  parsed; the percent vocabulary refused them), positioning untouched
  (`position`/`line` None, alignment from the style — the sane output),
  `damage` empty (crafted numbers are syntactically valid ASS).
- Control `fx1_a07_ass_sane_pos…`: 384×288 doc, `\pos(192,144)` → exactly
  50%/50%, `\pos(96,72)` → exactly 25%/25% — the tightened math must not
  refuse well-formed coordinates.
- Arithmetic oracle re-derived independently (python3, /tmp) before writing
  the assertions — values confirmed, including the pre-fix overflow bit.

**ASF (`fx1_a07_asf_child_size.rs`)** — builder-blob patching (the crate's
own `test_support::minimal_asf_audio` + one size-QWORD patch per case):
- `fx1_a07_asf_child_size_overflow…`: first-child (FPO) size := `u64::MAX`
  (pre-fix: the overflowing `off + size` add / release wrap-into-slice) and
  second-child (SP) size := `u64::MAX` (same class mid-walk) — both must be
  the typed `demux.asf.bad-object-size` refusal (`err.context.code`
  equality, the `mkv_fixtures.rs`/in-crate `code_of` convention).
- `fx1_a07_asf_child_overrun…`: second-child size := 1000 in a 230-byte
  header — no u64 overflow, the pre-existing `end > header_size` refusal:
  pins that the tightened check changed nothing for non-overflowing sizes.
- `fx1_a07_asf_well_formed…`: control — the unpatched minimal file still
  `start()`s to its one `pcm_s16le` track.

Style follows each crate's conventions: demux — `match`/`unreachable!`
error extraction (no unwrap/expect, house rule); subtitles — plain
`assert!`/`assert_eq!` on model types (`ass_ffmpeg_ac.rs`-style).
