## Changes per item

### (a) scripts/quality/23_alloc_budget.sh — exit-swallow (W17-A03 F-001, S0)

The Python gate (`sys.exit(1)` on OVER THRESHOLD) died at the trailing
`say`/`say` lines, so the script always exited 0. Restructured to the single
exit path: `rc=0` before the heredoc, `rc=$?` after it, the two human `say`
lines, then `exit "$rc"` (with a comment block explaining the gate semantics
for 99_run_all.sh's JG). The `security` tier's `JG 23_alloc_budget.sh` now
actually fails the tier/CI job on an over-threshold tree.
**Prove it can fail (executed):** crafted OVER-THRESHOLD MEMAUDIT input
(`/tmp/fx1a10_mem_raw.txt`: 100 B file, 20 MB peak → excess 98500x > 64x) fed to
the script's own extracted heredoc → PY_EXIT=1; old-tail replica → exit 0,
new-tail replica → **exit 1**.

### (b) .github/workflows/rust-clippy.yml — continue-on-error + no -D warnings

Removed `continue-on-error: true` from the clippy step, added `-- -D warnings`
to the invocation, and added `set -o pipefail`. The pipefail line is not
optional: GitHub's default step shell is `bash -e` WITHOUT pipefail, so the
trailing `sarif-fmt` would otherwise mask clippy's exit code — the same swallow
class the audit killed in (a). Invocation now:
`cargo clippy --all-features --message-format=json -- -D warnings | clippy-sarif | tee ... | sarif-fmt`
(message-format before `--`, `-D warnings` after — the canonical form already
used by ci.yml gate step 2 and ci-full.yml clippy).
**Prove it can fail (executed mechanics):** `bash -c 'set -o pipefail; (exit 101) | cat | tee /dev/null | cat'` → **101**; without pipefail → 0. With `-D warnings`, any warning makes clippy itself exit non-zero, and pipefail carries it through the SARIF pipeline to a red step.
