# FX1-A02 — TS-188 probe panics (FIX-PLAN §2 F0.4a)

## Approach

Both sites are the same hand-mirrored off-by-one (the audit's F-001, executed
twice: standalone rustc repro + shipped CLI): the guard admits a window of
**exactly** `PACKET_BYTES` (188) and then indexes `[188]` — one past the end.

- `media-probe/src/signature/phase5.rs` (live production site — the CLI's
  `probe_stream` reaches it for every opened file, no `catch_unwind`): the
  guard `prefix.len() >= TS_PACKET_BYTES` becomes `> TS_PACKET_BYTES`, per
  the audit's own "what correct looks like". An exactly-188-byte window now
  falls through to the existing "lone sync byte" hit — exactly the
  documented contract ("a whole single-packet file is the demuxer's own
  walk to judge").
- `demux/src/ts/mod.rs` `probe` (the test-only twin, panics identically at
  len==188): the guard `header.len() < PACKET_BYTES ||` becomes `<=`, per
  the audit's twin recommendation. At len==188 it returns `true` (accepted
  — the walk will tell), honoring the function's own comment.

Twin agreement is preserved at **every** length (the round-trip suite's
mirror contract): len<188 → hit/`true`; len==188 → hit/`true` (was: panic in
both); len>188 → second-sync check decides. No public API change, no new
error kinds, no exit-code changes.

## Test design

Each crate gets a NEW integration test file (per assignment; both crates
already have `tests/` harnesses — `registry_roundtrip.rs` /
`probe_io.rs`-style for media-probe, `ts_fuzz_survival.rs`-style for demux)
using only deps already present: media-probe uses `testkit` (Must),
`media-types` (PipelineStage); demux uses the public
`demux::ts::test_support::mem_stream`, `plugin_api::Demuxer`, `testkit`.
No `.unwrap()`/`.expect()` anywhere — `match` + `assert!`/`assert_eq!` +
`unreachable!` on impossible arms, matching the neighboring suites.

The oracle is the audit's executed reproduction (187/188/189-byte
controls):

- media-probe `fx1_a02_one_packet_ts_window_never_panics`: the direct
  `TsSignature::probe` boundary sweep — exactly-188 0x47-led window →
  anchored `mpegts` hit, `prefix_consumed == 1` (no panic); 187 → same
  control; 189 without a second sync at [188] → `None`; 189 with 0x47 at
  [188] → hit consuming 189.
- media-probe `fx1_a02_registry_one_packet_ts_window_is_typed`: the
  registry lane the CLI actually runs (`registry.probe` on the window
  `fill_window` truncated to file size): 188-byte 0x47-led window →
  `Ok(mpegts)`; a 188-byte sync-less window → typed `probe.no-demuxer`
  at stage Probe (the existing exit-65 lane).
- demux `fx1_a02_probe_accepts_an_exactly_one_packet_header`:
  `demux::ts::probe` boundary sweep — 188 → true (no panic), 187 → true,
  189-without-second → false, 189-with-second → true.
- demux `fx1_a02_truncated_one_packet_ts_refuses_typed`: a crafted

  existing typed `demux.ts.no-pat` error, sticky across retries — the
  exact error the audit's executed 187-byte CLI control produced.
