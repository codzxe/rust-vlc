# FX1-A05 — ADTS zero-length walk guard + argv non-UTF8 typed refusal (FIX-PLAN §2 F0.4e+f)

## Approach

**F0.4e — where the defect really lives (no drift).** The assignment
asked to verify the cited lane: `rg "frame_length" apps/cli/src/containers/`
answers with exactly one file — `apps/cli/src/containers/ts.rs` (the
`PesBridge::mint_adts_aus` AU-split walk, pre-edit lines 354-377 ≈ the
cited 354-376). The finding is recorded against
`audit/files/apps/cli/src/containers/ts.rs.audit.md` (W13-A08 F-001, S1,
executed replica probe: 1 000 000 iterations, `at=0`, "NON-PROGRESS").
`containers/adts.rs` is a *different* lane (the raw-ADTS open path) — it
delegates to the demux crate's `AdtsDemuxer`, whose three own lanes
(`crates/demux/src/adts/mod.rs:530/659/928`) already refuse the shape;
nothing to fix there. So the fix lands in ts.rs, as the plan cited.

The fix adopts the audit's own "what correct looks like" and the demux
crate's strict policy: `frame_length < header_len()` (zero included,
and 1..=6 sub-header lengths too — the audit's "unify" open question)
→ mint nothing, count the remaining payload bytes as recovered damage
(`ts.pes.adts-short-frame`), stop the walk — bounded, never a re-parse
of the same header. Secondary effect: the walk no longer falls through
to the whole-PES fallback on confirmed ADTS damage (a third policy the
audit explicitly asked not to introduce).

**F0.4f — argv non-UTF8.** `std::env::args()` (main.rs:14, as cited)
panicked on any non-UTF-8 argv element (executed: `$'\xff\xfe'` → exit
101 before a single player line). Now `std::env::args_os()` + a small
testable library helper `parse::argv_string(&OsStr) ->
Result<String, ParseError>`: a non-UTF-8 token is the grammar's own
typed `invalid-argument` refusal — message names the class only
(redaction-safe, no lossy mojibake), `USAGE` hint rides along, printed
by the runner's own `print_parse_error` (made `pub`, so main's refusal
cannot drift from `run`'s parse-refusal shape) + exit 64 EX_USAGE via
the tested `exit::exit_code(InvalidArgument)` table — the same lane
every other argv-grammar refusal takes. No panic, no magic number, no
`CommandError`/`Stage` vocabulary abuse (grammar failures were never
pipeline-stage failures — `run` keeps its `ParseError` lane).

## Test design

All four tests are `fx1_a05_*` (assignment naming), in the one new
integration file, using only existing deps (`testkit`, `commands`,
`demux::ts::test_support` — public by design "for the integration
suites", `plugin_api`, `media_types`, `lumen_cli` itself):

- **argv** (helper unit tests, the pinned seam main.rs now rides):
  - `fx1_a05_argv_string_passes_valid_tokens_through` — ASCII and
    non-ASCII UTF-8 pass verbatim (the boundary is not a new refusal
    point for legal argv).
  - `fx1_a05_argv_string_refuses_non_utf8_typed` (cfg(unix) + a
    cfg(windows) twin of the same name) — the audit's executed 0xFF
    0xFE bytes / an unpaired surrogate: `Err`, hint == `USAGE`,
    message contains "not valid UTF-8", no `\u{FFFD}` echo.
- **ADTS** (through the REAL public open path — `open_source` →
  probe → container registry → the PES bridge; crafted TS built with
  the demux crate's public `test_support` builders, the ts.rs
  suite's own `synthetic_ts` shape with the audio PES replaced by
  the hostile payload):
  - `fx1_a05_zero_length_adts_frame_does_not_wedge_the_au_split_walk`
    — the audit's exact 7-byte crafted frame (`FF F1 50 00 00 00 00`:
    sync ok, rate resolvable 44 100, 13 zero length bits) as the whole
    audio PES. Pre-fix this test does not terminate (the finding);
    post-fix: bounded — audio mints **no** packet, the damage is
    counted typed `ts.pes.adts-short-frame` (7 bytes exactly), the
    video lane still demuxes, EndOfStream arrives. The second expected
    record `pes.length-overrun` (163) is the assembler's own honest
    accounting for the transport pad after the short crafted PES.
  - `fx1_a05_zero_length_adts_frame_stops_the_walk_after_good_aus`
    — `[good 85-byte AU][zero-length frame]`: the good AU still mints
    with its 128 000 anchor stamp, the walk stops AT the damage
    (neither skips past it nor re-parses it), remaining 7 bytes
    counted, EndOfStream arrives. Pins the bounded-advance semantics
    and the stop-and-count policy choice.

## Acceptance vs FIX-PLAN

- F0.4e acceptance ("crafted zero-length ADTS packet must not wedge
  the stream"): satisfied — the walk is provably bounded (both tests
  terminate; the pure-hostile PES mints nothing and counts the damage
  typed through the module's own `Recovered` ledger).
- F1.1's ADTS clause ("a crafted zero-length ADTS packet does not
  wedge the stream (F0.4e)") — the CLI lane is the guarded one.
- F0.4f acceptance: non-UTF-8 argv now produces the CLI's typed
  refusal (parse-error shape, exit 64) instead of a Rust panic
  (exit 101 + rustc path leak); the executed repro
  `./lumen $'\xff\xfe'` now lands in the refusal arm.
- Workspace lints: no unwrap/expect/panic added in src; tests use
  assert/unreachable! per the file's own convention.

## Risks & followups

- **Policy choice, documented**: the guard stops at the first short
  frame (counting the rest of that PES as damage) rather than
  resync-scanning past it — this matches the demux crate's strict
  first-frame refusal and the audit's suggested fix; a mid-PES
  byte-resync was deliberately not built (bigger semantic change).
  Good AUs after a short frame inside the SAME PES are dropped as
  counted damage; the next PES still mints normally.
- **argv refusal is refuse-typed, not lossy-with-warning**: the audit
  offered both; refusing matches the crate's own non-UTF-8 *path*
  refusal posture (`file_uri_from_canonical`'s typed "the path is not
  valid UTF-8") and avoids mojibake `input.inaccessible` lies. A
  follow-up subprocess test (raw-bytes argv → real binary, exit 64)
  would pin the main.rs arm end-to-end; the in-process tests pin the
  conversion seam.
- The same `std::env::args()` panic class remains at other entry
  points outside this assignment's scope (rg: `apps/desktop-tauri/
  src/app.rs:276`, `apps/control-server/src/main.rs:265`, several
  tools/* binaries) — flagged for a follow-up card (the audit's own
  open question).
- Not compiled (wave gating): the five files are rustfmt-parse-clean
  (edition 2024) and lint-audited by review; the ADTS tests' expected
  event ledger (the `pes.length-overrun` counts 163/78) is derived
  from `PesAssembler::try_complete`'s pad accounting — if that policy
  ever changes, these two assertions track it.
