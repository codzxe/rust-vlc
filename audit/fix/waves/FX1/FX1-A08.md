# FX1-A08 — mp3 xing VBRI slice OOB + ogg-flac second-header 38→34 (F0.4k+l)

## Approach

**F0.4k (xing.rs `parse_vbri` slice OOB).** The audit's exact finding
(W07-A04 F-001 S1; re-verified W20-A01 F6): the guard `rest.len() < 14`
admits every tail length in 14..22 and then indexes `rest[14]`..`rest[21]`
(four TOC-geometry words) — "the guard admits len ∈ [14, ∞); `rest[14]`
needs len ≥ 15; `rest[20]` needs len ≥ 21" → `index out of bounds` panic.
The audit's own "what correct looks like": `if rest.len() < 22` (the fixed
VBRI fields are 22 bytes past the magic). Fix = exactly that, plus the
audit's secondary correction: the error's `expected: pos + 18` was wrong —
the fixed fields end at `pos + 4 + 22`. Site confirmed at
`crates/codecs/src/audio/mp3/xing.rs` guard + `rest[14..21]` indexing (was
340/344/364-367; no drift).

**F0.4l (ogg-flac second header 38→34).** The assignment's search hints
(rg "38" alongside flac/ogg in `crates/codecs/src/` + `crates/demux/src/ogg/`)
find **no** 38-byte length check there — the demuxer side is correct
(`demux/src/ogg/mod.rs:304-314` documents "native block header (4 bytes) +
…" and `flac_streaminfo_rate` bounds-checks `len < 17`). The real
38-vs-34 defect per the audit evidence (W13-A06 F-001 S1,
DEVIL-AUDIT-REPORT:178, wave-FX1.tsv "ogg-flac header location per audit
evidence") is `apps/cli/src/containers/ogg.rs:191-199`: the host seeds the
second header packet **verbatim** (38 bytes = 4-byte METADATA_BLOCK_HEADER +
34-byte STREAMINFO) into `FlacDecoder`, whose contract (decoder.rs:30-34,
"the 34-byte STREAMINFO body verbatim") parses the first 34 bytes as the
body → block header parsed AS body → garbage rate. Executed proof:
crafted spec-shaped .oga through `lumen open` → `flac.streaminfo.rate:
sample rate 0 is invalid`; every real .oga flac hits it. The audit's fix:
seed `h[4..]` (strip the METADATA_BLOCK_HEADER) after validating the block
type/length. **Drift noted:** assignment text suggested codecs/demux sites;
actual site is the CLI ogg host (the wave tsv anticipated locating it "per
audit evidence").

## Changes per file

1. `crates/codecs/src/audio/mp3/xing.rs` — `parse_vbri` guard
   `rest.len() < 14` → `< 22` (+ 5-line comment stating the fixed-field
   span and the panic window); `expected: pos + 18` → `pos + 4 + 22`. No
   API change; the `mp3.vbri.truncated` code is unchanged.
2. `apps/cli/src/containers/ogg.rs` —
   - new private fn `flac_streaminfo_body(Option<&SharedBytes>) -> Vec<u8>`:
     validates the second header packet's 4-byte metadata-block header
     (type 0 = STREAMINFO after masking the last-block flag, 24-bit BE
     declared length == 34) and returns the packet's bytes 4..38 — the
     34-byte body. Malformed (missing / wrong type / lying length / shorter
     than 38 bytes) → the empty blob, so `FlacDecoder::configure` refuses
     typed, never a guess (pre-existing shape for a missing second header).
   - harvest's flac arm now seeds `flac_streaminfo_body(headers.get(1))`
     instead of the verbatim packet (replaces the `match headers.get(1)`
     block).
   - module doc's FLAC bullet rewritten to the true contract (the audit
     rated the old "the FLAC decoder's 34-byte requirement" doc claim
     FALSE alongside the 38-byte seed).
   - one new unit test in the file's existing `mod tests` (see below).
3. `crates/codecs/tests/fx1_a08_tag_bounds.rs` — NEW integration test
   file (the assignment's prescribed location), 2 tests, existing deps
   only (`codecs`, `media-types` — no dev-dep additions).

## Test design

All expected outcomes were first re-derived with a cargo-free python3
simulation of the exact parse logic (scratch in /tmp, deleted nothing in
repo) — every assertion below matches the simulated pre/post behavior.

- `fx1_a08_truncated_vbri_and_xing_tails_refuse_typed_never_panic`
  (codecs integration): the audit's crafted shape (MPEG-1 L3 stereo frame
  `FF FB 90 00`, 32-byte side info, `VBRI` at ancillary offset 36,
  nonzero `0x41` filler — scratch/W20-A01/vbri_repro.rs) through the
  public `codecs::audio::mp3::parse_vbri` for **every tail length
  0..21** → typed `mp3.vbri.truncated` (pre-fix, tails 14..21 panicked at
  `rest[14]`..`rest[21]`; a regressed guard aborts the test process, so
  the pin cannot pass silently); tail 22 (first in-bounds length) → the
  unchanged `mp3.vbri.toc_truncated` boundary behavior; plus two truncated
  Xing-tag shapes through `parse_xing` → `mp3.xing.frames_truncated` /
  `mp3.xing.toc_truncated` (the assignment's "truncated VBRI/Xing tag …
  asserting no panic", both parser paths).
- `fx1_a08_ogg_flac_second_header_body_is_exactly_34_bytes` (codecs
  integration): the audit's crafted STREAMINFO body (scratch/W20-A01/
  mkoga.py: 48 kHz, stereo, 16-bit, 4096 fixed block, 4096 total) parses
  with exact facts; a 33-byte body is typed-refused
  (`flac.streaminfo.short`, the assignment's "33-byte one is
  typed-refused"); the verbatim 38-byte second-header packet
  (`80 00 00 22` ‖ body) parses as **garbage** — pinned to the audit's
  executed refusal code `flac.streaminfo.rate` (the `lumen open` output)
  so the packet can never again be handed as the body.
- `fx1_a08_flac_extra_data_is_the_stripped_34_byte_body` (unit test in
  apps/cli containers/ogg.rs `mod tests`): the helper on the spec-shaped
  38-byte packet yields the 34-byte body that
  `codecs::audio::flac::parse_streaminfo` accepts (48 k/2ch/16-bit);
  malformed second headers (33-byte body, PADDING block type 1, declared
  length 33, no second header) seed the empty blob → typed refusal at
  configure. This is the direct pin of the host-side strip fix.

## Risks & followups

- The audit's exact end-to-end oracle for F0.4l (`lumen open` on a
  crafted .oga file) is not a committed binary fixture (crafting one
  needs an ogg-CRC generator; the audit's mkoga.py lives in
  audit/scratch, outside my editable set). Coverage stands at the
  parser boundary + host helper; a fixture + full open-lane test is the
  natural follow-up card.
- xing.rs audit items out of F0.4k scope remain: F-004
  (`toc_entry_size.max(1)` fabrication), F-002 (demuxer's own Xing/VBRI
  skip duplication — verified bounds-safe at es/mp3.rs:599-633), F-005
  (64-byte tolerant scan).
- ogg.rs audit F-006 residue kept deliberately: malformed FLAC second
  headers seed an empty blob (→ `flac.streaminfo.short` typed refusal),
  not `None` (→ `flac.streaminfo.missing`) — changing that is a separate
  S4 decision, not F0.4l.
- The demuxer's own `flac_streaminfo_rate` (len<17) and
  `is_header_packet`'s un-flagged `[0x00,0x00,0x00,0x22]` prefix are
  the demux crate's seams — untouched, no defect found there; the
  second header is stashed via the `flac_clock_now` arm regardless of
  that prefix, so the fixed host arm is reachable for both 0x00- and
  0x80-flagged writers.
