# FX1-A06 — streaming crate numeric-overflow guards (FIX-PLAN §2 F0.4g+h)

## Approach

All four defects are the same class: attacker-controlled numeric facts
(playlist/manifest attributes) flow into unchecked arithmetic in a crate
whose own contract (module docs, fuzz harnesses, wave-10 audit) promises
panic-free typed refusals. The fix posture at every site is the module's
existing typed refusal — no new error variants, no signature changes, no
public API churn:

* **DASH (resolve.rs)** — both divisions are ceil-division of a span by a
  tile duration that a crafted manifest sets to zero; the count is then
  mathematically undefined/infinite. The module's existing
  `DashResolveError::TimelineExtentUnknown` is the honest refusal for
  exactly that ("the extent is unknowable — never a guess", per the module
  doc); the audit itself accepted a typed refusal at this site. I chose it
  over `MissingFact` because "fact absent" is a false statement for a
  present-but-zero attribute, while "extent unknown" is true for both
  inputs. No line drift: the audit's cited sites (:410 and :735) match the
  current source verbatim, and the guard also covers the :416 twin that
  F-002 names ("both occurrences, L410 and L416").
* **HLS master (master.rs)** — the assignment allowed "checked/saturating
  math per file style"; a *saturating* subtraction at the panic site would
  compute a wrong window offset and silently serve bytes from the wrong
  position (data corruption — the file's own doctrine is "a gap is never
  served silently"), and the audit's alternative (clamping absorb's
  retention to the tail) still leaves the evicted prefix unreachable from
  a sequential cursor. The honest behavior is the *typed refusal*
  (the audit's other accepted option): the read at an evicted cursor
  refuses with a stable dotted code, the cursor is untouched, and a
  forward seek past the evicted body resumes the stream — all pinned by
  the test.
* **timestamp_map.rs** — the ISO-8601 parser's documented contract is that
  an out-of-range value is `None` (never fatal, never a wrapped anchor);
  the "typed error" for this function *is* `None`. The accumulation chain
  becomes `checked_mul`/`checked_add`, bit-identical in range.

## Changes per file

**crates/streaming/src/dash/resolve.rs** (3 hunks)
1. `expand_timeline`, negative-`@r` arm: early `entry.d == 0` guard →
   `Err(TimelineExtentUnknown)` before the `span / entry.d` ceil-divisions
   (covers both the next-`@t` and period-end branches — audit F-002, panic
   at :410, twin at :416).
2. `fixed_segment_count`: `duration == 0` → `return None`, which the sole
   caller already converts to `Err(TimelineExtentUnknown)` (audit F-001,
   panic at :735). Zero-`@duration` tiles no period finitely — the count
   is unknowable, the same `None` semantics the function already uses.
3. Module doc: one added clause stating the zero-tile rule (zero `@d` /
   `@duration` refuses the same way — never a divide-by-zero), so the
   module's contract text stays true after the change.

**crates/streaming/src/hls/master.rs** (1 hunk)
* `serve`: before the retained-window offset math, a guard
  `if self.pos < self.retained_from` mints
  `ErrorKind::Inaccessible { AccessDenied::NotFound }` with code
  `streaming.hls.read-unretained` (mirroring the file's existing
  `streaming.hls.seek-unretained` refusal shape). This is the audit's
  F-001 usize-underflow site: previously `pos - retained_from` wrapped
  (debug: "attempt to subtract with overflow"; release: the wrapped index
  sliced an empty window and panicked). Invariant analysis: the only
  reachable `pos < retained_from` state is the oversized-body eviction
  (a body larger than `max_retained_bytes`, which `HlsMasterConfig::
  validate` accepts), so the guard never fires on the healthy path; after
  the guard, `at ≤ retained.len()` holds by the window-coverage invariant,
  so `have ≥ 1` and the loop always progresses (no livelock introduced).

**crates/streaming/src/hls/timestamp_map.rs** (2 hunks)
* `parse_iso8601_utc`: the unchecked chain
  `((days * 24 + hour) * 60 + minute) * 60 * 1000 + second * 1000 +
  frac_ms` replaced by the equivalent checked chain
  (`days.checked_mul(24)?.checked_add(hour)?` … through
  `checked_add(frac_ms)?`), returning `None` on any overflow step — the
  executed 9-digit-year repro (audit W10-A06 F-001, panic at :195 under
  overflow-checks, silently wrapped anchor `-5336598346174303232` in
  release; netfuzz-reachable via `from_playlist_text`).
* Function doc extended: "a year past the i64 epoch-millisecond horizon"
  added to the refused-field list.

**crates/streaming/tests/fx1_a06_numeric_guards.rs** — NEW file (see next
section). Existing dependencies only (`playlists` is a regular dependency
of `streaming`, same as `tests/netfuzz_sweep.rs` uses it; mockhttp +
testkit are the crate's own testkit; no Cargo.toml changes).

## Test design

One test per guard, named `fx1_a06_*`, in a NEW integration-test file
(avoiding edit collisions with sibling agents in the crate):

1. `fx1_a06_dash_template_duration_zero_refuses_typed` — the audit's
   F-001 shape: a tiny crafted MPD (`PT10S` period with a known end,
   `SegmentTemplate duration="0" media="$Number$.m4s"`) parsed by the real
   `playlists::parse_mpd_bytes` and driven through the public
   `plan_representation` → exact `Err(TimelineExtentUnknown)`; control:
   the identical manifest with `duration="3"` plans `ceil(10/3) = 4`
   segments (the normal division is unchanged — the guard refuses only
   zero).
2. `fx1_a06_dash_timeline_d_zero_negative_r_refuses_typed` — the audit's
   exact executed vector `[S(t=0,d=0,r=-1), S(t=50,d=10)]` → exact
   `Err(TimelineExtentUnknown)`; control: the resolve.rs unit test's own
   vector (`d=10`, bounded by `t=35`) plans 5 segments end-to-end
   through the parser.
3. `fx1_a06_hls_master_oversized_segment_refuses_typed` — a 3-segment VOD
   ladder over the real mockhttp server (the `tests/hls_master_e2e.rs`
   convention): seg0 = 24 B (fits, serves byte-exact), seg1 = 64 B >
   `max_retained_bytes = 32` (a config `validate` accepts — only the
   zero limits and the 1 GiB ceiling are checked; the response budget
   still admits the body, the audit's exact trigger) → `read` refuses
   typed `streaming.hls.read-unretained`, the cursor is unmoved
   (`position() == 24`), and a forward seek past the evicted body
   resumes the stream on seg2 (the guard refuses only the evicted range,
   never wedges the session). Pre-fix, this test's middle read is the
   debug panic site itself.
4. `fx1_a06_hls_timestamp_map_year_overflow_refuses_none` — the audit's
   executed input `LOCAL=999999999-01-01T00:00:00Z` → `None` both via
   `parse_tag_value` and via the netfuzz-reachable
   `from_playlist_text`; an in-range year (292277025 — the audit
   probe's own boundary pick, far inside the true horizon) still
   parses with the probe's exact image `9223309881446400000`, so the
   guard is exact arithmetic, not a blanket year cap — a
   `year > 9999` cap would have refused it (the checked chain's true
   horizon is year ≈ 292 278 994, per re-derivation); a sane anchor
   (2000-02-29T12:34:56.789Z) is unchanged.

Every test asserts the *specific* refusal value, so a misparsed crafted
input cannot pass vacuously; every test carries its non-overflowing
control, so the guards demonstrably refuse only the overflowing
arithmetic.

## Acceptance vs FIX-PLAN

* **F0.4g** ("dash resolve div-by-zero ×2 — resolve.rs:410,735"):
  both sites guarded (plus the :416 twin from audit F-002); crafted MPDs
  with `@duration="0"` / `@d="0"` + negative `@r` no longer panic — they
  refuse typed, pinned by tests 1 and 2.
* **F0.4h master underflow**: the usize/u64 underflow path is a typed
  read refusal; healthy reads, backward-seek refusals, and the
  post-eviction resume are unchanged/pinned (test 3).
* **F0.4h timestamp_map overflow**: "overflow on accumulation; checked
  arithmetic" — the accumulation chain is fully checked; the typed
  error surface for this parser is its documented `None` contract
  (test 4 pins both the refusal and the exact in-range boundary).
* Cluster acceptance (F0.4 row: "every crafted input from the audit
  re-runs … no exit 101"): each of the four audit-executed crafted shapes
  re-runs as a test oracle; the panic lanes are removed.
* Lints: no `unwrap`/`expect`/`panic!` added (tests use `testkit::Must`
  / `assert_err` / `unreachable!` exactly like the crate's existing
  tests); no new TODO/FIXME markers; no dependency or Cargo.toml edits.

## Risks & followups

1. **The same underflow lives in the siblings** (out of scope):
   `hls/media.rs` `absorb`/`serve` (W10-A09 confirmed S2 — identical
   code) and `hls/live.rs` carry the same retained-window shape and are
   NOT fixed by this assignment (F0.4h names master.rs only). They need
   their own guard assignment.
2. **timestamp_map F-002 (S4) not fixed** (not in F0.4h's scope — it
   names the executed parse-chain overflow): `wallclock_ms_for_pts`
   still has an unsaturated add; with F-001 fixed, a parseable
   legal-year anchor near the i64 ceiling can still overflow the forward
   map. Small `saturating_add` follow-up (the inverse map already
   saturates).
3. **Wording**: `TimelineExtentUnknown`'s Display enumerates only the
   no-bounding-`@t` cause; the two zero-tile refusals are semantically
   "extent unknown" but the message text does not list the zero-duration
   cause (same pre-existing wording class as audit F-007). A dedicated
   variant or wording amendment is a Lead decision (public API).
4. **Still open in resolve.rs** (audit F-003/F-004/F-005…): the pre-fold
   URL budget accounting and the f64 tick truncation are untouched —
   separate defects, separate assignments.
5. Tests were not executed by this agent (cargo is centrally gated);
   rustfmt-parsed (all four files) and manually type-reviewed. The
   orchestrator's central compile+test run is the compile oracle — if a
   crafted-MPD string mismatches the playlists parser's tolerance (my
   shapes mirror the parser's own test vectors and the ffmpeg fixture
   nesting), that is the one place this could surface.
6. Transparency note (honesty contract): one read-only
   `git diff | head -1` was invoked by accident mid-session (it printed
   one header line, changed nothing); no other git or cargo command was
   run, and no state was altered by it.
