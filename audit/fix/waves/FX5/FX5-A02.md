# FX5-A02 — the audio-controls catalog verbs (FIX-PLAN §3 F1.1c, wave-FX5.tsv row FX5-A02)

## Approach

The drift this row exists to close was disclosed by FX4-A02's report
(drift #1): the engine seam (FX3-A03's `AudioControls`) carries
`set_balance(position: f32)` / `set_eq(low_db, mid_db, high_db,
preamp: Volume)` / `balance()` / `eq_bands()`, but the command catalog
had NO `audio.set-balance` and NO `audio.set-eq` id anywhere — the UI
dispatched `audio.set-eq` into the host's honest `unsupported-for-host`
refusal and balance had no verb at all. My file domain is the catalog
itself: add the ids mirroring the set-volume family everywhere a verb
id touches (id enum, spec table, payload enum, result enum, wire types,
the three committed codegen artifacts, and the count pins the catalog's
own tests carry).

**How the family was read first.** `audio.set-volume` (class S,
engine-targeted, not gen-bumping, args `volume: Volume` → result
`AudioVolume` shared by set+get), `audio.get-volume` (args none, same
result), `audio.set-mute` (args `muted: bool` → `AppliedBool`), and the
additive-row precedent (the issue #32 bookmark trio and the w31.1
frame-channel bind are appended at the tail of their family in
ids.rs/spec.rs/`Command`). The get-verb convention EXISTS in the volume
family (`audio.get-volume`), so the assignment's parenthetical adds the
read twins too — four rows total, all class S, appended after
`audio.set-delay` in every table (enum order == spec-table order ==
schema oneOf order; `tables_cover_every_id_exactly_once_in_order` and
`spec_table_covers_exactly_the_enum_variants` pin all three as the same
set/order).

**The sibling contracts, read before finalizing the shapes** (my
assignment names them): FX4-A02's report (AudioVolume/AppliedBool
result discipline — "the response says what IS, never the request
echoed"), FX4-A08's UI payload `{ lowDb, midDb, highDb, preampDb }`
(camelCase, one-to-one with the engine setter), FX5-A03's landed host
routing, and FX5-A05's landed UI reconciliation. FX5-A03's landed code
guessed `balance` for the set-balance field and a FLAT
`CommandResult::AudioEq { low_db, … }`; FX5-A05's final-verification
pass (after both siblings landed) read MY landed catalog and pinned the
opposite: their report's risk #2 states the mismatch verbatim ("the
destructuring must read `position`") and their test
`fx5_a05_eq_completed_answer_smears_no_player_state` asserts MY nested
result (`{ kind: "audio-eq", eq: { lowDb, … } }`) as "the REAL landed
result". FX5-A03's own report pre-authorized its four sites as the
reconciliation surface ("a rename, no architecture"). I kept my shapes
(see Risks #1 for the exact sites + why bending could not have made the
wave compile anyway).

## Verb ids added and payload shapes (precise)

- **`audio.set-balance`** — `Command::AudioSetBalance { position: f32 }`.
  The pan position the engine seam takes
  (`AudioControls::set_balance`): `−1.0` hard left … `0.0` center …
  `+1.0` hard right; the doc comment pins the hard stops and the
  typed-not-clamped discipline (the boundary refuses
  non-finite/out-of-range with the engine's own
  `audio.effects_balance_position` — never a clamp).
- **`audio.get-balance`** — `Command::AudioGetBalance`, args none (the
  `audio.get-volume` read-twin pattern).
- **`audio.set-eq`** — `Command::AudioSetEq { low_db, mid_db, high_db,
  preamp_db }` (f32; wire camelCase `lowDb`/`midDb`/`highDb`/
  `preampDb`). The engine's `Eq3Band` truth: low 250 Hz shelf / mid
  1 kHz peak / high 4 kHz shelf (fixed corners), band gains in dB
  (runtime bound ±40). The preamp mapping is documented in the variant's
  doc comment: the wire carries the trim in dB (the `20·log10`/
  `10^(db/20)` amplitude convention — FX4-A08's UI payload maps
  ONE-TO-ONE, which is why the field set is exactly the UI's), and the
  host converts to the engine's linear `Volume` at the boundary (the
  conversion FX5-A03's landed `audio_set_eq` already performs via
  `Volume::from_db`).
- **`audio.get-eq`** — `Command::AudioGetEq`, args none.
- **Results** (shared by each set/get pair, the `AudioVolume`
  precedent): `CommandResult::AudioBalance { position: Option<f32> }`
  and `CommandResult::AudioEq { eq: Option<AudioEqBands> }`, where
  `AudioEqBands` (new wire struct in types.rs) is `{ low_db, mid_db,
  high_db, preamp_db: f32 }` (`deny_unknown_fields`, camelCase wire).
  The `Option` is the stage truth the engine's own getters carry
  (`balance()`/`eq_bands()` return `Option` — a balance stage ABSENT is
  the identity split, ≠ position `0.0`; an armed flat EQ is
  `(0, 0, 0, 0 dB)`, ≠ absence). Set verbs answer `Some(applied)` (the
  chain's read-back); get verbs answer the stage truth, `null` for
  absent — never a sentinel (V3).

**The artifacts were regenerated without cargo** (the ban forbids
`cargo xtask codegen`, the designed regenerator): the schema entries
follow the committed file's own emission patterns exactly (properties
sorted, `required` in declaration order, descriptions = the
rustfmt'd doc comments joined with `\n`, f32 → `number`/`format:
"float"`, `Option<f32>` → `type: ["number","null"]`, `Option<struct>`
→ `anyOf [$ref, null]`, `$defs` sorted, oneOf arms in declaration
order), the TS follows the emitter's conventions (`export type
AudioEqBands = { highDb: number; … }`, the four request members and
two result members at the family positions), and the checksum file's
three FNV-1a digests were computed over the new bytes + the canonical
catalog text. The method is machine-validated: the pre-quartet
canonical text reproduces the committed baseline digest
`debb80f9922a192a` exactly, the new file's digests recompute from the
live tables and the final artifact bytes, and every new schema
description equals its source doc comment (all asserted by the
verification scripts; final values: catalog `4c76daa855302ba1`, schema
`be9a1f9da6fe4edd`, typescript `a52a9a6eda71263f`). The central run's
`committed_artifacts_match_regeneration` (catalog_drift.rs) is the
byte-identity gate — if schemars would emit even one different byte
anywhere, that test fails loudly with the first differing line and
`cargo xtask codegen` is the one-command authoritative fix (see Risks
#3).
