# FX5-A03 — the host routing for the two new audio verbs (FIX-PLAN §3 F1.1c, wave-FX5.tsv row FX5-A03)

## Approach

FX4-A02 landed the volume family (`audio.set-volume`/`get-volume`/
`set-mute`) through host methods → `audio_limb_controls` (the one
seam helper over `ConsumerState::audio_mut()` →
`AudioLimb::audio_controls()`) → SERVED dispatch arms, and its report
disclosed the drift my row exists to close: there was no
`audio.set-balance`/`audio.set-eq` catalog id to route ("the day the
catalog grows those ids the routing is a dispatch arm away"). FX5-A02
(same wave) grows the catalog; my job is exactly that dispatch arm
plus the two host methods — the identical pattern, verb for verb:

- **set-balance**: the range refusal lives at the
  `AudioControls::set_balance` boundary itself (the setter returns
  `Result` — `audio.effects_balance_position` for non-finite or
  out-of-range positions), mapped through the one `wire_error`
  bridge; refused-without-session (`no_session_open`,
  Stage::Session/NotReady) and limb-less refusal
  (`no_audio_limb`, Stage::AudioOutput/NotReady) mirror the volume
  family exactly.
- **set-eq**: the preamp crosses at the control boundary
  (dB → the engine's linear `Volume` via `from_db`, the
  `audio.gain_db_*` codes), then `AudioControls::set_eq` — the
  in-place coefficient recompute with the biquad state preserved,
  never a rebuild (FX3-A03's `Eq3Band::set_bands`).

Both verbs are class S and answer the chain's own read-back getters
(`balance()` / `eq_bands()`), never the request echoed — FX4-A02's
"the response says what IS" discipline. The read-backs are `Some` by
construction after the accepted set; the `unwrap_or` fallback names
the just-applied value, never a fabricated default (documented at the
site; `unwrap_or` is not the denied `unwrap_used` pattern — the
codebase's own `unserved()` uses `unwrap_or_else`).

**Same-wave parallel landing, stated per the honesty contract.** At my
write time the catalog ids do NOT exist in the tree
(`rg 'set-balance|set-eq|SetBalance|SetEq' crates/commands` → empty)
and FX5-A02's report does not exist yet
(`audit/fix/waves/FX5/` had no FX5-A02.md). Per the assignment I coded
against the frozen contract — the verb ids
`audio.set-balance`/`audio.set-eq` (the wave tsv's own naming) — with
payload shapes following the set-volume family's conventions plus the
wave's one prior shape declaration (FX4-A08's UI seam, which its
report describes as "shape-identical to the catalog's
command-request members"):

- `Command::AudioSetBalance { balance: f32 }` — the position,
  −1.0..=+1.0 (the engine's own hard stops; the mechanical
  `audio.set-balance` → `AudioSetBalance` id mapping of ids.rs §2.1);
- `Command::AudioSetEq { low_db, mid_db, high_db, preamp_db }` (f32
  scalars, wire camelCase `lowDb`/`midDb`/`highDb`/`preampDb`) —
  FX4-A08's `EqSetArgs`, "the direct mirror of the engine's
  `AudioControls::set_eq(low_db, mid_db, high_db, preamp)` in the
  wire's camelCase convention", which FX5-A05's row re-points the UI
  onto;
- results `CommandResult::AudioBalance { balance: f32 }` and
  `CommandResult::AudioEq { low_db, mid_db, high_db, preamp_db }` —
  the applied-truth scalars, following the same family's
  `AudioVolume { volume }` precedent (§2.6's "the applied value is
  the truth").

This is the FX4-A02 posture toward FX4-A01's then-unlanded seam: the
orchestrator's central compile is the oracle. **The reconciliation
surface if FX5-A02's landed shapes differ** is exactly four
mechanical sites, each naming the guessed id once: the two result
constructions + one destructure in host.rs, the two route-arm
patterns in dispatch.rs, the `catalog_ids` mapping row in help.rs,
and the Command constructions/result matches in the one test file.
No architecture changes with any of them.

## Risks & followups

1. **The FX5-A02 contract assumption is the one real risk** (document
   in Approach): my four files reference the catalog variants
   `AudioSetBalance { balance }` / `AudioSetEq { low_db, mid_db,
   high_db, preamp_db }` and the results `AudioBalance { balance }` /
   `AudioEq { low_db, mid_db, high_db, preamp_db }`, none of which
   were in the tree at my write time. If FX5-A02's landed shapes
   differ (field names, an `Option`-carrying result, a `Balance` type
   alias, a bands object), the central compile fails and the
   reconciliation is the four mechanical sites listed in Approach —
   a rename, no architecture. If FX5-A02 instead lands nothing, the
   wave's compile breaks on the missing variants themselves and the
   orchestrator sees it immediately (the same visibility FX4-A02's
   seam risk had).
2. **The balance stereo gate rides at process time through this raw
   handle** (FX4-A01's own documented seam posture —
   `AudioLimb::audio_controls`'s doc): the pipeline's surface
   pre-validates `spec.channels == 2`, the raw `&mut AudioControls`
   hand-off cannot, so a `set-balance` on a MONO session takes the
   `Ok` here and the typed `audio.effects_balance_channels` fires
   from the next `stage` (surfaced loudly by the pump's error lane,
   never a silent mislabel). My tests run the stereo fixture; a mono
   balance pin belongs to whoever wants a pre-validation at the host
   (it would need the limb's channel count at the seam — a
   pipeline_host change, not mine).
3. The EQ read-back renders the preamp from the stored linear `Volume`
   back to dB (`Volume::db()`); non-unity preamps round-trip within
   float noise (FX3-A03's own from_db/db round-trip tolerance) — the
   tests pin the exact-zero identity case and the band gains verbatim.
   A deep-negative preamp dB underflows to linear silence and `db()`
   renders −inf, the type's own documented honest rendering; not
   poked by the tests (no shipped UI sends it; FX4-A08's panel range
   is ±20 dB).
4. `audio.get-balance`/`get-eq` read twins do not exist (the wave
   adds only the two set verbs, per the tsv) — the UI's faders remain
   the editing surface (FX4-A08's design) and hydration of balance/EQ
   state awaits a snapshot/read-verb card; noted, not invented here.
