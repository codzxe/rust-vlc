# FX2-A10 — the HLS retained-window underflow twins (media.rs + live.rs)

## Approach

The two siblings carry the *identical* code FX1-A06 fixed in
`hls/master.rs` (FIX-PLAN F0.4h class; FX1-A06's risk item #1): the
same `absorb` budget rule ("retain nothing for a single body over the
whole budget") and the same `serve` retained-window math, where a
config-accepted oversized segment body sets `retained_from =
fetched_upto` past the read cursor and `pos - retained_from`
underflows (debug: "attempt to subtract with overflow"; release: the
wrapped index then fails the retained-slice bounds check — a
guaranteed panic in both profiles). The fix is the exact idiom of the
master.rs guard, mirrored in both files: a `pos < retained_from`
check before the offset math that mints
`ErrorKind::Inaccessible { AccessDenied::NotFound }` with the code
`streaming.hls.read-unretained` — the master fix's code, so the three
sessions refuse identically. The cursor is untouched by the refusal; a
forward seek past the evicted body resumes the stream.

Invariant analysis (same as the master fix's, re-derived per file):
the only reachable `pos < retained_from` state is the
oversized-body eviction (a body larger than `max_retained_bytes`,
which both configs' `validate` accepts — only zero limits and the
1 GiB ceiling are checked), so the guard never fires on the healthy
path; after the guard, `absorb`'s coverage invariant
(`retained_from + retained.len() == fetched_upto`, W10-A06's own
re-derivation for live.rs, W10-A09's for the module family) gives
`at ≤ retained.len()`, so `have ≥ 1` and the serve loop always
progresses — no livelock introduced.

## Test design

One test per file, following FX1-A06's
`fx1_a06_hls_master_oversized_segment_refuses_typed` conventions
(the `hls_master_e2e.rs` mock-socket pattern): a 3-segment ladder —
seg0 24 B `'H'` (fits, the control), seg1 64 B `'X'` (over the whole
`max_retained_bytes = 32` budget a `validate()` accepts — the
audit's trigger shape), seg2 24 B `'Y'` (the resume):

1. `fx2_a10_hls_vod_oversized_segment_refuses_typed` — a crafted VOD
   playlist (`ENDLIST`, `PLAYLIST-TYPE:VOD`, `MEDIA-SEQUENCE:100`) at
   `/media.m3u8` over the real mock HTTP server. Asserts: the
   open-time probes still fix the total (`size() == Some(112)` — the
   known-length contract the guard must not disturb); the healthy
   prefix serves byte-exact (`'H'×24`); the read at the evicted
   cursor refuses typed — exact code
   `streaming.hls.read-unretained`, cursor unmoved
   (`position() == SourcePosition(24)`); a forward seek past the
   evicted body resumes on seg2 (`'Y'×8`). Pre-fix, the middle read
   is the debug "subtract with overflow" panic site itself.
2. `fx2_a10_hls_live_oversized_segment_refuses_typed` — a crafted
   live window (no `ENDLIST`, `live_edge_back = 3` over the 3-segment
   window joins at the oldest segment) at `/pl.m3u8`. Same
   assertions minus the probe total (live has none), plus the
   live-specific pin that the resume is served by the pending queue
   with **no reload spent** (a static playlist route — any reload
   loop would hang/fail the test). Pre-fix, the same panic site.

Each test asserts the *specific* refusal code (a misparsed input
cannot pass vacuously) and carries its healthy control, so the guard
demonstrably refuses only the evicted range.

## Risks & followups

1. **Tests not executed by this agent** (cargo is centrally gated);
   rustfmt-clean (edition-2024 `--check` on the src files, the
   rules' edition-2021 pass on the new test file) and manually
   type-reviewed. The one place a mismatch could surface in the
   central run is crafted-playlist parser tolerance — the test text
   is the identical shape FX1-A06's passing master test used, and the
   parser trims every line (`hls.rs:470`), so indented continuation
   lines are already proven tolerated.
2. **The eviction state remains recoverable only by forward seek**
   (the evicted prefix is unreachable — the same accepted posture
   as the master fix, per its report's reasoning: a saturating
   subtraction would serve wrong-position bytes, a retention clamp
   still strands the prefix). A policy-level alternative (e.g. refetch-on-demand)
   is a Lead decision, out of scope.
3. **Adjacent live.rs defects left open** (out of this row's scope,
   named by W10-A06): F-006 gap-terminal `pending` dead state, F-007
   unbounded refusal-retry reload loop, F-008 unchecked
   MEDIA-SEQUENCE u64 adds. The guard does not interact with any of
   them.
4. **Reachability unchanged**: both modules remain unreachable from
   shipped entry points (W10-A09 F-002 / W10-A06 F-001) — this fix
   hardens the library island; if/when the HLS open lane lands, the
   guard is the panic-free contract that lane inherits.
