# FX2-A02 — decode-bench real measurement (plan item F0.2)

## Approach

The audit's root finding (W13-A07 F-001, wave-13 "LIE 2"): the bench
hand-rolled a two-codec registry (`fact.codec == "mjpeg"`,
`starts_with("pcm_")`) instead of consulting the dispatch, so for the
very file the same binary plays it printed an all-zero success-shaped
BENCH line, exit 0, and the stderr lie "no decoder in this build
(first vertical: mjpeg + pcm)".

The fix routes the bench's limbs through the one true registry:
`apps/cli/src/pipeline_host.rs`'s `HostDecoderProvider::decoder_for`
(the 14-family dispatch `lumen open` wires through the engine's
`obtain_decoder`). The bench now:

1. opens via the unchanged `demux_host::open_source` (the player's
   own path — already true before);
2. builds `HostDecoderProvider::new(Arc::new(opened.facts))` — the
   same construction host.rs:948 uses — and offers the FIRST video
   stream and FIRST audio stream to `decoder_for` with the engine's
   own `obtain_decoder` config shape (`DecoderConfig::new(codec,
   GenerationId::FIRST, ThreadBudget::default(), None, None)`); the
   dispatch does the extra_data seeding (avcC/esds/flac/vorbis/…),
   the PCM `with_format` seam and the per-codec configure gates —
   the bench has no codec knowledge left;
3. a dispatch refusal for a benched kind rides the coverage note
   (the dispatch's own sentence, e.g. "no decoder for `hevc` in this
   build (landed: …)"), and when NOTHING was benched it is the
   command's typed failure: exit 65, no BENCH line (F-003's
   "benched nothing ⇒ successful zero" hole closed for the
   nothing-benched case);
4. end-of-stream drain loops to the decoder's `Drained` answer,
   bounded (`FLUSH_BUDGET = 64`, the engine's flush-to-Drained shape)
   — the old single `flush()` call would under-count an inter-frame
   codec's held frames (h264 reorder).

Refactor per assignment §2: the measurement is now
`fn measure(source) -> Result<BenchReport, CommandError>` — a pure
seam with no output I/O beyond the input path; the coverage notes
and container name ride back in the report as data, and `run_bench`
owns every print. The CLI output shapes are unchanged: the BENCH line
format is byte-identical (still pinned by
`bench_line_is_the_exact_contract`), the stderr coverage-note shape
("bench: … (container …)") is preserved, and the note phrases the
`bench_decode.rs` tests pin ("first-of-kind already benched",
"bench:") survive verbatim.

## Test design

The audit's §5 table says no test exercised a non-mjpeg/pcm track
through the gate — F-001/F-002/F-003 were invisible to the suite.
The two integration tests close exactly that: a known-good h264+aac
fixture the CLI tests already use (asserted played to 100%
end-of-media in `container_conformance.rs`) must MEASURE > 0 through
the same binary, and an unsupported family (h263) must answer the
dispatch's typed refusal (65, no BENCH line) instead of a
success-shaped zero. Assertions pin the honest words ("decoding",
"no decoder for `h263`", "landed") and pin the dead lie ("first
vertical" must not appear) — wording-drift-tolerant substrings, so
FX2-A03's dispatch-string rework in the same wave cannot silently
break them.

## Risks & followups

- Not executed here (no cargo per RULES): the orchestrator's central
  compile+test run is the verifier; the riskiest assumption is that
  `measure`'s h264/aac lane on the committed fixture decodes as the
  engine lane does (the conformance test proves the same dispatch
  decodes this file to end-of-media).
- Partial-bench case (one kind benched, the other refused — e.g. an
  hevc+aac file) still answers exit 0 with an honest note and a real
  measurement for the benched limb; tightening that (e.g. a
  `benched=` field or a nonzero exit) is a consumer contract decision
  (rc-smoke.sh / baseline.py parse the line) and is left as a
  followup, deliberately.
- Out-of-scope findings in this file left as the audit filed them:
  F-004 (shared cross-limb concealment budget), F-005 (dead
  NullSink.frames counter + its optimistic comment), F-006 (stale
  speed_bench.py "decode-null" citation in the module header — the
  defect lives in tools/corpus/speed_bench.py, not this file).
- `FLUSH_BUDGET = 64` is generous for every landed codec (h264's
  flush emits all held frames at once); if a future inter-frame codec
  needs more, the budget is a named constant, not a hidden literal.
