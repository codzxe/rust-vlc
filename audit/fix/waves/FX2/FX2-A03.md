# FX2-A03 — the `landed:` refusal string derives from the dispatch table

## Approach

Wave-13 F-003 (`audit/files/apps/cli/src/pipeline_host.rs.audit.md`, S3):
the `other` arm's message at pipeline_host.rs:372-378 hand-maintained a
`landed:` family list that had already drifted **inside its own file** —
omitting `vp9`/`dnxhd` (arms at :313/:326) while naming `aac-lc` for the
`aac`|`aac-lc` family. Same binary, fourth registry answering differently.

A Rust `match` cannot be reflected at runtime, so "derive from the
dispatch table" is implemented the way FIX-PLAN Principle 2 prescribes:
the match is exported as data — `LANDED_DECODER_FAMILIES`, one row per
arm family, colocated with the match it mirrors — and the string, the
tests, and (per the wave tsv) engine-info/decode-bench consume that one
table. Two seams keep the table honest against the match itself:

- `codec_unavailable_message(codec)` — the `other` arm's message is now
  *only* this function: `no decoder for \`X\` in this build (landed: <table
  names, comma-joined>)`. The hand-list literal is deleted.
- `descriptor_is_landed(descriptor)` — the introspection probe: drives one
  fact-less `Track` through `HostDecoderProvider::decoder_for` and
  answers whether the outcome is the registry's own
  `cli.codec_unavailable` catch-all. An arm whose honest `configure` gate
  refuses a fact-less lane (flac without STREAMINFO, pcm without strf
  facts) still counts as landed — the gate's error code is the codec's
  own, never the catch-all's — so this is an arm-existence oracle, not a
  decode-capability promise. FX2-A01 (host.rs) and FX2-A02 (bench.rs) may
  reuse these exported seams; they were told to derive from this file's
  table.

The 14 codec dispatch arms are untouched (only the catch-all arm's
message expression changed). Note: FIX-PLAN calls it "the 16 arms"; the
match actually has 14 codec arms + the catch-all (the audit's "18
descriptors" counts aliases — `mp3|mp1`, `aac|aac-lc`, `av1|av01`,
`h264|avc1`, plus the `pcm_*`/`adpcm_*` prefix guards). No line drift at
the cited :372-378 otherwise.

## Test design

Both tests probe the **real** dispatch (`HostDecoderProvider::decoder_for`
on a fact-less `MediaFacts`), never the table alone, so the pin holds
against the arms' actual behavior:

- `fx2_a03_refusal_family_set_matches_dispatch_arms` — the message the
  dispatch mints for an unknown codec equals
  `codec_unavailable_message` byte-for-byte (the arm provably uses the
  derivation); its parsed `landed:` family set equals
  `LANDED_DECODER_FAMILIES`' names in table order; every row's
  descriptors have live arms (table cannot overstate); nine known
  arm-less descriptors (hevc, mpeg2video, mpeg4video, ac3, dts, theora,
  vp8, ffv1, wmapro) refuse with the `no decoder for \`X\`…(landed:`
  prefix shape the existing tests pin (table cannot understate — the
  vp9/dnxhd omission class).
- `fx2_a03_dispatch_family_not_reported_unlanded` — the wave-13
  regression pair `vp9`/`dnxhd` (and then every dispatched family):
  probe proves the arm live, proves probing the family never mints
  `no decoder for \`X\``, and the minted refusal string lists the family
  as landed.

Per RULES §DoD the tests live in a NEW integration-test file (sibling
agents FX2-A01/A02 edit host.rs/bench.rs in the same crate — zero
collision); all types used are regular deps of the package
(`media_types`, `codec_api`, `playback_engine`, `lumen_cli`).

## Acceptance vs FIX-PLAN

F0.2 (my third): "landed-string derives from the dispatch table" — done;
the string is now computed from the one exported table, and the tests
would have caught the wave-13 finding (delete the vp9 row or the vp9

engine-info/bench halves are FX2-A01/A02's rows, not mine — noted for

`kind` so `DecoderInfo.kind` derives too) / `descriptor_is_landed` /
`codec_unavailable_message` rather than re-listing.

## Risks & followups

- **Compile-unverified** (cargo forbidden on this box; rustfmt absent
  from the toolchain — formatting hand-matched to the file's
  conventions). The new code uses only APIs verified by read
  (`DecoderConfig::new` argument shape cross-checked against
  codecs/src/video/vp9/decoder.rs's own test usage; `MediaFacts`/
  `Track`/`TrackTiming` construction mirrors
  plugin-api/src/demux.rs:290-307). Orchestrator's central build is the
  gate.
- The probe calls real decoder constructors for every family; a future
  arm that panicked (rather than typed-refused) on a fact-less config
  would surface in these tests — that is the desired failure mode.
- The prefix families' `descriptors` rows (`pcm_s16le`, `pcm_u8`,
  `adpcm_ima_wav`, `adpcm_ms`) are representative, not exhaustive
  (`pcm_*` is infinite); the tests pin that listed descriptors land,
  not that unlisted prefixes don't (the prefix guards themselves are
  arms, hence covered).
- Residual stale doc, out of scope but on record: the module header
  (pipeline_host.rs:5-12, "MJPEG + PCM ... BT.601 full-range") still
  describes the first-vertical era (audit §6 rows 1-2) — a docs-wave
  item, not F0.2's string.
