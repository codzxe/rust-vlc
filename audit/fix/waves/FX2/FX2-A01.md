# FX2-A01 — engine-info single-source (F0.2) + seekable truth (F0.3)

## Approach

Both defects are in `apps/cli/src/host.rs` (my sole owned file; line cites
in the wave tsv matched exactly, no drift):

- **F0.2 (W13-A02 F-002, wave-13 "LIE 1"):** `engine_info()` hand-listed
  two decoders (`mjpeg`, `pcm_s16le`) while the same binary's
  `HostDecoderProvider::decoder_for` (pipeline_host.rs) dispatched 14
  families — the four-registry lie.
- **F0.3 (W13-A02 F-001, re-verified W20-A02):** `media_info()` hardcoded
  `seekable: true`; one FLAC-in-WAV run printed engine event
  `seekable: false` / host `seekable: yes` / seek terminal
  `not-seekable` — three contradictions in one session.

**The single-source design.** A Rust `match` cannot be reflected at
runtime, and FX2-A03 (sibling, owns pipeline_host.rs) landed exactly the
needed seam before I finished: the match is exported as data —
`pub const LANDED_DECODER_FAMILIES` (one row per codec arm: name, kind,
descriptors) plus the probe `pub fn descriptor_is_landed` (drives a
fact-less track through the real `decoder_for`; the catch-all arm's
`cli.codec_unavailable` is the not-found marker). So
`engine_info()` now DERIVES its decoder rows from that registry by code
(`LANDED_DECODER_FAMILIES` → `DecoderInfo`, `MediaKind`→`TrackKind` via a
new `wire_kind` helper) — the same one source the `landed:` refusal
string derives from. There is no second list in host.rs; the hand-list
literal is deleted. The registry is kept honest by the regression test
below, which probes the REAL dispatch for every registry descriptor.

**The seekable fix.** `CliHost` gains `seekable: Option<bool>`:
`open_session` reads `opened.demuxer.seekability() != SeekSupport::None`
BEFORE the demuxer moves into the engine's `SessionConfig` — the exact
fact `Pipeline::seekability()` consults for the seek flow's step 1
(session.rs:2018-2021) and the `MediaInfoReady` event carries
(session.rs:2781-2792) — and `media_info()` answers it
(`unwrap_or(false)`; `None` is the cleared no-session shape, unreachable
behind the existing `facts` gate). The `true` constant is gone; the field
clears in `teardown_session_scoped` with the other session-scoped halves.

## Test design

All in the new integration file (drives the REAL surfaces; regular deps
only — `commands`, `lumen_cli`):

- `fx2_a01_engine_info_lists_the_dispatch_tables_families` — builds the
  expected list from the SAME source of truth (the registry is reachable:
  `lumen_cli::pipeline_host::{LANDED_DECODER_FAMILIES,
  descriptor_is_landed}`), and (a) probes the REAL dispatch for every
  registry descriptor (`descriptor_is_landed` — arm-existence oracle:
  a codec gate refusing a fact-less lane is routing, not refusal); (b)
  refusal controls — the audit's executed refusals `hevc`/`mpeg2video`/
  `mpeg4video` stay refused; (c) registry == the pinned 14-family
  literal; (d) `engine_info()` == the pinned list exactly (names + kinds
  + order + count, software-only). Would have caught F-002: the
  pre-fix 2-entry answer fails (d); a dropped/renamed arm fails (a);
  a registry/table split fails (c).
- `fx2_a01_engine_info_cli_surface_lists_all_dispatch_families` — the
  CLI surface end-to-end: `lumen engine-info` prints the 14-family
  decoders line (arm order).
- `fx2_a01_info_seekable_answers_the_engine_for_flac_in_wav` — the
  W13-A02 disproof flipped: crafts the audit's FLAC-in-WAV fixture
  in-test (byte-identical to `audit/verify/make_flac_wav.py`, the shape
  executed twice by the audit — verified by a python byte-compare of my
  Rust crafting against the script's output), runs
  `lumen open <file>` + `info` + `seek 1s` + `quit`, and asserts the
  three answers now AGREE: engine event `seekable: false`, `info` line
  `seekable: no` (pre-fix: `yes`), seek terminal `not-seekable`, exit 0.
  The temp file lands in a self-removing TempDir (the fx1_a09
  convention — no /tmp leak).
- `fx2_a01_info_seekable_stays_yes_for_the_pcm_wav_family` — the
  control: the committed `wav_pcm_s16le_44k1_st.wav` (CBR PCM →
  `Fast { indexed: false }`) keeps `seekable: yes` — the fix answers the
  engine, it does not blanket-flip.

## Acceptance vs FIX-PLAN

- **F0.2 (engine-info half): "engine-info lists all 14 shipped
  families"** — DONE. Exact numbers found (reported per assignment):
  `decoder_for`'s match has **15 arms total = 14 codec arms + 1
  catch-all refusal**; the 14 arms route **18 descriptor spellings —
  16 exact literals** (`mjpeg, flac, mp3, mp1, mp2, vorbis, opus, aac,
  aac-lc, alac, av1, av01, vp9, dnxhd, h264, avc1` — the plan's "16
  arms incl. aliases") **plus 2 prefix guards** (`adpcm_*`, `pcm_*`).
  engine-info lists the **14 families**:
  `decoders: mjpeg, flac, mp3, mp2, vorbis, opus, aac-lc, alac, adpcm,
  av1, vp9, dnxhd, h264, pcm` (`aac-lc` is FX2-A03's registry name for
  the `aac|aac-lc` arm — engine-info and the `landed:` refusal string
  now agree by construction, from ONE table).
- **F0.3: "FLAC-in-WAV run: engine false → CLI prints false"** — DONE
  (test 3, above). The constant is deleted; `info` answers the engine's
  declared `SeekSupport`.
- Honest nuance, not papered over: MP4's demuxer DECLARES
  `SeekSupport::Fast{indexed:true}`, so `info` prints `seekable: yes`
  for MP4 today even though in-session seek dies at the unimplemented
  `reanchor` (W20-A05 F-001 — F1.3's item). The field reports the
  engine's own declaration, exactly as the assignment scoped ("report
  what the ENGINE reports today"); the seek failure itself remains the
  honest typed terminal.
