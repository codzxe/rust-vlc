# FX2-A06 — dxgi vtable slot fix (W08-A10 F-001, the S0)

## Approach

The audit's executed proof (wave-08 / dxgi.rs.audit.md F-001): both hand-declared
COM vtables in `dxgi.rs` omit the four `IDXGIObject` slots every dxgi interface
inherits between `IUnknown` and its own methods, so every declared slot resolved
four positions early — `get_desc1` actually called `EnumOutputs`, and
`enum_adapters1` actually called `EnumAdapters`.

Fix: declare the `IDXGIObject` quartet once (`DxgiObjectVtbl`: `SetPrivateData`,
`SetPrivateDataInterface`, `GetPrivateData`, `GetParent`, in dxgi.h order) and
embed it in both vtables between `UnknownVtbl` and the interface's own methods.
The runtime call sites (`enum_adapters` → `enum_adapters1`, `describe_adapter`
→ `get_desc1`) are unchanged; only the declared layout shifted, so both calls
now land on their true slots. `com.rs` untouched (FX2-A05 owns it).

**Drift located and corrected (honesty note).** The audit prose tallies
`IDXGIFactory1 = IUnknown(3) + IDXGIObject(4) + IDXGIFactory(6) + 2 = 15`
slots, and the pre-fix file declared a `_get_adapter` slot between
`CreateSwapChain` and `EnumAdapters`. `IDXGIFactory` has exactly **five** own
methods (CreateSwapChain, CreateSoftwareAdapter, EnumAdapters,
MakeWindowAssociation, GetWindowAssociation — the documented MSDN set; no dxgi
interface defines `GetAdapter`); the "6" tally counts the file's fabricated
slot. The audit's own per-slot claims are all consistent with the true layout:
`EnumAdapters` at slot 10 (1-based), `EnumOutputs` at slot 8, `GetDesc1` at
slot 11 — so its executed proofs hold. I removed the fabricated slot as part of
the fix because keeping it would defeat the assignment: with the quartet
inserted but a sixth factory method retained, `enum_adapters1` would sit at
slot 14 = `IsCurrent`'s slot — the out-pointer would never be written, the
adapter would stay null, the loop would break, and the GPU seam would still
return `Ok(vec![])` on every machine, i.e. the same silent failure in a new
costume.

## The slot-count proof (counted aloud, 1-based)

`IDXGIAdapter1` = IUnknown(3) + IDXGIObject(4) + IDXGIAdapter(3) + 1 = **11
slots**:

1. QueryInterface, 2. AddRef, 3. Release (IUnknown)
4. SetPrivateData, 5. SetPrivateDataInterface, 6. GetPrivateData,
   7. GetParent (IDXGIObject)
8. EnumOutputs, 9. GetDesc, 10. CheckInterfaceSupport (IDXGIAdapter)
11. **GetDesc1** (IDXGIAdapter1)

- Pre-fix `Adapter1Vtbl` declared: unknown(1–3), `_get_parent`(4),
  `_enum_outputs`(5), `_get_desc`(6), `_check_interface_support`(7),
  `get_desc1`(8) → `get_desc1` resolved at slot 8 = **real EnumOutputs**
  (different arity, garbage register — the audit's executed proof).
- Post-fix: `object`(slots 4–7), `_enum_outputs`(8), `_get_desc`(9),
  `_check_interface_support`(10), `get_desc1`(**11**) → `describe_adapter`
  now calls the true `GetDesc1`.

`IDXGIFactory1` = IUnknown(3) + IDXGIObject(4) + IDXGIFactory(5) + 2 = **14
slots**:

1. QueryInterface, 2. AddRef, 3. Release (IUnknown)
4. SetPrivateData, 5. SetPrivateDataInterface, 6. GetPrivateData,
   7. GetParent (IDXGIObject)
8. CreateSwapChain, 9. CreateSoftwareAdapter, 10. EnumAdapters,
   11. MakeWindowAssociation, 12. GetWindowAssociation (IDXGIFactory)
13. **EnumAdapters1**, 14. IsCurrent (IDXGIFactory1)

- Pre-fix `Factory1Vtbl` declared: unknown(1–3), `_create_swap_chain`(4),
  `_get_adapter`(5), `_enum_adapters`(6), `_make_window_association`(7),
  `_get_window_association`(8), `_create_software_adapter`(9),
  `enum_adapters1`(10), `_is_current`(11) → `enum_adapters1` resolved at slot
  10 = **real EnumAdapters** (identical signature by luck — but returns
  `IDXGIAdapter`, on which `GetDesc1` does not even exist).
- Post-fix: `object`(slots 4–7), then slots 8–12 as above, `enum_adapters1`
  (**13**), `_is_current`(14) → `enum_adapters` now calls the true
  `EnumAdapters1`, returning `IDXGIAdapter1`, whose `GetDesc1` is slot 11 —
  matching the audit's "real slot 11 is GetDesc1" verbatim.

Byte-level cross-check on x64 (one slot = 8 bytes): factory —
`enum_adapters1` at 96 = 12×8, `_enum_adapters` at 72 = 9×8, size 112 =
14×8; adapter — `get_desc1` at 80 = 10×8, `_enum_outputs` at 56 = 7×8,
size 88 = 11×8. Exactly what the pins assert.

## Test design

The vtable types are private to the `#[cfg(target_os = "windows")]` module and
are never constructed, so an integration test file cannot name them (FX2-A05's
`tests/fx2_a05_*.rs` pattern works for `com.rs`'s pub types only). The suite
therefore lives in-file — the crate's existing style for private FFI layout
pinning (`codecs/.../videotoolbox/ffi.rs`'s `const _: () = assert!`):

- `#[cfg(all(test, target_os = "windows"))] mod tests` — Linux-compile-safe
  (the module is never parsed off-Windows, like the sibling FX2-A05 cfg
  discipline), Windows-CI-executable (the assertions run under `cargo test` on
  the Windows lanes).
- 0-based slot-index constants (`SLOT_ENUM_OUTPUTS = 7`, `SLOT_GET_DESC1 = 10`,
  `SLOT_ENUM_ADAPTERS = 9`, `SLOT_ENUM_ADAPTERS1 = 12`, …) mirror the dxgi.h
  inheritance arithmetic; every declared field's `std::mem::offset_of!` is
  pinned to its constant, plus total sizes (11 / 14 slots).
- The three `fx2_a06_*` tests are the regression that would have caught the
  audit finding: against the pre-fix declarations, `get_desc1`'s offset was
  7×SLOT (= `EnumOutputs`) ≠ `SLOT_GET_DESC1` → red; same for
  `enum_adapters1` at 9×SLOT (= `EnumAdapters`). The task's asked-for
  invariant is explicit: `assert_ne!` of the GetDesc1/EnumOutputs and
  EnumAdapters1/EnumAdapters offsets.
- Two non-test `const _` pins re-assert the called-slot arithmetic at compile
  time, so even a non-test Windows build fails loudly on future slot drift —
  answering audit F-005's "compile-checking cannot catch vtable slot errors"
  for this file.

## Risks & followups

1. IDXGIFactory's internal method order (never-called slots) is declared per
   dxgi.h with `CreateSoftwareAdapter` at slot 9. Both called slots depend
   only on the method **count** (5 — documented, and matching the audit's
   slot-10 arithmetic), so a residual order doubt cannot affect
   `EnumAdapters1`/`GetDesc1` resolution; it would only permute
   never-invoked documentation-level fields.
2. Left in this file, out of my scope (audit F-002/F-003/F-004/F-006, unowned
   by any FX2 row): the `break`-on-any-HRESULT + `if let Ok` error swallowing
   in `enum_adapters`; `flags` never read in the WARP detection; the module
   header's "vendor id 0x8C" doc lie; the unbounded `from_wide` scan of
   `Description[128]`. These should get their own row/agent before wiring the
   GPU seam into a shipped lane.
3. The tests and const pins execute/compile only on Windows targets; the
   orchestrator's central Windows lane is their first real run.
