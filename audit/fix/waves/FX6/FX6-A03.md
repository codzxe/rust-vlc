# FX6-A03 — the tauri frame channel's ship side, bounded

## Approach

The assignment (wave-FX6.tsv row FX6-A03, FIX-PLAN §3 F1.2's "channel
stall behavior — a stalled webview must not OOM", FX4-A04's handoff
note naming `frame_channel.rs::send_record`'s ship side): bound the
queue feeding the tauri Channel, count shipped vs dropped, pass
timestamps through, test headlessly.

**The hard engineering fact first (it shaped everything):** tauri
2.12.5's per-webview `ChannelDataIpcQueue` — where every Raw record
≥ 1024 bytes is parked until the webview's JS fetch arrives — is
unbounded AND unobservable from the app crate. Verified against the
vendored source (`~/.cargo/registry/.../tauri-2.12.5/src/ipc/
channel.rs:47-106`, read in full): the queue's entries map is
private, its methods are `pub(crate)`/`#[cfg(test)]`, the fetch that
drains it is a tauri-internal plugin command, and `Channel::send` is
fire-and-forget (it returns after `webview.eval`, never when the
payload is consumed). **No depth API, no ack, no natural
backpressure signal exists** — the assignment anticipated this
("backpressure signal if a natural one exists" — none does). I also
worked through and rejected every synthetic approximation before
writing code: a time-released in-flight window must sustain the
playback frame rate (cap/TTL ≥ fps) or it throttles healthy playback,
and at cap/TTL ≥ fps it parks records at ≥ fps under a stall — it
cannot reduce stall accumulation below the frame rate while not
throttling health; releasing only on liveness signals freezes the
lane after ~4 ticks of healthy playback (no invokes occur during
idle playback). No Rust-side-only policy closes the parked-queue
hazard; every candidate either false-positives on healthy playback
or false-negatives the stall. That closure needs a webview→shell ack
epoch — a UI-side protocol change outside this crate's file domain
(named in Risks).

**What IS in my file domain is the queue feeding the channel** — the
assigned seam ("bounded buffer between the ticker and the webview
dispatch"). That is what I built: `FrameLane` in `frame_channel.rs`
— the `BoundedEventSink` twin (`apps/desktop/src/dispatch.rs:152`:
bounded, drop-oldest, counted, conserving) for the frame lane, pure
std so the bound is provable headlessly. The ticker in `app.rs` now
drains the mailbox into the lane, flushes it on every re-bind, and
dispatches one `take_newest` per tick into `send_record`.

**The mid-wave sibling convergence (drift note, honesty contract):**
row FX6-A02's file column says `apps/desktop/src/app.rs` — that file
does not exist in the tree; the 10 ms ticker that ships
`records.last()` lives in `apps/desktop-tauri/src/app.rs:223-229` —
MY file domain. FX6-A02 landed their ticker-lane instrumentation into
the same file while I was editing it (three successive states
observed at 18:21/18:25/18:27; a MultiEdit of mine failed against a
moved target mid-race, which is how I detected it). The final
converged state — verified by re-reading the whole file after their
last write — is a clean composition, and I preserved ALL of it:
my `FrameLane` (bound + policy + counters, wired as the ticker's
queue) + their `ShipLog`/`RecordStamps`/`record_stamps`
(`app.rs:202-302`: reads the dispatched record's own wire stamps —
the F1.2 timestamp-passthrough observable — and prints the lane's
produced-vs-dropped receipt every `FRAME_RECEIPT_EVERY` = 128 ships).
During my own reconciliation pass I briefly renamed my type to
`BoundedFrameQueue` (to de-collide with their first-draft
`FrameLane`); after their second write adopted my original API
verbatim (`crate::frame_channel::FrameLane`, `take_newest`, my stats
field names — their tests `fx6_a02_lane_receipt.rs` import exactly
it), I reverted to the original names: the tree now has ONE lane
type, one policy, one stats struct, consumed by both rows' tests.

## Changes per file

**`apps/desktop-tauri/src/frame_channel.rs`** — the assignment's
core deliverable:
- `FrameLane` (`:184`): the bounded queue between the ticker's drain
  and the webview dispatch. `offer` (`:210`, drop-oldest on overflow,
  counted), `take_newest` (`:225`, the dispatch half: newest ships,
  superseded purged and counted, lane empty after — the
  one-frame-per-tick contract made explicit), `flush_stale` (`:237`,
  bind-generation purge, the mailbox's own semantics mirrored),
  `queued`/`is_full`/`stats`/`conserves`, `Default`.
- `FRAME_LANE_CAPACITY` (`:101`): **2** — one landing record plus one
  in flight, the upstream mailbox's own reasoning; at ~3.7 MB per
  1280×720 RGBA record the lane's worst-case retained memory is
  **~7.4 MB, a constant, never a function of the consumer's speed**
  (the W14-A07 property, at this seam by construction and test-pinned).
- `FrameLaneStats` (`:148`): `offered / shipped / dropped_overflow /
  dropped_superseded / dropped_stale` + `conserves(queued)` (`:169`):
  `offered == shipped + dropped_overflow + dropped_superseded +
  dropped_stale + queued` — every offered record shipped or dropped
  exactly once. This is the "shipped vs dropped-by-overflow" counter
  pair the assignment asks for, at the channel seam.
- `send_record` (`:140`) now takes the record **owned** (`Vec<u8>`,
  was `&[u8]` + `to_vec()`): the lane owns the bytes, the dispatch
  moves them — the audit's F-003 double full-frame copy (~3.7 MB
  per ship) is gone. FX6-A02's dispatch call site passes the owned
  record (their second write adopted the signature).
- Module docs: the bounded-ship-side policy (capacity justification,
  latest-wins, bind-generation flush, verbatim passthrough), the
  composition with FX6-A02's ShipLog, and the honest backpressure
  limit (the vendored-source proof above).

**`apps/desktop-tauri/src/app.rs`** — the channel region of
`spawn_event_pump` (`:325`), plus what the sibling convergence left
in place around it:
- The ticker now drains the mailbox **into the lane** (offer loop,
  `:386`), flushes the lane on every successful re-bind (a bind is a
  fresh generation — the previous page's records never ship stale),
  and dispatches `take_newest` per tick into `send_record` (`:398-416`)
  — replacing the pre-FX6 `records.last()` ship whose intermediate
  drops were silent.
- Drain trigger is now `frame_channel.is_some() || bind.is_some()`
  — a fresh bind counts as a drain trigger, so the first frame after
  a (re)bind ships in the same tick instead of waiting one (the
  audit's F-005b, closed by the lane's buffer).
- The `records` Vec is hoisted and drained in place (the audit's
  F-005c per-tick `Vec::new()` churn — closed as a side effect).
- My stall notice: one stderr line per full-lane episode (the
  occupancy instrumentation — a full lane is the ship-side stall
  signature), totals in the line; FX6-A02's periodic 128-ship
  receipt (counters + stamps) rides alongside it.
- Everything else in the file (FX6-A02's RecordStamps/ShipLog
  section, the single command, the window spec, the file funnels) is
  the sibling's or pre-existing — untouched by me beyond the region
  above.

**`apps/desktop-tauri/tests/fx6_a03_frame_lane.rs`** — five
`fx6_a03_*` tests (below), following `fx4_a04_audio_lane.rs`
conventions: file-level doc stating the CI gate, plain `#[test]`s,
`assert!`/`assert_eq!`/`match`-with-`unreachable!`, no unwrap/expect,
no new dependencies (the lane is pure std; the crate has no
`[dev-dependencies]` and none were added).

## Test design

The lane is pure std, so the W14-A07 property is falsifiable
headlessly, exactly like the mailbox tests (FX6-A01's, the upstream
oracle). All five are CI-gated with the crate (below) but need no
webview:

- `fx6_a03_stalled_dispatch_stays_bounded_and_counts_drops` — **the
  stall bound**: 6×capacity offers with NO dispatch (the stalled
  consumer's shape); occupancy asserted ≤ capacity after every
  offer; exact counters (offered 12, dropped_overflow 10); the
  survivor handed to the eventual dispatch is the newest burst
  member, bytewise; conservation.
- `fx6_a03_take_newest_ships_newest_counts_superseded` — the
  one-frame-per-tick contract: the shipped record is the newest
  offered record bytewise; the superseded one is counted (the
  pre-FX6 silent `records.last()` discard, now arithmetic); the lane
  is empty after a dispatch (no zombie leftovers).
- `fx6_a03_shipped_records_carry_upstream_timestamps_verbatim` —
  the passthrough oracle: records hand-built on the real LUF1 layout
  (48-byte header, `pts_ns` @ 32, `emitted_ns` @ 40, per
  `apps/desktop/src/wire.rs`'s table); the shipped bytes equal the
  offered bytes exactly; the `pts_ns`/`emitted_ns` read back off the
  shipped record are the upstream values — never the lane's; two
  slots never blur.
- `fx6_a03_conservation_holds_under_mixed_traffic` — 24 ticks of
  mixed bursts (0-3 records) and alternate dispatches at capacity 3:
  the identity holds after every step; occupancy within capacity;
  final drain to the pure identity.
- `fx6_a03_rebind_flushes_pending_records_counted` — the
  bind-generation flush: wholesale, counted once, not cumulative;
  post-flush frames flow normally.

Determinism note (honest, since cargo is prohibited here): the lane's
decision arithmetic was additionally simulated out-of-band in python
against every assertion's exact expected numbers (all five pass by
construction); the tests themselves are CI-gated.

## Acceptance vs FIX-PLAN

FIX-PLAN §3 F1.2's frame-lane bullets, at my seam:
- "Instrument: frames produced vs frames dropped" — the lane's
  `offered/shipped/dropped_*` counters, printed periodically on
  stderr (FX6-A02's receipt) and pinned by tests; the end-to-end
  latency half rides the records' own `emitted_ns` (FX6-A02's
  ShipLog latches them; FX6-A05's UI counter surfaces the webview
  side).
- "channel stall behavior (a stalled webview must not OOM — the
  W14-A07 unbounded-queue class)" — **at the queue feeding the
  channel: closed by construction and test-pinned** (capacity 2 ≈
  7.4 MB retained worst-case, drop-oldest by policy, conservation).
  Inside tauri's own fetch queue: **not closable from this crate**
  (no ack exists — proven against the vendored source); the
  one-ship-per-tick cadence remains the only hand-off-rate bound
  (~100 ships/s ceiling, the audit's ~370 MB/s worst case stands
  there). Named as the residual risk below, with the exact follow-up.
- "drop-policy + timestamp passthrough" — drop-oldest latest-wins
  with three counted drop reasons; records ship bytewise verbatim
  (pinned).
- "confirm 10 ms cadence does not starve the webview on 4K" — out of
  my file domain (cadence is `SESSION_TICK`, untouched; the 4K
  hardware question is the F1.2 hardware run's).

## Risks & followups

1. **The residual W14-A07 hazard is real and named honestly: tauri's
   internal per-webview fetch queue remains unbounded under a webview
   that never fetches.** No API to observe it, no ack to gate sends,
   `Channel::send` is fire-and-forget (vendored `channel.rs:47-106`).
   The closure needs a webview→shell ack epoch (e.g. the UI consumer
   acknowledging receipt per frame or per batch, on the existing
   single-command channel) — a UI-side protocol change, FX6-A05's lane
   + `crates/commands` territory, deliberately not invented here.
2. **The tests and the composition have never executed** — the crate
   cannot build on this box (gdk-sys / webkit2gtk-4.1 absent, the
   known tauri-check gate); authored against the headless
   mailbox/BoundedEventSink conventions with arithmetic
   simulation-verified expectations, CI-gated like `single_command.rs`
   and `fx4_a04_audio_lane.rs`. If tauri-check is red on first run,
   the calibration risk is in the two agents' shared app.rs seam, not
   in the lane's own logic.
3. **Mid-wave shared-file convergence with FX6-A02** (same file,
   three observed states): the final state was verified consistent —
   one lane type, their tests and mine compile against the same API
   — but a further sibling write after my last verification (18:27)
   could drift it again; the orchestrator's central compile is the
   arbiter. FX6-A02's report should be cross-read with this one.
4. `frame_channel_bound` (shell.rs:210, audit F-013: production-dead
   guard API) remains unused — the ticker guards on its local
   channel state; noted, not my row.
