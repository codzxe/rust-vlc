# FX6-A01 — frame mailbox backpressure hardening

## Approach

**Drift note first (honesty contract):** the wave-FX6.tsv row describes the
mailbox as having "no timestamps, no drop policy, no produced-vs-dropped
counters". That has drifted: the current `apps/desktop/src/mailbox.rs` already
carries a latest-wins drop-oldest policy, per-record `pts_ns`/`emitted_ns`
passthrough via `FrameHeader`, and `offered/drawn/dropped_overflow/
dropped_stale/flushes` counters (W13-A04's audit of this exact file says the
same: "a small, correct, honest data structure", 3×S4 hygiene only). The
unfixed F1.2 defects that actually remain **in my file domain** were:

1. no drop *reason* (a drop was counted but never attributed);
2. no latency-relevant last-enqueued/dequeued stamps;
3. no `capacity()` accessor — the bound was unobservable, so "bounded
   occupancy" was unverifiable by a consumer;
4. no lane-vocabulary produced-vs-dropped readout and no one-call drain
   primitive for the ticker lane;
5. the `conserves()` doc omitted its empty-queue precondition (audit F-002).

So the fix is **observability hardening of an already-bounded structure**, all
additive (zero churn to the existing public surface — verified by rg that no
code outside mailbox.rs constructs `MailboxStats` or reads anything I touched).

**Capacity decision (plan bullet 2, "raise OR policy-govern"):** kept at the
default 2, i.e. *policy-governed*, not raised. Justification against the
~3.7 MB/frame reality: 1280×720 RGBA = 3,686,400 B payload ⇒ capacity 2 ≈
7.4 MB worst-case resident payload (plus the decoder's bounded `RECYCLE_SLOTS`
pool — the whole lane stays ≤ ~5 frame-buffers ≈ 18 MB at 720p) and a stalled
consumer can never OOM this side because occupancy ≤ capacity by construction
regardless of producer rate (the W14-A07 unbounded-queue class lives in the
tauri channel, FX6-A03's domain, never here). Depth buys nothing today: the
pacer's 10 ms drain (`FrameTap::drain_records` → `draw_next` until empty) is
exhaustive, so extra depth only *ages* frames into the `records.last()`
shipper's drops (that consumer-side bug is FX6-A02's row). Also binding: the
lane's only default-capacity consumer `frame_tap.rs::a_full_mailbox_
drops_oldest_never_blocks` hard-asserts the default is 2, and frame_tap.rs is
outside my file domain — raising the default would break a sibling's test I
may not edit. Documented in `MailboxConfig::capacity`'s field doc and the
module doc; the default is now also pinned by my own test so any future change
is a conscious, test-flagged one.

## The new public surface (for the wave's reconciliation)

Existing surface is unchanged (`new`, `offer`, `draw_next`, `peek`, `len`,
`is_empty`, `flush_stale`, `stats`, `MailboxConfig{capacity}`, `MailboxError`,
`LatencyAccountant`, `LatencySummary`). Added, all in `crate::mailbox`
(reachable as `desktop::mailbox::*`; the `pub use` list in lib.rs is not mine
to edit, and the module path is the one tests/pipeline.rs already uses):

```rust
pub enum MailboxDropReason { Overflow, Stale }          // Debug, Clone, Copy, PartialEq, Eq

// MailboxStats — three new pub fields (one stats() call = one atomic snapshot):
pub last_drop_reason: Option<MailboxDropReason>,       // None before the first drop
pub last_enqueued_ns: Option<u64>,                     // emitted_ns of the most recently offered frame
pub last_dequeued_ns: Option<u64>,                    // emitted_ns of the most recently drawn frame

impl MailboxStats {
    pub fn frames_produced(&self) -> u64;              // == offered (the lane's vocabulary)
    pub fn frames_dropped(&self) -> u64;               // == dropped_overflow + dropped_stale
}

impl FrameMailbox {
    pub fn capacity(&self) -> usize;                   // the bound; len()/capacity() is observable occupancy
    pub fn drain_to(&mut self, out: &mut Vec<ShippedFrame>) -> usize; // exhaustive FIFO drain; accounting == repeated draw_next
}
```

For FX6-A02 (ticker), FX6-A03 (tauri channel), FX6-A04 (integration tests):
push = `offer(frame)` (timestamps ride `frame.header.pts_ns`/`.emitted_ns`,
untouched end-to-end); drain-with-timestamps = `draw_next()` loop or
`drain_to(&mut v)`; counters/reason/stamps = one `stats()` copy
(`stats().frames_produced()`, `stats().frames_dropped()`,
`stats().last_drop_reason`, `stats().last_enqueued_ns`,
`stats().last_dequeued_ns`); bounded occupancy = `len()` vs `capacity()`.
The mailbox still reads no clock — determinism preserved (the stamps are the
frames' own `emitted_ns`).

## Changes per file

`apps/desktop/src/mailbox.rs` (only file changed):

- Module doc: "Bounded" bullet now states the occupancy/memory bound (≈3.7 MB
  × capacity; default 2 ≈ 7.4 MB; W14-A07 class impossible here); "counted"
  bullet becomes "counted AND attributed" naming the new observables; latency
  paragraph documents the no-clock stamp rule for
  `last_enqueued_ns`/`last_dequeued_ns`.
- `MailboxConfig::capacity` field doc: the policy-governed-capacity decision
  and its ~3.7·N MB math.
- New `MailboxDropReason` enum (Overflow/Stale).
- `MailboxStats`: +3 pub fields (`last_drop_reason`, `last_enqueued_ns`,
  `last_dequeued_ns`) + `frames_produced()`/`frames_dropped()`; `conserves()`
  doc now states the empty-queue precondition (audit F-002).
- `offer`: overflow drop now also records `last_drop_reason = Overflow`; every
  offer stamps `last_enqueued_ns` from the frame's own `emitted_ns`.
- `draw_next`: stamps `last_dequeued_ns` from the drawn frame's `emitted_ns`.
- New `drain_to` (FIFO exhaustive drain, identical accounting to repeated
  `draw_next`) and `capacity()` accessor.
- `flush_stale`: sets `last_drop_reason = Stale` only when it actually dropped
  (a zero-drop flush changes no observable).
- Tests: +1 builder (`stamped`) + 5 `fx6_a01_*` tests in the module's
  co-located `#[cfg(test)] mod tests` (the crate's unit-test convention for
  this module; `tests/` holds cross-module integration files — FX6-A04 owns
  the lane-wide `tests/fx6_*.rs`, so no collision).

## Test design

- `fx6_a01_occupancy_never_exceeds_capacity_under_endless_production` — the
  stalled-webview/OOM-class property at THIS seam: 25 offers, zero drains,
  occupancy asserted ≤ capacity after every single offer; exact counters
  (offered 25, dropped 22) and the oldest survivor's id (22).
- `fx6_a01_drop_policy_reports_last_reason_and_keeps_latest` — drop-oldest
  survivors {3,4} of 5 offers into capacity 2; reason `Overflow` under
  pressure, flips to `Stale` on a dropping flush, unchanged by a zero-drop
  flush; conservation at end.
- `fx6_a01_timestamps_pass_through_and_stamp_the_observables` — exact
  `pts_ns`/`emitted_ns` out the drain for every drawn record (untouched
  bytes); `last_enqueued_ns` before any draw, `last_dequeued_ns` None→Some
  across the first draw.
- `fx6_a01_counters_tick_through_the_lifecycle_and_conserve` — offers +
  overflow drops + one draw + one flush: every counter exact, `conserves()`
  true on the empty queue, and the governed default capacity pinned at 2.
- `fx6_a01_drain_to_empties_fifo_and_accounts_like_draws` — FIFO order, stamps
  intact, `drawn` ticks per drained frame, `last_dequeued_ns` lands, second
  drain appends 0, queue empty, conservation.

## Acceptance vs FIX-PLAN

§3 F1.2 bullet-by-bullet: **instrument** (frames produced vs dropped at the
mailbox) — done via `frames_produced()`/`frames_dropped()`/`last_drop_reason`;
**end-to-end latency** — per-record `emitted_ns` passthrough + the
`last_dequeued_ns` observable (the `LatencyAccountant` half was already real,
pinned by tests/pipeline.rs); **stalled webview must not OOM** — at this seam
by construction, now *test-pinned* (occupancy-bound test) and
memory-justified in docs; **raise capacity or drop-policy + timestamp
passthrough** — drop policy + passthrough existed (drift noted), capacity kept
policy-governed at 2 with the ~3.7 MB math written down. The
`records.last()`-drops-intermediate-frames half of the finding is the
consumer's (FX6-A02, app.rs ticker) — outside my file domain; the surface it
needs (per-record timestamps, counters, bounded drain) is what this change
lands.

## Risks & followups

- `MailboxDropReason` is exported from `desktop::mailbox` but not added to
  lib.rs's `pub use` list (lib.rs is outside my file domain) — consumers
  should import `desktop::mailbox::MailboxDropReason`; a wave-late one-line
  re-export in lib.rs would tidy this.
- frame_tap.rs audit F-002 (drain-side encode skips are uncounted) still
  stands: a `drain_skipped` counter would need incrementing in frame_tap.rs
  (not my file). The surface now exists to add it without API churn.
- Dead zero-capacity arm in `offer` (audit F-001) intentionally kept:
  removing it would break `MailboxError`/`TransportError::MailboxMisconfigured`
  in transport.rs (not my file).
- The mailbox-side `frames_produced` counts *offered* frames, i.e. frames that
  reached the tap; "counter matches decode count" acceptance also depends on
  FX6-A02/FX6-A03 shipping/draining honestly — reconciliation hint: compare
  `stats().frames_produced()` against the engine's decode count, and
  `stats().frames_dropped()` against the lane's drop reports.
