## 1. One-paragraph verdict
This is the strongest test module audited so far in this wave: RFC 1321/4648/2617 vectors against the hand-rolled MD5/base64/digest core, exact-format redaction pins, origin-keyed store discrimination, and three behavioral security regressions (conservative-transport fallback, AUD-07 scheme-downgrade, cross-host credential leak) that assert on the *recorded request log* — probe-without-credential, retry-with-credential, and the refused/credential-less third hop — not on mocks of the subject. The test doubles implement the TRANSPORT (`HttpFetch`), not the code under test (`AuthFetch` is the real subject in every test). The two hard truths: none of it protects anything a user can reach — no shipped entry point wires `AuthFetch`, so the redaction and leak-posture contracts here pin dead code (the matrix's own `network-auth` row says `not_started` while the `protocol-http` row's notes claim auth "landed"); and none of it executed in the committed baseline, because both baseline `cargo test` runs aborted before the streaming crate's test binary ran.

## 2. What actually works (verified)
— Vector quality: `digest_rfc2617_known_vector` (:977-1008) pins the RFC 2617 §3.5 constant `6629fae49393a05397450978507c4ef1` (an external constant — NOT generated by the code under test) and independently recomputes the legacy no-qop shape via `md5_hex` composition; `md5_rfc1321_vectors` (:932-948) includes the 62-byte vector that forces a two-block MD5 walk (62+1 padding → 120 bytes → 2×64-byte blocks, verified against `md5`'s padding loop :866-875); `base64_rfc4648_vectors` (:952-971) is the full RFC 4648 §10 table plus round-trip plus a malformed-input refusal.
— Behavioral pins verified against the production flow (read :647-743): `conservative_transport_gets_basic_fallback` asserts `logged.len() == 2` with header placement on hop 2 only — matches the `fetch` conservative arm (:733-740) and would fail if the probe leaked credentials or the retry were skipped; `downgrade_hop_never_receives_credentials` (:1274-1324) asserts `CrossSchemeRedirect { hops: 1 }` + exactly two `https://` requests — removing the gate at :624-626 would issue the `http` hop and break both the count and the scheme assertion; `cross_host_hop_never_receives_credentials` (:1401-1447) asserts the third hop is followed (default policy) but header-free — killing the allowed-host filter at :591-597 breaks it.
— Redaction pins are exact-format, not substring-only: :1113-1116 asserts the verbatim `Userinfo { username: "u", password: "[redacted]" }` Debug shape; store Debug pinned to entry-count-only (:1098-1100), wrapper Debug to booleans (:1102-1105, matches :749-756).
— `digest_parameters_are_escaped_and_control_bytes_refused` (:1456-1552) round-trips the escaping through the module's own `parse_auth_params` (losslessness, not just presence) and refuses CR/DEL/LF/NUL in nonce/realm/opaque/username — matches `escape_quoted_string` (:439-453).

### F-001 [S3]

What is wrong: the entire auth feature whose security contracts these 11 tests pin — credential redaction, challenge-first probing, downgrade/cross-host leak refusal — is constructed by zero production code. The shipped `lumen open http://user:pass@host/x` path parses the URL, drops the userinfo (demux_host only calls `Url::parse` for validation), and opens through a bare `UreqClient`: a 401-protected URL fails as a typed `HttpStatus{401}` error. What correct looks like: either wire `AuthFetch` into `SchemeRegistry::new()` (one-line composition, the pieces exist and are tested) and flip the matrix row to `implemented` with the e2e evidence, or strike the "auth incl. …" clause from the protocol-http notes so the matrix stops claiming landed-but-unwired code.
