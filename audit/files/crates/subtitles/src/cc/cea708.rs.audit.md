## 1. One-paragraph verdict
CEA-708 here is an honest SUBSET, not "full 708": DTVCC packet reassembly (cc_type 2/3, size-code formula `2×code+1`, re-lock on start), the service-block walk (4-bit service/size headers, two-byte escape for services 8–63, size 0 = 32), the service-1 → EIA-608 compatibility route, and — for native services 2–63 — an op-histogram record instead of any window/glyph interpretation. The module docs state this split plainly and the honesty table in `super` matches it; the 6 unit tests are real and pass when run. Two genuine defects: the CTA-708 §8.4.9 length table omits SET_CURRENT_WINDOW's parameter byte (walk desyncs after every 0x80–0x87 code), and every damage variant this file raises bypasses the advertised 256-event ledger cap by pushing straight into the decoder's vec. Plus a null-block conformance question the module itself flags with an unfilled "§?" citation. As with eia608.rs: none of this is reachable from a shipped binary.

## 2. What actually works (verified)
— verified by `cargo test -p subtitles --lib cc::cea708` → 6 passed: reassembly length arithmetic (code 2 → 5 bytes, exact byte vector), typed `DtvContinuationWithoutStart`, 6-bit size-code ceiling 63 → 127 < 128 cap ("defensive only" claim verified by the test asserting `r.expected == 127` with empty damage), escape form + zero-size = 32, truncated/bad-header typing, op histogram with correct DEFINE_WINDOW(7)/SET_PEN_COLOR(4) lengths.

## 3. Findings
F-001 [S3]
Where: crates/subtitles/src/cc/cea708.rs:139-155
Code (verbatim):
```
            // The window-bitmap and delay commands carry one byte.
            Cc708Op::ClearWindows
            | Cc708Op::DisplayWindows
            | Cc708Op::HideWindows
            | Cc708Op::ToggleWindows
            | Cc708Op::DeleteWindows
            | Cc708Op::Delay => 2,
            Cc708Op::SetPenAttributes => 3,
```
What is wrong: `Cc708Op::SetCurrentWindow` (0x80–0x87, declared at line 70-71) is missing from the 2-byte family and falls into `_ => 1` (line 154). Per CTA-708 §8.4.9, SET_CURRENT_WINDOW carries one parameter byte (the window ID) — total 2, exactly like every other 0x80–0x8D window command. Consequence in `walk_native_block` (292-303): after each SET_CURRENT_WINDOW the walk consumes the window-ID byte as the next opcode, desynchronizing the whole remaining block — the op histogram then records garbage (e.g. window ID 0x00 records a spurious `Miscellaneous`). Real 708 caption streams send SET_CURRENT_WINDOW constantly (every windowed cue). Why it matters: the histogram is the module's only evidence that native streams "parse" (its honesty-table claim), and it is wrong for the most common command after text. No test pins 0x80–0x87 (native_walk_counts_ops uses DEFINE_WINDOW/SET_PEN_COLOR/text only). What correct looks like: add `| Cc708Op::SetCurrentWindow` to the 2-byte arm and pin it in a test. Confidence: HIGH (spec table) — Verification: read; UNVERIFIED: no CTA-708 copy in tree (module cites the same §8.4.9 table).

What is wrong: `CcDecoder::note()` gates 608-path damage at `MAX_DAMAGE_EVENTS = 256` (mod.rs:226-230), but the 708 paths push directly into the same `self.damage` vec (mod.rs:252 passes `&mut self.damage` into `DtvccReassembler::push`, mod.rs:370 into `parse_dtvcc_packet`) with no cap. F-003 [S3]
Where: crates/subtitles/src/cc/cea708.rs:267-270, 271
Code (verbatim):
```
        if service == 0 {
            damage.push(CcDamage::UnknownService708 { service: 0 });

```
What is wrong: Per CTA-708, a service block header with service_number 0 and block_size 0 is the null block used to pad DTVCC packets to their declared size; conforming encoders emit them. This code records `UnknownService708 { service: 0 }` damage for every such header — damage-ledger noise on spec-conformant input (the break itself is harmless since padding trails the packet). The citation for the neighboring rule is literally "CTA-708 §?" — an unfilled section reference, so the module never pinned which spec section it implemented. Confidence: MEDIUM — Verification: read; UNVERIFIED against the CTA-708 text (no copy in tree). What correct looks like: treat (0,0) as end-of-walk padding, damage only service 0 with size ≠ 0.
