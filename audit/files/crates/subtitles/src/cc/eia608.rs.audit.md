## 1. One-paragraph verdict
This is a real EIA-608 channel state machine, not a stub: odd-parity helpers, the PAC row map (byte-identical layout to the ffmpeg `row_map`), mid-row/tab/misc control families, extended charsets, the 15×32 double-buffered grid with pop-on/roll-up/paint-on/text modes — and its 8 unit tests pass when run (`cargo test -p subtitles --lib cc::eia608` → 8 passed). Parity checking, the channel latch, and XDS skipping live in the caller (`cc/mod.rs:316-365`), which I verified feeds this code correctly. But the whole machine is dead code in the shipped product: no crate outside `crates/subtitles` and `fuzz/` depends on the `subtitles` crate, and the codecs H.264 SEI parser that the module docs cite as the "consume seam" throws type-4 (GA94 caption) payloads away as `Unparsed`. The matrix row `subtitle-cc-608-708` claims status `implemented` on win/linux/macos for this — that claim is false for any user-visible meaning of "implemented" (details in F-001, filed here because this file is the cited evidence).

## 2. What actually works (verified)
— verified by `cargo test -p subtitles --lib cc::eia608` → `test result: ok. 8 passed; 0 failed` (parity inverse property over all 128 bytes, PAC row pinning incl. indent clamp to col 31, charset spot-pins, mid-row column advance, roll-up scroll "1\r2\r3" shape, pop-on swap+erase, backspace/delete-to-end-of-row, PAC pen carry).
