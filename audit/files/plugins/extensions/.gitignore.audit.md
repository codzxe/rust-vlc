What is wrong: the ignore policy ("committed trees carry only the sources") is enforced only under `plugins/extensions/`. `lumenext package <ext-dir> [--out <file>]` (USAGE, lumenext.rs:55) accepts an arbitrary output path, and the root .gitignore's dedicated build-artifact section lists eight installer formats but not `*.lumenext` — an artifact packaged to the repo root, `docs/`, or anywhere else is silently committable, defeating the stated policy outside the one directory.
Why it matters: the repo's own history is the precedent — the root .gitignore's comment at :50-51 records a `__pycache__/` artifact "committed by accident in r1, removed in r3 — never again", and W01-A03 found `*.log` silently eating the baseline logs. Artifact-ignore gaps in this repo have already produced committed junk twice; this is the same shape for the plugin packaging lane.
What correct looks like: add `*.lumenext` to the root .gitignore's build-artifact block (with `!` exceptions if a lane ever needs to commit one, mirroring the `!docs/gates/logs/**` precedent), keeping the local file for documentation value.
Confidence: HIGH — Verification: read (both files; flag verified in USAGE and the `--out` plumbing at lumenext.rs:145-149).
