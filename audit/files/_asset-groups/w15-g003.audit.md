## 1. One-paragraph verdict
This group is the UI's bridge layer done honestly: a real transport seam
(app-transport.ts probes `window.__TAURI_INTERNALS__` once, picks
TauriTransport vs the badged DemoTransport, announces the choice), a
generated wire catalog that is the single source of truth for commands
(transport.ts is its only import site), real barrels/hooks with wide screen
consumption, and 16 i18n "lane key" staging files of which 15 are live
importer-backed fallback seams. Every one of the 50 assets exists, is sized
sanely (only demo-transport.ts at 992 LOC and the 344 KB variable font are
large, both legitimately), and is referenced by code or scripts — no orphans,
no stashed binaries, the woff2 is a genuine `wOF2` file with an OFL
LICENSE.txt beside it. The defects are hygiene: the production tree carries
wave/lane IDs in module names and comments (w26.a10.ts … w26.b15.ts, "the
Lead", "post-wave merge"), w26.a14.ts is a dead post-merge staging copy whose
two live keys are duplicated verbatim in the catalog with no machine check
comparing the two definition sites, and demo-transport.ts's header still
calls the desktop wiring "a separate GitHub issue" two landed issues later.
The catalog itself proves a cross-wave fact: `audio.set-eq` does not exist
among the 65 wire commands while ToolsDialog stages it — W8's finding,
corroborated from the type side.

## 3. Findings
### F-001 [S4] Generation-process lane IDs leaked into production module names and comments
Where: ui/src/i18n/keys/w26.a10.ts:1 (and the 15 sibling files in this group; same pattern across the group's client/component comments)
Code:
```
// w26.a14 — player control bar lane. Genuinely new keys introduced this lane
// (CONTRACT §4.5): the rebuilt bottom bar's additive controls (Player.svg
// bottom-bar composition). The Lead registers these into
```
(w26.a14.ts:1-3; identical convention in w26.a10/a12/a16/a17/a18/b01/b02/
b07–b13/b15, plus comments citing "w26.k18", "w28 fix 2", "the Lead",
"post-wave merge" in stripContext.ts, useSwitchLabels.ts, wire-time.ts,
window-controls.ts, demo-transport.ts, menu/index.ts, density.ts,
PlaylistPanel comments, etc.)
What is wrong: production source files are named after the internal
build-wave/lane that produced them (w26.a10 … w26.b15, 52 files in the dir;
16 in this group) and the comments narrate an internal sprint process
("the Lead", "after the wave merge") instead of the product.
Why it matters: zero functional impact; but module names that encode process
artifacts mislead any reader mapping code to features, and the scheme makes
the tree's structure indecipherable without the internal wave docs.
What correct looks like: rename to domain names (keys/player-controls.ts,
keys/onboarding.ts …) in a mechanical sweep; comments describe behavior, not
lanes.
Confidence: HIGH — Verification: read (file list + quotes above).

### F-002 [S3] w26.a14.ts is a dead post-merge staging copy duplicating catalog keys with no consistency gate
Where: ui/src/i18n/keys/w26.a14.ts:19-23; duplicate at ui/src/i18n/messages.ts:2169-2170
Code:
```
  /** Player.svg Frame 10 — the next-track transport glyph (right of the pill). */
  "player.controls.next": "Next",
  /** aria group name for the output cluster (fullscreen/cast/gear/menu). */
  "player.controls.group-output": "Player controls",
```
What is wrong: after the "Lead merge", this lane file has no importer
anywhere in ui/src, e2e, or scripts (`rg -l 'keys/w26.a14'` → only docs);
its two surviving keys are registered verbatim in the real catalog
(messages.ts:691-692 union, 2169-2170 values), and scripts/l10n-check.mjs
never compares lane files to the catalog (keys/ is excluded at
l10n-check.mjs:169-170 as a "definition site") — the two copies can drift
silently. Its other three keys were already pruned and grandfathered into
ui/i18n-dead-keys.json ("lane copy pruned from w26.a14.ts by w26.k18"), and
per docs/waves/w26/findings/w26.e14.md the components read local
CONTROLS_COPY constants instead of either copy.
Why it matters: dead code shipped in the tree + user-visible copy defined in
two ungated places; a future edit to one site changes nothing at runtime and
fails no check.
What correct looks like: delete the file (its live content is already in the
catalog), or add an l10n-check rule that lane-key unions ⊆ catalog.
Confidence: HIGH — Verification: rg census + Read of both sites + l10n-check
logic; registration confirmed in messages.ts.

Code:

//     separate GitHub issue. Nothing in this file fabricates engine

Why it matters: a reader auditing "is any UI element wired to a real
backend?" is told by this file that the desktop seam doesn't exist yet — the
opposite of the truth at HEAD (the seam exists; it is the tauri crate that
cannot compile, W14).
What correct looks like: update the header to point at app-transport.ts's
probe as the live selector.
Confidence: HIGH — Verification: Read of both files; rg selectAppTransport
main.tsx.
