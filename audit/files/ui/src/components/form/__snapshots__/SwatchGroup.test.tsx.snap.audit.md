## 1. One-paragraph verdict
Snapshot honesty, done right. The golden pins DOM structure and ARIA only — radiogroup with 9 radio swatches in the exact frame order, orange checked + tabbable, the rest roving-tabindex −1, dots aria-hidden — and every attribute in it traces to a real line of SwatchGroup.tsx. It is not load-bearing testimony: the test file's eight explicit behavioral tests (order, semantics, onChange, keyboard wrap-around, disabled group, per-option disabled, id wiring, custom options) already assert the important parts, and four css-contract tests pin the visual skin (per-accent dot colors, geometry, tokens) that a DOM snapshot structurally cannot see — so the classic "golden generated by the code under test proves nothing" failure mode is neutralized. One nit: the snapshot bakes React's internal useId prefix (`_r_8_`) into ids, an implementation detail that can break the golden on a React upgrade with zero product change.

## 3. Findings
### F-001 [S4]
Where: ui/src/components/form/__snapshots__/SwatchGroup.test.tsx.snap:7,15,30,45,60,75,90,105,120,135
Code:
```
  id="_r_8_"
```
(and every swatch id, e.g. `id="_r_8_-orange"`)
What is wrong: The golden hard-codes React's internal useId output. `_r_8_` is React-version-specific id generation (component renders without an `id` prop, SwatchGroup.tsx:67 `const autoId = useId()`); a React upgrade that changes the useId format fails this snapshot with zero product change — pure golden noise.
Why it matters: Spurious snapshot failures train developers to run `-u` (blind update), which is how goldens rot; pinning a library's internal detail is the classic trigger.
What correct looks like: render the snapshot case with an explicit `id="accent-picker"` (the j01-7 test already shows the prop exists) so the golden pins product structure, not React internals.
Confidence: HIGH — Verification: useId call site read; snapshot ids read; no other file references `_r_8_`.
