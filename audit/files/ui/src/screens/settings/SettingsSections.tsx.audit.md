## 1. One-paragraph verdict
Clean rendering layer: schema sections come from the GENERATED settings schema (generated/schema.ts, "do not edit" header, regenerated by npm run settings:generate with a drift guard), compound-widget keys are filtered so they render inside their widget row, hand-authored rows splice in at frame order via a pure helper, and `advanced` entries segregate behind ONE exported AdvancedDisclosure (a documented 3×-duplication fix) with a jsdom-guarded scrollIntoView. Master-question context verified one level up: SettingsScreen.tsx:461-462 constructs `createConfigSettingsPersistence(client, SETTINGS_ENTRIES)` when `isDesktopShell()` — the desktop lane's Apply round-trips real `config.set-setting`/`config.reset-setting` over TauriTransport with a hydration gate; the browser dev shell falls back to localStorage. Settings is therefore one of the genuinely backend-wired surfaces in the desktop build.

## 3. Findings
F-001 [S4]
Where: ui/src/screens/settings/SettingsSections.tsx:191
Code:
```
  const visible = rows.filter((row) => isSettingEntry(row) && row.featureExposed);
```
What is wrong: Nothing in the logic — flagging the trust boundary. `featureExposed` is baked at generation time from product.toml (schema.ts:41), so a feature that ships disabled in product.toml is hidden even if the running engine actually exposes the command (and vice versa: a schema row can be visible while the engine answers feature-not-exposed — the write path reports it via onWriteResult, which is honest, but the row still renders as if configurable). Static gate vs runtime capability are different things; the dialog-tool panels gate on the runtime command listing instead. Blast radius: cosmetic + a failed Apply. Confidence: MEDIUM — Verification: read (generator provenance from schema.ts:1-5; runtime listing gate seen in customize/panels.ts lane). Note: while auditing the adjacent SettingsScreen.tsx hydration gate I initially read line 464 as a syntax error (`const ydrated,`); `od -C` proved the file actually contains `const [hydrated,` — a display-pipeline artifact, NOT a defect. File is valid; baseline typecheck consistent.
