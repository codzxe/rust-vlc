## 1. One-paragraph verdict
This is a genuinely least-privilege Tauri 2 capability set, and the rare config file whose prose description can be cross-checked against code — mostly successfully. The permission list is `core:default` plus exactly four window-mutation grants; there is no shell, no fs, no http, no dialog, no opener plugin permission, and — decisive for the security-surface question — none of those plugins even exist as dependencies (Cargo.toml has only `desktop`, `commands`, `tauri`, `serde`), so there is nothing wide-open to open. The four explicit grants map 1:1 to verified UI invoke sites plus the drag-region attribute path. The description's claim that the four window grants are "the ONLY direct core commands the UI may invoke" is false as written: the UI also directly invokes `plugin:window|is_maximized`, `plugin:event|listen`/`unlisten`, and `plugin:__TAURI_CHANNEL__|fetch` — all covered by `core:default` (and the channel fetch is ACL-exempt in tauri itself). No security impact, but the file's self-inventory of its own surface is wrong, and the UI's own header says so.

## 2. What actually works (verified)
— The four grants match the exact commands the UI sends: ui/src/client/window-controls.ts:70-72 `minimize: () => invoke("plugin:window|minimize")`, `toggleMaximize: () => invoke("plugin:window|toggle_maximize")`, `close: () => invoke("plugin:window|close")`; start_dragging rides `data-tauri-drag-region` (AppShell.tsx:541 `<header className="app-shell__banner" data-tauri-drag-region="deep">`), which tauri's drag.js routes through the granted command. Verified by rg + Read.
— `core:default` expansion verified byte-verbatim from the locked crate (Cargo.lock:3688-3689 `name = "tauri"` / `version = "2.12.5"`), file ~/.cargo/registry/src/.../tauri-2.12.5/permissions/{app,event,image,menu,path,resources,tray,webview,window}/autogenerated/reference.md: 9 plugin default sets; `core:window:default` = 28 read-only queries + `allow-internal-toggle-maximize`, including `allow-is-maximized` (which the UI uses, window-controls.ts:75).
— Single-command rule verified: app.rs:293 `.invoke_handler(tauri::generate_handler![lumen_dispatch])` — exactly one command; enforced by tests/single_command.rs (§7.4 anti-bypass).
— `windows: ["main"]` matches the single window tauri.conf.json defines (label "main", line 13); a second window would get NO capability (fail-closed), and remote origins are rejected absent an explicit `remote` capability (tauri-2.12.5 src/webview/mod.rs:2076-2079).

## 3. Findings
F-001 [S3]
Where: apps/desktop-tauri/capabilities/default.json:4 (description)
Code: "The window grants are the ONLY direct core commands the UI may invoke (plugin:window|minimize / toggle_maximize / close / start_dragging):"
What is wrong: The UI invokes at least three more direct core commands: `plugin:window|is_maximized` (window-controls.ts:75 `internals.invoke("plugin:window|is_maximized", { label })`), `plugin:event|listen`/`unlisten` (window-controls.ts:79, 90), and `plugin:__TAURI_CHANNEL__|fetch` (frame-channel.ts:288 comment; ACL-exempt in tauri — src/webview/mod.rs:2081-2082 `// TODO: Remove this special check in v3` / `&& request.cmd != crate::ipc::channel::FETCH_CHANNEL_DATA_COMMAND`). The UI's own header contradicts this file: window-controls.ts:21-22 "`is_maximized` and the `tauri://resize` listen are covered by / `core:window:default` / `core:event:default` inside `core:default`." Why it matters: this description is the security documentation of the file; an auditor reading only it under-models the webview's command surface by two command families and one exempt internal command. What correct looks like: "the only direct core MUTATING commands" or enumerate is_maximized/event-listen as default-covered. Confidence: HIGH — Verification: read + rg across ui/src.

F-003 [S4]
Where: apps/desktop-tauri/capabilities/default.json:7
Code: `"core:default",`
What is wrong: least-privilege residue — `core:default` ships the full default sets of plugins this app never uses: full menu mutation (core:menu:default: allow-set-as-app-menu, …), full tray mutation (core:tray:default), `core:image:allow-from-path` (webview can request the shell load an image from an arbitrary filesystem path), `core:event:allow-emit`/`allow-emit-to` (a compromised webview could forge `lumen://event` engine events — though it could equally call `lumen_dispatch` directly, so no escalation), and `allow-internal-toggle-maximize`. Standard Tauri posture, all verified from the vendored 2.12.5 reference.md files; note for tightening, not a defect of this file's own choosing. Confidence: HIGH — Verification: read vendored ACL manifests.
