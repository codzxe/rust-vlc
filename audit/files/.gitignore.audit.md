## 3. Findings
### F-001 [S2] — global `*.log` rule silently excluded the audit program's own baseline evidence from git
Where: .gitignore:31-38; impact on audit/runs/baseline/INDEX.md (Log column)
Code:
```gitignore
# Logs & temp (gate logs are COMMITTED — D-d protocol, 3.MERGE-1)
*.log
!docs/gates/logs/**
!docs/gates/logs/*.log
```
What is wrong: The exceptions cover only `docs/gates/logs/` and
`docs/packaging/evidence/`. Everything else `.log` in the tree is ignored —
including `audit/runs/baseline/*.log`. Proof:
`git check-ignore -v audit/runs/baseline/test-workspace.log` →
`.gitignore:32:*.log  audit/runs/baseline/test-workspace.log`;
`git ls-files audit/runs/baseline/` → 17 files (INDEX.md, 10 `.txt`, 2 hygiene
`.txt`, 4 sample `.mp4`) — ZERO of the ~24 `.log` files INDEX.md's Log column
cites (build-release-workspace.log, test-workspace.log, clippy-workspace.log,
full-gate.log, xtask-*.log, gate-*.log, ui-*.log, cargo-deny-*.log,
rc-smoke-engine-only.log …). `git log --all --follow -- 'audit/runs/baseline/test-workspace.log'`
→ empty: that exact file was never committed on any branch. The only .log
commit in history (e5a42200, a stale 2026-11-16 audit branch, not an ancestor
of HEAD) carries different filenames (cargo-test-workspace.log, ui-npm-install.log).
Why it matters: AGENT-INSTRUCTIONS.md orders every agent: "Wave 0 baseline
evidence (build/test/smoke outputs) is committed under audit/runs/baseline/ —
cite it instead of re-running builds." That claim is materially false for all
`.log` evidence: the verbatim run outputs exist only in the wave-0 sandbox and
are unrecoverable from this repo. Every downstream citation of a baseline
`.log` is trust-in-prose, not verifiable evidence — the audit chain's
"verify every quote" rule is broken at its root. The `.txt` smoke files got
committed precisely because they dodge this rule — the asymmetry (txt in, log
out) proves the mechanism.
What correct looks like: add `!audit/runs/**` (and `!audit/runs/**/*.log`)
next to the existing negations, or commit evidence as `.txt`; then have the
orchestrator re-add the wave-0 logs with `git add -f audit/runs/baseline/*.log`.
Confidence: HIGH — Verification: ran git check-ignore / ls-files / log --all
(probes pasted above).
