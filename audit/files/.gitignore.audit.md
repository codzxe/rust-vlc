## 1. One-paragraph verdict
The ignore set does its primary jobs: `target/` and `node_modules/` are
ignored (L2, L10), secrets patterns (`.env*`, `*.pem`, `*.key`, `secrets/`)
are excluded with the one intentional `!.env.example` carve-out, Cargo.lock
is explicitly documented as COMMITTED (L91-94, matching reality — the
lockfile is in-tree and CI builds --locked), and the evidence-log
carve-outs point at real committed content (docs/gates/logs/*.log and
docs/packaging/evidence/*.log exist on disk). Nothing suspicious is hidden:
every "environment dir" pattern (skills/, upload/, agent-ctx/, worktrees/,
tool-results/) matches nothing on disk; the only ignored dir with content
is download/ holding a one-line generated-files marker README. The defects
are all hygiene: one redundant `/target` duplicate of `target/`, a global
`*.log` ignore whose evidence carve-outs are narrower than the repo's
evidence-producing surface (and half-redundant), and a global `*.snap`
ignore that already caused one CI incident (ui snapshots silently
untracked — the W25 fix comment) and will bite again the moment a Rust
snapshot test lands.

## 3. Findings
F-001 [S4]
Where: .gitignore:106 (vs L2)
Code:
```
# Wave-1 corpora (regenerable via recorded seeds; too big for git)
/corpus-big/
/target
corpus-v4/
```
What is wrong: `/target` is a strict subset of the L2 rule `target/`
(which matches at every depth, root included). The file's own L112-114
comment celebrates dropping a lane-g duplicate of `target-xtask/`
("duplicate dropped in the rehearsal union") while this duplicate of
`target/` survives two lines below it. Why it matters: duplication in an
append-mostly file accretes; the dedup discipline the comment claims is
not actually applied. What correct looks like: delete L106.
Confidence: HIGH — Verification: read + pattern semantics.
F-002 [S4]
Where: .gitignore:31-38
Code:
```
*.log
!docs/gates/logs/**
!docs/gates/logs/*.log
```
(and the parallel packaging pair L37-38)
What is wrong: a global `*.log` ignore with exactly two carved-out
evidence directories. (a) Any future lane that writes a .log anywhere else
— e.g. an rc-smoke log under scripts/, or a baseline log under audit/ —
is silently untracked; this repo's D-d evidence protocol depends on every
producer remembering the carve-out. (b) L34 `!docs/gates/logs/*.log` and
L38 `!docs/packaging/evidence/*.log` are redundant: the preceding `/**`
unignores everything below those dirs, including .log files. Why it
matters: redundant rules imply a precision that is not there, and the
global ignore is a standing trap for evidence workflows. What correct
looks like: `/logs/` + `tmp/` style anchored patterns for scratch logs,
or drop `*.log` entirely and ignore the specific log-producing dirs.
Confidence: HIGH — Verification: read (gitignore `**` semantics).
F-003 [S4]
Where: .gitignore:82 + 84-88
Code:
```
*.snap
```
with
```
!ui/src/**/__snapshots__/*.snap
```
What is wrong: the Linux-package rule `*.snap` globally ignores ALL
`.snap` files and the only re-include is the UI vitest path. The file's
own comment records that this exact shape already caused a CI failure
("a fresh checkout had none and CI vitest failed on all 8 files" — the
W25 fix). Today nothing else matches (find for *.snap outside ui/ ->
none), but the first Rust insta-snapshot (or snapshot in apps/web, or
tools/) will be silently untracked and the same incident repeats. What
correct looks like: `/*.snap`, `/target/**/*.snap` or an anchored
packaging dir pattern instead of the global `*.snap`.
Confidence: HIGH — Verification: ran (find: 0 .snap outside ui) + read.
