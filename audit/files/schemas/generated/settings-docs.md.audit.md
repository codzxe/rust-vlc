## 1. Blunt verdict

byte-checked against regeneration by a passing test, and every sampled row
(counts, types, defaults, domains, restart flags, gates, D1 references)
matches schemas/settings.toml and product.toml exactly. What is false is the
reference's practical promise: the "CLI flag" column documents 121 flags and
the shipped `lumen` binary rejects every one of them — I executed
`--audio-volume-step` myself: `error: unknown command`, exit 64. Same root
cause W11-A04 proved exhaustively on the G2 golden (settings-help.txt, S0).
A user reading this reference to configure the player from the command line
is documenting 121 options that do not exist.

| Key | Type | Default | Domain | Since | Restart | CLI flag | Gate |
|---|---|---|---|---|---|---|---|
| `audio.volume-step` | `int` | `1` | 1..25 | 0.1.0 | — | `--audio-volume-step` | — |

What is wrong: the reference documents 121 CLI flags; the shipped `lumen`
binary parses none of them. Own execution: `./target/debug/lumen
--audio-volume-step 5` -> `error: unknown command `--audio-volume-step``,
exit 64. A settings reference whose actionable content (how do I set this
from the CLI?) is 100% non-functional is a false user-facing claim, not a
formatting nit. Root cause already S0-filed by W11-A04 on the G2 golden
(settings-help.txt) — same defect, second artifact. What correct looks like:
either wire the generated flags into the CLI parser (doc 07 §5.3 G2's
promise) or mark the column as schema-only/unimplemented in the generated
output.
Confidence: HIGH — Verification: ran (exit 64).
F-002 [S4]
Where: schemas/generated/settings-docs.md:108,138,269
Code:
```
| `global.log-file` | `path` | `""` | — | 0.1.0 | — | `--global-log-file` | — |
```
What is wrong: three entries document empty-string defaults for path/url
types (global.log-file, interface.skin-file, privacy.lastfm-submission-url).
The empty default is legal at parse time only via a carve-out
(parse.rs:337-343 "an EMPTY string default on a Path/Url entry is legal");
the runtime write path still rejects the same value (model.rs:367-374
V-FORMAT "paths cannot be empty"). So `config.set-setting` cannot restore a
setting to its own documented default; only reset-setting can. The
generated reference renders `""` with no hint of this asymmetry.
Confidence: HIGH — Verification: read parse.rs:333-343 + model.rs:367-381.
