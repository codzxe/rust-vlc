#  vbr_q4 12K) and one [corpus.<name>] section per real-corpus MP3

# (corpus is /tmp-resident; the corpus differential SKIPs with a
# message when absent — the fixture rows are the always-on coverage).
#
# PROVENANCE (honesty rules): every fixture's PCM essence is authored
# by the external ffmpeg 7.1.5-0+deb13u1 encoder (oracle, never a
# dependency) during the 5.A3 dev sessions — libmp3lame for the Layer
# III set (CBR 128k stereo 44.1 kHz; VBR q4; mono 48 kHz; MPEG-2 LSF
# 24 kHz; the same CBR audio plus a large ID3v2.3 tag + embedded art
# for tagged_art), the mp2 encoder for the Layer II 48 kHz stereo
# file. All facts below were re-derived live this session with the
# exact commands:
#   ffmpeg -i F -map 0:a -c:a pcm_s16le -f md5 -        (ffmpeg_pcm_md5)
#   ffmpeg -i F -map 0:a -c:a pcm_s16le -f s16le -      (sample counts)
#   ffprobe -select_streams a -show_entries stream=sample_rate,channels
#
# THE GAPLESS WINDOW (what each side decodes — the card's mandate to
# document it exactly): ffmpeg decodes the LAME-tagged Layer III
# fixtures to exactly frames × spf − delay − padding samples
# (its mp3 demuxer exports skip_samples/trim from the LAME tag),
# Layer II/MP2 to all frames × 1152 (no tag). Lumen decodes the same
# window: Xing/Info header frame excluded from the audio count, raw
# pipeline window [delay, total − padding) SHIFTED by +529
# samples/channel — the Layer III synthesis-pipeline latency that
# symphonia's raw output carries and ffmpeg's never emits (measured:
# exhaustive shift search, bit-exact ±1 LSB once aligned; see
# src/audio/mp3/decoder.rs module doc). Both windows therefore cover
# the SAME samples; lumen_pcm_md5 is Lumen's s16le MD5 over that
# window (regression pin — a lossy decoder's MD5 is NOT expected to
# equal ffmpeg's), and max_sample_delta is the measured per-sample
# |lumen − ffmpeg| bound on the aligned window (the honest lossy-
# decoder tolerance: ±1 LSB rounding).
